# Соглашения базы

> [!abstract] О чём
> Единый контракт оформления: YAML, структура конспекта, стиль текста, ссылки, задачи.
> Соблюдается во **всех** дисциплинах и **курсах `02_Курсы/`** — именно это делает базу одним
> ресурсом, а не набором папок. Шаблоны, реализующие контракт, лежат в `Шаблоны/`.
> Расхождения допустимы только там, где они описаны явно (например, у курсов нет `teacher`,
> а `subject` содержит название курса).

# 1. YAML-заголовок

Порядок ключей фиксирован. Пустое значение допустимо только у `teacher` и `related_lecture`. `date` обязательно в заметках дисциплин и в оглавлении конкретного курса; у лекций, практик и мини-проектов в `02_Курсы/` его не ставят.

```yaml
---
date: 2026-09-23          # для дисциплин и оглавления курса: дата создания файла, YYYY-MM-DD
subject: Технология разработки ПО   # как в названии папки дисциплины, без номера
teacher: Подтяжкин Владимир Дмитриевич
type: лекция              # лекция | практика | курс | аудит | контекст | соглашение
                          # | реестр | бэклог | журнал (полный список — в проверка_базы.py)
related_lecture: "[[03. Жизненный цикл ПО]]"   # только у практик
tags:
  - тема-в-нижнем-регистре   # минимум 3 тега, kebab-case, кириллица допустима
author: Архипов Павел     # во всех материалах, где есть авторство
status: черновик          # черновик | в работе | готово
---
```

Для отдельного курса дата создания хранится **только в его оглавлении** `02_Курсы/<папка курса>/00. <Название курса>.md`. Из YAML лекций, практик и мини-проектов этого курса поле `date` удаляется. Семестр, учебный год, срок сдачи и дата занятия не являются датой создания заметки и записываются в тексте только там, где это нужно по смыслу. Общий каталог `02_Курсы/Курсы — обзор.md` — не оглавление отдельного курса.

Пустое или отсутствующее поле `status` **семантически равно `черновик`**: такая заметка никогда не считается готовой. В новых файлах `status` всё равно указывается явно; при импорте легаси-поля checker трактует его как `черновик` и сообщает о пропуске.

**Значения `status`:**

| Значение | Когда ставить |
|---|---|
| `черновик` | Записано с пары, не вычитано, нет служебных разделов |
| `в работе` | Структура есть, но остались открытые `- [ ] #task` или пустые подразделы |
| `готово` | Все задачи закрыты и удалены, служебные разделы заполнены, связи проставлены |

> [!note] Как это выглядит в `02_Курсы/`
> Заметки курсов пишутся по тому же контракту и проверяются тем же скриптом, отличия минимальны:
> `subject` — название курса (`Инженерные практики Python`, `NumPy`), `teacher` не нужен,
> `type` — `лекция`, `практика` или `курс` (для оглавления курса), у практик заполняется
> `related_lecture`. Дата создания есть в YAML только оглавления `00. <Название курса>.md`;
> лекции, практики и мини-проекты курса не получают `date`. Служебные файлы курсов
> (прототипы, тестовые прогоны) в заметки не попадают: все числа в примерах — из фактических
> прогонов, зафиксированные в тексте.

> [!tip] Правило тега
> Тег — это то, по чему заметку найдут через полгода. `жизненный-цикл-ПО`, `scrum`, `dfd`.
> Не теги: `лекция`, `важное`, `конспект`.

# 2. Структура лекции

```text
# Заголовок (= имя файла без номера)

> [!abstract] О чём эта лекция
> **Зачем это нужно.**
> **Что ты должен уметь после лекции:**

# Разделы темы            ← только то, что реально было на паре
...
# Ключевые термины        ← таблица «Термин | Определение»
# Типичные заблуждения    ← список «❌ «Миф». Опровержение.»
# Связи с другими темами  ← список ссылок с пояснением «зачем идти»
```

# 3. Структура практики

```text
# Заголовок

> [!abstract] Что за работа
> **Теория:** ссылка на лекцию
> **Что даёт результат:**

# Ход работы
# Вывод
# Связи с другими темами
```

Практика всегда имеет `related_lecture`. Если работа состоит из задач, каждая задача —
`## Задача N. Название`, условие и ответ разделяются, ответ оформляется как ответ, а не как черновик.

# 4. Структура `00_Курс.md` (оглавление дисциплины)

Обязателен в **каждой** дисциплине. Разделы:

1. `> [!abstract] Что такое «X» как предмет` — в 2–3 предложениях, о чём дисциплина на самом деле.
2. **Преподаватель / период в базе / состав материалов** — и они должны соответствовать реальности.
3. **Как проходить курс** — схема порядка тем + таблица «практика → после какой лекции».
4. **Уровни курса** — что считается базовым, средним и профессиональным уровнем по этой дисциплине.
5. **Оглавление** — по каждой заметке: 1–2 предложения о теме + строка «*Ключевое:*».
6. **Все материалы курса** — Dataview-таблица.
7. **Карта понятий курса** — сквозные понятия: где определено → где применяется.
8. **Связи с другими дисциплинами** — таблица пересечений.
9. **Подготовка к экзамену** — опоры, по которым повторяется курс.

Dataview-блок:

````markdown
```dataview
TABLE WITHOUT ID
  file.link AS "Материал",
  date AS "Дата",
  type AS "Тип",
  status AS "Статус"
FROM "01_Дисциплины/<папка дисциплины>"
WHERE file.name != "00_Курс"
SORT file.path ASC
```
````

# 5. Именование файлов

| Тип | Формат | Пример |
|---|---|---|
| Оглавление дисциплины | `00_Курс` | `00_Курс.md` |
| Лекция | `NN. Тема` | `03. Жизненный цикл ПО.md` |
| Практика | `NN. Тема` | `02. Вариант 6. Система учета заказов…md` |
| Папка дисциплины | `NN_Название` | `01_Технология_Разработки_ПО` |
| Внутри дисциплины | `01_Лекции`, `02_Практика` | — |

Правила: номер и точка обязательны (по ним работает порядок и ссылки);
имя файла — это заголовок H1; точка в конце имени запрещена;
название дисциплины — через точку с пробелом (`07. Основы Философии`) **или** через подчёркивание,
но единообразно: новые папки — `NN_Название`.

# 6. Самодостаточность конспекта (важно для выгрузки)

База выгружается в **NotebookLM**, где из неё генерируются тесты для самопроверки.
Отсюда два следствия, обязательных при оформлении:

1. **Блоки «Проверь себя» в конспекты не пишутся.** Вопросы генерирует NotebookLM —
   дублировать эту функцию в тексте не нужно. **Исключение — курсы дисциплин** (так собран курс
   дисциплины 02): там блок «Проверь себя» допустим, но обязательно с ответами под свёрнутой
   врезкой `> [!example]- Ответы`, иначе самопроверка превращается в список вопросов без ответов.
2. **Конспект должен читаться отдельно от остальных.** Определение понятия живёт в той же заметке
   (в тексте или в «Ключевых терминах»), а не только по ссылке. Ссылка — это указатель «где подробнее»,
   а не единственный носитель смысла.
3. **Каждая конструкция в примере кода объяснена или помечена.** Правило курса (введено после
   ревью 25.09.2026): то, что встречается в примере, либо разобрано в этой или более ранней лекции,
   либо рядом стоит пометка — «(продвинутое)», «подробнее — в лекции N», «подробнее — в инженерном
   модуле». Иначе читатель решает, что пропустил тему, и не спрашивает.
4. **Название функции или процесса сопровождается примером.** Если в тексте назван вызов, шаг
   или приём, рядом показывается короткий пример его использования.
5. **Незнакомый API объясняется на месте.** Если код использует тип ошибки, атрибут, параметр
   или результат метода, рядом объясняется, что это такое и зачем применяется; не отправлять
   читателя искать базовое объяснение в интернете.
6. **Маленькая самостоятельная тема не раздувается до курса.** Если она требует практики, но не
   многостраничной программы, допустим компактный модуль: отдельная папка, одна лекция и одна
   практика. Создавать его только при реальной необходимости, не заранее.

Подробно — [[Выгрузка_в_NotebookLM]].

# 7. Стиль текста

- **Заголовки** — только `#` … `###`; каждый заголовок обязан иметь содержимое.
  Пустой заголовок-заглушка допустим только как разделитель групп, если у него есть дочерние.
- **Callout'ы** — по назначению:
  `[!abstract]` вступление · `[!note]` уточнение · `[!tip]` как применить ·
  `[!warning]` где ошибаются · `[!important]` правило · `[!example]` разбор.
- **Таблицы** — для сравнений и перечней «параметр → значение».
- **Код** — в ``` ``` ``` с указанием языка. Текст **никогда** не заворачивается в code fence.
- **Схемы** — Mermaid (`flowchart`, `gitGraph`, `sequenceDiagram`) либо draw.io в `Диаграммы/`.
- **Обращение** — на «ты», как в существующих конспектах дисциплины 01.
- **Языки изучаемой культуры** — в философском материале можно приводить оригинальное слово или иероглиф, только если это помогает понять понятие. Обязательно рядом дать транслитерацию и объяснение по-русски; основной учебный текст остаётся русскоязычным.
- **Тире** — длинное `—` в тексте, дефис `-` только внутри слов.
- **Запрещено:** пустые заголовки без названия (`## 2.`), текст внутри code fence,
  незакрытые задачи в готовом конспекте, ссылки без пояснения.

# 8. Ссылки и связи

- Полное имя заметки вместе с номером: `[[02. Структура CASE-технологии. Структура среды разработки]]`.
- Ссылка на раздел: `[[03. Жизненный цикл ПО#Аналитика]]`; на конкретное место — блок-якорь `^xxxxxx`.
- В таблице экранировать пайп: `[[03. Жизненный цикл ПО#Аналитика\|Лекция 03]]`.
- **Алиас обязателен**, если ссылка ведёт на раздел или якорь: NotebookLM не раскрывает вики-ссылки
  и увидит только текст алиаса.
- Раздел «Связи с другими темами» — **обязателен** в каждом конспекте.
  Минимум: своя практика/лекция, соседняя тема курса, `00_Курс`, хотя бы один конспект
  **другой дисциплины**, если пересечение есть.
- Якоря `^xxxxxx` ставятся на разделы, на которые ссылаются извне (этапы ЖЦ, ключевые определения).

## Проверка ссылок раз в месяц

Ссылки на существующий материал проверяются **раз в месяц** — и сразу после любого переименования файлов или заголовков.

| Что проверять | Как | Что делать с результатом |
|---|---|---|
| Внутренние ссылки между заметками (`[[…]]`, якоря `^xxxxxx`) | `python3 00_Мета/проверка_базы.py` — в выводе не должно быть строк «битая ссылка» | Исправить ссылку под фактическое имя файла (имена файлов не откатывать, если владелец переименовал их сам) |
| Внешние ссылки (`http…` в лекциях и `00_Курс`) | Открыть каждую вручную или инструментом просмотра страниц; локальные адреса вида `127.0.0.1` пропускаются | Мёртвую ссылку заменить проверенной или убрать, рядом с заменой указать дату проверки |
| Ссылки «дисциплина ↔ курс» | По правилу приоритета ниже | Привести ссылки в соответствие |

**Приоритет дисциплин.** Когда тема есть и в дисциплине (`01_Дисциплины/`), и в курсе (`02_Курсы/`), основным материалом считается **дисциплина**. Следствия:

- курс ссылается на лекцию дисциплины как на первоисточник («Опора на дисциплину») и расширяет её, а не пересказывает;
- в ссылках «курс ↔ дисциплина» основная ссылка ведёт в дисциплину, ссылка в курс — как «углубление»;
- если содержание расходится, правится курс, а не дисциплина;
- у новых тем сначала проверяется, нет ли их в дисциплине.

Журнал проверок: 29.09.2026 — внутренние ссылки: битых 0 (восстановлены 14 ссылок на `02. Линии. настройка`); внешние: 5 ссылок дисциплины 02 (`docs.python.org`, `stepik.org` ×2, `py.checkio.org`) открываются. Следующая проверка — до 29.10.2026.

> [!warning] Переименование файла или раздела
> `alwaysUpdateLinks: true` в `app.json` правит ссылки автоматически **только при переименовании
> внутри Obsidian**. При переименовании файлом или через git ссылки нужно чинить вручную —
> и проверять не только свою дисциплину.

# 9. Задачи

Формат — плагин Tasks:

```markdown
- [ ] #task Что сделать. Конкретно и проверяемо 📅 2026-09-30
```

- Дата `📅` обязательна: без неё задача не попадает в выборки.
- Задача пишется **там, где её нужно выполнить** — в соответствующем разделе конспекта.
- После выполнения задачу **удалить вместе со строкой**, а не отмечать `[x]`.
  История остаётся в git и в [[Журнал_изменений]].
- Задачи, которые нельзя выполнить без владельца (личные данные, решение о новом разделе),
  переносятся в [[Бэклог]] и из конспекта убираются.
- После переноса задач из ежедневника в [[Бэклог]] и метаданные ежедневник очищается от второго
  списка `- [ ] #task`; в нём остаётся короткая ссылка на место, где теперь ведётся работа.

# 10. Шаблоны

| Шаблон | Для чего |
|---|---|
| `Шаблоны/Лекция.md` | Новый конспект лекции (Templater) |
| `Шаблоны/Практика.md` | Новая практическая работа (Templater) |
| `Шаблоны/Курс.md` | `00_Курс.md` для новой дисциплины |
| `Шаблоны/Лекция_legacy.md` | Ручной конспект «как есть» — для быстрой записи с пары |

Легаси-шаблон намеренно минимальный: конспект пишется с пары, когда некогда.
Такой файл имеет `status: черновик` и доводится до контракта отдельным проходом
(это нормальный путь: `черновик` → `в работе` → `готово`).

# 11. Уровни и связи курсов

В `02_Курсы/` курс помечается уровнем в оглавлении и общем каталоге:

| Уровень | Правило |
|---|---|
| **Начальный** | Не требует другого стороннего курса; объясняет предмет с нуля или опирается только на базовую дисциплину. |
| **Продвинутый** | В `00. <Название курса>.md` явно указывает необходимые курсы и знания, а также следующий результат. |
| **Мини-тема** | Небольшой самостоятельный модуль — отдельная папка, одна лекция и одна практика; не создавать пустую папку заранее. |

`02_Курсы/Курсы — обзор.md` — общий каталог, где фиксируются уровни, зависимости, рекомендуемый порядок и темы, которые можно проходить параллельно. Связанные курсы ссылаются друг на друга; отсутствие обязательной зависимости отмечается явно.
