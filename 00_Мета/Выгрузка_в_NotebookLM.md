# Выгрузка базы в NotebookLM

> [!abstract] Зачем этот файл
> База используется не только как хранилище Obsidian: она **выгружается в NotebookLM** (с 16.07.2026 продукт
> называется Gemini Notebook), где из конспектов генерируются тесты, флеш-карты и майнд-мапы для самопроверки.
> Это меняет требования к конспектам — и объясняет, почему в базе **нет** блоков «Проверь себя»:
> вопросы генерирует NotebookLM, а не текст конспекта.

---

# 1. Что это значит для стиля конспекта

| Требование | Почему |
|---|---|
| **Понятие определено там, где впервые используется, или в «Ключевых терминах» этой же заметки** | Модель отвечает только по загруженному тексту. Если определение живёт в другой заметке, а загружена одна — вопрос останется без опоры |
| **Ссылка-вики всегда с осмысленным алиасом** | NotebookLM не раскрывает `[[…]]`: текст `[[03. Жизненный цикл ПО#^etap-analitika\|Аналитика]]` он увидит как «Аналитика». Алиас — это то, что реально попадёт в контекст |
| **Таблица терминов в конце каждой лекции обязательна** | Это готовый словарь для флеш-карт: «термин → определение» переносится в карточку без переформулировки |
| **«Типичные заблуждения» писать через «❌ Миф. Опровержение.»** | Из этой пары получается качественный вопрос с подвохом, а не пересказ |
| **Один раздел — одна мысль, заголовок называет её** | При генерации вопросов модель опирается на структуру заголовков: размытый заголовок даёт размытый вопрос |
| **Факты, которые устаревают, помечать датой** | Иначе модель выдаст устаревшее как актуальное. В базе для этого есть формулировка «Снимок на MM.YYYY» |

> [!important] Отсюда следует правило для новых конспектов
> Конспект должен быть **самодостаточным для выгрузки**: прочитанный отдельно от остальных, он не должен
> содержать мест, где смысл зависит от невидимого текста. Связи с другими темами при этом остаются —
> они полезны в Obsidian, — но не должны быть единственным носителем определения.

# 2. Что загружать, а что нет

**Загружать:** только `01_Дисциплины/`.

**Не загружать:**

| Папка | Почему |
|---|---|
| `00_Мета/` | Это служебная информация о самой базе. Попав в источники, она даст вопросы вида «кто автор базы» и «какой статус у заметки» — мусор в тесте по предмету |
| `Шаблоны/` | Плейсхолдеры `[[01. Название лекции]]` породят вопросы по несуществующему материалу |
| `.obsidian/`, `Вложения/`, `Диаграммы/` | Настройки и бинарные файлы; изображения из `![[…]]` в markdown-источнике всё равно не читаются |

**Внутри конспектов шум, который стоит учитывать** (не критично, но снижает качество):

- блоки ```` ```dataview ```` — в выгрузке это просто текст запроса;
- строки блок-якорей `^ponyatie-kachestvennogo-koda` — видны как отдельные строки;
- YAML-заголовок — наоборот **полезен**: предмет, преподаватель и дата дают модели контекст.

# 3. Как нарезать на источники

Лимиты NotebookLM (проверено 23.09.2026): **500 000 слов на источник**, **200 МБ** на файл,
**50 источников на ноутбук** в бесплатном тарифе (100 в Plus, 300 в Pro). Markdown поддерживается как тип источника.
Объём всей базы — около **38 тыс. слов**, то есть в лимит не упираемся ни при какой нарезке.

| Нарезка | Источников | Когда выбирать |
|---|---|---|
| **По дисциплине** (рекомендуется) | 7 | Нужны сквозные вопросы по курсу: «свяжите этап ЖЦ с инструментом VCS». Цитаты указывают на дисциплину |
| По лекции | ~20 | Нужна точная цитата на конкретный конспект и вопросы в рамках одной темы |
| Всей базой одним файлом | 1 | Быстро, но цитаты становятся бесполезными, а вопросы смешивают философию с Git |

**Один ноутбук = одна дисциплина.** Смешивать предметы в одном ноутбуке не стоит: модель начнёт
строить вопросы на пересечении тем, которых в реальности нет.

# 4. Настройка генерации

- **Custom instructions** (лимит 10 000 символов) — сюда стоит вписать:
  «Вопросы только по загруженным конспектам. Уровень — студент колледжа, программа "Технология разработки ПО".
  Не использовать знания вне источников. В ответах опираться на раздел "Ключевые термины"».
- **Quizzes / Flashcards** — основной инструмент самопроверки; в бесплатном тарифе есть дневные лимиты.
- **Mind map** — полезен как проверка структуры: если карта не повторяет оглавление `00_Курс`,
  значит, заголовки конспекта названы размыто.

# 5. Как выгружать

Скрипт `00_Мета/экспорт_в_notebooklm.py` собирает по одному файлу на дисциплину в папку `_Экспорт/`
(в git не попадает — добавлена в `.gitignore`):

```bash
python3 00_Мета/экспорт_в_notebooklm.py
```

Что делает скрипт: берёт только `01_Дисциплины/`, склеивает заметки дисциплины по порядку файлов,
добавляет заголовок-разделитель с именем исходной заметки, вырезает блоки `dataview` и строки блок-якорей,
сохраняет YAML первой заметки как шапку документа.

> [!tip] После обновления конспекта
> Экспорт — снимок. После правок в Obsidian файл в `_Экспорт/` нужно пересобрать и **перезагрузить источник**
> в NotebookLM: сам он не обновится.
