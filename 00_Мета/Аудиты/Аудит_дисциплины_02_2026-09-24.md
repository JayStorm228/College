# 3. Главный разрыв: конспекты отстают от собственного кода

Код в `CollegeProgramming-master` — это **другой уровень**, чем текст конспектов.
Практически вся инженерия, которой владеет автор, в конспект не попала.

| Что уже есть в коде автора | Где именно | В конспектах |
|---|---|---|
| `@dataclass`, `__post_init__`, валидация в конструкторе | `Labs/Lab 13` (Triangle) | `4.1.1` знает слово `dataclass`, но без примера |
| `ABC` + `@abstractmethod` + общий интерфейс фигур | `4.1.2 - 4.1.4/Ex 1–9` (задачи ООП) | `4.1.1` — абзац про `abc` без кода |
| `@property` для вычисляемых величин | `Labs/Lab 13`, `4.1.2 - 4.1.4/Ex 1–9` | `4.1.1` — один абзац |
| `TypeAlias`, `TypeVar`, `Callable` | `F1_20.py` | не упоминается |
| Фабрика через словарь и реестр | разбирается на учебных примерах в лекции модуля | не упоминается |
| Docstring: описание функции и её параметров | `F1_20` | не упоминается |
| Свои проверки-ассерты и свои исключения | `Mods/custom_assertions.py`, `2.3.1` | `1.2.1` — список типов исключений без примеров |
| `pathlib`, `json`, `numpy`, pandas, uv, `pyproject.toml` | `Labs/Lab 12`, `3.2.2`, `2.6.x` | `3.2.1` — есть `pathlib` и `json`, но с ошибками |
| Разделение «модуль / точка входа» (`if __name__ == "__main__"`) | почти все файлы | `3.1.1` — приём есть, но с опечаткой `=` вместо `==` |

**Вывод.** Курс можно строить не «с нуля из ничего», а как **путь к собственному коду автора**:
каждая тема получает «профессиональный слой» — то, как эта же задача решается в реальном
проекте (типизация, dataclass, протоколы, фабрики, тесты, разделение слоёв).
Это одновременно и есть запрошенные «хорошие привычки», и прямая подготовка к Django:
django-модель — это class, `views` — это функции/классы, `urls` — реестр,
`settings` — конфигурация и внедрение зависимостей.

## 3.1 Дефекты примеров кода (проверено запуском)

Из 31 python-блока в конспектах **11 не компилируются**, ещё часть компилируется, но падает
при запуске. Ниже — то, что проверено; полный список проверок в § 6.

| Конспект | Что не так | Что показал запуск |
|---|---|---|
| `1.2.1` | `x = input(...)`, затем `print(f"Hello, {name}")`; `class Exceptions` — такого класса в Python нет (есть `Exception`) | `NameError: name 'name' is not defined` |
| `2.2.1` | три «блока» вида `if ...` — псевдокод, ни разу не помеченный как псевдокод | SyntaxError: expected ':' |
| `2.3.1` | `print(f"{i=}, {j=})` — незакрытая кавычка | SyntaxError: unterminated string |
| `2.4.1` | `tup - (`…`)` вместо `=`, `a - (1, 2, 3)`; `tup:tuple[int] = (i for i in range(100))` — это генератор, а не кортеж; в словаре пропущены запятые | `TypeError: 'generator' object is not subscriptable` |
| `2.6.1` | четыре заголовка-комментария «а здесь можно привести код» и ни одной матрицы | запускать нечего |
| `3.1.1` | в примере «хорошего модульного кода» — `if __name__ = "__main__":`; `from cotan.py import ctg`; `*args, *kwargs` вместо `**kwargs` | `ModuleNotFoundError: No module named 'cotan'` |
| `3.2.1` | `from pathlib import path` (нижний регистр); `with file.open(...)` без `as f`; `json.dumps(file, …)` — передан файл вместо данных; `pickle.loads(f)` вместо `load(f)`; `.pk1` вместо `.pkl` | `ImportError: cannot import name 'path'` |
| `4.1.1` | `def speak():` без `self` в `Dog`/`Cat`; `def __init__(self, title, author, file_size)` без двоеточия | `TypeError: Dog.speak() takes 0 positional arguments but 1 was given` |

> [!important] Правило для сборки курса
> Каждый блок кода в готовом конспекте должен **запускаться** (или быть явно помечен
> как псевдокод). Это не придирка: конспект читает человек с нуля, и первое, что он делает,
> — копирует пример. Падающий пример учит неправильно.

## 4.2 Каркас курса: 7 модулей + сквозной инженерный трек

Порядок отражает и учебник, и реальный путь новичка. «Инженерный слой» идёт не отдельным
блоком в конце, а **врезкой в каждую тему** плюс финальным блоком практик.

| Модуль | Тема | Из чего собирается | Инженерный слой (врезка) |

**Плюс сквозной трек «Инженерные привычки»** — 6 практик, которые идут фоном через модули
0–7 и опираются на собственный код автора:

1. **Читаемость**: имена, PEP 8, `ruff`/`black` (уже в `pyproject.toml` репозитория).
2. **Типизация**: аннотации с первого дня, `mypy` как проверка.
3. **Документирование**: docstring у функций (образец — `F1_20.py`).
4. **Тесты**: от самодельных `assert` в `custom_assertions.py` до `pytest`; падающий пример — первый тест.
5. **Проектирование**: от одной функции к слоям; фабрика и реестр; DI на функциях и на классах (учебные примеры в лекции модуля).
6. **Работа с чужим кодом**: ревью чужого решения (в репозитории есть работы Куценко, Шупенина, Вавиловой) и починка собственных ошибок из § 3.1.

## 4.3 Что делать с задачами из конспектов

19 незакрытых задач — это **готовый план доработки**, потому что каждая написана там,
где чего-то не хватает. Предложение: перенести их в [[Бэклог]] как чек-лист сборки курса
и из конспектов удалить (правило базы: конспект — не таск-трекер), а сами задачи закрывать
в порядке модулей. Часть задач сформулирована как «сделай диаграмму» — такие закрываются
Mermaid-схемой, как уже сделано в дисциплинах 01 и 06.

## 4.4 Критерий готовности курса

Курс считается собранным, когда:

1. По нему может пройти человек **без опыта**: ни одно понятие не используется до определения.
2. Каждый конспект — по контракту [[Соглашения]]: YAML, служебные разделы, связи, темы.
3. Каждый блок кода **запускается** и проверен; псевдокод помечен.
4. Каждая тема имеет практику с условием и разбором (не только `.py` в репозитории).
5. Есть `00_Курс.md` с порядком прохождения, уровнями и картой понятий.
6. К концу курса человек знает классы, типизацию, модули, файлы, тесты — и понимает,
   **зачем** каждый из этих слоёв существует в Django-проекте.
