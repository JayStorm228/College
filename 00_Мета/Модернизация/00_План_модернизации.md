> **Одна сессия = один этап.** Не начинай следующий этап, даже если остался запас по времени:
> именно это требование владельца — разбивка нужна, чтобы избежать переполнения контекста,
> оборванных правок и артефактов.
>
> Точка входа — этот файл. Список файлов своего этапа бери из соответствующего
> `Этап_NN_*.md`; не пересчитывай объём сам и не «добирай» файлы из соседних этапов.
>
> Правила владельца и границы работ — [[Соглашения|Соглашения]], [[Бэклог|Бэклог]],
> [[Доска_задач|Доска задач]]. Этот план не отменяет их и не заменяет.

## Что это и зачем

База приведена к рабочему состоянию: ссылки целы, якоря понятны, код в примерах прогнан,
карточки бэклога сверены с фактом. Остался системный долг — **оформление по контракту**:
172 заметки из 183 не соответствуют [[Соглашения|Соглашениям]] по одному или нескольким
формальным признакам.

Это не содержательные дыры. Материал в заметках есть и проверен. Не хватает того, что требует
контракт: обязательных разделов (§2, §3), Mermaid-диаграмм и пояснения «для чайника» (§8).

Модернизация разбита на 10 этапов по разделам — так каждая сессия работает с одним курсом
или дисциплиной, держит в голове один предмет и не тащит контекст из чужого.

## Три типа работ — что именно делать

### 1. Обязательные разделы (§2, §3)

Лекция обязана иметь `# Ключевые термины`, `# Типичные заблуждения`, `# Связи с другими темами`.
Практика — `# Ход работы`, `# Вывод`, `# Связи с другими темами`.

> [!warning] Главное — не писать разделы с нуля
> Проверено пересчётом 06.10.2026: в практиках разделы в основном **переименованы**, а не
> отсутствуют. `# Что запомнить из практики` стоит в 13 файлах и по смыслу это `# Вывод`.
> Задачи идут как `## Задача N. …` там, где контракт ждёт `# Ход работы`.
>
> **Сначала читай файл и ищи существующий раздел под другим именем.** Переименовывай
> заголовок, а не добавляй второй раздел рядом — иначе получится дубль, и читатель увидит
> два вывода в одной практике.

Если содержимого для раздела в файле действительно нет — напиши его по материалу этой же
заметки. Не выдумывай фактов и не тащи объяснения из интернета: §6.2 требует, чтобы
определение жило в той же заметке, но оно должно быть верным.

### 2. Mermaid-диаграмма (§8.1)

Минимум 1–2 на лекцию. Диаграмма — объяснение, а не украшение: без неё текст должен быть
понятен, с ней — в два раза быстрее. Типы: `flowchart` для процесса, `sequenceDiagram` для
взаимодействий, `gitGraph` для веток, `xychart-beta` для роста.

Обязательно прогони проверку перед коммитом — синтаксис Mermaid ломается легко:

```bash
MERMAID_MODULES=/tmp/mmval/node_modules node 00_Мета/проверка_mermaid.mjs
```

Если `/tmp/mmval` не пережил перерыв (а он не переживает), харнесс ставится так:

```bash
mkdir -p /tmp/mmval && cd /tmp/mmval && npm init -y && npm install mermaid@11 jsdom
```

### 3. Пояснение «для чайника» (§8.3)

Строка-аналогия в `abstract` или выделенный блок внутри лекции. Пиши как будто читатель
вчера поставил Python, но в академической рамке: аналогия, шаг за шагом, «что будет если
не так». Аудитор ищет подстроки `для чайника`, `Пояснение для начинающих`, `для начинающих`.

Эталон — `02_Курсы/01. Инженерные практики Python/01_Лекции/07. Декораторы.md` и
`02_Курсы/02. NumPy/01_Лекции/01. Введение в NumPy…md`.

## Правила на каждый этап

1. **Только свой этап.** Файлы — строго из списка в `Этап_NN_*.md`.
2. **Не менять содержательный материал.** Правится оформление: заголовки разделов, диаграммы,
   пояснения. Факты, примеры кода, формулировки преподавателя — не трогать.
3. **Правило Р7 для дисциплин** (этапы 7–10): материалы поступают из колледжа. Если для
   раздела не хватает фактов — не дописывай «по общим знаниям», а зафиксируй пробел в
   [[Реестр_дисциплин|реестре]]. На `02_Курсы/` (этапы 1–6) Р7 не действует.
4. **Правило Р8:** имена блок-якорей — `kebab-case`, латиницей, по смыслу раздела.
5. **Не добавлять блоки «Проверь себя»** — §6.1 их запрещает. По существующим 33 блокам
   решение принимает владелец (см. [[Бэклог#^m5-melochi|М5 п. 5]]).
6. **Проверки перед коммитом** — все три, из корня репозитория:

```bash
python3 00_Мета/линк_чекер.py --strict
python3 00_Мета/проверка_базы.py
python3 00_Мета/аудит_базы.py --only 02_Курсы     # или --only 01_Дисциплины
```

Плюс Mermaid-проверка, если добавлялись диаграммы. Целевой результат: линк-чекер 0 проблем,
`проверка_базы` 0 проблем, в аудите счётчик твоего раздела уменьшился ровно на число
обработанных файлов.

7. **Коммит — по этапу**, сообщение начинается с `Этап N:`. Пуш только в свою ветку.
8. **Запись в [[Журнал_изменений|Журнал изменений]]**: что сделано, сколько файлов,
   какие проверки прогнаны и что они вернули.
9. **Обновить этот файл**: отметить этап выполненным в таблице ниже.
