# Словарь реформы

> Единый словарь терминов, который используют **все** последующие агентские сессии (R0.2 → R10).
> Карточка термина: **определение → что он НЕ означает → пример из репозитория**.
> Соответствия дисциплин и курсов — в [[Карта_соответствия_дисциплин]]. Правила обращения —
> в разделах 1–2 этого файла. При конфликте: словарь > проза отдельных документов
> (дрейф прозы — фиксировать в [[Журнал_реформы]], а не читать молча).

# 1. Правила обращения к дисциплинам

> [!important] Главное правило
> В документах реформы (`00_Мета/Реформа/`, записи журналов, backlog'и, отчёты сессий)
> **нельзя писать «дисциплина 02», «предмет 04», «курс 01» и любые другие голые номера** —
> две системы нумерации (репозиторий 01–07 и ГП 01–24) несовместимы, совпадений по смыслу ноль
> (R0-аудит §4 A2). Выражение «дисциплина 04» после R0.2 считается **недопустимо неоднозначным**.

| Запись | Что означает |
|---|---|
| `ГП-04` | дисциплина «Основы алгоритмизации и программирования» **генерального плана** (`МОДЕРНИЗАЦИЯ/02`), из 24 |
| `РЕПО-02` | текущая папка/дисциплина репозитория `01_Дисциплины/02_Основы_Алгоритмизации_и_Программирования/` |
| `РЕПО-04` | текущая папка/дисциплина репозитория `01_Дисциплины/04_Психология_Личности/` (НЕ «Алгоритмизация и программирование» — это ГП-04!) |
| `К1` … `К5` | авторские курсы `02_Курсы` (первое упоминание — с полным именем) |
| `ВЕБ` | фрагмент `02_Курсы/Веб/` (не курс, не дисциплина) |

Правила:

1. **Канонический регистр — заглавный**: `ГП-`, `РЕПО-`. Обозначение `репо-02` в R0-аудите
   приравнивается к `РЕПО-02` (регистр не является частью идентификатора), каноническая
   запись в новых текстах — заглавная.
2. Префикс обязателен во всех документах реформы, в именах задач и в ссылках.
   `ГП-15` ≠ `РЕПО-15` (второго не существует) — префикс исключает класс ошибок.
3. В **учебных материалах** (лекции, практики) нумерация остаётся как в файлах: имена папок
   `NN_Название` и ссылки по ним не меняются до R5/RF-16. Словарь не переписывает учебные тексты.
4. Внутренние номера внутри сущности (лекция 09, блок B, тема N) пишутся в связке с ней:
   «РЕПО-01, лекция 07», «К1, блок C», «модуль «02. Django» (РЕПО-02)» — без префикса сущности
   внутренний номер снова неоднозначен.

# 2. Правила именования сущностей

| Сущность | Правило | Пример |
|---|---|---|
| Дисциплины | `ГП-NN` (1–24) — генеральный план; `РЕПО-NN` (01–07) — репозиторий. Номера неизменны; новые дисциплины ГП получают следующий номер **только через правку ГП по решению владельца** (RF-08) | `ГП-15`, `РЕПО-03` |
| Курсы | `КN` — авторские курсы `02_Курсы` (сейчас К1–К5). Новый курс: `К6` со следующим номером + строка в [[Карта_соответствия_дисциплин]] **до** первой ссылки на него. ГП-номер курсу **не присваивается** (курсы относятся к ГП только содержательным пересечением — тип B) | `К5` — курс C++ |
| Модули | Не нумеруются отдельно; обращение — «модуль X (Сущность)»: смысловые блоки курса (К1: A–F) или тематические папки дисциплины (РЕПО-02: «01. Алгоритмы и Python», «02. Django») | «модуль B (К1)», «модуль «02. Django» (РЕПО-02)» |
| Мини-проекты | По имени внутри курса (текущий контракт: `NN. Мини-проект. Название`); отдельного глобального номера нет | «Мини-проект «Банк с отчётом» (К1)» |
| Сквозные проекты | Будущий идентификатор `СП-N` (сквозной проект, N — порядковый) — вводится при создании первого сквозного проекта (R6) со строкой в карте; до тех пор обращение по имени | (пока нет — R0: «сквозных проектов нет») |
| Учебные траектории | Обращение по имени («срочный план Django», «веб-маршрут»); после формализации графа (R3.2) — `Т-N`. Дорожная карта — текущий нарративный носитель траекторий, **не** траектория как сущность | «срочный план Django (Дорожная карта, §4)» |
| Любые новые типы сущностей | Правило: **префикс + номер** (префикс — 1–4 буквы, заглавный регистр; номер — порядковый). Прежде чем использовать новый префикс, его нужно зарегистрировать в этом словаре (таблица ниже) и в карте. Голые номера без префикса в документах реформы запрещены | `СП-1` (запасной пример, вводится в R6) |

Зарегистрированные префиксы (срез R0.2):

| Префикс | Сущность | Статус |
|---|---|---|
| `ГП-` | дисциплина генерального плана | активен |
| `РЕПО-` | дисциплина/папка репозитория | активен |
| `К` | авторский курс `02_Курсы` | активен |
| `ВЕБ` | фрагмент веб-материалов (без номера: единая сущность) | активен |
| `СП-` | сквозной проект | зарезервирован (R6) |
| `Т-` | учебная траектория (формализованная) | зарезервирован (R3.2) |
| `RF-` | задача реформы (бэклог) | активен |
| `В`/`Ж`/`С`/`П`/`М` | карточки операционного бэклога (владелец/журнал/курс/путь/модернизация) | активен (не реформенные, не смешивать с RF) |

# 3. Термины

## Идентификаторы

### РЕПО-XX

1. **Определение.** Идентификатор текущей дисциплины репозитория: папки `01_Дисциплины/NN_…/`.
   Всего 7 (РЕПО-01…РЕПО-07). Номера — исторические, совпадают с именами папок.
2. **НЕ означает.** Не является номером дисциплины генерального плана (РЕПО-04 ≠ ГП-04!),
   не является номером дисциплины в официальном учебном плане колледжа (он неизвестен и в базе
   отсутствует), не меняется при реформе до R5/RF-16.
3. **Пример.** `РЕПО-02` = `01_Дисциплины/02_Основы_Алгоритмизации_и_Программирования/`.

### ГП-XX

1. **Определение.** Идентификатор дисциплины генерального плана (`МОДЕРНИЗАЦИЯ/02`, v1.0),
   24 дисциплины (ГП-01…ГП-24).
2. **НЕ означает.** Не является номером папки репозитория (ГП-01 — «Операционные системы»,
   папки `01_` в репозитории — «Технология разработки ПО»); не является официальным номером
   дисциплины в плане конкретного колледжа — ГП это **авторская** интегрированная программа.
3. **Пример.** `ГП-15` = «Разработка и написание кода ИС».

## Образовательная структура

### Дисциплина

1. **Определение.** Учебная область / единица программы. Два слоя: (а) дисциплина генерального
   плана (`ГП-NN`) — единица стратегической программы; (б) дисциплина колледжа в репозитории
   (`РЕПО-NN`) — контейнер фактических материалов колледжа. Дисциплина отвечает на вопрос
   «откуда тема пришла и в какую программу она входит» (МОДЕРНИЗАЦИЯ/01 §2).
2. **НЕ означает.** Не является маршрутом обучения («Дисциплина — не маршрут обучения»,
   МОДЕРНИЗАЦИЯ/01 §2) и не является курсом в смысле `02_Курсы`: дисциплина не может
   поддерживать несколько ГП пересечениями. Не является папкой (папка `Веб` не дисциплина).
3. **Пример.** `ГП-15` (программный слой), `РЕПО-01` (фактическая папка с 9 лекциями и 7 практиками).

### Курс

1. **Определение.** Конкретно спроектированная последовательность обучения. Две формы в репозитории:
   **(а) курс дисциплины** — программа прохождения внутри дисциплины (`00_Курс.md` + лекции +
   практики + уровни); **(б) самостоятельный курс** — курс в `02_Курсы` (К1–К5), не привязанный
   к одной дисциплине. Курс отвечает на вопрос «как осваивать» (МОДЕРНИЗАЦИЯ/01 §2).
2. **НЕ означает.** Не является дисциплиной (курс может поддерживать несколько ГП — тип B в карте).
   Не является темой, лекцией или модулем. Правило «Дисциплина = курс» из Контекста (§2.3)
   **не** делает слова синонимами — см. раздел 4.
3. **Пример.** Курс дисциплины: «курс РЕПО-02» (16 лекций Python + практики). Самостоятельный:
   `К1` «Инженерные практики Python».

### Модуль

1. **Определение.** Смысловой блок внутри курса: либо именованный блок программы курса
   (К1: блоки A–F), либо тематическая папка учебной области дисциплины (РЕПО-02:
   «01. Алгоритмы и Python», «02. Django»).
2. **НЕ означает.** Не является дисциплиной и не является самостоятельным курсом (модуль
   «02. Django» не курс — до решения владельца); не является практикой.
3. **Пример.** «модуль «02. Django» (РЕПО-02)» — черновик лекции + PDF-учебник, срочный семестр.

### Тема

1. **Определение.** Единица учебного содержания в пределах модуля/курса; как правило, соответствует
   одной лекции (или паре «лекция + практика» по ней).
2. **НЕ означает.** Не является заметкой (заметка — носитель, тема — содержание; одна тема может
   иметь несколько заметок — см. «Проекция»), не является понятием (тема шире понятия).
3. **Пример.** Тема «Декораторы» (К1, лекция 07); тема «Индексы» (будущий курс ГП-20, пример из ГП §31).

### Лекция

1. **Определение.** Заметка `type: лекция`, имя `NN. Тема.md`, структура по [[Соглашения]] §2
   (abstract, разделы, «Ключевые термины», «Типичные заблуждения», «Связи с другими темами»).
2. **НЕ означает.** Не является практикой (практика — `type: практика` + `related_lecture`),
   не является оглавлением курса (`00_Курс.md` / `00. Название.md` — `type: курс`).
3. **Пример.** `02_Курсы/02. NumPy/01_Лекции/01. Введение в NumPy.md`.

### Практика

1. **Определение.** Заметка `type: практика` — практическая работа, всегда связана с лекцией
   (`related_lecture`); состоит из ход работы / задач / вывода.
2. **НЕ означает.** Не является проектом (практика закрепляет тему; проект собирает несколько
   знаний), не является отдельной задачей (задача — внутри практики, `## Задача N`).
3. **Пример.** `02_Практика/05. Тестирование ПО — вопросы и тестовая документация (шаблон)` (РЕПО-01).

### Мини-проект

1. **Определение.** Курсовой проект: небольшая самодостаточная программа с требованиями, планом
   и таблицей самопроверки; замыкает курс или его блок. Формат решения владельца (РЕПО-02):
   требования, план шагов, самопроверка, пример-аналог из другой темы.
2. **НЕ означает.** Не является сквозным проектом (не проходит через несколько дисциплин),
   не является курсом (мини-проект лежит внутри курса), не является дисциплиной.
3. **Пример.** `06. Мини-проект. Банк с отчётом — архитектура, реестр и тестирование` (К1).

### Сквозной проект

1. **Определение.** Проект, проходящий один и тот же учебный кейс через несколько дисциплин/курсов:
   `требования → модель → БД → код → тесты → развёртывание → сопровождение` (R0: таких проектов
   в базе пока **нет**; появится на R6).
2. **НЕ означает.** Не является мини-проектом (не выходит за пределы одной дисциплины/курса),
   не является дисциплиной.
3. **Пример.** Нет — будущий; первый идентификатор будет `СП-1`.

### Компетенция

1. **Определение.** Профессиональный результат «умеет X»: результат, который должен показать
   выпускник (ГП §29: анализировать, проектировать, разрабатывать, проверять, внедрять/
   сопровождать, работать профессионально).
2. **НЕ означает.** Не является темой или дисциплиной: компетенцию покрывают темы и практики
   **нескольких** дисциплин одновременно; не является оценкой конкретного ученика.
3. **Пример.** «Составлять тесты, находить дефекты, выполнять регрессионные проверки» (ГП §29) —
   покрывается РЕПО-01-Л07, К1-Л08 и будущим ГП-16.

### Учебная траектория

1. **Определение.** Упорядоченный маршрут прохождения тем/курсов/дисциплин под конкретную цель
   (профессию, семестр, дедайн). Текущий носитель — нарративная [[Дорожная карта]] («срочный
   план Django» — её §4); после R3.2 траектория формализуется как граф с идентификатором `Т-N`.
2. **НЕ означает.** Не является курсом (траектория может идти через несколько курсов и за пределы
   `02_Курсы`), не является планом одной дисциплины (это уровень выше), не является расписанием
   колледжа (официальный учебный порядок — отдельно, ГП §28).
3. **Пример.** «срочный план Django на семестр 01.09–31.12.2026» (Дорожная карта §4).

### Понятие

1. **Определение.** Именованный элемент знания (термин/конструкт), определённый в заметке
   (в тексте или в «Ключевых терминах»); у понятия есть ровно одно **каноническое** место,
   остальные места — проекции.
2. **НЕ означает.** Не является темой (понятие уже темы), не является словом/синонимом,
   не является ссылкой (ссылка — указатель, не носитель определения; [[Соглашения]] §6.2).
3. **Пример.** Понятие «замыкание» (К1-Л07); понятие `dataclass` (канон — К1-Л04, проекции —
   РЕПО-02-Л16, сравнения в К3 — R0 §8.5).

## Слои материала

### Канон

1. **Определение.** Проверенный основной текст базы: заметка `status: готово` по контракту
   [[Соглашения]], с определениями в месте, связями и (где уместно) источниками; то, на что
   ссылаются остальные заметки как на первоисточник.
2. **НЕ означает.** Не является сырьём (сырой файл — не канон, даже если лежит рядом),
   не является черновиком. Каноничность — свойство **текста и статуса**, а не папки:
   папка может содержать и канон, и сырьё (проблема A1 — решается в R2).
3. **Пример.** 16 лекций Python-блока РЕПО-02 (переписаны заново, 0 проблем — «все лекции
   курса написаны заново», РЕЕСТР §02).

### Проекция

1. **Определение.** Показание понятия/темы в **ином** контексте (не каноническом месте) с явной
   ссылкой на канон и пояснением, что именно здесь добавляется. Управление: правило приоритета
   дисциплин — курс ссылается на дисциплину как на первоисточник и «углубляет», а не пересказывает
   ([[Соглашения]] §9).
2. **НЕ означает.** Не является дубликатом (дубликат не знает о каноне; проекция — сознательная
   ссылка), не является каноном (если содержание расходит — правится проекция, а не канон).
3. **Пример.** Git: канон концепции — РЕПО-01-Л05; проекция-практика — К1-Л13
   (R0 §8.5: «управляется правилом приоритета дисциплин и перекрёстными ссылками»).

### Сырьё

1. **Определение.** Первичный необработанный материал: записи с пар, презентации преподавателя
   (HTML), PDF-учебники, RAR-архивы, черновики конспектов «как было на паре».
2. **НЕ означает.** Не является учебным материалом автоматически: «сырой файл не должен
   автоматически считаться качественным учебным материалом» (МОДЕРНИЗАЦИЯ/03 §9). Не является
   каноном. Сырьё не удаляется и не перемещается без владельца (R0 §13).
3. **Пример.** `01_Лекции/презентация занятие 11.html` (РЕПО-01), PDF-учебник в модуле «02. Django»
   (РЕПО-02), `02_Курсы/Веб.rar`, PDF учебника 2019 в `ВЕБ`.

### Поток A

1. **Определение.** Оперативный поток: `новая пара → сырой материал → первичная обработка →
   пометка статуса` (МОДЕРНИЗАЦИЯ/03 §2). Живёт своей жизнью и **не ждёт** завершения реформы.
2. **НЕ означает.** Не является реформой (реформа — Поток B), не является каноном: принятый
   сырой материал регистрируется и «не считается канонической» (МОДЕРНИЗАЦИЯ/03 §24).
3. **Пример.** Приём записи ежедневника 02.10 и лекции 09/практики 07 РЕПО-01 из выгрузки 03.10
   (Передача работы, сессия 06.10).

### Поток B

1. **Определение.** Стратегический поток реформы: `аудит → архитектура → генеральный план →
   рефакторинг → курсы → связи → практика → контроль качества` (МОДЕРНИЗАЦИЯ/03 §2).
   Сессии R0–R10 принадлежат Потоку B.
2. **НЕ означает.** Не блокирует Поток A (потoki не должны блокировать друг друга) и не означает
   «завершить семестровую работу»: срочные работы колледжа идут в Потоке A параллельно.
3. **Пример.** Сессия R0.2 (эта: карта + словарь) — Поток B; разбор пары Django — Поток A.

### Источник

1. **Определение.** Документ, по которому **проверяется** утверждение/тема: официальная
   документация, стандарт/RFC, учебник, университетский курс (иерархия — МОДЕРНИЗАЦИЯ/03 §16).
   Источник должен быть связан с **темой**, а не только с курсом (ГП §31).
2. **НЕ означает.** Не является цитатой без даты проверки (дата проверки — обязательная
   составная часть; Р7/Ж7), не является материалом для пересказа без сверки.
3. **Пример.** «PostgreSQL: Indexes» для темы «Индексы» (ГП §31); Scrum Guide 2020 для
   РЕПО-01-Л08.

### Provenance

1. **Определение.** Происхождение материала — ответ на вопрос «откуда он»: `college` (колледж/
   преподаватель), `author` (автор — владелец/агент), `external` (внешние источники), `mixed`
   (смешанное). Сейчас фиксируется **прозой** (блоки «Что из материала преподавателя, а что
   добавлено» — РЕПО-07; оговорки «не является пересказом занятия» — РЕПО-06); системное YAML-
   поле `origin` вводится в R1.1 (RF-02).
2. **НЕ означает.** Не является статусом готовности (`status` — другое поле, см. «Состояние
   материала»), не является лицензией (права на распространение — отдельный вопрос, Ж4).
3. **Пример.** Лекции РЕПО-07: «3 темы из истории» + пометки, что дополнения взяты из открытых
   источников и «не выдаются за диктовку пары» (РЕЕСТР §07).

### Состояние материала

1. **Определение.** Текущее состояние заметки по действующему контракту: `черновик` | `в работе` |
   `готово` (YAML `status`; пустое/отсутствующее = `черновик`). Запланированное расширение
   для реформы (R1.1, RF-02): `raw → extracted → draft → reviewed → verified → ready → archived`.
2. **НЕ означает.** Не является оценкой качества (оценки 8.4/9.8 в РЕЕСТРЕ — отдельная методика
   аудита), не является статусом задачи (задачи — `- [ ] #task`), не является версией.
3. **Пример.** `status: готово` у лекций Python-блока РЕПО-02; `status: черновик` у заметки
   «Что вообще было на паре» (ВЕБ).

## Зависимости и результаты

### Prerequisite

1. **Определение.** Предварительное знание: то, что **должно быть освоено до** данной темы/курса
   (учебная зависимость). Машиночитаемого формата пока нет (проза: раздел «Опора на дисциплину
   02» (= опора на РЕПО-02), «Кому:» в оглавлениях); пилот полей `requires/feeds_into` — R3.2 (RF-07).
2. **НЕ означает.** Не является профессиональной связью ГП→ГП (это тип C, «нужен для» в графе
   программы — другой слой), не является опциональной рекомендацией («можно параллельно» —
   не prerequisite).
3. **Пример.** К2 (NumPy) требует К1 (типизация, тесты, структура проекта) — «Курсы — обзор»,
   таблица; ГП-05 требует ГП-23/ГП-04 (граф ГП §26).

### Dependency

1. **Определение.** Общее название для направленных связей «X — до X / X нужен для X» трёх видов:
   учебная (prerequisite), программа дисциплин (тип C в карте), зависимость курсов
   (К1 → К2, «Курсы — обзор»).
2. **НЕ означает.** Не является ненаправленной связанностью («пересечение», тип B — не
   зависимость), не является ссылкой (ссылка — указатель навигации; dependency — порядок).
3. **Пример.** Будущее поле `requires: [К1]` в YAML оглавления К2 (пилот RF-07).

### Outcome

1. **Определение.** Проверяемый результат освоения темы/курса/траектории: «умеет X», подтверждённая
   работа, воспроизводимый результат (ГП §34: путь `задача → … → сопровождение`).
2. **НЕ означает.** Не является процессом (процесс — то, что делают; outcome — что показано),
   не является статусом заметки, не является оценкой (оценка — число; outcome — результат).
3. **Пример.** «Владелец способен объяснить каждую основную часть» учебного Django-проекта
   (Дорожная карта §4, блок D).

## Происхождение материалов

### Авторский материал

1. **Определение.** Материал, созданный владельцем/агентом **по программе**, а не переписанный
   с пары: авторские лекции, разборы, дополнения, переписанные курсы. Провенанс — `author`
   (внешние дополнения внутри авторского текста помечаются: «дополнено по Зееру»).
2. **НЕ означает.** Не является материалом колледжа (нельзя выдавать за занятие преподавателя —
   нарушение Р7), не является внешним материалом (автор пишет сам, а не переносит).
3. **Пример.** `01. Введение в моделирование и анализ ПО` (РЕПО-06): «самостоятельная
   предметная вводная … авторская ориентация … не материал преподавателя».

### Материал колледжа

1. **Определение.** Материал, пришедший **из колледжа**: записи с пар, условия практик,
   презентации преподавателя, задания. Провенанс — `college`. Может быть сырьём (черновик)
   или доведённым до канона (например, лекции РЕПО-03 «собраны по презентациям преподавателя;
   .pptx удалены после сверки»).
2. **НЕ означает.** Не является автоматически каноном (нужна сверка и доработка), не является
   авторским материалом (граница — кто и откуда).
3. **Пример.** Три лекции РЕПО-03 (ООА, CASE, UML) — по презентациям преподавателя.

### Внешний материал

1. **Определение.** Материал **внешних** источников (ни колледжа, ни автора): официальная
   документация, учебники, открытые университетские курсы, стандарты. Провенанс — `external`.
   Используется для проверки и дополнения; при переносе в заметку помечается, что он добавлен
   по источнику, а не диктован парой.
2. **НЕ означает.** Не является источником «по определению»: внешний файл (PDF учебника) —
   материал; **источник** — то, по чему проверяется утверждение (разница в использовании).
   Не является авторским материалом (даже если переписан своими словами — провенанс `mixed`).
3. **Пример.** OSTEP (будущий ГП-01, Source Map ГП §30); учебник 2019 в ВЕБ; «Баопу-цзы»
   как источник цифры «1200 добрых дел» (РЕПО-07, аудит 05.10).

# 4. Граница: «дисциплина» и «курс» — рабочая версия

Существующие договорённости (изучены до формулировки):

- **МОДЕРНИЗАЦИЯ/01 §2**: «Дисциплина — не маршрут обучения. … **дисциплина** говорит, откуда
  тема пришла в учебной системе; **курс** говорит, как её изучать»; дисциплина — «контейнер
  программы колледжа».
- **[[00_Контекст]] §2.3**: «**Дисциплина = курс.** Каждая дисциплина должна читаться как
  полноценный курс «с нуля до профессионального уровня»: с оглавлением `00_Курс.md`, порядком
  прохождения, картой понятий и блоком подготовки к экзамену».
- **[[Соглашения]] §12**: уровни курсов `02_Курсы` (начальный/продвинутый/мини-тема).

**Окончательная рабочая формулировка (R0.2):**

> **Дисциплина** — учебная область / единица программы: контейнер, который отвечает, откуда
> тема пришла и к какой программе относится (ГП-NN в стратегии, РЕПО-NN в факте).
>
> **Курс** — конкретно спроектированная последовательность обучения: как область осваивается.
> Курс дисциплины живёт **внутри** дисциплины (`00_Курс.md` + порядок + уровни); самостоятельный
> курс живёт в `02_Курсы` (К1–К5) и может быть междисциплинарным.
>
> Правило «Дисциплина = курс» из Контекста означает: **каждая дисциплина спроектирована как
> курс** (обязательное оглавление, порядок, уровни, подготовка к экзамену) — но **не** делает
> слова «дисциплина» и «курс» синонимами. Самостоятельный курс — не дисциплина: у него нет
> номера в ГП-24, нет преподавателя колледжа, и он может поддерживать несколько дисциплин.

**Правило для будущих сессий.** При записи «курс» уточнить, какой из двух:

- «курс дисциплины» → писать **«курс РЕПО-NN»** (или «курс ГП-NN» для будущих курсов по ГП);
- «самостоятельный курс» → писать **КN** (первое упоминание — с именем);
- если сущность — блок внутри курса → «модуль X (сущность)».

Проверка: если после замены «курс → дисциплина» (или наоборот) смысл не меняется — запись
однозначна, можно писать без уточнения.
