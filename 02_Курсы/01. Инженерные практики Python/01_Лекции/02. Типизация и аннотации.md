# 02. Типизация и аннотации

> [!abstract] О чём лекция
> В курсе Python типы были свойством **значения**: `type(5) → int`. Здесь второй слой — как записать **ожидаемый** тип прямо в коде, чтобы редактор (Pylance) и проверщик (`mypy`) находили ошибки до запуска. Аннотации **не меняют поведение** — они меняют момент, когда ты узнаёшь что перепутал `int` и `str`: сразу в редакторе или позже на глазах у пользователя.
>
> После лекции ты напишешь `def average(nums: Sequence[float]) -> float` и поймёшь, почему `list[int]` иногда хуже `Sequence[int]`, зачем `T = TypeVar("T")` и почему `str | None` честнее `str`.

> [!tip] Минимум для старта
> Нужно: переменные, функции, `list/dict`, `for`. Всё новое разжёвано на месте. Запускай примеры — `uv run python` — и смотри подсказки Pylance в VS Code.

# Аннотации — обещание, а не проверка

```python
def greet(name: str, times: int = 1) -> str:
    return ("Привет, " + name + "! ") * times

print(repr(greet("Аня")))        # 'Привет, Аня! '
print(repr(greet("Аня", 2)))     # 'Привет, Аня! Привет, Аня! '
print(greet.__annotations__)
# {'name': <class 'str'>, 'times': <class 'int'>, 'return': <class 'str'>}
```

Аннотация — запись в `__annotations__`. Python её **не проверяет**: `greet(123)` выполнится, даже если сказал `str`. Проверяют **инструменты**:

| Кто | Когда | Что делает |
|---|---|---|
| **Python** | при запуске | выполняет код, аннотации игнорирует |
| **Pylance** (VS Code) | при наборе | подчёркивает несоответствия, показывает типы при наведении |
| **mypy** | по команде `uv run mypy src` / в CI | проходит весь проект и печатает ошибки типов |

Аналогия: аннотация как подпись на коробке «внутри стекло — не кантовать». Коробку всё равно можно бросить, но носильщик (mypy) предупредит.

> [!warning] Новая форма записи
> В курсе — современный синтаксис: `list[int]` (с 3.9), `str | None` (с 3.10), `Number = int | float` — псевдоним (с 3.12 также `type Number = ...`). В старом коде встретишь `List[int]` / `Optional[str]` / `Union` — это то же, просто старые имена из `typing`. Курс требует `requires-python = ">=3.12"` (см. [[12. Структура проекта и модули]]).

# Что и как аннотировать — шпаргалка

| Что | Как | Пример |
|---|---|---|
| переменная | `name: type = value` | `price: float = 199.90` |
| параметр/возврат | `def f(x: int) -> str:` | `def rubles(n: int) -> str: return f"{n} ₽"` |
| нет возврата | `-> None` | `def log(text: str) -> None: ...` |
| список целых | `list[int]` | `scores: list[int] = [4,5,3]` |
| словарь | `dict[str, float]` | `rates: dict[str, float] = {"usd": 92.5}` |
| кортеж фиксированный | `tuple[int, str]` | `pair: tuple[int, str] = (1, "a")` |
| кортеж любой длины | `tuple[int, ...]` | `nums: tuple[int, ...] = (1,2,3,4)` |
| «или ничего» | `str \| None` | `def find(...) -> str \| None:` |
| псевдоним | `Alias = ...` | `Number = int \| float` |

Полный пример с комментариями:

```python
from collections.abc import Sequence
from typing import TypeVar

Number = int | float                # псевдоним — имя говорит смысл
Scores = list[int]

T = TypeVar("T")                    # «какой-то тип, один и тот же»

def average(numbers: Sequence[Number]) -> float:
    """Среднее — принимает любую последовательность чисел."""
    if not numbers:
        raise ValueError("пустой список")
    return sum(numbers) / len(numbers)

def find_longest(words: list[str]) -> str | None:
    if not words: return None
    return max(words, key=len)

def first(items: Sequence[T]) -> T | None:
    return items[0] if items else None

scores: Scores = [4, 5, 3]
print(f"{average(scores):.2f}")            # 4.00
print(f"{average([1.5, 2.5]):.2f}")        # 2.00
print(find_longest(["мама","мыла","раму"])) # мама
print(first(scores), first([]))            # 4 None
```

Разберём три тонких места — именно они путают новичка:

### 1) `Sequence` vs `list` — почему не всегда `list[int]`

`list[int]` значит «именно список, который можно менять (`append`)». Если функция только **читает** ( `len`, `for`, `[i]` ), бери `Sequence[int]` из `collections.abc`. Тогда подойдёт и список, и кортеж, и `range`.

Почему `list` хуже: `mypy` не примет `list[int]` там, где ждут `list[float]` — список изменяемый, в него могли бы добавить `float` и сломать ожидания вызывающего. `Sequence` только читают, поэтому `Sequence[int]` и `Sequence[float]` — безопасны. Подробнее — [PEP 484](https://peps.python.org/pep-0484/) и [mypy docs — generics](https://mypy.readthedocs.io/en/latest/generics.html).

### 2) `TypeVar` — когда тип результата зависит от входа

```python
T = TypeVar("T")

def first(items: Sequence[T]) -> T | None: ...
```

Без `TypeVar` пришлось бы `-> Any` — потеряли связь. С `TypeVar` `first([1,2])` вернёт `int | None`, `first(["a"])` — `str | None`. Если тип встречается один раз (только на входе), `TypeVar` не нужен.

Современный Python 3.12+ позволяет короче `def first[T](...)` — смысл тот же, но в лекции оставляем совместимый `TypeVar`.

### 3) `str | None` честнее `str`

Если функция иногда возвращает `None`, так и пиши. Вызывающий обязан проверить:

```python
name = find_longest([])
if name is None: ...  # mypy заставит проверить
else: print(name.upper())
```

Спрячешь `None` за `str` — получишь `AttributeError: 'NoneType' has no attribute 'upper'` в проде.

# `collections.abc` — `Sequence`, `Iterable`, `Callable` и `*args`

Когда функции всё равно какая коллекция, бери общий тип:

| Тип | Что умеет | Подходит |
|---|---|---|
| `Sequence[int]` | `len`, `[i]` | `list`, `tuple`, `range`, `str` (но `str` → `Sequence[str]`) |
| `Iterable[int]` | `for x in ...` | всё выше + `set`, `dict`, генератор |
| `Callable[[int], str]` | вызваться | функции, `lambda`, методы |

```python
from collections.abc import Callable, Sequence

def apply_all(items: Sequence[int], func: Callable[[int], int]) -> list[int]:
    return [func(x) for x in items]

def total(*values: float) -> float:
    return sum(values)          # values: tuple[float, ...]

def make_query(**params: str) -> str:
    return "&".join(f"{k}={v}" for k,v in params.items())  # params: dict[str,str]

print(apply_all([1,2,3], lambda x: x*x))  # [1,4,9]
print(total(1.5, 2.5, 6))                 # 10.0
print(make_query(city="Казань", page="2"))# city=Казань&page=2
```

Как аннотируют `*args`/`**kwargs` (подробно — [[06. Остатки продвинутого синтаксиса]]): аннотация относится к **каждому** аргументу. `*values: float` → внутри `tuple[float, ...]`, `**params: str` → `dict[str,str]`.

> [!tip] Подсказка Pylance
> Наведи на `values` — увидишь `tuple[float, ...]`. Если видишь `Any` — аннотация потерялась.

# Как проверять — редактор и `mypy`

**В VS Code** — Pylance. Уровень строгости в `.vscode/settings.json`:

```json
{ "python.analysis.typeCheckingMode": "strict" }
```

Подчёркивает несоответствия прямо в тексте.

**В терминале** — `mypy`:

```python
# mypy_demo.py
def discounted(price: float, percent: int) -> float:
    return price * (1 - percent / 100)

total: int = discounted(1000, 10)   # ← ошибка: float нельзя в int
print(total)
```

```bash
uv add --dev mypy
uv run mypy mypy_demo.py
# mypy_demo.py:6: error: Incompatible types in assignment ... [assignment]
```

А теперь запусти: `uv run python mypy_demo.py` → напечатает `900.0`. Вывод: **программа работает, но типы неверны** — проверка типов отдельный шаг, не защита во время выполнения. Настройку строгости можно вынести в `pyproject.toml` (`[tool.mypy]`), но для старта хватит дефолта. В CI (`[[13. Git и GitHub]]`) `mypy` запускают после каждого пуша.

# Что даёт на практике

1. **Ошибка в редакторе, а не в проде.** Вместо `print(type(x))` — красное подчёркивание.
2. **Документация из сигнатуры.** `def total(rows: list[dict[str,int]]) -> int` понятнее `def total(rows)`.
3. **Проверка до запуска.** Опечатку `row["prcie"]` ловит Pylance, если `row: TypedDict` (см. [[03. Словари с формой — TypedDict и современный синтаксис]]).
4. **Безопасный рефакторинг.** Переименовал поле — `mypy` покажет все места.

# Чего не делать

| Заблуждение | Как на самом деле |
|---|---|
| «Аннотации ускоряют код» | Не влияют — интерпретатор их игнорирует |
| «Python будет проверять» | Проверяют Pylance/mypy, не Python |
| `Any` — универсальный тип | `Any` **выключает** проверку — заметен на ревью, избегай |
| «Нужно аннотировать каждую переменную» | Обязательны публичные функции/методы; внутри — где помогает читать |
| `str` вместо `str \| None` | Ложь — `None` придётся обработать, иначе упадёт |
| «Сначала весь проект в `strict`» | В старом проекте — постепенно, файл за файлом |

Мини-чек-лист ревью:

- Публичная функция аннотирована?
- `None` указан честно?
- `Sequence` вместо `list` где только читаешь?
- Нет `Any` без комментария `# type: ignore[ ]`?

# Проверь себя

1. Что будет если вызвать `greet(123)`?
2. Чем `list[int]` отличается от `list`?
3. Когда нужен `TypeVar`, а когда `int | float`?
4. Почему `Sequence[int]` принимает и `list[int]` и `tuple[int, ...]`?
5. Как запустить проверку типов?
6. Чем опасен `Any`?

> [!success]- Ответы
> 1. Выполнится — Python не проверяет; ошибку покажут Pylance/mypy.
> 2. `list[int]` — проверка элементов; `list` — любой список без проверки.
> 3. `TypeVar` когда выход зависит от входа (`first: Sequence[T] -> T`); `int|float` когда просто «любое из».
> 4. `Sequence` описывает «есть `len` и `[i]`» — это есть и у списка, и у кортежа, и у `range`.
> 5. `uv run mypy src` (и включить `typeCheckingMode: strict` в VS Code).
> 6. Отключает проверку — ошибки дойдут до выполнения.
