# 05. Сторонние библиотеки

> [!abstract] О чём лекция
> До сих пор всё писалось своими руками: язык, стандартная библиотека (`math`, `json`, `pathlib`) и немного своего кода. Дальше так продолжаться не может: в реальной работе большая часть кода проекта — это **чужие библиотеки**.
>
> Здесь разбирается, как их подключать, как не утонуть в версиях и — главное — когда библиотеку брать, а когда писать самому.

# Зачем библиотека

Правило простое: **библиотеку берут, когда она закрывает целый слой работы**. Не «чтобы было короче», а потому что своя реализация будет хуже:

| Задача | Своими руками | Библиотека |
|---|---|---|
| среднее по 10 числам | 3 строки | `sum` и `len` (или `statistics.mean`) — уже есть, библиотека не нужна |
| вычисления на сотнях тысяч чисел | цикл на чистом Python — миллисекунды и десятки миллисекунд на каждую операцию | NumPy — доли миллисекунды (замер — в [[05. Практика. Библиотеки и качество]]) |
| проверить данные из формы | десятки `if` | Pydantic — модель с правилами |
| график для отчёта | рисовать вручную нельзя | Matplotlib — 5 строк |

Первая строка в таблице важна: если задача решается на стандартных средствах за несколько
строк, библиотека только добавит зависимость.

# Установка: `uv add`

В курсе Python разбирался инструмент `uv`. Библиотеки добавляются одной командой:

```bash
uv init my-project          # создать проект
uv add numpy                # добавить библиотеку в зависимости
uv add --dev pytest mypy    # инструменты разработки
uv run python main.py       # запуск в окружении проекта
uv sync                     # восстановить окружение по файлам проекта
```

Что происходит под капотом:

«Коммитят» значит «сохраняют в общую историю проекта» (система Git; подробно — в [[08. Git и GitHub]]); `.gitignore` — файл со списком того, что в историю не идёт.

| Файл | Что в нём | Коммитят? |
|---|---|---|
| `pyproject.toml` | список зависимостей проекта | **да** — это часть кода |
| `uv.lock` | точные версии всех пакетов, включая косвенные | **да** — чтобы у всех было одинаково |
| `.venv/` | сами скачанные пакеты | нет, он в `.gitignore` |

Установка «напрямую» через `pip install` в системный Python — источник хаоса: версии незаметно меняются, у коллеги не тот набор, программа работает «у меня, но не у тебя».
Так выглядит правильно настроенный проект: в `pyproject.toml` перечислены рабочие зависимости (`numpy`, `pandas`), а инструменты разработки вынесены в отдельную группу:

```toml
dependencies = ["numpy>=2.4.2", "pandas>=2.0,<3.0"]

[dependency-groups]
dev = ["black>=26.1.0", "ruff>=0.15.2"]
```

# Версии: что значат значок и цифры

| Запись | Смысл |
|---|---|
| `numpy` | любая версия |
| `numpy>=2.4.2` | не ниже указанной |
| `numpy>=2.0,<3.0` | в пределах мажорной версии: новая 3.0 не поставится |
| `numpy==2.4.2` | ровно эта версия |

Логика такая (её называют семантическим версионированием, SemVer): в версии `1.5.0`
первая цифра — **мажорная** (ломающие изменения), вторая — минорная (новая
функциональность), третья — патч (исправления). Не все библиотеки соблюдают это строго,
поэтому перед обновлением мажорной версии читают список изменений. Итак,
`>=2.0,<3.0` — обычная запись «любая версия второй мажорной линейки»: обновления приходят,
но ломающее обновление — нет.

> [!warning] Обновил версию — запусти тесты
> Библиотеки меняются. После `uv sync` с новыми версиями первым делом запускают тесты
> ([[03. Тесты]]): именно для этого они и нужны.

# Как работать с незнакомой библиотекой

1. **Найти официальную документацию.** Ориентиры: `docs.python.org` для стандартной
   библиотеки, `readthedocs` и сайты проектов (`numpy.org/doc`, `docs.pydantic.dev`,
   `matplotlib.org`) для сторонних. Статьи и форумы — после документации, потому что
   устаревают быстрее.
2. **Прочитать раздел «Getting started» / «Quickstart».** Обычно там минимальный пример,
   который копируется и запускается.
3. **Проверить версию.** В документации есть переключатель версий: пример может относиться
   к другой версии, чем у тебя.
4. **Посмотреть установленную версию.** `python -c "import numpy; print(numpy.__version__)"`
   печатает версию, с которой работает код.
5. **Задать вопрос компьютеру, а не только документации.** `help(функция)` и
   `print(функция.__doc__)` показывают встроенную справку с описанием параметров,
   а `inspect.getsource(функция)` — исходный код, если справка не всё объяснила.

# Когда библиотека не нужна

- **Задача решается стандартной библиотекой.** `json`, `csv`, `pathlib`, `math`, `statistics`,
  `datetime`, `collections` — это тоже «библиотеки», только уже входящие в Python.
  Например, для статистики по списку не нужен NumPy: `statistics.mean`, `statistics.median`.
- **Нужна одна маленькая функция.** Тащить пакет на 50 МБ ради одной формулы — плохая сделка.
- **Библиотека без поддержки.** Последний коммит три года назад, сотни открытых issues —
  риск, что при обновлении Python она перестанет работать.
- **Учебная цель.** В курсе Python циклы и словари писались руками именно чтобы понять,
  как это работает внутри. Это не отменяется: библиотека ускоряет, но не объясняет.

# Типичные заблуждения

| Заблуждение | Как на самом деле |
|---|---|
| «Чем больше библиотек, тем мощнее проект» | Каждая зависимость — риск и вес. Минимум, который закрывает задачу |
| «`pip install` в терминале VS Code — то же самое» | Часто ставится в другой интерпретатор; в проекте нужен `uv add` + `uv run` |
| «Версии неважны» | «У меня работает» и «у коллеги падает» — обычно разница версий. `uv.lock` решает |
| «Документация на английском — пойду искать русский ответ» | Официальная документация точнее; примеры копируются как есть |
| «Библиотека заменит знание языка» | Ошибки в использовании библиотек — это ошибки в типах, данных, циклах |

# Как это делают в проекте

1. **Зависимости фиксируются файлами.** `pyproject.toml` + `uv.lock` в репозитории,
   `.venv` — в `.gitignore`.
2. **Dev-инструменты отдельно от рабочих.** `--dev` для тестов и линтеров: пользователю
   программы они не нужны.
3. **Библиотеку оборачивают, если она размазана по коду.** Вызовы собирают в одном модуле —
   тогда замена библиотеки не переписывает весь проект (это уже про зависимости,
   [[07. Внедрение зависимостей]]).
4. **Обновление — отдельная задача с тестами**, а не «между делом».

> [!success]- Ответы
> 1. `uv add` — в проект: обновляет `pyproject.toml`, `uv.lock` и окружение `.venv`.
>    `pip install` — в текущий интерпретатор, следов в проекте не остаётся.
> 2. Любая версия pandas от 2.0 (включительно) до 3.0 (не включая): обновления второй
>    линейки приходят, третья не поставится.
> 3. `pyproject.toml` (что нужно проекту) и `uv.lock` (точные версии всего дерева).
>    Вдвоём они дают одинаковое окружение у всех.
> 4. Когда задача решается стандартной библиотекой за пару строк или когда нужна
>    одна маленькая функция.
> 5. В официальной документации; быстро — через `help(функция)` и `функция.__doc__`.
> 6. Обновление библиотеки может изменить поведение функций: тесты — единственный способ
>    узнать об этом до пользователя.
