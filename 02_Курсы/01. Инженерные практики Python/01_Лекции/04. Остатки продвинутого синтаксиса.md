# 04. Остатки продвинутого синтаксиса

> [!abstract] О чём лекция
> Синтаксис, который в курсе Python был помечен как «продвинутое» и оставлен на потом:
> короткие функции `lambda`, генераторные выражения, `*args` и `**kwargs`, распаковка,
> `for ... else` и моржовый оператор `:=`. Каждая из этих вещей в проекте встречается
> постоянно, поэтому их нужно не «знать», а уверенно читать.
>
> Правило всей лекции: **сначала понятность, потом краткость**. Половина этих конструкций
> уместна ровно там, где делает код короче без потери смысла.

# `lambda`: функция без имени

```python
prices = [120, 350, 80, 500]

print("по цене:", sorted(prices, key=lambda value: -value))
```

```text
по цене: [500, 350, 120, 80]
```

`lambda value: -value` — то же, что функция из одной строки:

```python
def by_price_desc(value):
    return -value
```

В проектах `lambda` используют **на месте вызова**, когда правило короткое и не будет
переиспользоваться: `sorted(..., key=lambda pair: pair[1])`, `max(..., key=len)`,
`filter(lambda x: x > 0, ...)`. Как только правило длиннее одной строки или нужно
дважды — это обычная функция с именем.

> [!note] `key=len` вместо `lambda` там, где можно
> `max(words, key=len)` читается лучше, чем `max(words, key=lambda w: len(w))`:
> если подходит встроенная функция, `lambda` не нужна.

# Генераторные выражения: считаем без лишнего списка

```python
total = sum(price for price in prices if price > 100)
print("сумма дороже 100:", total)
```

```text
сумма дороже 100: 970
```

Разница со списковым включением `[price for price in prices if price > 100]` в одном:
скобки `[...]` создают **список в памяти**, а `(...)` — генератор, который выдаёт значения
по одному. Для `sum`, `max`, `any`, `all` выгоднее генератор: лишний список не создаётся.

```python
numbers = [3, -1, 0, 7, 2]

print("есть отрицательные:", any(number < 0 for number in numbers))
print("все положительные:", all(number > 0 for number in numbers))
print("первое отрицательное:", next((number for number in numbers if number < 0), None))
```

```text
есть отрицательные: True
все положительные: False
первое отрицательное: -1
```

Генератор **одноразовый**: пройдя по нему один раз, второй раз уже ничего не получишь.
Если данные нужны дважды — делай список.

# `*args` и `**kwargs`: «сколько угодно аргументов»

```python
def report(title, *values, unit=""):
    return f"{title}: {', '.join(str(value) for value in values)}{unit}"


print(report("Цены", 120, 350, 80, 500, unit=" руб."))
```

```text
Цены: 120, 350, 80, 500 руб.
```

Разбор:

| Запись | Что означает |
|---|---|
| `*values` | все позиционные аргументы после `title` собираются в **кортеж** |
| `**options` | все именованные аргументы собираются в **словарь** |
| `unit=""` после `*values` | именованный аргумент со значением по умолчанию |

`*args` / `**kwargs` нужны, когда функция передаёт аргументы дальше (обёртки, декораторы,
логирование вызовов) или когда число аргументов действительно произвольное. Для обычных
функций честнее перечислить параметры: тогда видно, что функция принимает.

# Распаковка

```python
prices = [120, 350, 80, 500]

first, *rest = prices
print("first:", first, "rest:", rest)

a, b = 1, 2
a, b = b, a
print("обмен:", a, b)

print(report("Цены", *prices, unit=" руб."))
```

```text
first: 120 rest: [350, 80, 500]
обмен: 2 1
Цены: 120, 350, 80, 500 руб.
```

- `first, *rest = prices` — «первый отдельно, остальное списком»; удобно в разборе строк
  и заголовков;
- `a, b = b, a` — обмен без временной переменной;
- `*prices` в вызове — распаковка списка в аргументы.

# `for ... else` и моржовый оператор

```python
def find_negative(numbers):
    for number in numbers:
        if number < 0:
            print("нашли отрицательное:", number)
            break
    else:
        print("отрицательных нет")


find_negative([1, 2, -3])
find_negative([1, 2, 3])

if (count := len(prices)) > 3:
    print("чисел больше трёх:", count)
```

```text
нашли отрицательное: -3
отрицательных нет
чисел больше трёх: 4
```

- **`for ... else`**: `else` выполняется, если цикл дошёл до конца **без `break`**.
  Читается как «если не нашли — сообщить». Легко перепутать с `else` у `if`,
  поэтому в проектах это редкая конструкция: чаще пишут функцию с `return`.
- **`:=` (моржовый оператор)**: присваивает значение прямо внутри условия, чтобы
  не считать его дважды. Уместен в условиях и включениях; в обычном коде лишний.

# Как это делают в проекте

1. **`lambda` — только короткая и только на месте.** Правило с именем становится функцией.
2. **Генераторы — для сумм, максимумов и проверок** (`any` / `all`): экономят память
   и читаются как фраза.
3. **`*args` / `**kwargs` — в обёртках**, а не в бизнес-логике: «пробросить аргументы
   дальше» — их прямое назначение.
4. **Экзотика — по необходимости.** `for ... else` и `:=` разрешены, но если коллега
   переспрашивает «что тут происходит», конструкция не оправдана.

# Типичные заблуждения

| Заблуждение | Как на самом деле |
|---|---|
| «`lambda` — это быстрая функция» | Скорость та же; выигрыш только в краткости записи |
| «Генератор — то же, что список» | Генератор ленивый и одноразовый: второй проход пуст |
| «`*args` делает функцию универсальной» | Скрывает интерфейс: вызывающему не видно, что передать |
| «`else` у цикла — когда цикл не выполнился ни разу» | `else` выполняется, если не было `break`, — в том числе после полного прохода |
| «`:=` экономит код везде» | Экономит только там, где значение нужно и в условии, и в теле |

# Проверь себя

1. Когда `lambda` уместна, а когда нужна обычная функция?
2. Чем генераторное выражение отличается от спискового включения?
3. Что попадёт в `values` при вызове `report("Итог", 1, 2, 3)`?
4. Что выведет `find_negative([5, 6])` и почему?
5. Как распаковать первый элемент списка в переменную, а остальные — в список?
6. Почему после `sum(number for number in numbers)` нельзя «пройтись» по этому генератору ещё раз?

> [!success]- Ответы
> 1. `lambda` — если правило короткое и используется один раз на месте вызова
>    (`key=len`, `key=lambda pair: pair[1]`). Иначе — `def` с именем.
> 2. Списковое включение строит список в памяти; генератор выдаёт значения по одному
>    и не хранит их.
> 3. Кортеж `(1, 2, 3)`: всё после `title` собирается в `*values`.
> 4. `отрицательных нет`: цикл прошёл полностью без `break`, поэтому сработал `else`.
> 5. `first, *rest = numbers`.
> 6. Генератор не хранит элементы: он выдаёт их один раз и заканчивается.
