# 04. Практика. Система контроля версий, структура проекта и диагностика

> [!abstract] Цель и задачи практического занятия
> **Цель:** отработать полный инженерный цикл — версионирование, компоновка пакета и диагностика неисправностей.
> **Задачи:** выполнить сценарий `init`/`add`/`commit`/`branch`/`merge` с `.gitignore`; собрать пакет `school` по `pyproject.toml` с точкой входа; локализовать дефект по `traceback`, настроить `logging` и закрепить исправление тестами.
>
> *Пояснение для начинающих (для чайника):* Git — история с ветками как черновики, `school` — коробка с `src/` и биркой `pyproject.toml`, а `logging` — не `print`, а журнал с уровнями.
>
> ```mermaid
> flowchart LR
>   A[git init] --> B[commit]
>   B --> C[branch / merge]
>   C --> D[пакет school<br>pyproject]
>   D --> E[traceback → logging → тесты]
> ```

> [!important] Как работать с задачей
> 1. Прочитай условие и **не открывай разбор**.
> 2. Выполняй команды по одной и смотри на вывод — он информативнее, чем кажется.
> 3. Если что-то не совпало с ожиданием, разберись **до** того, как смотреть разбор.
> 4. Сверься с разбором и сравни не только команды, но и сообщения об ошибках.

## Задача 1. История и ветка

★☆☆ · `git init`, `git add`, `git commit`, `.gitignore`, `git switch`, `git merge`

**Условие.** Нужно завести репозиторий для маленького модуля `greet.py` с функцией
`greet(name)` и провести одну задачу через ветку.

**Задание.** 1) Создай папку, выполни `git init` и настрой имя и почту (в своём репозитории:
`git config user.name`, `git config user.email`). 2) Создай `greet.py` с функцией
`greet(name)` (она возвращает строку `Привет, <имя>!`) и посмотри `git status`.
3) Закоммить файл с понятным сообщением. 4) Добавь точку входа
`if __name__ == "__main__":` с `print(greet("Аня"))` и посмотри `git diff --stat`.
5) Создай файл `report.txt` с любым текстом (это «результат запуска», которому не место
в истории) и `.gitignore` с `.venv/`, `__pycache__/`, `report.txt`; импортируй модуль,
чтобы появился `__pycache__/`, и проверь, что `__pycache__/` и `report.txt` в `git status`
**не видны**; закоммить `.gitignore` и точку входа. 6) Создай ветку `feature/hello`,
добавь в неё функцию `farewell(name)`, закоммить, вернись в `main` и влей ветку.
7) Посмотри `git log --oneline`.

> [!example]- Разбор
> **Идея.** Коммит — версия всего проекта, а не «сохранение файла». `.gitignore` описывает,
> что в историю не идёт: восстановимое и генерируемое. Ветка позволяет сделать задачу
> отдельно, а вливание оставляет в `main` одну понятную запись.
>
> **Команды.**
>
> ```bash
> git init -q -b main .
> git config user.name "Ученик"
> git config user.email "student@example.com"
>
> # greet.py: def greet(name): return f"Привет, {name}!"
> git status --short          # ?? greet.py
> git add greet.py
> git commit -m "Добавляет функцию приветствия"
> git log --oneline           # efef065 Добавляет функцию приветствия
> ```
>
> Хеши коммитов (`efef065`, дальше `c80fb7b`, `25372a7`) у тебя будут другими: они зависят
> от автора и времени.
>
> **Добавляем точку входа и смотрим изменения:**
>
> ```text
> $ git diff --stat
>  greet.py | 4 ++++
>  1 file changed, 4 insertions(+)
> ```
>
> **Добавляем `report.txt` и `.gitignore` и проверяем:**
>
> ```text
> $ echo "черновик" > report.txt
> $ python3 -c "import greet; print(greet.greet('Аня'))"
> Привет, Аня!
>
> $ git status --short
>  M greet.py
> ?? .gitignore
> ```
>
> `__pycache__/` появился после импорта, `report.txt` создан — но в выводе их **нет**:
> они в `.gitignore`. Модифицированный `greet.py` и новый `.gitignore` — единственное,
> что Git предлагает закоммитить. Коммитим оба файла:
> `git add .gitignore greet.py`, затем `git commit -m "Добавляет точку входа и .gitignore"`.
>
> **Ветка и слияние:**
>
> ```bash
> git switch -c feature/hello
> # добавляем в greet.py функцию farewell(name)
> git add greet.py
> git commit -m "Добавляет функцию прощания"
> git switch main
> git merge feature/hello
> git log --oneline
> ```
>
> ```text
> 25372a7 Добавляет функцию прощания
> c80fb7b Добавляет точку входа и .gitignore
> efef065 Добавляет функцию приветствия
> ```
>
> Ветка `main` просто «догнала» `feature/hello` (быстрая перемотка, fast-forward): своих
> коммитов у `main` за это время не появилось, поэтому отдельного коммита слияния нет.
>
> **Что здесь важно.** `git status` и `git diff` — глаза Git: сначала посмотреть, что изменилось,
> и только потом `git add`. `.gitignore` лучше заводить в первый же день — иначе сгенерированные
> файлы попадут в историю, и убирать их оттуда неприятно.
>
> **Типичная ошибка.** Делать `git add -A` сразу после `git init`: в историю уходят `.venv/`,
> `__pycache__/` и локальные файлы. Вторая ошибка — коммит `update` или `fix`: через неделю
> по такому журналу невозможно понять, что было сделано.
>
> **Граница.** В учебном репозитории можно позволить себе один коммит на задачу и работать
> в `main`. В общем проекте в `main` обычно нельзя коммитить напрямую: изменения приходят
> через ветку и pull request ([[13. Git и GitHub]]) — это вопрос договорённости команды,
> а не возможностей Git.

## Задача 2. Пакет `school`

★★☆ · `src`-layout, пакеты, импорты, настройки из окружения, точка входа

**Условие.** Проект «школьные оценки» состоит из пакета и точки входа:

```text
pr4school/
├── src/
│   └── school/
│       ├── __init__.py
│       ├── marks.py      ← average(marks)
│       ├── report.py     ← summary(marks)
│       └── config.py     ← Config.from_env()
├── tests/
│   └── test_report.py
├── .env.example          ← CLASS_NAME= и DEBUG= (имена без значений)
└── main.py               ← main()
```

**Задание.** 1) Собери структуру. 2) В `marks.py` — `average(marks) -> float | None`,
в `report.py` — `summary(marks) -> str` (импортирует `average` из пакета),
в `config.py` — `Config.from_env()`, который читает `CLASS_NAME` и `DEBUG` из окружения
и падает с понятным сообщением, если `CLASS_NAME` нет. Файл `.env.example` просто
перечисляет имена настроек (он подсказка для человека). 3) `main()` печатает настройки
и отчёт. 4) Запусти `python3 main.py` **без** `PYTHONPATH` и объясни ошибку. 5) Запусти
с `PYTHONPATH=src CLASS_NAME=9А DEBUG=true`. 6) Прогони тесты и `mypy`.

> [!example]- Разбор
> **Идея.** Код живёт в пакете `school`, а не в корне: так `main.py` и тесты импортируют
> его одинаково — `from school.report import summary`. Настройки приходят снаружи
> ([[17. Внедрение зависимостей]]): в коде нет ни класса `9А`, ни паролей.
>
> **Код (`src/school/marks.py`, `report.py`, `config.py`).**
>
> ```python
> def average(marks: dict[str, int]) -> float | None:
>     """Средний балл; None, если оценок нет."""
>     if not marks:
>         return None
>     return sum(marks.values()) / len(marks)
> ```
>
> ```python
> from school.marks import average
>
>
> def summary(marks: dict[str, int]) -> str:
>     """Строка-отчёт по оценкам."""
>     value = average(marks)
>     if value is None:
>         return "Оценок нет"
>     return f"Учеников: {len(marks)}, средний балл: {value:.2f}"
> ```
>
> ```python
> import os
> from dataclasses import dataclass
>
>
> @dataclass
> class Config:
>     """Настройки приложения из окружения."""
>
>     class_name: str
>     debug: bool
>
>     @classmethod
>     def from_env(cls) -> "Config":
>         """Читает настройки; RuntimeError, если обязательной нет."""
>         name = os.environ.get("CLASS_NAME")
>         if not name:
>             raise RuntimeError("не задан CLASS_NAME: посмотри .env.example")
>         return cls(class_name=name, debug=os.environ.get("DEBUG", "") == "true")
> ```
>
> **Точка входа (`main.py`).**
>
> ```python
> from school.config import Config
> from school.report import summary
>
>
> def main() -> None:
>     """Точка входа: читает настройки и печатает отчёт."""
>     config = Config.from_env()
>     print(f"Класс: {config.class_name} (отладка: {config.debug})")
>     print(summary({"Аня": 5, "Борис": 4}))
>
>
> if __name__ == "__main__":
>     main()
> ```
>
> **Запуск без `PYTHONPATH`:**
>
> ```text
> $ python3 main.py
> ...
> ModuleNotFoundError: No module named 'school'
> ```
>
> Python ищет модули в текущей папке и в путях из `sys.path`; папка `src` в этот список
> не входит. Отсюда правило: запускать программу из корня проекта с указанием пути к пакету
> (`PYTHONPATH=src`) либо установить проект в окружение (в `pyproject.toml` описывают сборку
> пакета, и `uv sync` ставит его в `.venv`; подробнее — [[12. Структура проекта и модули]]).
> Настройки `CLASS_NAME` и `DEBUG` Python берёт только из окружения: файл `.env.example`
> сам ничего не задаёт, а подсказывает, какие переменные нужно задать при запуске.
>
> **Запуск с настройками:**
>
> ```text
> $ PYTHONPATH=src CLASS_NAME=9А DEBUG=true python3 main.py
> Класс: 9А (отладка: True)
> Учеников: 2, средний балл: 4.50
> ```
>
> ```text
> $ PYTHONPATH=src python3 main.py
> ...
> RuntimeError: не задан CLASS_NAME: посмотри .env.example
> ```
>
> **Тесты и `mypy`:**
>
> ```python
> from school.report import summary
>
>
> def test_summary():
>     assert summary({"Аня": 5, "Борис": 4}) == "Учеников: 2, средний балл: 4.50"
>
>
> def test_summary_empty():
>     assert summary({}) == "Оценок нет"
> ```
>
> ```text
> $ PYTHONPATH=src pytest -q tests
> ..                                                                       [100%]
> 2 passed in 0.00s
>
> $ PYTHONPATH=src mypy src main.py tests
> Success: no issues found in 6 source files
> ```
>
> **Что здесь важно.** Сообщение об отсутствующей настройке говорит, **что делать**
> («посмотри `.env.example`»), а не просто «нет переменной». Тест на пустой словарь —
> это проверка границы: без него деление на ноль (`sum / len`) пришло бы в проект позже,
> уже в виде непонятного сбоя.
>
> **Типичная ошибка.** Импортировать файлы «через папку»: `from ..marks import average`
> в модуле, который запускается напрямую. Такие импорты ломаются при `python3 report.py`.
> Вторая ошибка — держать настройки в коде: класс `9А` в константе выглядит безобидно,
> пока проект не запускается на втором компьютере.
>
> **Граница.** Один и тот же `summary` может обслуживать и маленькую программу, и веб-сервис:
> он не знает, откуда взялись оценки. А вот `main()` в веб-приложении обычно не пишут:
> точку входа там задаёт сам фреймворк (в Django — файл `manage.py`).

## Задача 3. Починить сломанный отчёт

★★★ · чтение traceback, logging, исправление, тесты

**Условие.** Есть программа, которая читает оценки из `marks.csv` (формат `Имя;оценка`)
и печатает словарь и средний балл:

```python
from pathlib import Path


def parse_row(row):
    name, mark_text = row.split(";")
    return name, int(mark_text)


def load(path):
    rows = Path(path).read_text(encoding="utf-8").splitlines()
    students = {}
    for row in rows:
        name, mark = parse_row(row)
        students[name] = mark
    return students


def average(students):
    return sum(students.values()) / len(students)


if __name__ == "__main__":
    students = load("marks.csv")
    print(students)
    print("средний балл:", average(students))
```

Файл `marks.csv`:

```text
Аня;5
Борис;4

Вика;3
```

**Задание.** 1) Запусти программу и **прочитай traceback**: какая функция виновата, с какими
данными она работала? 2) Добавь `logging` и добейся, чтобы пропуск пустой строки был виден
при уровне `DEBUG`. 3) Исправь так, чтобы: пустые строки пропускались, плохая строка
не роняла программу, но попадала в список ошибок с номером строки, а `average({})` возвращал
`None` с предупреждением в лог. 4) Напиши тесты на всё исправленное поведение.

> [!example]- Разбор
> **Идея.** Отладка идёт от симптома к причине: сначала traceback говорит, **где** упало,
> затем данные показывают **почему**, затем решение закрывает **класс** таких ситуаций,
> а тесты фиксируют результат.
>
> **Шаг 1. Ошибка.**
>
> ```text
> Traceback (most recent call last):
>   File "/tmp/eng/pr4/marks_report.py", line 23, in <module>
>     students = load("marks.csv")
>                ^^^^^^^^^^^^^^^^^
>   File "/tmp/eng/pr4/marks_report.py", line 13, in load
>     name, mark = parse_row(row)
>                  ^^^^^^^^^^^^^^
>   File "/tmp/eng/pr4/marks_report.py", line 5, in parse_row
>     name, mark_text = row.split(";")
>     ^^^^^^^^^^^^^^^
> ValueError: not enough values to unpack (expected 2, got 1)
> ```
>
> Читаем снизу: `ValueError` в `parse_row`, строка 5 — `row.split(";")` вернул **один**
> элемент вместо двух. Значит, в `parse_row` пришла строка без `;` — это пустая строка
> из файла (третья). Причина найдена **без единого изменения в коде**.
>
> **Шаг 2. Смотрим, что происходит.** В исправленном варианте пропуск пустой строки пишется
> в лог на уровне `DEBUG`:
>
> ```python
> logger.debug("строка %d пустая: пропускаю", number)
> ```
>
> ```text
> $ python3 -c "..."  # basicConfig(level=logging.DEBUG); load("marks.csv"); print("оценки:", ...)
> DEBUG строка 3 пустая: пропускаю
> оценки: {'Аня': 5, 'Борис': 4, 'Вика': 3}
> ```
>
> При обычном уровне `INFO` этой строки не видно — в логе остаётся только важное.
>
> **Шаг 3. Исправленный код (`fixed_report.py`).**
>
> ```python
> import logging
> from pathlib import Path
>
> logging.basicConfig(level=logging.INFO, format="%(levelname)s %(message)s")
> logger = logging.getLogger(__name__)
>
>
> class RowError(Exception):
>     """Строку с оценкой не удалось разобрать."""
>
>
> def parse_row(row, number):
>     """Разбирает строку «Имя;оценка»; RowError с номером строки, если не вышло."""
>     name, separator, mark_text = row.partition(";")
>     if not separator:
>         raise RowError(f"строка {number}: нет разделителя «;»")
>     try:
>         mark = int(mark_text)
>     except ValueError as exc:
>         raise RowError(f"строка {number}: «{mark_text.strip()}» — не число") from exc
>     if not 1 <= mark <= 5:
>         raise RowError(f"строка {number}: оценка {mark} вне 1–5")
>     return name.strip(), mark
>
>
> def load(path):
>     """Читает файл: словарь оценок и список ошибок."""
>     text = Path(path).read_text(encoding="utf-8")
>     students = {}
>     errors = []
>     for number, row in enumerate(text.splitlines(), start=1):
>         if not row.strip():
>             logger.debug("строка %d пустая: пропускаю", number)
>             continue
>         try:
>             name, mark = parse_row(row, number)
>         except RowError as exc:
>             errors.append(str(exc))
>         else:
>             students[name] = mark
>     return students, errors
>
>
> def average(students):
>     """Средний балл; None, если данных нет."""
>     if not students:
>         logger.warning("нет данных: средний балл не определён")
>         return None
>     return sum(students.values()) / len(students)
> ```
>
> **Проверка на «плохом» файле** `marks.csv` (`Аня;5`, `Борис;4`, пустая строка, `Вика;семь`,
> `Гена;7`) — файл `demo_fixed.py`:
>
> ```python
> from fixed_report import average, load
>
> students, errors = load("marks.csv")
> print(students)
> print("средний балл:", average(students))
> for error in errors:
>     print("ошибка:", error)
> print("пустые данные:", average({}))
> ```
>
> ```text
> $ python3 -u demo_fixed.py 2>&1
> {'Аня': 5, 'Борис': 4}
> средний балл: 4.5
> ошибка: строка 4: «семь» — не число
> ошибка: строка 5: оценка 7 вне 1–5
> WARNING нет данных: средний балл не определён
> пустые данные: None
> ```
>
> Ключ `2>&1` направляет сообщения лога (они идут в поток ошибок) туда же, куда и `print`,
> а `-u` отключает буферизацию, чтобы строки шли в порядке выполнения. Предупреждение
> про пустые данные — то самое требование «`average({})` возвращает `None` с предупреждением
> в лог».
>
> **Шаг 4. Тесты (`test_fixed_report.py`).**
>
> ```python
> import pytest
>
> from fixed_report import RowError, average, load, parse_row
>
>
> def test_row_with_number():
>     assert parse_row("Аня;5", 1) == ("Аня", 5)
>
>
> def test_row_without_separator():
>     with pytest.raises(RowError, match="строка 2"):
>         parse_row("Борис", 2)
>
>
> def test_row_with_text_mark():
>     with pytest.raises(RowError, match="не число"):
>         parse_row("Вика;семь", 3)
>
>
> def test_row_out_of_range():
>     with pytest.raises(RowError, match="вне 1–5"):
>         parse_row("Гена;7", 4)
>
>
> def test_load_skips_empty_lines(tmp_path):
>     path = tmp_path / "marks.csv"
>     path.write_text("Аня;5\n\nБорис;4\n", encoding="utf-8")
>     students, errors = load(path)
>     assert students == {"Аня": 5, "Борис": 4}
>     assert errors == []
>
>
> def test_load_collects_errors(tmp_path):
>     path = tmp_path / "marks.csv"
>     path.write_text("Аня;5\nВика;семь\n", encoding="utf-8")
>     students, errors = load(path)
>     assert students == {"Аня": 5}
>     assert errors == ["строка 2: «семь» — не число"]
>
>
> def test_average_normal():
>     assert average({"Аня": 5, "Борис": 4}) == 4.5
>
>
> def test_average_empty():
>     assert average({}) is None
> ```
>
> ```text
> $ pytest -q test_fixed_report.py
> ........                                                                 [100%]
> 8 passed in 0.01s
> ```
>
> **Что здесь важно.** Каждый тест соответствует одной найденной проблеме: пустая строка,
> строка без разделителя, нечисловая оценка, оценка вне диапазона, пустые данные. Именно так
> ошибка превращается в защиту от повторения.
>
> **Типичная ошибка.** «Залатать» симптом: `if row == "": continue` — и не заметить строку
> из пробелов (`"   "`) или строку без `;` с непустым именем. Второй вариант — обернуть весь
> цикл в `except Exception` и потерять остальные записи.
>
> **Граница.** Номер строки в сообщении — из `enumerate(..., start=1)`; если файл содержит
> символы, отличные от UTF-8, чтение упадёт раньше разбора, и это отдельный случай, который
> стоит обработать явно (`errors="replace"` или своё сообщение), — но сначала убедись,
> что это действительно нужно, а не «на всякий случай».

# Что запомнить из практики

| Приём | Когда |
|---|---|
| `git status` / `git diff` перед `git add` | чтобы не отправить в историю лишнее |
| `.gitignore` в первый день | генерируемые файлы и секреты не попадают в репозиторий |
| ветка под задачу | в `main` приходит только законченная работа |
| `src`-layout и импорт от пакета | код, тесты и запуск видят проект одинаково |
| настройки из окружения с проверкой | параметры не зашиты в код, ошибка видна сразу |
| traceback: сначала последняя строка | тип и причина ошибки; затем — свой первый блок `File ...` в цепочке вызовов |
| `logging.debug` для подробностей | в обычном режиме лог не забит мелочами |
| тест на каждую найденную проблему | ошибка больше не вернётся незамеченной |
