# 06. Мини-проект. Банк с отчётом

> [!abstract] Что это за проект
> Небольшая программа, которая читает список банковских операций и строит отчёт в одном
> из форматов. Внешне она простая — сложность в **устройстве**: пакет, настройки
> из окружения, реестр отчётов, источник данных, который можно подменить в тестах,
> логирование и тесты.
>
> Это первый проект курса, собранный «как в настоящей работе»: те же приёмы, что
> в [[16. Проектирование - фабрики и реестры]], [[17. Внедрение зависимостей]],
> [[12. Структура проекта и модули]] и [[09. Отладка и диагностика]].
>
> **Перед началом** нужно пройти практики [[01. Практика. Ошибки и типизация]],
> [[02. Практика. Тесты и синтаксис]], [[03. Практика. Проектирование]],
> [[04. Практика. Инструменты и структура]] и [[05. Практика. Библиотеки и качество]] —
> здесь всё это используется сразу.

# Что должно получиться

Программа запускается из корня проекта и строит отчёт по файлу `data/operations.csv`:

```text
$ PYTHONPATH=src BANK_NAME=Учебный python3 main.py
INFO банк Учебный, формат: summary
Операций: 5
Доходы: 5800.00
Расходы: 1640.50
Баланс: 4159.50
```

Формат отчёта выбирается настройкой:

```text
$ PYTHONPATH=src BANK_NAME=Учебный REPORT_FORMAT=text python3 main.py
INFO банк Учебный, формат: text
2026-09-01 доход: 5000.00
2026-09-02 расход: 1200.00
2026-09-03 расход: 350.50
2026-09-05 доход: 800.00
2026-09-06 расход: 90.00
```

Если какая-то строка файла испорчена, программа **не падает**: строка пропускается,
остальные операции попадают в отчёт, а в лог уходит предупреждение:

```text
WARNING пропускаю: строка 7: неизвестный вид «подарок»
```

# Как идти

1. **Подготовь проект.** Создай папки и файлы сам — стартовых заготовок нет:

   ```text
   bank-report/
   ├── src/bank/__init__.py
   ├── src/bank/models.py
   ├── src/bank/sources.py
   ├── src/bank/reports.py
   ├── src/bank/config.py
   ├── main.py
   ├── tests/test_bank.py
   ├── data/operations.csv
   ├── .gitignore
   └── README.md
   ```

2. **Сделай первый коммит** — до кода: `.gitignore` (`.venv/`, `__pycache__/`, `.env`),
   `README.md` с двумя строками, пустые модули с docstring модуля.

3. **Начни с модели и источника.** `Operation`, затем `parse_row` и `MemorySource` —
   их легко проверить без файлов. Сразу пиши тесты: хорошая строка, плохая строка,
   пустой источник.

4. **Добавь `CsvSource`.** Чтение файла, пропуск пустых строк, сбор предупреждений
   через `logger.warning`. Проверь на своём `data/operations.csv` — в отчёте должно
   оказаться **5 операций**, а не 6.

5. **Собери отчёты.** Три функции и реестр `REPORTS`. Проверь, что `ReportBuilder`
   не знает, откуда данные: он вызывает `self.source.load()`.

6. **Добавь настройки.** `Config.from_env()` читает `BANK_NAME` (обязательно)
   и `REPORT_FORMAT` (по умолчанию `summary`); неизвестный формат — понятная ошибка
   со списком доступных.

7. **Соедини в `main()`.** Собери источник, отчёт и конфиг в одном месте; сообщения —
   через `logger.info`.

8. **Прогони проверки:** `pytest`, `mypy`, `black --check`, `ruff check`. Затем —
   `PYTHONPATH=src BANK_NAME=Учебный python3 main.py` и сверь числа со списком ниже.

9. **Закоммить по шагам.** Хорошая история: «Структура проекта и модели», «Чтение CSV
   и ошибки строк», «Реестр отчётов и точка входа», «Тесты и настройки».

# Пример-аналог

> [!example]- Библиотека: учёт просрочек (другая задача, то же устройство)
> Это **не решение** твоего проекта, а маленькая программа, собранная похожим образом:
> другой сюжет, другая предметная область, но то же устройство — пакет, источники, реестр
> отчётов, настройки из окружения, тесты.
>
> В фрагментах ниже опущены импорты и `logger`: понадобятся `import os`, `import logging`,
> `from pathlib import Path` и `logger = logging.getLogger(__name__)`, а для запуска
> с выводом `INFO` — `logging.basicConfig(level=logging.INFO, format="%(levelname)s %(message)s")`
> в `main.py`.
>
> **Структура:**
>
> ```text
> library/
> ├── src/library/
> │   ├── __init__.py
> │   ├── models.py     ← Loan: название, срок, просрочка, свойство fine
> │   ├── sources.py    ← MemorySource, CsvSource
> │   ├── reports.py    ← REPORTS = {"text": ..., "short": ...}, ReportBuilder
> │   └── config.py     ← Config.from_env()
> ├── tests/test_reports.py
> ├── loans.csv
> └── main.py
> ```
>
> **Модель:**
>
> ```python
> from dataclasses import dataclass
>
>
> @dataclass
> class Loan:
>     """Выдача книги: название, срок в днях, просрочка в днях."""
>
>     title: str
>     days: int
>     overdue: int
>
>     @property
>     def fine(self) -> float:
>         """Пеня: 10 руб. за каждый день просрочки."""
>         return self.overdue * 10.0
> ```
>
> **Источник из файла** (`loans.csv`: `Алгебра;14;0`, `Физика;7;3`, `История;10;1`):
>
> ```python
> class CsvSource:
>     """Источник: читает «название;срок;просрочка» из файла."""
>
>     def __init__(self, path):
>         self.path = Path(path)
>
>     def load(self):
>         """Читает файл и возвращает список выдач."""
>         loans = []
>         for row in self.path.read_text(encoding="utf-8").splitlines():
>             if not row.strip():
>                 continue
>             title, days, overdue = row.split(";")
>             loans.append(Loan(title, int(days), int(overdue)))
>         return loans
> ```
>
> **Реестр и построитель отчёта:**
>
> ```python
> def report_text(loans):
>     """Отчёт по строкам: книга и пеня."""
>     lines = [f"{loan.title}: пеня {loan.fine:.2f}" for loan in loans]
>     return "\n".join(lines)
>
>
> def report_short(loans):
>     """Короткий отчёт: только итог."""
>     return f"выдач: {len(loans)}, пеня: {sum(loan.fine for loan in loans):.2f}"
>
>
> REPORTS = {"text": report_text, "short": report_short}
>
>
> class ReportBuilder:
>     """Строит отчёт: берёт выдачи из источника, формат — из реестра."""
>
>     def __init__(self, source, report):
>         self.source = source
>         self.report = report
>
>     def build(self):
>         """Возвращает готовый отчёт строкой."""
>         return self.report(self.source.load())
> ```
>
> **Настройки и точка входа:**
>
> ```python
> @dataclass
> class Config:
>     """Настройки библиотеки из окружения."""
>
>     name: str
>     report_kind: str
>
>     @classmethod
>     def from_env(cls) -> "Config":
>         """Читает настройки; RuntimeError, если чего-то не хватает."""
>         name = os.environ.get("LIBRARY_NAME")
>         if not name:
>             raise RuntimeError("не задан LIBRARY_NAME: посмотри .env.example")
>         kind = os.environ.get("REPORT_KIND", "short")
>         if kind not in ("text", "short"):
>             raise RuntimeError(f"неизвестный REPORT_KIND: {kind}")
>         return cls(name=name, report_kind=kind)
> ```
>
> ```python
> def main():
>     """Точка входа: отчёт по файлу loans.csv."""
>     config = Config.from_env()
>     source = CsvSource("loans.csv")
>     builder = ReportBuilder(source, REPORTS[config.report_kind])
>     logger.info("библиотека %s, отчёт: %s", config.name, config.report_kind)
>     print(builder.build())
> ```
>
> **Запуск:**
>
> ```text
> $ PYTHONPATH=src LIBRARY_NAME=Школьная python3 main.py
> INFO библиотека Школьная, отчёт: short
> выдач: 3, пеня: 40.00
>
> $ PYTHONPATH=src LIBRARY_NAME=Школьная REPORT_KIND=text python3 main.py
> INFO библиотека Школьная, отчёт: text
> Алгебра: пеня 0.00
> Физика: пеня 30.00
> История: пеня 10.00
> ```
>
> **Тесты и проверки:**
>
> ```text
> $ PYTHONPATH=src pytest -q tests
> ...                                                                      [100%]
> 3 passed in 0.01s
>
> $ PYTHONPATH=src mypy src main.py tests
> Success: no issues found in 7 source files
> ```
>
> Посмотри, **что здесь общее** с твоим проектом: источник передаётся в построитель, отчёт
> выбирается из реестра по настройке, тесты работают на `MemorySource` и не читают файл.
> Разница только в предметной области — а она у тебя другая.

| Симптом | Куда смотреть |
|---|---|
| `ModuleNotFoundError: No module named 'bank'` | [[12. Структура проекта и модули]]: запуск из корня с `PYTHONPATH=src` |
| `ValueError: not enough values to unpack` при чтении CSV | [[09. Отладка и диагностика]]: последняя строка traceback и свой первый блок `File ...`; пустая строка в файле |
| Тест падает из-за файлов | [[17. Внедрение зависимостей]]: подменить источник на `MemorySource` |

# Типичные ошибки

| Ошибка | Чем плоха |
|---|---|
| `open("data/operations.csv")` прямо в отчёте | формат отчёта зависит от файла; тесты требуют настоящих данных |
| Итог считается в `print` | логику нельзя переиспользовать и проверить тестом |
| Один файл `main.py` со всем кодом | через неделю непонятно, где что; требование 1 нарушено |
| `except Exception: pass` вокруг чтения файла | ошибки исчезают вместе с операциями: отчёт «правильный», но неполный |
| Настройки зашиты в код | нельзя запустить с другим форматом отчёта без правки |
| Тесты, читающие рабочий `data/operations.csv` | тест зависит от данных, которые кто-то поменяет |
