# 05. Практика. Сторонние библиотеки, читаемость и оценка производительности

> [!abstract] Цель и задачи практического занятия
> **Цель:** сформировать критерии выбора зависимостей и навыки обеспечения качества кода через анализ производительности и стилевые проверки.
> **Задачи:** сопоставить решение стандартной библиотекой и `numpy` для оценки целесообразности зависимости; нормализовать код `black`/`ruff` и оценить границы автоформатирования; измерить `timeit`/`cProfile` и документировать `docstring` до оптимизации.
>
> *Пояснение для начинающих (для чайника):* нужна ли библиотека — смотри `statistics` vs `numpy`; `black`/`ruff` — как авто-корректор, а `timeit` — линейка, без неё «кажется быстрее» не считается.
>
> ```mermaid
> flowchart LR
>   A[задача] --> B{нужна ли<br>зависимость?}
>   B --> C[black/ruff<br>форма]
>   C --> D[docstring]
>   D --> E[timeit/cProfile<br>замер]
> ```

> [!important] Как работать с задачей
> 1. Прочитай условие и **не открывай разбор**. Разбор свёрнут (`> [!example]-`).
> 2. Сначала посмотри на код глазами и запиши, что не так, — **потом** запускай инструмент.
>    Так видно, что инструмент ловит, а что нет.
> 3. Запускай и сверяй вывод: здесь важны и числа, и текст сообщений.
> 4. В задачах на скорость не верь «кажется быстрее» — только `timeit` и `cProfile`.

## Задача 1. Библиотека или стандартная библиотека

★☆☆ · `statistics`, `numpy`, `uv add`, решение о зависимости

**Условие.** Есть оценки класса:

```python
MARKS = [4, 5, 3, 5, 4, 4, 5, 3, 5, 4, 4, 5]
```

Нужно посчитать: сколько оценок, среднее, медиану и разброс (стандартное отклонение).

**Задание.** 1) Напиши `stats_stdlib.py` — только стандартная библиотека, без сторонних
пакетов. 2) Напиши `stats_numpy.py` — то же через NumPy (`uv add numpy`). 3) Сравни
выводы: совпали ли числа? 4) Напиши `compare_speed.py`: на данных в 200 004 значения
замерь `timeit`-ом три варианта — `statistics.mean`, `np.mean` по готовому массиву
и `np.mean` по списку. 5) Ответь: нужна ли в проекте зависимость `numpy`, если все расчёты
такие же, как в условии?

> [!example]- Разбор
> **Идея.** `statistics` — часть стандартной библиотеки: её не нужно устанавливать, она
> всегда под рукой. NumPy нужен, когда данных много: на 12 значениях обе библиотеки дадут
> одно и то же, а на двухстах тысячах — разное время. Значит, вопрос «нужна ли зависимость»
> решается **данными**, а не привычкой.
>
> **Код** (`stats_stdlib.py`):
>
> ```python
> """Статистика по оценкам средствами стандартной библиотеки."""
>
> import statistics
>
> MARKS = [4, 5, 3, 5, 4, 4, 5, 3, 5, 4, 4, 5]
>
> print("оценок:", len(MARKS))
> print("среднее:", round(statistics.mean(MARKS), 2))
> print("медиана:", statistics.median(MARKS))
> print("разброс (pstdev):", round(statistics.pstdev(MARKS), 2))
> ```
>
> ```text
> оценок: 12
> среднее: 4.25
> медиана: 4.0
> разброс (pstdev): 0.72
> ```
>
> **Код** (`stats_numpy.py`):
>
> ```python
> """Та же статистика через NumPy: понадобилась библиотека numpy."""
>
> import numpy as np
>
> MARKS = [4, 5, 3, 5, 4, 4, 5, 3, 5, 4, 4, 5]
> data = np.array(MARKS)
>
> print("оценок:", data.size)
> print("среднее:", round(float(data.mean()), 2))
> print("медиана:", float(np.median(data)))
> print("разброс (std):", round(float(data.std()), 2))
> ```
>
> ```text
> оценок: 12
> среднее: 4.25
> медиана: 4.0
> разброс (std): 0.72
> ```
>
> Числа совпали во всём. Замер на больших данных:
>
> ```python
> """Сколько стоит библиотека: тот же расчёт на 200 004 значениях."""
>
> import statistics
> import timeit
>
> import numpy as np
>
> MARKS = [4, 5, 3, 5, 4, 4, 5, 3, 5, 4, 4, 5] * 16_667
> DATA = np.array(MARKS)
> RUNS = 20
>
>
> def use_stdlib() -> float:
>     """Среднее средствами стандартной библиотеки."""
>     return statistics.mean(MARKS)
>
>
> def use_numpy() -> float:
>     """Среднее по готовому массиву NumPy."""
>     return float(np.mean(DATA))
>
>
> def numpy_from_list() -> float:
>     """Среднее, если массив каждый раз строится из списка."""
>     return float(np.mean(MARKS))
>
>
> print("значений:", len(MARKS))
> for function in (use_stdlib, use_numpy, numpy_from_list):
>     seconds = timeit.timeit(function, number=RUNS) / RUNS
>     print(f"{function.__name__:16} {seconds * 1000:7.2f} мс")
> ```
>
> ```text
> значений: 200004
> use_stdlib         18.94 мс
> use_numpy           0.13 мс
> numpy_from_list     3.80 мс
> ```
>
> **Что здесь важно.** Три числа вместо одного:
>
> | Вариант | Время | Что это значит |
> |---|---|---|
> | `statistics.mean` | 18.94 мс | чистый Python: проходит по списку по одному элементу |
> | `np.mean` по готовому массиву | 0.13 мс | данные уже в массиве — почти в 150 раз быстрее |
> | `np.mean` по списку | 3.80 мс | массив строится заново при каждом вызове: выигрыш в 5 раз, а не в 150 |
>
> Отсюда и ответ: для 12 оценок зависимость не нужна — хватает `statistics`. Для сотен тысяч
> значений NumPy нужен, но только если массив готовится один раз ([[00. NumPy]]).
>
> **Типичная ошибка.** Тащить NumPy «на всякий случай» в проект, где считаются три средних:
> зависимость появляется, выигрыша нет. Обратная ошибка — писать статистику циклами руками,
> когда `statistics` уже есть.
>
> **Граница.** Время зависит от машины: на другом компьютере числа будут другими, а порядок
> сохранится. И осторожно с определением разброса: `statistics.pstdev` и `np.std` считают
> одно и то же («по всей совокупности»), а `statistics.stdev` и `np.std(ddof=1)` — выборочное
> отклонение. Для класса из 12 человек это разные числа, и выбирать нужно осознанно.

## Задача 2. Привести файл в порядок

★★☆ · `black`, `ruff --fix`, docstring, смысловые ошибки

**Условие.** Так выглядит рабочий (запускается!) файл `dirty.py`:

```python
import json
import os


def average(marks,tags=[]):
    '''Средний балл'''
    if marks==None or len(marks)==0: return 0
    result=sum(marks)/len(marks)
    tags.append("посчитано")
    return round(result,2)


def report(students):
    lines=[]
    for s in students:
        lines.append(s["name"]+": "+str(average(s["marks"])))
    return "\n".join(lines)


print(report([{"name":"Аня","marks":[5,4,5]},{"name":"Борис","marks":[]}]))
```

**Задание.** 1) Запусти файл. Что он печатает для Бориса и почему это плохо?
2) Запусти `black --check` и `black --diff` — что исправляет форматтер?
3) Запусти `ruff check --select "E,F,I,UP,B"` — сколько проблем нашёл линтер?
4) Запусти `ruff check --fix` — что исправилось само, а что осталось и почему?
5) Перепиши файл в `grades.py`: аннотации типов, docstring, явная ошибка на пустом списке,
   без изменяемого значения по умолчанию. 6) Прогони `black --check`, `ruff check`, `mypy`.

> [!example]- Разбор
> **Идея.** Инструменты не заменяют чтение кода: `black` выравнивает форму, `ruff` ловит
> типовые ошибки, но **смысл** проверяет человек. Строка «Борис: 0» — как раз смысловая
> ошибка: у Бориса нет оценок, и «0» — это неправда, а не результат.
>
> **1. Запуск «грязного» файла:**
>
> ```text
> Аня: 4.67
> Борис: 0
> ```
>
> **2. Формат:**
>
> ```bash
> $ black --check dirty.py
> would reformat dirty.py
>
> Oh no! 💥 💔 💥
> 1 file would be reformatted.
> ```
>
> `black --diff` показывает, что именно меняется: пробелы вокруг `=` и после запятых,
> двойные кавычки в docstring, `if ...: return 0` разбивается на две строки. Смысл при этом
> не трогается — `marks == None` так и остаётся сравнением, хотя правильнее `is None`.
>
> **3. Линтер:**
>
> ```text
> $ ruff check --output-format=concise --select "E,F,I,UP,B" dirty.py
> dirty.py:1:8: F401 [*] `json` imported but unused
> dirty.py:2:8: F401 [*] `os` imported but unused
> dirty.py:5:24: B006 Do not use mutable data structures for argument defaults
> dirty.py:7:15: E711 Comparison to `None` should be `cond is None`
> dirty.py:7:36: E701 Multiple statements on one line (colon)
> Found 5 errors.
> [*] 2 fixable with the `--fix` option (2 hidden fixes can be enabled with the `--unsafe-fixes` option).
> ```
>
> **4. Что исправляется само:**
>
> ```text
> $ ruff check --fix --select "E,F,I,UP,B" dirty.py
> Found 5 errors (2 fixed, 3 remaining).
> No fixes available (2 hidden fixes can be enabled with the `--unsafe-fixes` option).
> ```
>
> Само ушли два неиспользуемых импорта (`json`, `os`). Остались три: изменяемое значение
> по умолчанию, сравнение с `None`, два оператора в строке. Для двух из них у `ruff` есть
> «скрытые» автоправки (hidden fixes, включаются ключом `--unsafe-fixes`): замена
> `marks == None` на `marks is None` может изменить поведение кода (у класса `==` бывает
> переопределён), а как исправить `tags=[]`, зависит от замысла функции — это меняет смысл.
> Для третьего, `E701` (два оператора в строке), автоправки у `ruff` нет вовсе: разнесёт
> строку `black`. Такие места инструмент показывает, но не правит за тебя.
>
> **5. Чистая версия** (`grades.py`):
>
> ```python
> """Отчёт по оценкам учеников: средний балл и список строк."""
>
>
> def average(marks: list[int]) -> float:
>     """Возвращает средний балл по списку оценок.
>
>     Оценки — целые числа от 2 до 5. Пустой список — ошибка данных: среднего
>     у него нет, поэтому функция поднимает ValueError, а не возвращает «0».
>     """
>     if not marks:
>         raise ValueError("список оценок пуст")
>     if any(mark < 2 or mark > 5 for mark in marks):
>         raise ValueError(f"оценки должны быть от 2 до 5: {marks}")
>     return round(sum(marks) / len(marks), 2)
>
>
> def report(students: list[dict]) -> str:
>     """Собирает отчёт: по строке на ученика с непустым списком оценок.
>
>     Ученики без оценок пропускаются — их не с чем сравнивать.
>     """
>     lines: list[str] = []
>     for student in students:
>         name = student["name"]
>         marks = student["marks"]
>         if not marks:
>             continue
>         lines.append(f"{name}: {average(marks)}")
>     return "\n".join(lines)
>
>
> if __name__ == "__main__":
>     print(report([{"name": "Аня", "marks": [5, 4, 5]}, {"name": "Борис", "marks": []}]))
> ```
>
> ```text
> Аня: 4.67
> ```
>
> **6. Проверки:**
>
> ```text
> $ black --check grades.py
> All done! ✨ 🍰 ✨
> 1 file would be left unchanged.
>
> $ ruff check --select "E,F,I,UP,B" grades.py
> All checks passed!
>
> $ mypy grades.py
> Success: no issues found in 1 source file
> ```
>
> **Что здесь важно.** Изменилось не только оформление:
>
> | Было | Стало | Почему это не про форму |
> |---|---|---|
> | `average([])` возвращала `0` | поднимает `ValueError` | «нет данных» перестало быть похожим на настоящий балл |
> | `tags=[]` в параметрах | параметра нет | изменяемое значение по умолчанию — скрытая ловушка |
> | `marks == None` | `if not marks` | пустой список и `None` проверяются одинаково и читаемо |
> | Борис пропускался молча | цикл пропускает ученика без оценок **явно** | решение видно в коде, а не «так получилось» |
>
> Почему `tags=[]` — ловушка: значение по умолчанию создаётся **один раз** при определении
> функции и живёт до конца программы.
>
> ```python
> def add_mark(mark, marks=[]):
>     """Копит оценки в списке по умолчанию."""
>     marks.append(mark)
>     return marks
>
>
> print("первый вызов:", add_mark(5))
> print("второй вызов:", add_mark(4))
> print("третий вызов:", add_mark(3))
> ```
>
> ```text
> первый вызов: [5]
> второй вызов: [5, 4]
> третий вызов: [5, 4, 3]
> ```
>
> Функция «помнит» прошлые вызовы — а должна была каждый раз начинать с пустого списка.
> `ruff` показал это ещё до запуска (B006).
>
> **Типичная ошибка.** Прогнать `ruff --fix`, увидеть «2 fixed» и решить, что файл в порядке.
> Оставшиеся три замечания — как раз про смысл, именно они самые важные.
>
> **Граница.** Если у ученика нет оценок — это ещё не обязательно ошибка: в отчёте его можно
> просто пропустить (как здесь) или написать «нет оценок». Что именно — решает задача, а не
> инструмент. `mypy` тут не при чём: он проверяет типы, а не правила предметной области.

## Задача 3. Измерить и ускорить

★★★ · `timeit`, `cProfile`, O(n) и O(1)

**Условие.** Есть 20 000 имён и 5 000 проверок «есть ли такое имя». Нужно понять, где
находится имя: в списке, множестве или словаре — и насколько это важно.

**Задание.** 1) Напиши функцию поиска по списку и замерь её `timeit`-ом. 2) Сделай то же
для множества и словаря. 3) Запиши множители. 4) Посмотри `cProfile` для варианта со списком:
на какую строку уходит время? 5) Объясни результат через O(n) и O(1).
6) Ответь, что изменится, если проверок будет 5, — и проверь догадку замером.

> [!example]- Разбор
> **Идея.** `in` по списку перебирает элементы один за другим: время растёт вместе
> с размером (O(n)). Множество и словарь — хеш-таблицы: поиск почти не зависит от размера
> (O(1)). Разница не «стилистическая», а в сотни раз, и её видно только замером.
>
> **Код:**
>
> ```python
> """Сравнение скорости поиска: список, множество, словарь."""
>
> import cProfile
> import timeit
>
> NAMES_IN_LIST = [f"ученик-{number}" for number in range(20_000)]
> NAMES_IN_SET = set(NAMES_IN_LIST)
> MARKS_BY_NAME = {name: (number % 4) + 2 for number, name in enumerate(NAMES_IN_LIST)}
> CHECKS = [f"ученик-{number}" for number in range(0, 20_000, 4)]  # 5 000 проверок
>
>
> def in_list() -> int:
>     """Сколько из проверяемых имён есть в списке."""
>     return sum(1 for name in CHECKS if name in NAMES_IN_LIST)
>
>
> def in_set() -> int:
>     """Сколько из проверяемых имён есть в множестве."""
>     return sum(1 for name in CHECKS if name in NAMES_IN_SET)
>
>
> def in_dict() -> int:
>     """Сколько из проверяемых имён есть в словаре."""
>     return sum(1 for name in CHECKS if name in MARKS_BY_NAME)
>
>
> print("имён в списке:", len(NAMES_IN_LIST), "| проверок:", len(CHECKS))
> for function in (in_list, in_set, in_dict):
>     found = function()
>     seconds = timeit.timeit(function, number=3) / 3
>     milliseconds = seconds * 1000
>     print(f"{function.__name__:8} {milliseconds:8.2f} мс | найдено: {found}")
>
> print()
> print("профиль поиска по списку:")
> cProfile.run("in_list()", sort="tottime")
> ```
>
> **Вывод:**
>
> ```text
> имён в списке: 20000 | проверок: 5000
> in_list    315.31 мс | найдено: 5000
> in_set       0.41 мс | найдено: 5000
> in_dict      0.34 мс | найдено: 5000
>
> профиль поиска по списку:
>          5006 function calls in 0.282 seconds
>
>    Ordered by: internal time
>
>    ncalls  tottime  percall  cumtime  percall filename:lineno(function)
>      5001    0.281    0.000    0.281    0.000 speed.py:14(<genexpr>)
>         1    0.001    0.001    0.282    0.282 {built-in method builtins.sum}
>         1    0.000    0.000    0.282    0.282 speed.py:12(in_list)
> ```
>
> **Что здесь важно.** Список — 315 мс, множество — 0.41 мс: **примерно в 770 раз**. Профиль
> показывает, где время: 0.281 с из 0.282 — в выражении `name in NAMES_IN_LIST` (строка 14),
> которое выполнилось 5001 раз. Не «Python медленный», а конкретная строка с линейным поиском.
>
> Множитель считается просто:
>
> ```python
> print("быстрее в", round(315.31 / 0.41), "раз")
> ```
>
> ```text
> быстрее в 769 раз
> ```
>
> **Типичная ошибка.** Оптимизировать «на глаз»: переписывать цикл, менять `sum` на счётчик —
> и не заметить, что всё время уходит в структуру данных. Вторая ошибка — поверить замеру
> на трёх элементах: там разницы нет вовсе.
>
> **Граница.** Множество нужно сначала собрать, и это стоит времени. Ответ на вопрос 6 из
> задания: если проверок всего пять, множество **проиграет** списку. Замер (файл `few_checks.py`):
>
> ```python
> import timeit
>
> NAMES_IN_LIST = [f"ученик-{number}" for number in range(20_000)]
> FEW_CHECKS = [f"ученик-{number}" for number in (1_000, 5_000, 10_000, 15_000, 19_999)]
>
>
> def few_in_list() -> int:
>     """Пять проверок по списку."""
>     return sum(1 for name in FEW_CHECKS if name in NAMES_IN_LIST)
>
>
> def few_in_set() -> int:
>     """Пять проверок по множеству, которое сначала нужно собрать."""
>     names = set(NAMES_IN_LIST)
>     return sum(1 for name in FEW_CHECKS if name in names)
>
>
> for function in (few_in_list, few_in_set):
>     milliseconds = timeit.timeit(function, number=100) / 100 * 1000
>     print(f"{function.__name__:12} {milliseconds:6.3f} мс")
> ```
>
> ```text
> few_in_list   0.636 мс
> few_in_set    0.996 мс
> ```
>
> Пять поисков по списку — это пять неполных проходов; сборка множества из 20 000 имён —
> один полный проход с хешированием. Этот замер сделан отдельно, на другой машине, чем
> замеры выше, поэтому сравнивай только соотношение внутри одного замера. Поэтому правило простое: **сначала замер, потом решение.** Если проверок мало и данные
> крошечные — обычный список нормален и читается проще. Если поиск повторяется тысячи раз
> или данных много — множество или словарь.

# Что запомнить из практики

| Приём | Когда |
|---|---|
| `statistics` вместо своих формул | средние, медиана, разброс по небольшому списку |
| `uv add <библиотека>` только по делу | зависимость оправдана задачей, а не привычкой |
| `black --check` / `--diff` | посмотреть, что изменит форматтер |
| `ruff check --select …` | найти ошибки и подозрительные места |
| `ruff --fix` + ручная правка остатка | автоправка не трогает то, что меняет смысл |
| docstring в стиле «что обещает функция» | описания для людей, а не для галочки |
| `timeit.timeit(..., number=N) / N` | честное среднее время одного прогона |
| `cProfile.run(..., sort="tottime")` | найти строку, на которую уходит время |
| список vs множество vs словарь | поиск: O(n) против O(1) |
