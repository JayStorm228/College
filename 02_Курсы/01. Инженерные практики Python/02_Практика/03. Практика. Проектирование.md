# 03. Практика. Проектирование

> [!abstract] О чём эта практика
> Три задачи по лекциям [[06. Проектирование - фабрики и реестры]] и [[07. Внедрение зависимостей]].
> Сначала реестр создателей вместо лестницы `if`, затем класс, который не создаёт свои
> зависимости сам, и в конце — маленькое приложение, где реестр и внедрение зависимостей
> работают вместе и проверяются тестами.
>
> Общая мысль: **код дешевле расширять, чем менять.** Реестр отвечает за то, «какой объект
> создать», внедрение зависимостей — за то, «откуда взять готовое».

> [!important] Как работать с задачей
> 1. Прочитай условие и **не открывай разбор**.
> 2. Напиши решение, прогони сценарии из условия, запусти тесты.
> 3. Проверь расширяемость: добавь новый вариант, **не меняя** существующую функцию.
> 4. Сверься с разбором — особенно если решение получилось другим.

## Задача 1. Тарифы через реестр

★☆☆ · реестр функций-создателей, `dict.get`, понятная ошибка

**Условие.** Программа знает три тарифа: «Эконом» — 300 руб./мес, «Стандарт» — 600,
«Бизнес» — 1200. По имени тарифа нужно получить объект с названием и ценой.

**Задание.** 1) Сделай класс `Tariff` (подойдёт `@dataclass`) с методом `describe()`.
2) Заведи словарь `TARIFFS`, где по имени лежит функция, создающая тариф, и функцию
`make_tariff(kind)`, которая берёт создателя из словаря. 3) Для неизвестного имени поднимай
`ValueError` со списком доступных тарифов. 4) Добавь «Люкс» за 2500, **не меняя**
`make_tariff`, и убедись, что он работает. 5) Выведи, сколько тарифов известно программе.

> [!example]- Разбор
> **Идея.** Реестр превращает «лестницу условий» в данные: словарь — это оглавление возможностей
> программы. `make_tariff` ничего не знает о конкретных тарифах, поэтому новый тариф — это
> новая функция и одна строка в словаре.
>
> **Код (`tariffs.py`).**
>
> ```python
> from dataclasses import dataclass
>
>
> @dataclass
> class Tariff:
>     """Тариф: название и цена за месяц в рублях."""
>
>     name: str
>     price: int
>
>     def describe(self) -> str:
>         """Строка для вывода тарифа."""
>         return f"{self.name}: {self.price} руб./мес"
>
>
> def make_economy() -> Tariff:
>     """Создаёт тариф «Эконом»."""
>     return Tariff("Эконом", 300)
>
>
> def make_standard() -> Tariff:
>     """Создаёт тариф «Стандарт»."""
>     return Tariff("Стандарт", 600)
>
>
> def make_business() -> Tariff:
>     """Создаёт тариф «Бизнес»."""
>     return Tariff("Бизнес", 1200)
>
>
> TARIFFS = {
>     "эконом": make_economy,
>     "стандарт": make_standard,
>     "бизнес": make_business,
> }
>
>
> def make_tariff(kind: str) -> Tariff:
>     """Создаёт тариф по имени; ValueError, если такого нет."""
>     factory = TARIFFS.get(kind)
>     if factory is None:
>         raise ValueError(f"нет тарифа «{kind}»; доступны: {', '.join(TARIFFS)}")
>     return factory()
> ```
>
> **Проверка:**
>
> ```python
> for kind in ["эконом", "бизнес"]:
>     print(make_tariff(kind).describe())
> try:
>     make_tariff("люкс")
> except ValueError as exc:
>     print("ошибка:", exc)
> TARIFFS["люкс"] = lambda: Tariff("Люкс", 2500)
> print("после регистрации:", make_tariff("люкс").describe())
> print("всего тарифов:", len(TARIFFS))
> ```
>
> ```text
> Эконом: 300 руб./мес
> Бизнес: 1200 руб./мес
> ошибка: нет тарифа «люкс»; доступны: эконом, стандарт, бизнес
> после регистрации: Люкс: 2500 руб./мес
> всего тарифов: 4
> ```
>
> **Что здесь важно.** `', '.join(TARIFFS)` даёт список доступных вариантов из самого реестра —
> его не нужно обновлять отдельно. Тариф «Люкс» добавлен **снаружи** `make_tariff`:
> именно это и есть «расширение без правки».
>
> **Типичная ошибка.** Сделать словарь значений (`{"эконом": 300}`) и потом городить условия
> при создании объекта. Реестр создателей ценен тем, что умеет больше, чем «число по имени»:
> в функции-создателе помещаются проверки, вычисления и создание нескольких объектов.
>
> **Граница.** Проверка `if factory is None` нужна именно через `None`, а не
> `if not factory`: другой вариант может когда-нибудь оказаться ложным значением. И ещё:
> регистрация постороннего тарифа в общий словарь — приём для «плагинов», но злоупотреблять
> им не стоит: если все части программы пишут в один реестр, понять содержимое становится
> трудно.

## Задача 2. Уведомления через канал

★★☆ · внедрение зависимостей, подмена в тестах, фикстура `tmp_path`

**Условие.** Класс `Notifier` отправляет уведомления. **Куда** отправлять — не его забота:
канал передаётся в конструктор. Есть два канала:

- `MemoryChannel` — складывает сообщения в список (для тестов);
- `FileChannel` — дописывает сообщения в файл (для работы).

**Задание.** 1) Напиши оба канала с методом `send(text) -> str` (строка-отчёт о доставке).
2) Напиши `Notifier(channel)` с методом `notify_all(texts)`, возвращающим список отчётов.
3) Напиши тесты: отправка нескольких сообщений через `MemoryChannel`, отправка пустого списка,
   запись в файл через `FileChannel` во **временную** папку `tmp_path`. 4) Объясни, почему
   `Notifier` не должен сам создавать `FileChannel`.

> [!example]- Разбор
> **Идея.** `Notifier` зависит только от того, что у канала есть `send`. В тестах это
> `MemoryChannel` — быстро, без диска и без последствий. В работе — `FileChannel`. Один и тот
> же `Notifier` работает и там, и там: класс не знает, с чем имеет дело.
>
> **Код (`notifier.py`).**
>
> ```python
> from pathlib import Path
>
>
> class MemoryChannel:
>     """Канал для тестов: складывает сообщения в список."""
>
>     def __init__(self):
>         self.sent: list[str] = []
>
>     def send(self, text: str) -> str:
>         """Запоминает сообщение и возвращает отчёт."""
>         self.sent.append(text)
>         return f"в память: {text}"
>
>
> class FileChannel:
>     """Рабочий канал: дописывает сообщения в файл."""
>
>     def __init__(self, path: str | Path):
>         self.path = Path(path)
>
>     def send(self, text: str) -> str:
>         """Дописывает строку в файл и возвращает отчёт."""
>         with self.path.open("a", encoding="utf-8") as file:
>             file.write(text + "\n")
>         return f"в файл: {text}"
>
>
> class Notifier:
>     """Отправляет уведомления через переданный канал."""
>
>     def __init__(self, channel):
>         self.channel = channel
>
>     def notify_all(self, texts: list[str]) -> list[str]:
>         """Отправляет все сообщения, возвращает отчёты по каждому."""
>         return [self.channel.send(text) for text in texts]
> ```
>
> **Тесты (`test_notifier.py`).**
>
> ```python
> from pathlib import Path
>
> from notifier import FileChannel, MemoryChannel, Notifier
>
>
> def test_sends_all_messages():
>     channel = MemoryChannel()
>     result = Notifier(channel).notify_all(["Зачёт", "Долг"])
>     assert result == ["в память: Зачёт", "в память: Долг"]
>     assert channel.sent == ["Зачёт", "Долг"]
>
>
> def test_empty_list_sends_nothing():
>     channel = MemoryChannel()
>     assert Notifier(channel).notify_all([]) == []
>     assert channel.sent == []
>
>
> def test_file_channel_appends(tmp_path):
>     path = tmp_path / "notify.txt"
>     channel = FileChannel(path)
>     Notifier(channel).notify_all(["Первое", "Второе"])
>     assert path.read_text(encoding="utf-8") == "Первое\nВторое\n"
> ```
>
> **Запуск:**
>
> ```text
> $ pytest -q test_notifier.py
> ...                                                                      [100%]
> 3 passed in 0.01s
> ```
>
> **Проверка вручную:**
>
> ```python
> from notifier import FileChannel, MemoryChannel, Notifier
>
> print(Notifier(MemoryChannel()).notify_all(["Зачёт", "Долг"]))
> print(Notifier(FileChannel("notify.txt")).notify_all(["Зачёт"]))
> ```
>
> ```text
> ['в память: Зачёт', 'в память: Долг']
> ['в файл: Зачёт']
> ```
>
> **Что здесь важно.** Тест проверяет **взаимодействие**: не только «что вернулось», но и что
> канал получил ровно те сообщения (`channel.sent`). Фикстура `tmp_path` даёт каждой проверке
> свою пустую папку — тесты не мешают друг другу и не оставляют мусора в проекте.
>
> **Типичная ошибка.** Сделать `Notifier.__init__(self, path="notify.txt")` и создавать
> `FileChannel` внутри. Тест тогда обязательно пишет в файл: приходится подчищать его вручную,
> а параллельные тесты начинают мешать друг другу. Ответ на вопрос из задания: `Notifier`
> не должен знать, куда идёт запись, — иначе его нельзя использовать ни в тестах, ни в другом
> приложении без правки класса.
>
> **Граница.** Вместо `MemoryChannel` можно передать «шпиона» — объект, который просто считает
> вызовы. Иногда этого достаточно. Но проверять на «шпионе» бизнес-логику нельзя: он её
> не реализует, значит, тест проверит только факт вызова.

## Задача 3. Прайс-лист: источник и экспортёр

★★★ · реестр + внедрение зависимостей + точка входа + тесты

**Условие.** Нужно строить прайс-лист по списку товаров. Товар — название, цена за штуку,
количество. Источник товаров бывает разный (`MemorySource` для тестов, `CsvSource` из файла),
формат отчёта — тоже (`text`, `csv`).

**Задание.** 1) Опиши `Good` с вычисляемым свойством `total`. 2) Сделай два источника
с методом `load()`. 3) Сделай две функции-экспортёра и реестр `EXPORTERS`. 4) Класс `PriceList`
принимает источник и экспортёр, а метод `report()` возвращает строку с итоговой суммой
и позициями. 5) Напиши `main()` — точку входа для файла `goods.csv` и текстового отчёта.
6) Тесты: оба экспортёра, пустой источник, проверка реестра, «экспортёр не портит данные»,
чтение `CsvSource` из временного файла.

> [!example]- Разбор
> **Идея.** Здесь два приёма работают вместе. Внедрение зависимостей даёт `PriceList`
> безразличие к тому, откуда данные и куда они пойдут; реестр даёт удобный выбор экспортёра
> по имени. Тесты конструируют `PriceList` со «своими» частями и проверяют логику отчёта
> в отрыве от файлов.
>
> **Код (`price.py`).**
>
> ```python
> from dataclasses import dataclass
> from pathlib import Path
>
>
> @dataclass
> class Good:
>     """Товар: название, цена за штуку, количество."""
>
>     name: str
>     price: float
>     count: int
>
>     @property
>     def total(self) -> float:
>         """Стоимость позиции."""
>         return self.price * self.count
>
>
> class MemorySource:
>     """Источник для тестов: товары уже в памяти."""
>
>     def __init__(self, goods):
>         self.goods = list(goods)
>
>     def load(self):
>         """Возвращает копию списка товаров."""
>         return list(self.goods)
>
>
> class CsvSource:
>     """Рабочий источник: читает товары из файла «название;цена;количество»."""
>
>     def __init__(self, path):
>         self.path = Path(path)
>
>     def load(self):
>         """Читает файл и возвращает список товаров."""
>         goods = []
>         for row in self.path.read_text(encoding="utf-8").splitlines():
>             if not row.strip():
>                 continue
>             name, price, count = row.split(";")
>             goods.append(Good(name, float(price), int(count)))
>         return goods
>
>
> def export_text(goods):
>     """Экспорт в текстовом виде."""
>     return "\n".join(f"{good.name}: {good.total:.2f}" for good in goods)
>
>
> def export_csv(goods):
>     """Экспорт обратно в CSV."""
>     return "\n".join(f"{good.name};{good.price};{good.count}" for good in goods)
>
>
> EXPORTERS = {"text": export_text, "csv": export_csv}
>
>
> class PriceList:
>     """Прайс-лист: берёт товары из источника, отчёт формирует экспортёром."""
>
>     def __init__(self, source, exporter):
>         self.source = source
>         self.exporter = exporter
>
>     def report(self):
>         """Строит отчёт: итоговая сумма и список позиций."""
>         goods = self.source.load()
>         total = sum(good.total for good in goods)
>         return f"Итого: {total:.2f}\n{self.exporter(goods)}"
>
>
> def main():
>     """Точка входа: прайс-лист из файла, отчёт в текстовом виде."""
>     source = CsvSource("goods.csv")
>     exporter = EXPORTERS["text"]
>     print(PriceList(source, exporter).report())
>
>
> if __name__ == "__main__":
>     main()
> ```
>
> **Запуск** (файл `goods.csv`: `Тетрадь;45.5;3` и `Ручка;12.0;10`):
>
> ```text
> $ python3 price.py
> Итого: 256.50
> Тетрадь: 136.50
> Ручка: 120.00
> ```
>
> **Тесты (`test_price.py`).**
>
> ```python
> from price import (
>     EXPORTERS,
>     CsvSource,
>     Good,
>     MemorySource,
>     PriceList,
>     export_csv,
>     export_text,
> )
>
> GOODS = [Good("Тетрадь", 45.5, 3), Good("Ручка", 12.0, 10)]
>
>
> def test_text_report():
>     report = PriceList(MemorySource(GOODS), EXPORTERS["text"]).report()
>     assert report.startswith("Итого: 256.50")
>     assert "Тетрадь: 136.50" in report
>
>
> def test_csv_report():
>     report = PriceList(MemorySource(GOODS), EXPORTERS["csv"]).report()
>     assert "Тетрадь;45.5;3" in report
>
>
> def test_exporters_are_registered():
>     assert set(EXPORTERS) == {"text", "csv"}
>
>
> def test_empty_source():
>     report = PriceList(MemorySource([]), export_text).report()
>     assert report == "Итого: 0.00\n"
>
>
> def test_exporter_does_not_mutate_goods():
>     goods = list(GOODS)
>     export_csv(goods)
>     assert goods == GOODS
>
>
> def test_csv_source_reads_file(tmp_path):
>     path = tmp_path / "goods.csv"
>     path.write_text("Тетрадь;45.5;3\n\nРучка;12.0;10\n", encoding="utf-8")
>     assert CsvSource(path).load() == GOODS
> ```
>
> ```text
> $ pytest -q test_price.py
> ......                                                                   [100%]
> 6 passed in 0.01s
> ```
>
> **Что здесь важно.** Почти все тесты обходятся без файлов: `PriceList` получает
> `MemorySource`. Файл нужен ровно одному тесту — `test_csv_source_reads_file`: он проверяет
> сам `CsvSource` (пропуск пустой строки, разбор чисел) на временном файле из `tmp_path`.
> Так рабочий путь тоже проверен, а рабочие данные тесты не трогают.
>
> **Типичная ошибка.** Сделать `report()` собирающим данные самому: `open("goods.csv")`
> внутри. Тогда тест «пустой источник» невозможен, а смена формата потребует правки класса.
> Вторая ошибка — экспортёр, который сортирует или изменяет переданный список: он должен
> только читать данные (это и проверяет последний тест).
>
> **Граница.** Итог `Итого: 0.00\n` для пустого прайс-листа — договорённость: строка с нулём
> остаётся, а список позиций пустой. Как и раньше, такие решения фиксируются тестом, чтобы
> через месяц никто не «починил» поведение, посчитав его ошибкой.

# Что запомнить из практики

| Приём | Когда |
|---|---|
| реестр функций-создателей | вариантов много, и они будут добавляться |
| понятная ошибка со списком вариантов | неизвестное имя: показать, что доступно |
| зависимость в конструкторе | класс не создаёт файлы, время, каналы сам |
| подделка для тестов | `MemoryChannel`, `MemorySource`: быстро и без побочных эффектов |
| `tmp_path` | когда тесту всё-таки нужен настоящий файл |
| точка входа `main()` | сборка «что с чем соединить» живёт в одном месте |
