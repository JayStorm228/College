# 01. Практика. Ошибки и типизация

> [!abstract] О чём эта практика
> Три задачи по лекциям [[01. Обработка ошибок полностью]] и [[02. Типизация и аннотации]].
> Сначала — своё исключение для одной проверки, потом — разбор файла, в котором ошибки
> собраны, а не роняют программу, и в конце — маленький типизированный модуль, который
> проверяется `mypy` без единой ошибки.
>
> Общая мысль практики: **ошибка — это часть поведения программы, а тип — часть её описания.**
> Программист, который их продумывает, пишет функции, которыми можно пользоваться, не читая
> их реализацию.

> [!important] Как работать с задачей
> 1. Прочитай условие и **не открывай разбор**. Разбор свёрнут (`> [!example]-`).
> 2. Напиши решение и **запусти** его — на всех примерах из условия и на границах.
> 3. Отдельно проверь то, о чём просят в задании: «что произойдёт, если…».
> 4. Сверься с разбором и разберись, если решения разошлись.

## Задача 1. Возраст из строки

★☆☆ · свои исключения, `raise ... from`, `try / except / raise`

**Условие.** Функция `parse_age(text)` принимает строку и возвращает целое число лет в диапазоне от 0 до 150.

- Если строку нельзя превратить в число — функция поднимает **своё** исключение `AgeError` с сообщением «`«семнадцать» — не число`» и сохраняет причину (`from` исходной ошибки).
- Если число вне диапазона — тоже `AgeError`, но с сообщением «`возраст 151 вне диапазона 0–150`».

**Задание.** 1) Напиши класс исключения и функцию. 2) Проверь на `"17"`, `"0"`, `"151"`,
`"семнадцать"`. 3) Для каждого случая напечатай, что за ошибка была исходной причиной
(`exc.__cause__`): у одной из строк причины не будет — объясни, почему.

> [!example]- Разбор
> **Идея.** `int("семнадцать")` поднимает `ValueError` — это ошибка чужого типа, и по ней
> непонятно, что произошло в нашей функции. Поэтому мы **переводим** её в своё исключение
> через `raise ... from exc`: у нового исключения сохраняется причина, и traceback показывает
> всю цепочку. Проверка диапазона — уже наша собственная, исходной ошибки у неё нет.
>
> **Код.**
>
> ```python
> class AgeError(Exception):
>     """Возраст не удалось разобрать."""
>
>
> def parse_age(text: str) -> int:
>     """Превращает строку в возраст; AgeError, если разобрать нельзя."""
>     try:
>         age = int(text)
>     except ValueError as exc:
>         raise AgeError(f"«{text}» — не число") from exc
>     if not 0 <= age <= 150:
>         raise AgeError(f"возраст {age} вне диапазона 0–150")
>     return age
>
>
> for raw in ["17", "0", "151", "семнадцать"]:
>     try:
>         print(f"{raw!r} → {parse_age(raw)}")
>     except AgeError as exc:
>         cause = type(exc.__cause__).__name__ if exc.__cause__ else "нет"
>         print(f"{raw!r} → ошибка: {exc} (причина: {cause})")
> ```
>
> **Вывод:**
>
> ```text
> '17' → 17
> '0' → 0
> '151' → ошибка: возраст 151 вне диапазона 0–150 (причина: нет)
> 'семнадцать' → ошибка: «семнадцать» — не число (причина: ValueError)
> ```
>
> **Что здесь важно.** Свой тип исключения отделяет «ошибку разбора возраста» от всех
> остальных `ValueError` в программе: снаружи можно поймать `except AgeError` и не задеть
> ничего лишнего. А `from exc` сохраняет исходную причину — при разборе traceback видно
> обе ошибки, а не только верхнюю.
>
> **Типичная ошибка.** Написать `raise AgeError(...)` без `from`. Программа работает, и
> Python всё равно покажет обе ошибки, но как случайное совпадение («During handling of
> the above exception, another exception occurred»), а `exc.__cause__` останется пустым:
> код не сможет узнать, что `ValueError` — причина. С `from exc` причина названа прямо.
> Второй частый вариант — проверять диапазон внутри `try` и ловить собственное исключение
> тем же `except ValueError`: `AgeError` от `ValueError` не наследуется, так что «ловушка
> не поймает» — программа упадёт. Проверки диапазона держат **после** `try / except`.
>
> **Граница.** Возраст `0` — корректный по нашей договорённости (младенец), а `150` — верхняя
> граница: числа ровно на границе должны проходить. Если бы понадобилось принимать `"17 лет"`,
> это уже разбор другого формата — и тогда функция называется иначе.

## Задача 2. Оценки из файла: ошибки собираем, а не падаем

★★☆ · `try / except / else / finally`, сбор ошибок, `partition`, логирование

**Условие.** В файле `marks.txt` записаны оценки в формате `Имя:оценка`, например:

```text
Аня:5
Борис:4
Вика
Гена:семь
Даша:7

Егор:3
```

Функция `load_marks(path)` возвращает **две** вещи: словарь `{имя: оценка}` для правильных строк и список сообщений об ошибках для неправильных. Программа не должна падать: проблемная строка пропускается, остальные разбираются.

Требования.

1. Строки без `:`, с пустым именем или пустой оценкой — ошибка с номером строки.
2. Оценка, которую нельзя превратить в число — ошибка с номером строки и причиной `from exc`.
3. Оценка вне диапазона 1–5 — ошибка с номером строки.
4. Пустые строки пропускаются молча.
5. Если файла нет — функция поднимает `LineError` с причиной `FileNotFoundError`.
6. При чтении файла в блоке `finally` пишется сообщение в лог, а в `else` — сообщение о том, что файл прочитан.

**Задание.** 1) Напиши функцию и вспомогательный `parse_line`. 2) Прогони на файле выше. 3) Вызови функцию для несуществующего файла и объясни, что напечатает лог.

> [!example]- Разбор
> **Идея.** Две разные стратегии в одной задаче. **Чужую ошибку** (`FileNotFoundError`)
> переводим в своё исключение и **останавливаемся**: без файла разбирать нечего. А **ошибки
> строк** накапливаем в списке и продолжаем: одна кривая строка не должна лишать нас
> остальных оценок. `else` наступает, только если исключения не было, а `finally` выполняется
> в любом случае — поэтому в лог попадает «попытка завершена» даже при отсутствии файла.
>
> **Код.**
>
> ```python
> import logging
> from pathlib import Path
>
> logging.basicConfig(level=logging.INFO, format="%(levelname)s %(message)s")
> logger = logging.getLogger(__name__)
>
>
> class LineError(Exception):
>     """Строку файла с оценкой не удалось разобрать."""
>
>
> def parse_line(line: str, number: int) -> tuple[str, int]:
>     """Разбирает строку вида «Аня:5» в пару (имя, оценка)."""
>     name, separator, mark_text = line.partition(":")
>     if not separator:
>         raise LineError(f"строка {number}: нет разделителя «:»")
>     if not name.strip() or not mark_text.strip():
>         raise LineError(f"строка {number}: пустое имя или оценка")
>     try:
>         mark = int(mark_text)
>     except ValueError as exc:
>         raise LineError(f"строка {number}: «{mark_text.strip()}» — не число") from exc
>     if not 1 <= mark <= 5:
>         raise LineError(f"строка {number}: оценка {mark} вне диапазона 1–5")
>     return name.strip(), mark
>
>
> def load_marks(path: str | Path) -> tuple[dict[str, int], list[str]]:
>     """Читает файл с оценками: словарь оценок и список ошибок."""
>     file = Path(path)
>     try:
>         text = file.read_text(encoding="utf-8")
>     except FileNotFoundError as exc:
>         raise LineError(f"файл {file.name} не найден") from exc
>     else:
>         logger.info("файл %s прочитан", file.name)
>     finally:
>         logger.info("попытка чтения файла завершена")
>
>     marks: dict[str, int] = {}
>     errors: list[str] = []
>     for number, line in enumerate(text.splitlines(), start=1):
>         if not line.strip():
>             continue
>         try:
>             name, mark = parse_line(line, number)
>         except LineError as exc:
>             errors.append(str(exc))
>         else:
>             marks[name] = mark
>     return marks, errors
> ```
>
> **Проверка:**
>
> ```python
> Path("marks.txt").write_text(
>     "Аня:5\nБорис:4\nВика\nГена:семь\nДаша:7\n\nЕгор:3\n", encoding="utf-8"
> )
> marks, errors = load_marks("marks.txt")
> print("оценки:", marks)
> for error in errors:
>     print("ошибка:", error)
>
> try:
>     load_marks("нет_такого_файла.txt")
> except LineError as exc:
>     print("исключение:", exc, "| причина:", type(exc.__cause__).__name__)
> ```
>
> **Вывод:**
>
> ```text
> INFO файл marks.txt прочитан
> INFO попытка чтения файла завершена
> оценки: {'Аня': 5, 'Борис': 4, 'Егор': 3}
> ошибка: строка 3: нет разделителя «:»
> ошибка: строка 4: «семь» — не число
> ошибка: строка 5: оценка 7 вне диапазона 1–5
> INFO попытка чтения файла завершена
> исключение: файл нет_такого_файла.txt не найден | причина: FileNotFoundError
> ```
>
> Сообщений «попытка чтения файла завершена» — **два**: второй раз `finally` сработал при исключении, когда
> файл не нашёлся. А сообщения «файл … прочитан» во втором случае нет: блок `else`
> не выполнился, потому что было исключение.
>
> **Что здесь важно.** Номер строки в сообщении — не украшение: без него в файле на сотни
> строк невозможно понять, где ошибка. `partition` вместо `split(":")` не падает на строке
> без разделителя и сразу отдаёт три части. Исключения разделены по смыслу: `FileNotFoundError`
> — «нечего читать», `LineError` — «строка непонятная».
>
> **Типичная ошибка.** Сделать `except Exception:` вокруг всего цикла и на первой же плохой
> строке выйти: остальные оценки теряются. Вторая ошибка — перепутать `else` и `finally`:
> «файл прочитан» в `finally` напечаталось бы и при отсутствии файла, что неверно.
>
> **Граница.** Пустая строка и строка из одних пробелов пропускаются молча (`line.strip()`
> даёт пустую строку), а строка вроде ` :5` — уже ошибка: после `partition` имя пустое. Если в файле две записи об одном ученике, в словаре останется
> последняя: так решили мы, но в реальной задаче стоит решить это явно (ошибка или
> перезапись) — и записать решение в docstring.

## Задача 3. Типизированный модуль статистики

★★★ · аннотации, `Sequence`, `Callable`, `X | None`, `mypy`

**Условие.** Модуль `stats.py` содержит четыре функции:

| Функция | Что делает | Возвращает |
|---|---|---|
| `average(numbers)` | среднее арифметическое | `float` или `None`, если данных нет |
| `best(students)` | лучший ученик по баллу | пару `(имя, балл)` или `None` |
| `apply_all(items, func)` | применяет функцию к каждому элементу | новый список |
| `total(*values)` | сумму произвольного числа значений | `float` |

**Задание.** 1) Проставь аннотации всех параметров и результатов, используя типы
из `collections.abc` (`Sequence`, `Callable`), а не списки жёстко. 2) Оформи docstring
на каждую функцию (одной строкой достаточно). 3) Запусти `mypy stats.py demo_stats.py` —
должно быть «Success». 4) Проверь, что `mypy` находит ошибку в вызове `average("1,2,3")`,
и объясни, почему программа при этом падает только во время выполнения.

> [!example]- Разбор
> **Идея.** Аннотации описывают **договор**: «дай любую последовательность чисел — верну число или `None`». `Sequence[float]` принимает и список, и кортеж, и диапазон; `list[float]` был бы уже. `mypy` читает эти договоры и ловит несовпадения **до** запуска: для него строка — не последовательность чисел.
>
> **Код (`stats.py`).**
>
> ```python
> from collections.abc import Callable, Sequence
>
>
> def average(numbers: Sequence[float]) -> float | None:
>     """Среднее арифметическое; None, если данных нет."""
>     if not numbers:
>         return None
>     return sum(numbers) / len(numbers)
>
>
> def best(students: Sequence[tuple[str, float]]) -> tuple[str, float] | None:
>     """Лучший ученик по баллу; None для пустого списка."""
>     if not students:
>         return None
>     return max(students, key=lambda item: item[1])
>
>
> def apply_all(items: Sequence[int], func: Callable[[int], int]) -> list[int]:
>     """Применяет функцию к каждому элементу."""
>     return [func(item) for item in items]
>
>
> def total(*values: float) -> float:
>     """Сумма произвольного числа значений."""
>     return sum(values)
> ```
>
> **Проверка (`demo_stats.py`):**
>
> ```python
> from stats import apply_all, average, best, total
>
> print("среднее:", average([4, 5, 3]), average([]))
> print("лучший:", best([("Аня", 4.5), ("Борис", 3.8)]))
> print("квадраты:", apply_all([1, 2, 3], lambda x: x * x))
> print("сумма:", total(1.5, 2.5, 6))
> ```
>
> ```text
> среднее: 4.0 None
> лучший: ('Аня', 4.5)
> квадраты: [1, 4, 9]
> сумма: 10.0
> ```
>
> ```text
> $ mypy stats.py demo_stats.py
> Success: no issues found in 2 source files
> ```
>
> **Ошибка, которую ловит `mypy` (`wrong.py`):**
>
> ```python
> from stats import average
>
> print(average("1,2,3"))
> ```
>
> ```text
> $ mypy wrong.py
> wrong.py:3: error: Argument 1 to "average" has incompatible type "str"; expected "Sequence[float]"  [arg-type]
> Found 1 error in 1 file (checked 1 source file)
> ```
>
> Если запустить файл, Python выполнит вызов и упадёт только на вычислении (`sum` складывает
символы строки как числа — и спотыкается на первом):
>
> ```text
> TypeError: unsupported operand type(s) for +: 'int' and 'str'
> ```
>
> **Что здесь важно.** Проверка типов не заменяет тесты, а дополняет их: `mypy` читает весь
> код проекта и находит несовпадения в местах, куда тесты не добрались. Важно и то, что `X | None` честно описывает поведение: вызывающий код **обязан** обработать `None`, иначе `mypy` начнёт ругаться на арифметику с `None`.
>
> **Типичная ошибка.** Написать `def average(numbers: list) -> float` — без параметра типа.
> Формально проверка проходит, но смысл потерян: `mypy` не отличит список чисел от списка
> строк, а обещание «вернёт `float`» ложно, потому что бывает `None`. Вторая ошибка —
> добавлять аннотации, но не запускать проверку: договор без проверяющего не работает.
>
> **Граница.** `total()` без аргументов вернёт `0` (так работает `sum` пустого набора) —
> это надо решить явно: либо так и оставить, либо поднимать ошибку. `average([1, 2, "3"])` —
> тоже проблема: `mypy` этот вызов отклонит, а интерпретатор пропустит и упадёт на суммировании
> (`TypeError`): аннотации — договор, который проверяют **инструменты**, а не Python.

# Что запомнить из практики

| Приём | Когда |
|---|---|
| своё исключение для своей ошибки | чтобы вызывающий код отличал «наши» сбои от чужих |
| `raise ... from exc` | при переводе чужой ошибки в свою: сохраняется причина |
| сбор ошибок в список | когда часть данных плохая, но остальное обработать нужно |
| `try / except / else / finally` | «читаю файл»: `else` — успех, `finally` — в любом случае |
| `Sequence`, `Callable`, `X \| None` | параметры-«что угодно похожее», честное «может быть пусто» |
| `mypy` в проверке | ловит несовпадения типов до запуска |
