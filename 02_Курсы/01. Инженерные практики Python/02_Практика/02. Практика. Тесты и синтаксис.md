# 02. Практика. Тесты и синтаксис

> [!abstract] О чём эта практика
> Три задачи по лекциям [[03. Тесты]] и [[04. Остатки продвинутого синтаксиса]].
> Сначала пишем первые тесты на функцию-палиндром, затем осваиваем `parametrize`
> и `pytest.raises`, а в третьей задаче соединяем тесты с продвинутым синтаксисом:
> `for ... else`, моржовый оператор, `*args`, `**kwargs` и генераторы.
>
> Тест — это способ зафиксировать **договор** из предыдущей практики: если поведение
> изменится случайно, тест об этом скажет. Поэтому тесты пишут не «для галочки», а на всё,
> что обещает функция.

> [!important] Как работать с задачей
> 1. Прочитай условие и **не открывай разбор**.
> 2. Напиши код и тесты, запусти `pytest`. Падающий тест — это не провал, а найденная ошибка.
> 3. Проверь границы: пустые данные, один элемент, повтор.
> 4. Сверься с разбором: важно не «угадать ответ», а понять, какие случаи проверять.

## Задача 1. Первые тесты: палиндром

★☆☆ · `assert`, имена тестов, границы

**Условие.** Функция `is_palindrome(text)` отвечает, читается ли текст одинаково в обе стороны.
Считать нужно **только буквы и цифры**, игнорируя регистр и пробелы, — тогда
«А роза упала на лапу Азора» тоже палиндром.

**Задание.** 1) Напиши функцию. 2) Напиши четыре теста: простой палиндром, не-палиндром,
фраза с пробелами и разным регистром, **границы** (пустая строка и один символ).
3) Запусти `pytest`. 4) Ответь: какой из тестов поймает ошибку, если из функции убрать
приведение к нижнему регистру?

> [!example]- Разбор
> **Идея.** Тест — это не «проверка ради проверки», а утверждение о поведении. Имена тестов
> читаются как оглавление: `test_ignores_case_and_spaces` сразу говорит, что проверяется.
> Границы — обязательные случаи: пустая строка по определению палиндром (она читается
> одинаково в обе стороны), один символ тоже.
>
> **Код (`palindrome.py`).**
>
> ```python
> def is_palindrome(text: str) -> bool:
>     """True, если текст читается одинаково в обе стороны."""
>     cleaned = "".join(ch.lower() for ch in text if ch.isalnum())
>     return cleaned == cleaned[::-1]
> ```
>
> **Тесты (`test_palindrome.py`).**
>
> ```python
> from palindrome import is_palindrome
>
>
> def test_simple_palindrome():
>     assert is_palindrome("шалаш")
>
>
> def test_not_palindrome():
>     assert not is_palindrome("питон")
>
>
> def test_ignores_case_and_spaces():
>     assert is_palindrome("А роза упала на лапу Азора")
>
>
> def test_empty_and_single():
>     assert is_palindrome("")
>     assert is_palindrome("я")
> ```
>
> **Запуск:**
>
> ```text
> $ pytest -v test_palindrome.py
> test_palindrome.py::test_simple_palindrome PASSED                        [ 25%]
> test_palindrome.py::test_not_palindrome PASSED                           [ 50%]
> test_palindrome.py::test_ignores_case_and_spaces PASSED                  [ 75%]
> test_palindrome.py::test_empty_and_single PASSED                        [100%]
>
> ============================== 4 passed in 0.01s ===============================
> ```
>
> **Что здесь важно.** Тесты лежат в отдельном файле с именем `test_…` — `pytest` сам находит
> такие файлы и функции. Каждая проверка — один `assert`. Имена говорят, **что** проверяется,
> поэтому при падении сразу понятно, что именно сломалось.
>
> **Типичная ошибка.** Писать `assert is_palindrome("шалаш") == True`: сравнивать с `True`
> не нужно, `assert` и так проверяет истинность. Другая ошибка — проверять только «хорошие»
> примеры и не проверять отрицательные: тест `test_not_palindrome` нужен не меньше, иначе
> функция `return True` пройдёт все проверки.
>
> **Граница.** На пустой строке `cleaned[::-1]` тоже пустая — тест проходит сам собой; это
> и есть разница между «случайно работает» и «мы проверили, что работает». Ответ на вопрос
> из задания: `test_ignores_case_and_spaces` упадёт первым, если убрать `lower()` —
> регистр «А» и «а» перестанет совпадать.

## Задача 2. `parametrize` и проверка исключений

★★☆ · `parametrize`, `pytest.raises`, `match`

**Условие.** Функция `parse_mark(text)` превращает текст в оценку от 1 до 5.
Оценка вне диапазона — `ValueError` с сообщением, в котором есть число.

**Задание.** 1) Напиши функцию. 2) Оформи тесты так, чтобы несколько однотипных случаев
не дублировались: `parametrize` для корректных значений (в том числе с пробелами: `" 4 "`),
`parametrize` для плохих (`"0"`, `"6"`, `"3.5"`, `"пять"`). 3) Проверь, что в сообщении
об ошибке есть проблемное число. 4) Посмотри на вывод `pytest -v`: как называются
параметризованные тесты?

> [!example]- Разбор
> **Идея.** `@pytest.mark.parametrize` превращает один тест в набор: каждый набор данных
> запускается отдельно, и в выводе видно, **какие именно** данные упали. Проверка исключений —
> тоже часть договора: `pytest.raises` говорит «здесь должно быть исключение», а `match`
> ищет текст в сообщении.
>
> **Код (`marks.py`).**
>
> ```python
> def parse_mark(text: str) -> int:
>     """Превращает текст в оценку от 1 до 5."""
>     mark = int(text)
>     if not 1 <= mark <= 5:
>         raise ValueError(f"оценка {mark} вне диапазона 1–5")
>     return mark
> ```
>
> **Тесты (`test_marks.py`).**
>
> ```python
> import pytest
>
> from marks import parse_mark
>
>
> @pytest.mark.parametrize(
>     "text, expected",
>     [("5", 5), ("1", 1), ("  4 ", 4)],
> )
> def test_good_marks(text, expected):
>     assert parse_mark(text) == expected
>
>
> @pytest.mark.parametrize(
>     "text",
>     ["0", "6", "3.5", "пять"],
>     ids=["ноль", "шесть", "дробная", "слово"],
> )
> def test_bad_marks(text):
>     with pytest.raises(ValueError):
>         parse_mark(text)
>
>
> def test_message_mentions_value():
>     with pytest.raises(ValueError, match="6"):
>         parse_mark("6")
> ```
>
> **Запуск:**
>
> ```text
> $ pytest -v test_marks.py
> test_marks.py::test_good_marks[5-5] PASSED                               [ 12%]
> test_marks.py::test_good_marks[1-1] PASSED                               [ 25%]
> test_marks.py::test_good_marks[  4 -4] PASSED                            [ 37%]
> test_marks.py::test_bad_marks[ноль] PASSED                               [ 50%]
> test_marks.py::test_bad_marks[шесть] PASSED                              [ 62%]
> test_marks.py::test_bad_marks[дробная] PASSED                            [ 75%]
> test_marks.py::test_bad_marks[слово] PASSED                              [ 87%]
> test_marks.py::test_message_mentions_value PASSED                        [100%]
>
> ============================== 8 passed in 0.01s ===============================
> ```
>
> В имени теста в квадратных скобках видно, **какой набор** данных выполнялся
> (`test_bad_marks[шесть]`). Если бы понадобилось запустить только его:
> `pytest test_marks.py -k "шесть"`.
>
> **Что здесь важно.** `parametrize` — это таблица случаев: добавить новый случай дешевле,
> чем написать новый тест. `pytest.raises` без `match` проверяет только тип исключения,
> с `match` — ещё и текст (по регулярному выражению), поэтому важно, чтобы сообщение
> было информативным.
>
> **Типичная ошибка.** Оборачивать проверку так:
>
> ```python
> try:
>     parse_mark("6")
> except ValueError:
>     pass
> ```
>
> Такой тест пройдёт даже если функция вернёт `6` вместо ошибки — он ничего не проверяет.
> Ещё одна ошибка — забыть про `"  4 "`: `int` сам убирает пробелы, и тест проходит,
> но если бы в функции было `float(text.strip())` с ручной проверкой — этот случай
> оказался бы важным.
>
> **Граница.** Если имена параметров содержат кириллицу, `pytest` по умолчанию показывает
> их экранированными (`test_bad_marks[\u043d\u043e\u043b\u044c]`). Читаемость возвращает
> строка в `pytest.ini` (или `pyproject.toml`):
>
> ```ini
> [pytest]
> disable_test_id_escaping_and_forfeit_all_rights_to_community_support = true
> ```
>
> Название длинное и шуточное, но параметр официальный.

## Задача 3. Синтаксис под тестами

★★★ · `for ... else`, моржовый оператор, `*args`, `**kwargs`, генераторы

**Условие.** Модуль `inventory.py` содержит пять маленьких функций:

| Функция | Что делает |
|---|---|
| `find_first(items, predicate)` | первый элемент, для которого `predicate` истинно; `None`, если нет |
| `read_lines(text)` | список непустых строк без лишних пробелов |
| `make_query(**params)` | строка вида `city=Казань&page=2` |
| `count_words(*texts)` | число слов во всех переданных текстах |
| `squares(limit)` | ленивая последовательность квадратов от 1 до `limit` |

**Задание.** 1) Напиши функции, используя подходящий приём из лекции
[[04. Остатки продвинутого синтаксиса]]: `for ... else` — там, где нужен «не нашлось»,
моржовый оператор — для значения, посчитанного прямо в условии. 2) Напиши тесты на каждую
функцию, включая «не нашлось» и пустые данные. 3) Отдельно проверь **ленивость** генератора:
`next()` должен вернуть первый квадрат, а остаток — только при следующем обращении.

> [!example]- Разбор
> **Идея.** Продвинутый синтаксис не самоцель: каждый приём заменяет несколько строк
> на конструкцию, которая читается как фраза. `for ... else` выражает «искали и не нашли»
> без флага-переменной; моржовый оператор избавляет от двойного вызова; генератор не строит
> список целиком; `*args` и `**kwargs` принимают переменное число аргументов в понятном виде.
>
> **Код (`inventory.py`).**
>
> ```python
> def find_first(items, predicate):
>     """Первый подходящий элемент; None, если такого нет."""
>     for item in items:
>         if predicate(item):
>             break
>     else:
>         return None
>     return item
>
>
> def read_lines(text):
>     """Непустые строки без лишних пробелов."""
>     lines = []
>     for line in text.splitlines():
>         if (clean := line.strip()):
>             lines.append(clean)
>     return lines
>
>
> def make_query(**params):
>     """Собирает строку запроса из именованных параметров."""
>     return "&".join(f"{key}={value}" for key, value in params.items())
>
>
> def count_words(*texts):
>     """Считает слова во всех переданных текстах."""
>     return sum(len(text.split()) for text in texts)
>
>
> def squares(limit):
>     """Ленивая последовательность квадратов от 1 до limit."""
>     for number in range(1, limit + 1):
>         yield number * number
> ```
>
> **Тесты (`test_inventory.py`).**
>
> ```python
> from inventory import count_words, find_first, make_query, read_lines, squares
>
>
> def test_find_first_found():
>     assert find_first([1, 4, 9], lambda n: n % 2 == 0) == 4
>
>
> def test_find_first_not_found():
>     assert find_first([1, 3, 5], lambda n: n % 2 == 0) is None
>
>
> def test_read_lines_skips_empty():
>     assert read_lines("Аня\n\n  \nБорис\n") == ["Аня", "Борис"]
>
>
> def test_make_query():
>     assert make_query(city="Казань", page=2) == "city=Казань&page=2"
>
>
> def test_make_query_empty():
>     assert make_query() == ""
>
>
> def test_count_words():
>     assert count_words("раз два", "три") == 3
>
>
> def test_squares_is_lazy():
>     numbers = squares(3)
>     assert next(numbers) == 1
>     assert list(numbers) == [4, 9]
>
>
> def test_squares_full():
>     assert list(squares(4)) == [1, 4, 9, 16]
> ```
>
> **Запуск:**
>
> ```text
> $ pytest -q test_inventory.py
> ........                                                                 [100%]
> 8 passed in 0.01s
> ```
>
> **Проверка вручную:**
>
> ```python
> from inventory import count_words, find_first, make_query, read_lines, squares
>
> print(find_first([1, 3, 6, 8], lambda n: n % 2 == 0))
> print(read_lines("Аня\n\n  \nБорис\n"))
> print(make_query(city="Казань", page=2))
> print(count_words("раз два", "три"))
> print(next(squares(3)), list(squares(3))[:3])
> ```
>
> ```text
> 6
> ['Аня', 'Борис']
> city=Казань&page=2
> 3
> 1 [1, 4, 9]
> ```
>
> **Что здесь важно.** `test_squares_is_lazy` проверяет не результат, а **поведение**:
> генератор отдаёт значения по одному. Такой тест поймает ошибку, если кто-то заменит `yield`
> на `return` со списком: `next(numbers)` тогда сломается. `test_make_query_empty` важен
> не меньше остальных: у `**params` есть краевой случай «ничего не передали».
>
> **Типичная ошибка.** Писать `find_first` через флаг:
>
> ```python
> def find_first(items, predicate):
>     found = None
>     for item in items:
>         if predicate(item):
>             found = item
>     return found
> ```
>
> Тут нет ничего страшного, но цикл просматривает **весь** список, хотя первый подходящий
> элемент уже найден: `break` из `for ... else` останавливает работу. Вторая ошибка —
> вызывать генератор дважды: `next(squares(3))` создаёт **новый** генератор, поэтому
> повторный вызов не «продолжает», а начинает сначала.
>
> **Граница.** `read_lines("   \n\n")` вернёт `[]` — пустой список, а не ошибку: это осознанное
> поведение, зафиксированное тестом. `count_words()` без аргументов вернёт `0`. Для обеих
> функций стоит держать такие тесты: именно пустые данные чаще всего ломают реальный разбор.

# Что запомнить из практики

| Приём | Когда |
|---|---|
| имя теста как утверждение | падение сразу объясняет, что сломалось |
| границы в тестах: пусто, один элемент, повтор | самые частые ошибки живут здесь |
| `parametrize` | один тест — таблица данных; в выводе видно, какой случай упал |
| `pytest.raises(..., match=...)` | проверка не только типа ошибки, но и сообщения |
| тест на поведение (`lazy`) | когда важно не только «что», но и «как» |
| `for ... else` | «искали и не нашли» без флага-переменной |
| моржовый оператор | значение считается прямо в условии и используется дальше |
