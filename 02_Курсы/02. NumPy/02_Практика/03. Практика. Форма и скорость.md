# 03. Практика. Форма и скорость

> [!abstract] О чём эта практика
> Три задачи по лекциям [[07. Форма, соединение и изменение]] и
> [[08. Векторизация и скорость]]. Первая — форма: разложить список в таблицу,
> транспонировать, соединить. Вторая — broadcasting: центрировать и нормировать таблицу,
> добавить столбец. Третья — векторизация и случайные числа: сгенерировать измерения
> воспроизводимо и сравнить цикл с NumPy.
>
> Это практика «почти проект»: её приёмы встречаются в анализе данных каждый день.

> [!important] Как работать с задачей
> 1. Прочитай условие и **не открывай разбор**.
> 2. Следи за `shape`: после каждой операции полезно печатать форму результата.
> 3. Сверь числа с разбором; для случайных данных важнее воспроизводимость, чем совпадение.
> 4. Сверься с разбором и проверь, не изменился ли исходный массив там, где не должен.

## Задача 1. Из списка в таблицу

★☆☆ · `reshape`, `T`, `ravel`, `concatenate`, `stack`

**Условие.** Есть 12 чисел — средние температуры по месяцам: `np.arange(1, 13) * 2.5`.

**Задание.** 1) Разложи их в таблицу `3 × 4` (три квартала по четыре месяца). 2) Выведи
форму таблицы и число столбцов. 3) Выведи транспонированную таблицу. 4) Разверни таблицу
в одну строку и в развёртку «по столбцам» (`order="F"`). 5) Соедини таблицу с такой же
по строкам (`concatenate(axis=0)`) и выведи форму результата. 6) Сделай из двух строк
формы `(4,)` массив формы `(2, 4)` через `np.stack` и объясни разницу с `vstack`.

> [!example]- Разбор
> **Идея.** `reshape` задаёт форму, `T` переставляет оси, `ravel` разворачивает в линию,
> `concatenate` склеивает по существующей оси, `stack` создаёт новое измерение.
>
> **Код.**
>
> ```python
> import numpy as np
>
> temperatures = np.arange(1, 13) * 2.5
> print("12 значений:", temperatures)
> table = temperatures.reshape(3, 4).round(1)
> print("таблица 3x4:\n", table)
> print("форма:", table.shape, "столбцов:", table.shape[1])
> print("транспонирование:\n", table.T)
> print("в одну строку:", table.ravel())
> print("по столбцам:", table.ravel(order="F"))
>
> half = np.array([[1.0, 2.0, 3.0, 4.0]])
> print("vstack:\n", np.vstack([half, half]))
> print("concatenate по строкам:\n", np.concatenate([table, table], axis=0).shape)
> print("stack:", np.stack([np.array([1, 2, 3]), np.array([4, 5, 6])]).shape)
> ```
>
> **Вывод:**
>
> ```text
> 12 значений: [ 2.5  5.   7.5 10.  12.5 15.  17.5 20.  22.5 25.  27.5 30. ]
> таблица 3x4:
>  [[ 2.5  5.   7.5 10. ]
>  [12.5 15.  17.5 20. ]
>  [22.5 25.  27.5 30. ]]
> форма: (3, 4) столбцов: 4
> транспонирование:
>  [[ 2.5 12.5 22.5]
>  [ 5.  15.  25. ]
>  [ 7.5 17.5 27.5]
>  [10.  20.  30. ]]
> в одну строку: [ 2.5  5.   7.5 10.  12.5 15.  17.5 20.  22.5 25.  27.5 30. ]
> по столбцам: [ 2.5 12.5 22.5  5.  15.  25.   7.5 17.5 27.5 10.  20.  30. ]
> vstack:
>  [[1. 2. 3. 4.]
>  [1. 2. 3. 4.]]
> concatenate по строкам:
>  (6, 4)
> stack: (2, 3)
> ```
>
> **Что здесь важно.** `ravel()` без аргумента идёт «по строкам» (`order="C"`): сначала первая
> строка целиком, потом вторая. `order="F"` читает таблицу по столбцам — это важно, когда
> данные пришли из системы, которая хранит их именно так. `np.concatenate([table, table])`
> дал форму `(6, 4)`: шесть строк по четыре столбца, оси совпали.
>
> **Типичная ошибка.** Перепутать `vstack` и `stack`: первый **склеивает** по существующей
> оси, второй **добавляет** измерение: две строки `(3,)` превращаются в таблицу `(2, 3)`.
> Вторая ошибка — пытаться сделать `reshape(4, 3)` «чтобы получилось красивее»: это изменит
> порядок элементов, а не только форму.
>
> **Граница.** `reshape` работает, только если общее число элементов совпадает: для 12 чисел
> подходят `(3, 4)`, `(2, 6)`, `(12,)`, но не `(5, 3)`. Ошибка формы — самая частая в NumPy.

## Задача 2. Центрирование и нормирование

★★☆ · broadcasting, `axis=0`, `hstack`, `keepdims`

**Условие.** Таблица оценок:

```python
table = np.array([[4, 5, 3], [5, 4, 4], [3, 3, 4]])
```

**Задание.** 1) Посчитай средние по предметам (`axis=0`) и вычти их из таблицы —
получится «центрированная» таблица. 2) Раздели центрированную таблицу на стандартное
отклонение по столбцам — получится «нормированная». 3) Убедись, что средние по столбцам
после нормировки равны нулю (с точностью до погрешности). 4) Добавь к таблице четвёртый
столбец `[[5], [5], [2]]` через `hstack` и посчитай средние по строкам заново.
5) Объясни, почему вычитание средних формы `(3,)` из таблицы `(3, 3)` работает,
а формы `(2,)` — нет.

> [!example]- Разбор
> **Идея.** Форма `(3,)` при вычитании из `(3, 3)` растягивается «по строкам»: один столбец
> средних применяется к каждому столбцу таблицы. Столбец данных, который нужно растянуть
> по строкам, должен иметь форму `(3, 1)` — поэтому при добавлении столбца через `hstack`
> ему нужно явно задать форму `(3, 1)` ([[04. Арифметика и broadcasting]]).
>
> **Код.**
>
> ```python
> import numpy as np
>
> table = np.array([[4, 5, 3], [5, 4, 4], [3, 3, 4]])
> means = table.mean(axis=0)
> print("средние по предметам:", means)
> print("центрированная таблица:\n", np.round(table - means, 2))
>
> centered = table - means
> scaled = centered / centered.std(axis=0)
> print("нормированная:\n", np.round(scaled, 2))
> print("средние по столбцам после нормировки:", np.round(scaled.mean(axis=0), 6))
>
> extra = np.array([[5], [5], [2]])
> with_extra = np.hstack([table, extra])
> print("таблица с новым столбцом:\n", with_extra)
> print("средние по строкам теперь:", np.round(with_extra.mean(axis=1), 2))
> ```
>
> **Вывод:**
>
> ```text
> средние по предметам: [4.         4.         3.66666667]
> центрированная таблица:
>  [[ 0.    1.   -0.67]
>  [ 1.    0.    0.33]
>  [-1.   -1.    0.33]]
> нормированная:
>  [[ 0.    1.22 -1.41]
>  [ 1.22  0.    0.71]
>  [-1.22 -1.22  0.71]]
> средние по столбцам после нормировки: [0. 0. 0.]
> таблица с новым столбцом:
>  [[4 5 3 5]
>  [5 4 4 5]
>  [3 3 4 2]]
> средние по строкам теперь: [4.25 4.5  3.  ]
> ```
>
> **Что здесь важно.** Суммы по столбцам центрированной таблицы — ноль (это проверка того,
> что вычиталось правильное среднее), а после деления на `std` средние остаются нулевыми:
> деление на положительное число не меняет знак и «центр». Такую обработку называют
> стандартизацией (z-оценка): она приводит разные шкалы к одной.
>
> **Типичная ошибка.** Забыть `np.round` и удивиться числам `-0.6666666666666667`.
> Вторая ошибка — добавлять «столбец» формы `(3,)` через `hstack`: NumPy посчитает его
> строкой и соединит не так, как ожидается, — форма `(3, 1)` здесь обязательна.
>
> **Граница.** Если стандартное отклонение по столбцу равно нулю (все значения одинаковы),
> деление даст `inf` или `nan`. Это не ошибка NumPy, а сигнал: такой столбец бесполезен
> для нормировки.

## Задача 3. Скорость и воспроизводимость

★★★ · `default_rng`, `timeit`, векторизация, `clip`

**Условие.** Нужно сгенерировать 100 000 измерений: нормальное распределение со средним
20 и отклонением 3, и посчитать по ним статистику.

**Задание.** 1) Сгенерируй измерения с `np.random.default_rng(seed=7)`. 2) Выведи первые
пять значений, среднее, медиану, минимум и максимум. 3) Найди измерения выше 22 и их долю.
4) Сравни время суммирования циклом и методом `.sum()` — сколько раз быстрее? 5) Докажи,
что с тем же `seed` данные повторяются, а с другим — нет. 6) «Зажми» значения в диапазон
от 15 до 25 через `np.clip` и выведи, какая доля исходных значений была за пределами.

> [!example]- Разбор
> **Идея.** Воспроизводимость случайных данных — обязательное условие для тестов и отчётов:
> с одним и тем же `seed` результат повторяется на любой машине. А суммирование массива
> против цикла показывает, что «писать проще» и «работать быстрее» здесь совпадают.
>
> **Код.**
>
> ```python
> import timeit
>
> import numpy as np
>
> rng = np.random.default_rng(seed=7)
> measurements = rng.normal(20, 3, 100_000)
> print("первые 5:", np.round(measurements[:5], 3))
> print("среднее:", round(float(measurements.mean()), 3))
> print("медиана:", round(float(np.median(measurements)), 3))
> print("минимум и максимум:", round(float(measurements.min()), 2), round(float(measurements.max()), 2))
>
> hot = measurements[measurements > 22]
> print("выше 22:", hot.size, f"({hot.size / measurements.size:.0%})")
>
> by_loop = timeit.timeit(
>     "total = 0.0\nfor value in measurements: total += value",
>     globals={"measurements": measurements},
>     number=1,
> )
> by_numpy = timeit.timeit("total = measurements.sum()", globals={"measurements": measurements}, number=1)
> print(f"цикл: {by_loop:.4f} с, numpy: {by_numpy:.6f} с, быстрее в {round(by_loop / by_numpy)} раз")
>
> again = np.random.default_rng(seed=7).normal(20, 3, 100_000)
> print("тот же seed даёт те же числа:", np.array_equal(measurements, again))
>
> clipped = np.clip(measurements, 15, 25)
> print("после clip:", round(float(clipped.min()), 2), round(float(clipped.max()), 2))
> print("доля за пределами:", f"{((measurements < 15) | (measurements > 25)).mean():.1%}")
> ```
>
> **Вывод:**
>
> ```text
> первые 5: [20.004 20.896 19.178 17.328 18.636]
> среднее: 19.996
> медиана: 19.993
> минимум и максимум: 6.49 32.18
> выше 22: 25150 (25%)
> цикл: 0.0051 с, numpy: 0.000054 с, быстрее в 94 раз
> тот же seed даёт те же числа: True
> после clip: 15.0 25.0
> доля за пределами: 9.6%
> ```
>
> **Что здесь важно.** Среднее `19.996` близко к 20 не потому, что «повезло», а потому,
> что 100 000 значений дают устойчивую оценку. Доля значений выше 22 (25%) — тоже
> ожидаемое число: 22 выше среднего на 2/3 отклонения, а за такой границей нормального
> распределения лежит примерно четверть данных. Такие факты стоит проверять «на здравый
> смысл» — тогда ошибка в коде видна до того, как попадёт в отчёт.
>
> **Типичная ошибка.** Использовать `np.random.seed` из старого стиля и глобальный генератор:
> в тестах два разных места начинают влиять друг на друга. Второй вариант ошибки —
> генерировать данные внутри функции без параметра `seed`: тест становится нестабильным.
>
> **Граница.** `np.clip` не убирает «выбросы», а **зажимает** их: после него в данных
> появляются одинаковые значения на границах (9.6% значений оказались за пределами
> диапазона). Если нужно удалить, а не зажать — используйте маску.

# Что запомнить из практики

| Приём | Когда |
|---|---|
| `reshape(3, -1)` | данные известны, форму задаём сами |
| `T`, `ravel(order=...)` | переставить оси, развернуть таблицу |
| `concatenate` / `vstack` / `stack` | склейка против нового измерения |
| `table - table.mean(axis=0)` | центрирование по столбцам |
| `centered / centered.std(axis=0)` | нормировка (z-оценка) |
| `np.hstack([table, extra])` при `extra` формы `(3, 1)` | добавить столбец данных |
| `default_rng(seed=...)` | воспроизводимые случайные данные |
| `.sum()` вместо цикла | скорость и читаемость |
