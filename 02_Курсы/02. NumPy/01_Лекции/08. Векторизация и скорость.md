# 08. Векторизация и скорость

> [!abstract] О чём лекция
> Векторизация — привычка писать вычисления «целиком по массиву», а не поэлементно в цикле на Python: `data.sum()` вместо `for v in data: total+=v`. Здесь — сколько это даёт на самом деле (в 21–73 раза), как генерировать случайные данные воспроизводимо (`default_rng` с `seed`) и какие конструкции чаще всего тормозят код: цикл по элементам, `append` в цикле, лишние `copy`.
>
> После лекции ты проверишь скорость `timeit`, зафиксируешь `seed` для тестов и не напишешь `np.append` в цикле.

# Цикл против массива — замер

```python
import timeit, numpy as np

rng = np.random.default_rng(seed=42)
rows = 200_000
data = rng.normal(4, 1, rows)

t_loop = timeit.timeit("total = 0.0\nfor v in data: total += v", globals={"data": data}, number=1)
t_np = timeit.timeit("total = data.sum()", globals={"data": data}, number=1)
print(f"цикл: {t_loop:.4f} с | numpy: {t_np:.5f} с | быстрее в {t_loop/t_np:.0f} раз")

many = list(range(1_000_000))
t_list = timeit.timeit("out = [x*2 for x in data]", globals={"data": many}, number=5)
t_arr = timeit.timeit("out = data*2", globals={"data": np.arange(1_000_000)}, number=5)
print(f"список *2: {t_list/5:.3f} с | массив *2: {t_arr/5:.4f} с | в {t_list/t_arr:.0f} раз")
```

```text
цикл: 0.0127 с | numpy: 0.00017 с | быстрее в 73 раз
список *2: 0.038 с | массив *2: 0.0018 с | в 21 раз
```

Разница — не проценты, а **разы**: 21× на умножении, 73× на сумме. Дальше — вывод: **в Python цикл по массиву означает отказ от NumPy**. Если пишешь `for v in array:`, скорее всего есть векторный вариант:

| Задача | Цикл Python | Векторно NumPy |
|---|---|---|
| сумма | `for x in a: total+=x` | `a.sum()` |
| прибавить число | `for i in range(len(a)): a[i]+=5` | `a + 5` |
| только положительные | `for x in a: if x>0: ...` | `a[a>0]` |
| среднее по строкам | двойной `for` | `a.mean(axis=1)` |
| нормировка столбцов | цикл по столбцам | `a / a.max(axis=0)` |
| заменить отрицательные | `if a[i]<0: a[i]=0` | `np.where(a<0, 0, a)` |

Правило: одна строка NumPy заменяет цикл и работает на C.

# Случайные числа: воспроизводимость

Генерация — часть проекта (данные для тестов, шум для примера). Современный способ — `default_rng`:

```python
rng = np.random.default_rng(seed=42)
print("целые 1..5:", rng.integers(1, 6, size=8))
print("дробные [0,1):", np.round(rng.random(4), 3))
print("нормальное mean=4 std=1:", np.round(rng.normal(4, 1, 5), 2))
print("выбор:", rng.choice(["Аня","Борис","Вика"], size=3))
print("перемешивание копия:", rng.permutation(np.arange(1,6)))
arr = np.arange(1,6)
rng.shuffle(arr)
print("на месте:", arr)
```

```text
целые 1..5: [1 4 4 3 3 5 1 4]
дробные [0,1): [0.094 0.976 0.761 0.786]
нормальное mean=4 std=1: [3.98 3.15 4.88 4.78 4.07]
выбор: ['Борис' 'Вика' 'Борис']
перемешивание копия: [2 1 4 5 3]
на месте: [2 1 3 5 4]
```

Что важно:

1. **`default_rng(seed=...)` — современный.** Устаревший `np.random.seed` + `np.random.*` оставлены для совместимости; новый генератор называют `rng`.
2. **`seed` делает результат воспроизводимым.** Один и тот же `seed` — одни и те же числа на любой машине. Для тестов и отчётов — обязательно, иначе тест «иногда» падает.
3. **`integers(1, 6)` — правый конец не входит**, как в `range`. Оценки `1..5` → `integers(1,6)`.
4. **`permutation` — копия, `shuffle` — на месте.** Путать — значит испортить исходный массив.

| Метод `rng.` | Что даёт |
|---|---|
| `integers(low, high, size)` | целые `[low, high)` |
| `random(size)` | дробные `[0,1)` |
| `normal(mean, std, size)` | нормальное |
| `choice(items, size)` | выбор из набора |
| `permutation(array)` | перестановка — копия |
| `shuffle(array)` | перемешивание на месте |

# Реалистичный пример: оценки класса

Одна строка вместо цикла с проверками — `clip` + `round` + `astype`:

```python
import numpy as np
rng = np.random.default_rng(42)
grades = np.clip(np.round(rng.normal(4, 1, 12)), 1, 5).astype(int)
print("оценки:", grades)
print("средний:", grades.mean().round(2), "отличников:", int((grades==5).sum()), "успеваемость:", f"{(grades>=4).mean():.0%}")
print("медиана:", np.median(grades), "стд:", grades.std().round(2))
```

```text
оценки: [4 3 5 5 2 3 4 4 4 3 5 5]
средний: 3.92 отличников: 4 успеваемость: 67%
медиана: 4.0 стд: 0.95
```

Разбор цепочки `np.clip(np.round(rng.normal(4,1,12)),1,5).astype(int)`:

1. `rng.normal(4,1,12)` — 12 «оценок» со средним 4, могут выйти 2.7 или 6.1;
2. `np.round(...)` — округляем (`float` `5.0`);
3. `np.clip(...,1,5)` — обрезаем за пределами шкалы 1–5;
4. `.astype(int)` — в целые.

Одна строка — вместо цикла с `if grade<1: grade=1`. Это и есть векторизация: **идея читается в последовательности операций, а не в теле цикла.**

# Что замедляет код чаще всего

| Причина | Как выглядит | Что делать |
|---|---|---|
| цикл по элементам | `for i in range(len(a)): a[i]+=5` | `a + 5` |
| `np.append` в цикле | `a = np.append(a, x)` | `np.zeros(n)` или список, затем один `np.array` |
| `if` внутри цикла по массиву | `if a[i]>0: ...` | маска `a[a>0]` |
| лишний `astype`/`copy` | копия на каждой итерации | привести тип один раз на границе |
| повторный расчёт | `a.mean()` в цикле | вынести `mean = a.mean()` до цикла |

Первые три причины можно измерить (Python 3.11.2, NumPy 2.4.6):

```python
import timeit
import numpy as np

data = np.arange(100_000, dtype=float) - 50_000


def loop_add():
    out = data.copy()
    for i in range(len(out)):
        out[i] += 5


def vector_add():
    out = data + 5


def loop_if():
    out = []
    for value in data:
        if value > 0:
            out.append(value)


def by_mask():
    out = data[data > 0]


def append_loop():
    out = np.array([])
    for x in range(2000):
        out = np.append(out, x)


def list_then_array():
    out = []
    for x in range(2000):
        out.append(x)
    return np.array(out)


for slow, fast in [(loop_add, vector_add), (loop_if, by_mask), (append_loop, list_then_array)]:
    t_slow = timeit.timeit(slow, number=5) / 5
    t_fast = timeit.timeit(fast, number=5) / 5
    print(f"{slow.__name__:11} {t_slow * 1000:7.3f} мс | {fast.__name__:15} {t_fast * 1000:7.3f} мс | в {t_slow / t_fast:.0f} раз")
```

```text
loop_add     19.215 мс | vector_add        0.065 мс | в 296 раз
loop_if       6.313 мс | by_mask           0.096 мс | в 66 раз
append_loop   4.044 мс | list_then_array   0.112 мс | в 36 раз
```

Три причины — три разных порядка: цикл с `+5` медленнее векторной записи в сотни раз, цикл с `if` — в десятки, а `np.append` в цикле — тоже в десятки уже на 2000 элементах (и дальше растёт). Числа зависят от машины, но порядок сохраняется.

> [!warning] `np.append` в цикле — квадратично
> `a = np.array([]); for x in range(1000): a = np.append(a, x)` — каждый `append` копирует весь массив: `1+2+…+1000` копий. Замер такого цикла: 1000 добавлений — 2.5 мс, 10 000 — 29 мс, 30 000 — 437 мс; время растёт быстрее, чем число элементов. Правильно: `a = np.zeros(1000); for i,x in enumerate(range(1000)): a[i]=x` или `np.arange(1000)` — один проход.

> [!note] Векторизация не всегда выигрывает
> Если данные маленькие (десятки чисел) или логика сложная (разные действия для разных случаев), цикл может оказаться понятнее — и это нормально. Векторизация нужна там, где объём большой и действие одинаковое. И помни: временные массивы `a+b` занимают память — `1_000_000` `float64` → 8 МБ на каждый, десять промежуточных — 80 МБ.

# Как это делают в проекте

Проект с NumPy — это `src/weather` с `data.py` и `report.py`, где данные — `ndarray`.

1. **Сначала правильность, потом скорость.** Код на массивах и так быстрее цикла; оптимизируют только после `timeit`/`cProfile` из [[10. Сложность и производительность]].

2. **Всегда фиксируют `seed` в тестах и примере.** `rng = np.random.default_rng(42)` — в `data.py` и в `tests/test_report.py`; без фиксации тест «иногда» падает, а картинка в Matplotlib каждый раз новая.

```python
# tests/test_report.py
def test_grades_mean():
    rng = np.random.default_rng(42)
    grades = np.clip(np.round(rng.normal(4,1,12)),1,5).astype(int)
    assert grades.mean().round(2) == 3.92
```

3. **Держат данные в массивах, а не в списках.** Преобразование списка в массив — один раз на границе `load_temps(path) -> np.ndarray` с `np.array(raw, dtype=np.float64)`.

4. **Проверяют память для больших данных.** Для 10 млн чисел `a+b` — 80 МБ + 80 МБ; считают частями `np.add(a, b, out=a)` на месте или чанками.

5. **Читают ошибки формы как подсказки.** `ValueError: operands could not be broadcast` → смотри `shape`, добавь `[:,None]` — как в [[04. Арифметика и broadcasting]].

# Типичные заблуждения

| Заблуждение | Как на самом деле |
|---|---|
| «NumPy просто ускоряет тот же цикл» | Он выполняет цикл на C без объектов Python — разница в разах, а не в процентах |
| «Векторизация — это `for ... in np.nditer`» | Это отказ от `for` на Python: операции над массивами целиком (`a.sum()`) |
| «`np.random.seed` и `default_rng` — одно» | Рекомендуемый — `default_rng(seed)`; глобальный `seed` устаревает и менее гибок |
| «Случайные данные нельзя тестировать» | С фиксированным `seed` — можно: числа воспроизводимы на любой машине |
| «Чем больше операций в строке, тем быстрее» | Важна векторность, а не краткость; `np.clip(round(...))` быстрее не из-за цепочки, а из-за C-цикла |
| «`np.append` в цикле — нормально для 1000» | Квадратично: для 10 000 уже секунды — нужен `zeros` или список |

# Проверь себя

1. Почему цикл по массиву NumPy медленный (в десятки раз)?
2. Как сделать случайные данные воспроизводимыми и где это важно?
3. Что делает `np.clip(x, 1, 5)` и когда его ставят до `astype(int)`?
4. Что даст `rng.integers(1, 6, size=10)`?
5. Что не так с `a = np.append(a, x)` внутри цикла и как исправить?

> [!success]- Ответы
> 1. Каждый элемент «вынимается» в объект Python, и цикл выполняет интерпретатор, а не скомпилированный код NumPy на C.
> 2. `rng = np.random.default_rng(seed=42)` — фиксированный `seed`; важно в тестах и отчётах, чтобы числа повторялись.
> 3. Обрезает по границам: `<1`→`1`, `>5`→`5`; перед `astype(int)` чтобы не было 0 или 6.
> 4. Десять целых 1..5 (6 не входит) — оценки.
> 5. Каждый `append` копирует массив — квадратично; нужен `np.zeros(n)` с индексами или список + один `np.array` в конце.
