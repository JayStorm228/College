# 07. Форма, соединение и изменение

> [!abstract] О чём лекция
> Данные приходят не в той форме, которая нужна: список — а надо таблицу; таблица —
> а надо один столбец; две таблицы — а надо одну. Здесь — инструменты формы:
> `reshape`, `ravel`, `T`, `concatenate`, `vstack`, `hstack` и работа с измерениями.
>
> Правило лекции: **форма — не деталь, а часть алгоритма.** Большая часть ошибок
> «не сходится размер» лечится не пересчётом формулы, а приведением формы.

# Изменение формы: `reshape`

```python
import numpy as np

a = np.arange(6)
print("исходный:", a)
print("reshape 2x3:\n", a.reshape(2, 3))
print("reshape с -1:\n", a.reshape(-1, 2))
print("flatten (копия):", a.reshape(2, 3).ravel())
print("исходный не изменился:", a)
```

```text
исходный: [0 1 2 3 4 5]
reshape 2x3:
 [[0 1 2]
 [3 4 5]]
reshape с -1:
 [[0 1]
 [2 3]
 [4 5]]
flatten (копия): [0 1 2 3 4 5]
исходный не изменился: [0 1 2 3 4 5]
```

Два правила:

1. **Число элементов должно совпадать.** `a.reshape(2, 3)` для 6 элементов — можно;
   `a.reshape(4, 2)` — `ValueError`.
2. **`-1` означает «посчитай сам».** `a.reshape(-1, 2)` — «сделай по 2 элемента в строке,
   сколько строк получится — реши сам»: получится `(3, 2)`.

`reshape` почти всегда возвращает **вид**, а не копию ([[03. Индексация, срезы и представления]]).
`ravel()` возвращает вид, если это возможно; `flatten()` всегда копирует.

# Транспонирование и оси

```python
matrix = np.array([[1, 2], [3, 4]])
print("транспонирование:\n", matrix.T)
print("сумма строк:", matrix.sum(axis=1))
print("порядок C (по строкам):", matrix.ravel(order="C"))
print("порядок F (по столбцам):", matrix.ravel(order="F"))
```

```text
транспонирование:
 [[1 3]
 [2 4]]
сумма строк: [3 7]
порядок C (по строкам): [1 2 3 4]
порядок F (по столбцам): [1 3 2 4]
```

`matrix.T` — вид с переставленными осями: строки становятся столбцами. Для двумерных
массивов это транспонирование, для многомерных — «обратный порядок осей».

Порядок `C` и `F` — про то, как «разворачивать» таблицу в линию: по строкам или
по столбцам. По умолчанию — `C` (как читают: слева направо и вниз).

# Соединение массивов

```python
first = np.array([[1, 2]])
second = np.array([[3, 4]])
print("vstack:\n", np.vstack([first, second]))
print("hstack:", np.hstack([np.array([1, 2]), np.array([3, 4])]))
print("concatenate по столбцам:\n", np.concatenate([matrix, matrix], axis=1))
print("столбик:", np.array([[1], [2]]).shape)
```

```text
vstack:
 [[1 2]
 [3 4]]
hstack: [1 2 3 4]
concatenate по столбцам:
 [[1 2 1 2]
 [3 4 3 4]]
столбик: (2, 1)
```

| Функция | Что делает | Условие |
|---|---|---|
| `np.concatenate([a, b], axis=0)` | соединяет по указанной оси | совпадают остальные измерения |
| `np.vstack([a, b])` | ставит массивы друг на друга (по строкам) | одинаковое число столбцов |
| `np.hstack([a, b])` | ставит рядом (по столбцам) | одинаковое число строк |
| `np.stack([a, b])` | создаёт **новое** измерение | одинаковые формы |

Разница `concatenate` и `stack`: первый склеивает существующую ось, второй добавляет новую.
Например, из трёх массивов формы `(4,)` `np.stack` даст `(3, 4)`, а `np.concatenate` —
`(12,)`.

# Операции «на месте» и новые массивы

```python
numbers = np.array([15, 7, 22, 3])
print("прибавка не изменила исходный:", (numbers + 1)[0], numbers[0])
numbers += 10
print("после +=:", numbers)
```

```text
прибавка не изменила исходный: 16 15
после +=: [25 17 32 13]
```

`numbers + 1` создаёт **новый** массив, `numbers += 10` меняет тот же самый. Вариант
«на месте» экономит память, но требует осторожности: если на массив ссылаются другие
виды, они увидят изменения.

То же касается сортировки: `np.sort(a)` возвращает копию и не трогает `a`, а `a.sort()`
сортирует **на месте** и возвращает `None` — классический источник ошибки
`a = a.sort()` (после такого `a` станет `None`).

# `keepdims`: сохранить измерение

```python
table = np.array([[1, 2, 3], [4, 5, 6]])
print("суммы:", table.sum(axis=1))
print("с keepdims:\n", table.sum(axis=1, keepdims=True))
```

```text
суммы: [6 15]
с keepdims:
 [[ 6]
 [15]]
```

Форма `(2,)` против `(2, 1)`. Второй вариант позволяет вычитать одну таблицу из другой
без дополнительных преобразований: broadcasting растянет столбец на нужное число столбцов
([[04. Арифметика и broadcasting]]).

```python
print(table - table.mean(axis=1, keepdims=True))
```

```text
[[-1.  0.  1.]
 [-1.  0.  1.]]
```

Так считают «отклонение от среднего по строке» в одну строку кода.

# Как это делают в проекте

1. **Форму приводят рядом с данными, а не по всему коду.** Один `reshape` при чтении,
   один `reshape` перед сохранением.
2. **Пишут `-1` вместо подсчёта вручную.** `reshape(-1, 3)` переживает изменение размера
   данных; `reshape(100, 3)` — нет.
3. **Проверяют `shape` перед `concatenate`.** «Не сходится размер» — это почти всегда
   про несовпадающие измерения.
4. **Используют `keepdims=True`** для расчётов «вычесть среднее по строкам».
5. **Не путают `sort` и `sorted`.** `np.sort(a)` — копия, `a.sort()` — на месте.

# Типичные заблуждения

| Заблуждение | Как на самом деле |
|---|---|
| «`reshape` копирует данные» | Возвращает вид, когда возможно |
| «`flatten` и `ravel` — одно и то же» | Первый всегда копирует, второй — вид при возможности |
| «Форма `(6,)` и `(6, 1)` — почти одно и то же» | Разные: сложение и соединение ведут себя иначе |
| «`hstack` и `vstack` взаимозаменяемы» | Зависит от того, что должно совпадать: строки или столбцы |
| «`a.sort()` вернёт отсортированный массив» | Возвращает `None`, сортирует на месте |

# Проверь себя

1. Что даст `np.arange(12).reshape(3, -1)`?
2. Как превратить `(4,)` в `(4, 1)`?
3. Чем `np.concatenate` отличается от `np.stack`?
4. Что делает `keepdims=True` и зачем он нужен?
5. Почему `a = a.sort()` — ошибка?

> [!success]- Ответы
> 1. Таблицу `(3, 4)`: 12 элементов по трём строкам.
> 2. `a.reshape(-1, 1)` или `a[:, None]`.
> 3. `concatenate` склеивает по существующей оси, `stack` создаёт новое измерение.
> 4. Сохраняет свёрнутое измерение размером 1: удобно для последующих вычислений
>    по той же таблице.
> 5. `a.sort()` возвращает `None` и сортирует на месте; после присваивания `a` станет `None`.
