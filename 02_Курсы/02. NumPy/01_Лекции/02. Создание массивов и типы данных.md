# 02. Создание массивов и типы данных

> [!abstract] О чём лекция
> Массив можно получить пятью способами: из готовых данных, «нулями», «единицами»,
> диапазоном и равномерной сеткой. Здесь — все пять, плюс тип элементов (`dtype`)
> и приведение типов, которое чаще всего ломает ожидания новичка.

# Пять способов получить массив

```python
import numpy as np

print("из списка:", np.array([3, 1, 2]))
print("нули:", np.zeros(4))
print("единицы 2x3:\n", np.ones((2, 3)))
print("диапазон:", np.arange(0, 10, 2))
print("равномерно:", np.linspace(0, 1, 5))
```

```text
из списка: [3 1 2]
нули: [0. 0. 0. 0.]
единицы 2x3:
 [[1. 1. 1.]
 [1. 1. 1.]]
диапазон: [0 2 4 6 8]
равномерно: [0.   0.25 0.5  0.75 1.  ]
```

| Функция | Что даёт | Типичный случай |
|---|---|---|
| `np.array(data)` | массив из списка или кортежа | данные уже есть |
| `np.zeros(shape)` | нули | заготовка под накопление результата |
| `np.ones(shape)` | единицы | тесты, начальные значения |
| `np.arange(start, stop, step)` | диапазон, шаг может быть дробным | счётчики, координаты |
| `np.linspace(start, stop, count)` | `count` равномерных точек **включая** `stop` | графики, сетки |

Разница `arange` и `linspace` — в последней точке: `np.arange(0, 1, 0.25)` даёт
`[0. 0.25 0.5 0.75]` (единица не входит), а `np.linspace(0, 1, 5)` — `[0. 0.25 0.5 0.75 1. ]`.
Для графиков и сеток почти всегда нужен `linspace`: в нём задаётся **количество точек**,
а не шаг, поэтому не бывает «неполного последнего интервала».

# Тип элементов: `dtype`

```python
marks = np.array([5, 4, 5, 3])
print("целые:", marks, marks.dtype)
print("вещественные:", marks.astype(float), marks.astype(float).dtype)
```

```text
целые: [5 4 5 3] int64
вещественные: [5. 4. 5. 3.] float64
```

Основные типы, которые встречаются каждый день:

| `dtype` | Что хранит | Пример |
|---|---|---|
| `int64` | целые числа | оценки, счётчики, индексы |
| `float64` | вещественные числа | среднее, проценты, измерения |
| `bool` | `True` / `False` | маски ([[06. Логические маски и фильтрация]]) |
| `<U5` | строки фиксированной длины | имена, метки |

Type приводится так: `marks.astype(float)`. Важно: **приведение создаёт новый массив**,
исходный не меняется. Обратное приведение обрезает дробную часть:

```python
print(np.array([2.7, 2.2]).astype(int))
```

```text
[2 2]
```

Это не округление: `astype(int)` отбрасывает дробную часть. Нужно округление —
`np.round` до приведения.

# Опасности преобразования типов

```python
mixed = np.array([1, 2.5, 3])
print("смешанный список:", mixed, mixed.dtype)
print("строки:", np.array(["Аня", "Борис"]).dtype)
```

```text
смешанный список: [1.  2.5 3. ] float64
строки: <U5
```

Две ловушки:

1. **Один тип на весь массив.** Список с числами и строками превратится в массив строк,
   и арифметика с ним перестанет работать:
   `np.array([1, "два"])` → `array(['1', 'два'], dtype='<U21')`.
2. **Потеря точности при приведении.** `np.array([1.5, 2.5]).astype(int)` даёт `[1 2]`,
   а не `[2 3]`. Если нужны целые по правилам округления — сначала `np.round`.

> [!warning] Целые и деление
> Деление целых в NumPy даёт вещественное число: `np.array([7, 8]) / 2` → `[3.5 4. ]`.
> А вот `np.array([7, 8]) // 2` даёт `[3 4]` — целочисленное деление. Путаница между
> `/` и `//` в расчётах встречается постоянно.

# Размерности

```python
print("размеры 2x3:", np.zeros((2, 3)).shape, np.zeros((2, 3)).size, np.zeros((2, 3)).ndim)
print("одна оценка:", np.array(5).shape, "и её размерность:", np.array(5).ndim)
```

```text
размеры 2x3: (2, 3) 6 2
одна оценка: () и её размерность: 0
```

`np.array(5)` — массив **нулевой размерности** (одно число без измерений). Иногда это удобно,
иногда мешает: форма `()` не равна форме `(1,)`. Если нужен «вектор из одного числа» —
`np.array([5])`.

# Как это делают в проекте

1. **Не создают массивы в цикле.** Вместо `np.append` на каждой итерации — заранее известная
   длина (`np.zeros(n)`) или список Python, который в массив превращают один раз в конце.
2. **Указывают `dtype`, когда важно.** Для денег и точных вычислений иногда нужны целые
   (копейки) или `float64` явно, чтобы не ловить сюрпризы.
3. **Проверяют `shape` перед расчётом.** Сложение массивов разных форм либо работает
   по правилам ([[04. Арифметика и broadcasting]]), либо падает с `ValueError`.
4. **`linspace` для графиков, `arange` для счётчиков.** Это разные задачи, и выбор виден
   в коде.

# Типичные заблуждения

| Заблуждение | Как на самом деле |
|---|---|
| «`np.array` копирует список «как есть»» | Тип приводится к общему: `[1, 2.5]` → `float64` |
| «`astype(int)` округляет» | Отбрасывает дробную часть; для округления — `np.round` |
| «В массиве можно держать разные типы» | Один `dtype` на массив; остальное приводится |
| «`arange(0, 1, 0.25)` включает 1» | Не включает: правый конец всегда исключён |
| «Массив нулевой размерности — это то же, что `(1,)`» | Формы `()` и `(1,)` разные |

# Проверь себя

1. Чем `np.arange(0, 1, 0.25)` отличается от `np.linspace(0, 1, 5)`?
2. Что вернёт `np.array([1, 2.5, 3]).dtype` и почему?
3. Как превратить массив `int64` в `float64`? Изменится ли исходный массив?
4. Что даст `np.array([2.7, 2.2]).astype(int)`?
5. Чем опасен `np.append` в цикле?

> [!success]- Ответы
> 1. Первый задаёт шаг и не включает правый конец: `[0. 0.25 0.5 0.75]`; второй задаёт
>    количество точек и включает: `[0. 0.25 0.5 0.75 1. ]`.
> 2. `float64`: тип общий для массива, поэтому целое приводится к вещественному.
> 3. `marks.astype(float)`; исходный массив не меняется — создаётся новый.
> 4. `[2 2]`: дробная часть отбрасывается, округления нет.
> 5. Он создаёт новый массив на каждой итерации: время растёт квадратично, память
>    расходуется зря. Нужен заранее подготовленный массив или список Python.
