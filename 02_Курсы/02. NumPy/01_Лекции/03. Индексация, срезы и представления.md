# 03. Индексация, срезы и представления

> [!abstract] О чём лекция
> К элементам массива обращаются как к элементам списка — по индексу и срезу — но в двух измерениях и с одной важной деталью: **срез возвращает вид, а не копию**. Здесь — индексы, срезы, выбор по списку индексов и по маске, разница вида и копии и почему `shares_memory` — главный способ проверить.
>
> После лекции ты отличишь вид от копии, не испортишь исходный массив случайным `a[:] = 0` и выберешь правильный способ скопировать.

# Индексы и срезы — как в списках, но быстрее

```python
import numpy as np

a = np.array([10, 20, 30, 40, 50])
print("a[0] =", a[0], "| a[-1] =", a[-1])
print("a[1:4] =", a[1:4])
print("a[::2] =", a[::2])
print("a[::-1] =", a[::-1])
```

```text
a[0] = 10 | a[-1] = 50
a[1:4] = [20 30 40]
a[::2] = [10 30 50]
a[::-1] = [50 40 30 20 10]
```

| Запись | Смысл |
|---|---|
| `a[0]` | первый элемент |
| `a[-1]` | последний |
| `a[1:4]` | с 1 до 3 включительно (4 не входит) |
| `a[::2]` | каждый второй |
| `a[::-1]` | развернуть |

На этом уровне массив ведёт себя как список, но результат — тоже массив `ndarray`, а не список. Индекс за границей — `IndexError`, как в списке.

# Два измерения — строка, столбец

```python
table = np.array([[5, 4, 5], [3, 4, 3], [4, 5, 5]])
print(table)
print("table[0, 1] =", table[0, 1])
print("первая строка:", table[0])
print("второй столбец:", table[:, 1])
print("подтаблица 2×2:", table[:2, :2])
```

```text
[[5 4 5]
 [3 4 3]
 [4 5 5]]
table[0, 1] = 4
первая строка: [5 4 5]
второй столбец: [4 4 5]
подтаблица 2×2: [[5 4]
 [3 4]]
```

| Запись | Что берёт |
|---|---|
| `table[0, 1]` | элемент строка 0, столбец 1 |
| `table[0]` | строка 0 целиком — массив `shape (3,)` |
| `table[:, 1]` | столбец 1 — все строки, один столбец |
| `table[:2, :2]` | левый верхний угол 2×2 |
| `table[::2, ::2]` | каждая вторая строка и каждый второй столбец |

Запятая разделяет измерения: до — строки, после — столбцы. Это как `matrix[row][col]`, только одной операцией.

# Выбор по списку индексов и по маске

Кроме срезов, есть два «расширенных» способа — **fancy indexing** и **маска**:

```python
a = np.array([10, 20, 30, 40, 50])
print("по списку:", a[[0, 2, 4]])
print("по маске:", a[a > 25])

table = np.array([[5, 4, 5], [3, 4, 3]])
mask = table[1] >= 4
print("вторая строка:", table[1])
print("маска:", mask)
print("отобраны:", table[1][mask])
```

```text
по списку: [10 30 50]
по маске: [30 40 50]
вторая строка: [3 4 3]
маска: [False  True False]
отобраны: [4]
```

- `a[[0,2,4]]` — выбор по списку индексов, порядок любой, можно повторять;
- `a[a > 25]` — булева маска `a > 25` → `[False False True True True]`, затем `a[mask]`.

Маска — мощный фильтр: `grades[grades >= 4]` — только хорошие оценки, `temps[(temps > 0) & (temps < 10)]` — в диапазоне. Подробнее — в [[06. Логические маски и фильтрация]].

> [!note] Срез vs список индексов vs маска
> Срез (`a[1:4]`) — **вид** (см. ниже), быстро и без копирования. Список индексов (`a[[0,2]]`) и маска (`a[a>0]`) — **копия**: новый массив, исходный не меняется. Отсюда правило: выбор через `:` — вид, через `[]` с массивом — копия.

# Срез — это вид, а не копия

Главное отличие от списка: **срез массива не копирует данные**, а показывает окно на тот же блок памяти.

```python
a = np.array([10, 20, 30, 40, 50])
view = a[1:4]
print("вид:", view, "| view.base is a:", view.base is a)
print("общая память?", np.shares_memory(a, view))

view[0] = 99
print("после view[0]=99, a =", a)

copy = a[1:4].copy()
copy[0] = 0
print("после copy[0]=0, a =", a)
```

```text
вид: [20 30 40] | view.base is a: True
общая память? True
после view[0]=99, a = [10 99 30 40 50]
после copy[0]=0, a = [10 99 30 40 50]
```

`view.base` — массив, чью память показывает вид; для среза это исходный `a` (для самостоятельного массива `base` равен `None`), а `np.shares_memory(a, view)` прямо отвечает, пересекаются ли блоки памяти.

| Что | Память | Изменение вида |
|---|---|---|
| `a[1:4]` | вид — общая память `shares_memory==True` | меняет `a` |
| `a[1:4].copy()` | копия — свой блок | не меняет `a` |
| `a[[0,2]]` | копия | не меняет `a` |
| `a[a>0]` | копия | не меняет `a` |

Это источник половины ошибок новичка: функция получила `x = arr[1:4]`, поменяла `x[0]`, и исходный `arr` «сам» изменился. В списках такого нет — `lst[1:4]` всегда копия.

# Зачем нужны виды

Вид — не баг, а фича: он **не копирует**, поэтому быстрый и экономит память.

```python
import numpy as np, timeit
big = np.arange(1_000_000)
t_view = timeit.timeit("x = big[100_000:900_000]", globals={"big": big}, number=1000)
t_copy = timeit.timeit("x = big[100_000:900_000].copy()", globals={"big": big}, number=1000)
print(f"вид: {t_view:.4f} с | копия: {t_copy:.4f} с")
print("размер вида:", big[100_000:900_000].nbytes/1e6, "МБ — без копирования")
```

```text
вид: 0.0001 с | копия: 0.4137 с
размер вида: 6.4 МБ — без копирования
```

Вид на три порядка быстрее и не занимает дополнительные 6 МБ. Для окна `800 000` чисел это заметно.

Правило курса:

- нужен **взгляд на часть** без изменения — бери вид (`a[1:4]`);
- нужен **независимый массив** для правки — `.copy()`;
- сомневаешься — проверь `np.shares_memory(a, b)`.

> [!warning] Вид и `reshape`/`T`
> `a.reshape(2,3)` и `a.T` тоже часто — виды (делят память), а не копии. После `b = a.reshape(2,3); b[0,0]=99` исходный `a[0]` тоже `99`. Подробнее — в [[07. Форма, соединение и изменение]].

# Как это делают в проекте

1. **Срез для чтения — вид, для записи — копия.** В `src/weather/report.py` — `week = temps[7:14]` для расчёта среднего недели — вид, быстро. Для исправления «выброса» — `fixed = temps.copy(); fixed[peak] = median`.

2. **Проверяют `shares_memory` в тестах.** `assert not np.shares_memory(original, filtered)` — гарантия, что фильтр не испортил исходный массив, который нужен дальше.

```python
def test_filter_does_not_change_original():
    orig = np.array([5, 4, 5, 3])
    filtered = orig[orig > 4].copy()  # копия, не вид
    filtered[0] = 0
    assert np.shares_memory(orig, filtered) == False
    assert orig[0] == 5
```

3. **Маска — вместо цикла с `if`.** Вместо `for v in grades: if v >=4: ...` — `grades[grades >=4]` — одна строка, без цикла Python.

4. **Не используют `a[a>0] = 0` без понимания.** Это меняет исходный `a` на месте; если `a` ещё нужен в исходном виде — сначала `b = a.copy()`.

5. **Документируют, вид или копия возвращается.** В `def get_window(arr: np.ndarray) -> np.ndarray: """Возвращает вид"""` — как в [[15. Docstring]]: явно, что можно менять и что нельзя.

# Типичные заблуждения

| Заблуждение | Как на самом деле |
|---|---|
| «Срез копирует, как в списке» | Срез `a[1:4]` — вид с общей памятью; меняет исходный |
| «`a[mask]` — вид» | Маска и список индексов — копия, не вид |
| «`view[0]=99` не трогает `a`» | Трогает — `shares_memory` покажет `True` |
| «`copy` не нужен, это медленно» | Копия медленнее, но иногда нужна — без неё испортишь данные |
| «`reshape` всегда копия» | Часто вид — `shares_memory(a, a.reshape(...))` может быть `True` |
