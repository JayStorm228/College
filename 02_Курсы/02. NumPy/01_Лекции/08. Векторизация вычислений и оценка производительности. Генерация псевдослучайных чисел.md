# 08. Векторизация вычислений и оценка производительности. Генерация псевдослучайных чисел

> [!abstract] Цель и задачи лекции
> **Цель:** обосновать принцип векторизации как отказа от циклов Python в пользу операций `ndarray` на C и ввести метрику производительности.
> **Задачи:** количественно сопоставить `for` vs `a.sum()`/`a+5` (`21×/73×` `timeit`); описать `default_rng(seed)` для воспроизводимости; проанализировать анти-паттерны (`append` в цикле — квадратично).
>
> *Пояснение для начинающих (для чайника):* векторизация — пишешь `data.sum()` вместо `for v in data: total+=v`, цикл внутри NumPy на C быстрее в **21–73 раза**; представь: цикл — идёшь пешком по каждому дому, векторизация — автобус везёт всех сразу.

# Сопоставление цикла и векторной операции: замеры

```python
import timeit, numpy as np
rng = np.random.default_rng(seed=42)
data = rng.normal(4,1,200_000)
t_loop = timeit.timeit("total=0.0\nfor v in data: total+=v", globals={"data":data}, number=1)
t_np = timeit.timeit("total=data.sum()", globals={"data":data}, number=1)
print(f"цикл {t_loop:.4f}с | numpy {t_np:.5f}с | в {t_loop/t_np:.0f} раз быстрее")

many = list(range(1_000_000))
t_list = timeit.timeit("out=[x*2 for x in data]", globals={"data":many}, number=5)
t_arr = timeit.timeit("out=data*2", globals={"data":np.arange(1_000_000)}, number=5)
print(f"список*2 {t_list/5:.3f}с | массив*2 {t_arr/5:.4f}с | в {t_list/t_arr:.0f} раз")
```

```text
цикл 0.0127с | numpy 0.00017с | в 73 раз
список*2 0.038с | массив*2 0.0018с | в 21 раз
```

Разница — **разы**, не проценты! 73× на сумме, 21× на `*2`.

Правило чайника: видишь `for v in array:` — ищи векторный вариант:

| Цикл чайника | Векторно |
|---|---|
| `for x in a: total+=x` | `a.sum()` |
| `for i: a[i]+=5` | `a+5` |
| `for x: if x>0` | `a[a>0]` |
| двойной `for` среднее | `a.mean(axis=1)` |
| `if a[i]<0: a[i]=0` | `np.where(a<0,0,a)` |

Одна строка NumPy = цикл на C.

# Генерация псевдослучайных чисел

Современный способ — `default_rng`, старый `np.random.seed` — устарел:

```python
rng = np.random.default_rng(seed=42)
print(rng.integers(1,6, size=8))  # [1 4 4 3 3 5 1 4] — 1..5, 6 не входит как range
print(np.round(rng.random(4),3))  # [0.094 0.976 0.761 0.786] [0,1)
print(np.round(rng.normal(4,1,5),2))  # [3.98 3.15 4.88 4.78 4.07]
print(rng.choice(["Аня","Борис","Вика"], size=3))  # выбор
print(rng.permutation(np.arange(1,6)))  # [2 1 4 5 3] копия
arr=np.arange(1,6); rng.shuffle(arr); print(arr)  # на месте [2 1 3 5 4]
```

| Для чайника `rng.` | Что |
|---|---|
| `integers(1,6)` | целые `[low,high)` — оценки `1..5` |
| `random` | `[0,1)` |
| `normal(4,1)` | колокол `mean=4 std=1` |
| `choice` | выбор |
| `permutation` | копия перестановки |
| `shuffle` | на месте — портит исходный! |

`seed` — воспроизводимость: один `seed` — одни числа везде. Для тестов обязательно — без него тест «иногда падает», картинка каждый раз новая.

# Прикладной пример: векторизованное формирование массива оценок

Вместо цикла с `if`:

```python
rng = np.random.default_rng(42)
grades = np.clip(np.round(rng.normal(4,1,12)),1,5).astype(int)
print(grades)  # [4 3 5 5 2 3 4 4 4 3 5 5]
print(grades.mean().round(2), (grades==5).sum(), f"{(grades>=4).mean():.0%}")
# 3.92 4 отличника 67%
```

Цепочка чайника:

1. `rng.normal(4,1,12)` — 12 чисел вокруг 4, могут 2.7 или 6.1
2. `np.round` → `5.0`
3. `np.clip(…,1,5)` → обрезает `>5→5 <1→1`
4. `.astype(int)` → целые

Одна строка читается как идея, не как тело цикла.

# Факторы снижения производительности

| Тормоз | Как | Делай |
|---|---|---|
| цикл | `for i: a[i]+=5` | `a+5` |
| `append` | `np.append(a,x)` копия | `zeros(n)` или `list→array` |
| `if` в цикле | `if a[i]>0` | `a[a>0]` |
| `astype/copy` в цикле | копия каждый раз | один раз на границе |
| повтор расчёта | `a.mean()` в цикле | вынеси до |

Замер (Python 3.11, NumPy 2.4):

```text
loop_add  19.215 мс | vector_add 0.065 мс | в 296 раз
loop_if   6.313  мс | by_mask    0.096 мс | в 66  раз
append_loop 4.044 мс| list_then  0.112 мс| в 36  раз
```

> `append` в цикле — квадратично: `1+2+…+1000` копий. 1к →2.5мс, 10к→29мс, 30к→437мс. Правильно `np.zeros(1000)` или `arange`.

> Не всегда векторизуй: десятки чисел или сложная логика — цикл понятнее. И `1М float64` =8МБ — 10 промежуточных `a+b` =80МБ, большие — чанками `np.add(a,b,out=a)`.

# Рекомендации по применению в проектах

1. **Сначала правильно, потом быстро** — и так быстрее, `timeit`/`cProfile` только потом.
2. **Фиксируй `seed`.** `rng=default_rng(42)` в `data.py` и `test_report.py` — `mean==3.92` всегда.
3. **Массивы, не списки** — `np.array(raw,dtype=float64)` один раз на границе.
4. **Память для больших** — чанками или `out=a`.
5. **Ошибку `broadcast` читай как `shape` подсказку** — `[:,None]`.

# Типичные заблуждения

| Думают | На самом деле |
|---|---|
| Просто ускоряет цикл | Цикл на C без объектов — разы, а не % |
| Векторизация `nditer` | Отказ от `for` на Python |
| `seed` и `default_rng` одно | `default_rng(seed)` современный |
| Случайные не тестируют | С `seed` — тестируют |
| `append` для 1к ок | Квадратично → секунды на 10к |
