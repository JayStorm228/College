# 04. Арифметика и broadcasting

> [!abstract] О чём лекция
> Операции в NumPy выполняются «поэлементно»: `a + b` складывает не массивы целиком,
> а каждый элемент с соответствующим. А если формы не совпадают, вступает **broadcasting** —
> правило, по которому меньший массив «растягивается» до большего.
>
> Broadcasting — самая полезная и самая путающая часть NumPy. Здесь — как он работает
> и как по форме быстро понять, что получится.

# Поэлементные операции

```python
import numpy as np

prices = np.array([199.9, 249.5, 99.9])
print("скидка 15%:", prices * 0.85)
print("округление до копеек:", np.round(prices * 0.85, 2))
print("плюс доставка 50:", prices + 50)
```

```text
скидка 15%: [169.915 212.075  84.915]
округление до копеек: [169.92 212.08  84.92]
```

Работают все обычные операторы: `+`, `-`, `*`, `/`, `//`, `%`, `**`, а также сравнения
(`>`, `<`, `==`), которые дают массив `bool`.

```python
a = np.array([1, 2, 3])
b = np.array([10, 20, 30])
print("поэлементно:", a + b)
print("сравнение:", prices > 150)
print("целочисленное деление:", np.array([7, 8, 9]) // 2)
print("остаток:", np.array([7, 8, 9]) % 2)
```

```text
поэлементно: [11 22 33]
сравнение: [ True  True False]
целочисленное деление: [3 4 4]
остаток: [1 0 1]
```

# Broadcasting: правило формы

Broadcasting сравнивает формы **справа налево** и растягивает те измерения, где размер
равен 1 (или отсутствует):

```python
matrix = np.array([[1, 2, 3], [4, 5, 6]])      # форма (2, 3)
column = np.array([[10], [20]])                # форма (2, 1)
row = np.array([100, 200, 300])                # форма (3,)

print("matrix + column:\n", matrix + column)
print("matrix + row:\n", matrix + row)
```

```text
matrix + column:
 [[11 12 13]
 [24 25 26]]
matrix + row:
 [[101 202 303]
 [104 205 306]]
```

Разберём по шагам:

| Случай | Формы | Что происходит |
|---|---|---|
| `matrix + column` | `(2, 3)` и `(2, 1)` | столбец растягивается на 3 позиции: прибавляется к каждой строке |
| `matrix + row` | `(2, 3)` и `(3,)` | строка считается формой `(1, 3)` и растягивается на 2 строки |
| `a + np.array(10)` | `(3,)` и `()` | скаляр прибавляется к каждому элементу |

Если формы несовместимы, NumPy честно падает:

```python
try:
    print(matrix + np.array([1, 2]))       # (2, 3) и (2,)
except ValueError as exc:
    print("ошибка формы:", exc)
```

```text
ошибка формы: operands could not be broadcast together with shapes (2,3) (2,)
```

Почему: справа налево сравниваются 3 и 2 — они не равны, и ни один не равен 1.
Форма `(2,)` здесь читается как `(1, 2)`, а не как `(2, 1)`.

> [!warning] Столбец и строка — разные формы
> Чтобы столбец участвовал в broadcasting как столбец, ему нужна форма `(n, 1)`.
> Одномерный массив формы `(n,)` NumPy считает **строкой**.
> Отсюда постоянная практика: `values.reshape(-1, 1)` или `values[:, None]`.

# Зачем это нужно на практике

Broadcasting избавляет от вложенных циклов и «табличных» вычислений:

| Задача | Без broadcasting | С broadcasting |
|---|---|---|
| наценка на все товары | цикл по списку | `prices * 1.15` |
| оценки со «сдвигом» по ученикам | два цикла | `table + shifts.reshape(-1, 1)` |
| нормировка по столбцам | цикл по столбцам | `table / means` (при `means` формы `(3,)`) |
| расстояние между точками | двойной цикл | `points[:, None, :] - centers[None, :, :]` |

Последняя строка — типичный «трюк» NumPy для матрицы расстояний; выглядит страшно, но
это то же правило: добавленные `None` создают новые измерения.

```python
points = np.array([[0.0, 0.0], [3.0, 4.0]])     # форма (2, 2)
centers = np.array([[0.0, 0.0]])                # форма (1, 2)
diff = points[:, None, :] - centers[None, :, :] # форма (2, 1, 2)
distance = np.sqrt((diff**2).sum(axis=-1))
print(distance)
```

```text
(2, 1, 2)
[[0.]
 [5.]]
```

Форма результата `(2, 1)` — по точке на каждое измерение-центр; иными словами, «расстояние
от каждой точки до единственного центра». Добавь второй центр — форма станет `(2, 2)`.

Нормировка по столбцам — та же идея без добавления измерений:

```python
table = np.array([[5, 4, 5], [3, 4, 3]])
means = table.mean(axis=0)
print(np.round(table - means, 3))
```

```text
[[ 1.  0.  1.]
 [-1.  0. -1.]]
```

Смысл: для каждой из двух точек (первое измерение) и каждого из одного центра
(второе измерение) посчитано расстояние.

# Как это делают в проекте

1. **Сначала смотрят на `shape`, потом на числа.** Если произведение форм «не сходится»,
   ошибка в форме, а не в формуле.
2. **Явно добавляют измерение:** `[:, None]`, `reshape(-1, 1)`, `keepdims=True`.
   Это дешевле, чем отлаживать непонятный результат.
3. **Не боятся временных массивов.** Broadcasting создаёт промежуточные данные;
   для очень больших массивов есть `np.einsum` и другие приёмы, но это уже оптимизация.
4. **Помнят про `np.round`.** Десятичные дроби в двоичном виде неточны; для денег
   результат округляют (или считают в копейках целыми числами).

# Типичные заблуждения

| Заблуждение | Как на самом деле |
|---|---|
| «`a * b` — умножение матриц» | Поэлементное умножение; матричное — `a @ b` |
| «Форма `(3,)` и `(3, 1)` — почти одно и то же» | Разные: в broadcasting ведут себя по-разному |
| «Broadcasting копирует данные» | Он не копирует массив целиком, но вычисления идут по растянутой форме |
| «Несовпадение форм — ошибка кода» | Иногда это признак неверного предположения о данных: проверь `shape` |
| «Округление не нужно, дробь и так короткая» | `0.1 + 0.2` в любом языке не равно `0.3`; для денег округляй |

# Проверь себя

1. Что значит «поэлементно»?
2. Какие формы складываются: `(3, 4)` и `(4,)`? А `(3, 4)` и `(3,)`?
3. Как превратить одномерный массив в столбец?
4. Чем `a * b` отличается от `a @ b`?
5. Почему `np.round` важен для денежных расчётов?

> [!success]- Ответы
> 1. Операция применяется к каждому элементу: результата столько же, сколько элементов.
> 2. `(3, 4)` и `(4,)` — да: строка растягивается на 3 строки. `(3, 4)` и `(3,)` — нет:
>    справа налево 4 и 3 несовместимы.
> 3. `a.reshape(-1, 1)` или `a[:, None]`.
> 4. `*` — поэлементное умножение; `@` — матричное произведение.
> 5. Двоичное представление дробей неточно: без округления в отчётах появляются
>    хвосты вроде `0.30000000000000004`.
