# 01. Зачем NumPy

> [!abstract] О чём лекция
> NumPy — библиотека для работы с **массивами чисел**. Списки в Python остаются удобными для коллекций «вообще» — разные типы, вставка, удаление — но для вычислений они медленные и неточные: каждое число — объект, каждый проход — цикл на уровне Python.
>
> Здесь — что такое массив, чем он отличается от списка, как из списка получить массив, что такое `shape`/`dtype`/`size` и почему почти вся научная работа на Python (анализ данных, машинное обучение, обработка сигналов, графики) начинается с NumPy. После лекции вы отличите задачу для списка от задачи для массива и измерите разницу во времени.

# Одна задача двумя способами

Магазин повышает цены на 10%: нужно посчитать новые цены для трёх товаров.

```python
import numpy as np

prices = [199.90, 249.50, 99.90]
print("списком:", [price * 1.1 for price in prices])
print("массивом:", np.array(prices) * 1.1)
print("тип списка:", type(prices), "| тип массива:", type(np.array(prices)))
```

```text
списком: [219.89000000000001, 274.45000000000005, 109.89]
массивом: [219.89 274.45 109.89]
тип списка: <class 'list'> | тип массива: <class 'numpy.ndarray'>
```

Две строки — два мира:

| | список Python | массив NumPy `ndarray` |
|---|---|---|
| как умножить на число | цикл или включение `[x*1.1 for x]` | `array * 1.1` — одна операция |
| что видно в выводе | `219.89000000000001` — полное значение | `219.89` — «по-человечески» |
| сколько памяти на 1 млн чисел | ~28 МБ (объекты) | ~8 МБ (непрерывный блок `float64`) |
| скорость на 1 млн | 0.031 с | 0.0035 с |
| один тип | можно смешать `1, "два", None` | один `dtype` на весь массив |

`219.89000000000001` — не «ошибка NumPy», а отсутствие маскировки: массив печатает числа, скрывая младшие разряды двойного представления, а список показывает полное значение. Внутри и там, и там двоичное представление дробей; разница в том, что массив знает, как показать число удобно.

Преимущество массива — не синтаксис, а **устройство**: он хранит числа непрерывным блоком одного типа и выполняет цикл на C.

# Насколько быстрее

Замер на учебной машине (Python 3.11, NumPy 2.4.6) — умножение миллиона чисел на 2:

```python
import timeit
import numpy as np

many = list(range(1_000_000))
as_list = timeit.timeit("out = [x * 2 for x in data]", globals={"data": many}, number=5)
as_array = timeit.timeit("out = data * 2", globals={"data": np.arange(1_000_000)}, number=5)
print(f"список: {as_list/5:.3f} с  |  массив: {as_array/5:.4f} с  |  быстрее в {as_list/as_array:.0f} раз")
```

```text
список: 0.031 с  |  массив: 0.0035 с  |  быстрее в 9 раз
```

Разница для умножения — в 9 раз. Для суммы миллиона чисел (`sum` против `np.sum`), для `np.sin` по всему массиву и для работы с таблицами разрыв ещё больше — десятки раз. Причина: NumPy выполняет цикл на языке C, а список — интерпретатором Python с проверкой типов на каждом элементе.

> [!note] Числа зависят от машины
> На вашей машине числа будут другими, но порядок — разы и десятки раз — сохранится. Важен не конкретный `0.031`, а вывод: на больших массивах разница измеряется разами, а не процентами. Для 1 000 чисел разница незаметна; для 1 000 000 — уже в 5–10 раз.

Ещё пример — сумма 200 000 случайных чисел (`normal`):

```python
import numpy as np, timeit
rng = np.random.default_rng(42)
data = rng.normal(4, 1, 200_000)
t_loop = timeit.timeit("total = 0.0\nfor v in data: total += v", globals={"data": data}, number=1)
t_np = timeit.timeit("total = data.sum()", globals={"data": data}, number=1)
print(f"цикл: {t_loop:.4f} с | numpy: {t_np:.5f} с | быстрее в {t_loop/t_np:.0f} раз")
```

```text
цикл: 0.0119 с | numpy: 0.00016 с | быстрее в 75 раз
```

Вывод тот же: **в Python цикл по массиву означает отказ от NumPy**. Если пишете `for v in array:`, скорее всего есть векторный вариант.

# Массив — это данные, форма и тип

Массив хранит два обязательных свойства: **форму** (`shape`) — размеры по измерениям, и **тип** элементов (`dtype`) — один на весь массив.

```python
import numpy as np

marks = np.array([5, 4, 5, 3])
print("вектор оценок:", marks, "| shape", marks.shape, "| dtype", marks.dtype, "| size", marks.size, "| ndim", marks.ndim)

table = np.array([[5, 4, 5], [3, 4, 3]])
print("таблица 2×3:\n", table)
print("shape", table.shape, "| ndim", table.ndim, "| size", table.size)
```

```text
вектор оценок: [5 4 5 3] | shape (4,) | dtype int64 | size 4 | ndim 1
таблица 2×3:
 [[5 4 5]
 [3 4 3]]
shape (2, 3) | ndim 2 | size 6
```

Читается так:

| Что | Значение | Пример |
|---|---|---|
| `shape = (4,)` | одно измерение, четыре элемента | вектор оценок |
| `shape = (2, 3)` | два измерения: 2 строки, 3 столбца | таблица 2×3 |
| `shape = ()` | ноль измерений — скаляр | `np.array(5)` |
| `ndim` | сколько измерений | `1`, `2`, `0` |
| `size` | сколько всего элементов | `shape` перемножить |
| `dtype` | тип всех элементов — **один на весь массив** | `int64`, `float64` |

Последнее правило — ключевое: в массиве не бывает «строка, потом число, потом `None`». Если элементы разные, NumPy приводит их к общему типу:

```python
print(np.array([1, 2.5, 3]), "→", np.array([1, 2.5, 3]).dtype)
print(np.array([1, "два"]).dtype)
print(np.array([1, 2.5, 3]).astype(int))
```

```text
[1.  2.5 3. ] → float64
<U21
[1 2 3]
```

Целое `1` стало `1.0` — иначе массив не смог бы хранить `2.5`. Эта дисциплина типов — не ограничение, а источник скорости: NumPy знает размер каждого элемента заранее и кладёт их подряд.

# Когда NumPy не нужен

| Задача | Инструмент | Почему |
|---|---|---|
| список дел на день, очередь, стек | `list`, `deque` | разные типы, вставка/удаление |
| «кто первый», пары ключ-значение | `dict` | нужен поиск по ключу |
| данные для отчёта: 20 записей | `list`/`dict` | объём мал, циклы незаметны |
| тысячи и миллионы чисел, таблицы | **NumPy** | одна операция по всем данным |
| таблица с разными типами столбцов и подписями | `pandas` (строится на NumPy) | нужны имена столбцов |

Сигнал простой: если речь про **числа, над которыми выполняют одинаковые действия** (умножить, сложить, усреднить, отфильтровать), NumPy выиграет. Если про объекты с разным смыслом — нет.

# Как это делают в проекте

В проекте массив — не «ускоренный список», а договор: данные лежат непрерывно, тип один, форма известна, и дальше всё считается без циклов.

1. **На границе — один раз в массив.** В `src/weather/data.py` список из файла или CSV превращается в `np.ndarray` один раз, дальше по коду — только массивы:

```python
# src/weather/data.py
import numpy as np
from pathlib import Path

def load_temps(path: Path) -> np.ndarray:
    """Читает температуры из файла и возвращает массив float64."""
    raw = [float(line.strip()) for line in path.read_text().splitlines() if line.strip()]
    return np.array(raw, dtype=np.float64)   # один раз, дальше — ndarray
```

2. **Форму и тип проверяют сразу.** `assert temps.shape == (30,)` и `assert temps.dtype == np.float64` — как валидация в Pydantic, только для массивов. Ошибка «не та форма» ловится на входе, а не в середине расчёта.

3. **Цикл по массиву — сигнал, что что-то не так.** В `src/weather/report.py` вместо `for v in temps: total += v` пишут `temps.sum()`, вместо `for i in range(len(temps)): temps[i] += 5` — `temps + 5`. Код короче и в 9–75 раз быстрее (см. замеры выше).

4. **Маленькие данные — списком, большие — массивом.** Для 20 значений разница не заметима; для `1_000_000` — в разы. В отчёте по классу из 30 человек любой подход сработает, в дневнике погоды за 10 лет (3 650 дней) — только массив.

5. **Память считают.** Массив `float64` из 1 млн чисел — 8 МБ непрерывной памяти; список из тех же чисел — ~28 МБ разрозненных объектов. При больших данных промежуточные массивы (`a + b`) тоже занимают память — иногда считают частями.

# Типичные заблуждения

| Заблуждение | Как на самом деле |
|---|---|
| «NumPy просто ускоряет тот же цикл» | Он выполняет цикл на C без проверок типов на каждом элементе — разница в разах, а не в процентах |
| «Массив — это список побыстрее» | Массив — непрерывный блок одного `dtype` с `shape`; список — ссылки на разные объекты |
| «`219.89` точнее, чем `219.89000000000001`» | Точность одинакова; массив просто печатает удобнее |
| «Один `dtype` — ограничение» | Это источник скорости: размер элемента известен заранее |
| «Для 20 чисел тоже нужен NumPy» | Для 20 чисел разница не заметна; NumPy — для тысяч и миллионов или таблиц |

# Проверь себя

1. Чем массив отличается от списка по устройству хранения и что такое `dtype`?
2. Почему `[price * 1.1 for price in prices]` печатает длинные числа, а массив — короткие?
3. Что такое `shape = (2, 3)` и сколько в массиве измерений?
4. Что произойдёт с `np.array([1, 2.5, 3])` и почему?
5. Когда список лучше массива — и когда массив в 9–75 раз быстрее?

> [!success]- Ответы
> 1. Массив — непрерывный блок одного `dtype`; список — ссылки на разные объекты. `dtype` — тип всех элементов, один на массив.
> 2. Массив показывает числа «по-человечески», скрывая младшие разряды; список — полное значение.
> 3. Два измерения: 2 строки, 3 столбца; `ndim = 2`, `size = 6`.
> 4. Получится `[1. 2.5 3.]` с `dtype float64`: целое приведено к вещественному, чтобы вместить `2.5`.
> 5. Список — когда разные типы, вставка/удаление, 20 записей; массив — когда тысячи чисел с одинаковым действием (сумма, умножение).
