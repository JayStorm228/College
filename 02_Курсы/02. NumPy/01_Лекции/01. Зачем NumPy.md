# 01. Зачем NumPy

> [!abstract] О чём лекция
> NumPy — библиотека для работы с **массивами чисел**. Списки в Python остаются удобными
> для коллекций «вообще», но для вычислений они медленные и неточные: каждое число — объект,
> каждый проход — цикл на уровне Python.
>
> Здесь — что такое массив, чем он отличается от списка и почему почти вся научная работа
> на Python (анализ данных, машинное обучение, обработка сигналов) начинается с NumPy.

# Одна задача двумя способами

Магазин повышает цены на 10%: нужно посчитать новые цены.

```python
import numpy as np

prices = [199.90, 249.50, 99.90]
print([price * 1.1 for price in prices])
print(np.array(prices) * 1.1)
```

```text
[219.89000000000001, 274.45000000000005, 109.89]
[219.89 274.45 109.89]
```

Две строки — два мира:

| | список | массив NumPy |
|---|---|---|
| как умножить на число | цикл или включение | `array * 1.1` |
| что видно в выводе | `219.89000000000001` | `219.89` |
| сколько памяти | объект на каждый элемент | непрерывный блок чисел |
| скорость | медленнее на больших данных | в десятки раз быстрее |

`219.89000000000001` — не ошибка NumPy, а **отсутствие ошибки отображения**: массив печатает
числа по-человечески, а список показывает полное значение. Внутри и там, и там двоичное
представление дробей; разница в том, что массив умеет это скрывать.

# Насколько быстрее

```python
import timeit

import numpy as np

many = list(range(1_000_000))
as_list = timeit.timeit("out = [x * 2 for x in data]", globals={"data": many}, number=1)
as_array = timeit.timeit("out = data * 2", globals={"data": np.arange(1_000_000)}, number=1)
```

```text
список: 0.031 с
массив: 0.0035 с
во сколько раз быстрее: 9
```

Разница для умножения — в 9 раз. Для суммы миллиона чисел, для математических функций
и для работы с многомерными таблицами разрыв ещё больше: NumPy выполняет цикл на языке C,
а не интерпретатором Python.

> [!note] Числа зависят от машины
> Замеры здесь — на учебной машине (Python 3.11, NumPy 2.4). Важен порядок: на больших
> массивах разница измеряется разами и десятками раз, а не процентами.

# Массив — это данные и форма

Массив хранит два обязательных свойства: **форму** (`shape`) и **тип** элементов (`dtype`).

```python
import numpy as np

marks = np.array([5, 4, 5, 3])
print(marks.shape, marks.dtype, marks.size)

table = np.array([[5, 4, 5], [3, 4, 3]])
print(table.shape, table.ndim, table.size)
```

```text
(4,) int64 4
(2, 3) 2 6
```

Читается так:

| Что | Значение |
|---|---|
| `shape = (4,)` | один измерение, четыре элемента |
| `shape = (2, 3)` | два измерения: 2 строки, 3 столбца |
| `ndim` | сколько измерений |
| `size` | сколько всего элементов |
| `dtype` | тип всех элементов — **один на весь массив** |

Последнее правило — ключевое: в массиве не бывает «строка, потом число, потом `None`».
Если элементы разные, NumPy приводит их к общему типу:

```python
print(np.array([1, 2.5, 3]), np.array([1, 2.5, 3]).dtype)
```

```text
[1.  2.5 3. ] float64
```

Целое `1` стало `1.0`: иначе массив не смог бы хранить `2.5`. Эта дисциплина типов —
не ограничение, а источник скорости: NumPy знает размер каждого элемента заранее.

# Когда NumPy не нужен

| Задача | Инструмент |
|---|---|
| список дел на день, очередь, стек | список Python |
| «кто первый в очереди», хранение пар ключ-значение | словарь, `deque` |
| данные для отчёта: словарь из 20 записей | список и словарь |
| тысячи и миллионы чисел, таблицы, матрицы | **NumPy** |
| таблица с разными типами столбцов и подписями | pandas (строится на NumPy) |

Сигнал простой: если речь про **числа, над которыми выполняют одинаковые действия**,
NumPy скорее всего выиграет. Если про объекты с разным смыслом — нет.

# Проверь себя

1. Чем массив отличается от списка по устройству хранения?
2. Почему `[price * 1.1 for price in prices]` печатает длинные числа, а массив — короткие?
3. Что такое `shape` и `dtype`? Почему в массиве один `dtype` на все элементы?
4. Что произойдёт с `np.array([1, 2.5, 3])`?
5. Когда список лучше массива?

> [!success]- Ответы
> 1. Массив хранит непрерывный блок чисел одного типа; список — ссылки на объекты Python.
> 2. Массив показывает числа «по-человечески», скрывая младшие разряды; список
>    показывает полное значение.
> 3. Форма — размеры по измерениям; тип — тип элементов. Общий тип нужен, чтобы каждый
>    элемент занимал одинаковое число байт и работал быстрый цикл на C.
> 4. Получится `[1. 2.5 3.]` с `dtype float64`: целое приведено к вещественному.
> 5. Когда нужны разные типы в одной коллекции, сложные объекты, вставка и удаление
>    в середину, когда важен размер коллекции, а не скорость вычислений.
