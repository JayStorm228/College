# Вектор и матрица как массив

В NumPy нет отдельного «типа-матрица» — это тот же `ndarray` с размерностью:

```python
import numpy as np

vec = np.array([1, 2, 3])          # вектор, shape (3,)
mat = np.array([[1, 2, 3],
                [4, 5, 6]])        # матрица 2×3, shape (2, 3)
print(vec.shape, mat.shape)
print(mat.ndim)  # 2 — двумерный
```

Математически: вектор — столбец $n\times 1$, матрица — таблица $m\times n$ ($m$ строк, $n$ столбцов). В коде `shape` — это те же $m$, $n$.

---

# Сложение и умножение на число — поэлементно

Математика:

$$C = A + B \iff c_{ij}=a_{ij}+b_{ij}\quad (\text{размеры равны})$$
$$C = k\cdot A \iff c_{ij}=k\cdot a_{ij}$$

```python
A = np.array([[1, 2], [3, 4]])
B = np.array([[5, 6], [7, 8]])

print(A + B)
# [[ 6  8]
#  [10 12]]

print(2 * A)
# [[2 4]
#  [6 8]]
```

В чистых списках то же — два вложенных цикла. Здесь — одна строка и работа на C.

> [!warning] Форма должна совпадать
> `A + B` требует `A.shape == B.shape`, иначе `ValueError`. Это не broadcasting-трюк, а математическое требование: складываются только одинаковые таблицы.

---

# Транспонирование — строки ↔ столбцы

$$A^T_{ij}=A_{ji},\quad (m\times n)^T = n\times m$$

```python
A = np.array([[1, 2, 3],
              [4, 5, 6]])
print(A.T)
# [[1 4]
#  [2 5]
#  [3 6]]

# проверка: shape меняется (2,3) -> (3,2)
print(A.shape, A.T.shape)
```

В списках транспонировали вложенным циклом, здесь — `A.T` (вид, без копирования — как срез в NumPy).

# Умножение матриц — скалярное произведение строк на столбцы

Математика: если $A$ — $m\times n$, $B$ — $n\times p$, то $C=A\cdot B$ — $m\times p$ и

$$c_{ij}=\sum_{k=1}^{n} a_{ik} b_{kj}$$

Условие: **число столбцов $A$ = числу строк $B$**.

```python
A = np.array([[1, 2, 3],
              [4, 5, 6]])       # 2×3
B = np.array([[7, 8],
              [9, 10],
              [11, 12]])        # 3×2

C = A @ B          # то же: np.matmul(A, B) или np.dot(A, B) для 2D
print(C)
# [[ 58  64]
#  [139 154]]
print(C.shape)  # (2, 2)

# проверка по формуле для C[0,0]: 1*7+2*9+3*11 = 7+18+33=58
```

Сравнение с чистым Python (тройной цикл, как в базовом курсе, но теперь не пишут):

```python
# чистый Python — медленно и длинно
rows_a, cols_a, cols_b = len(A), len(A[0]), len(B[0])
C_py = [[0]*cols_b for _ in range(rows_a)]
for i in range(rows_a):
    for j in range(cols_b):
        for k in range(cols_a):
            C_py[i][j] += A[i][k] * B[k][j]
# то же, но одна строка на NumPy
C_np = A @ B
```

На `1000×1000` NumPy быстрее в тысячи раз — циклы на C и векторизация.

> [!tip] `*` vs `@`
> `A * B` — поэлементно, `A @ B` — матрично. Путаница — классическая ошибка новичка.

# Определитель, обратная, решение системы

Для квадратной $n\times n$:

$$ \det A,\quad A^{-1}: A\cdot A^{-1}=I,\quad A x = b \Rightarrow x = A^{-1}b$$

```python
A = np.array([[2., 1.],
              [1., 2.]])
b = np.array([5., 4.])

det = np.linalg.det(A)          # 3.0
inv = np.linalg.inv(A)          # [[ 0.666 -0.333], [-0.333 0.666]]
x = np.linalg.solve(A, b)       # [2., 1.] — быстрее и точнее, чем inv @ b
print(det, x)

# проверка: A @ x ≈ b
print(A @ x)  # [5. 4.]

# норма вектора (длина): ||x|| = sqrt(sum x_i^2)
print(np.linalg.norm(x))  # 2.236...
```

> [!warning] Не считай обратную, если нужно решить систему
> `x = np.linalg.inv(A) @ b` — медленно и неточно. Всегда `np.linalg.solve(A,b)`.

# Где это нужно и как быстро

| Задача | Без NumPy | С NumPy | Ускорение |
|---|---|---|---|
| Сложить две `1000×1000` | двойной цикл | `A + B` | ~100× |
| Умножить `500×500` | тройной цикл | `A @ B` | ~1000× |
| Решить систему `100×100` | Гаусс руками | `solve` | ~500× + точность |

Практика из жизни:
- таблица оценок $m$ студентов × $n$ предметов: средний по строке `grades.mean(axis=1)`, по столбцу `mean(axis=0)` — уже было в [[05. Агрегаты и оси]], теперь `grades @ weights` — взвешенная оценка;
- картинки $h\times w$ как матрицы, преобразование — `A.T` и свёртки;
- линейная регрессия $X w = y$ — `np.linalg.lstsq`.

# Хорошие практики

1. **Храни матрицы как `float` для алгебры.** `int` для определителей переполняется; `A.astype(float)` перед `det`/`solve`.
2. **Проверяй `shape` до `@`.** `A.shape[1] == B.shape[0]` иначе `ValueError`.
3. **Не путай вид и копию.** `A.T` — вид, `A.copy()` — копия.
4. **Решай систему, не инвертируй.** `solve` вместо `inv`.
5. **Держи данные 2D.** Вектор `shape (n,)` и матрица `(n,1)` — разное для `@`; приводи явно `vec[:, None]` если нужен столбец.

---

# Типичные заблуждения

- ❌ **«`A * B` — умножение матриц»** — нет, поэлементно; матрично — `A @ B`.
- ❌ **«Определитель — размер»** — нет, число, свойство матрицы.
- ❌ **«Обратная всегда существует»** — только если `det != 0`.
- ❌ **«`A.T` копирует»** — нет, вид.

---

# Ключевые термины

| Термин | Определение |
|---|---|
| **Вектор** | массив `shape (n,)` |
| **Матрица** | массив `shape (m,n)` |
| **Транспонирование** | `A.T` |
| **Произведение** | `A @ B`, `np.matmul` |
| **Определитель** | `np.linalg.det` |
| **Обратная** | `np.linalg.inv` |
| **Решение системы** | `np.linalg.solve(A,b)` |
| **Норма** | `np.linalg.norm` |

# Проверь себя

1. Что делает `A + B` и когда оно возможно?
2. Чем `A * B` отличается от `A @ B`?
3. Когда существует $A^{-1}$?
4. Как решить $Ax=b$ без `inv`?
5. Что такое `A.T` и копирует ли он?

> [!example]- Ответы
> 1. Поэлементное сложение, требует `shape` одинаково.
> 2. `*` поэлементно, `@` — матрично (сумма произведений строки на столбец).
> 3. Когда `det A != 0` (матрица невырождена).
> 4. `x = np.linalg.solve(A,b)`.
> 5. Транспонирование, вид без копирования.
