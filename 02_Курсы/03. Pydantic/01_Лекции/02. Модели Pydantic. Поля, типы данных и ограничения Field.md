# 02. Модели Pydantic. Поля, типы данных и ограничения Field

> [!abstract] Цель и задачи лекции
> **Цель:** систематизировать описание полей модели `BaseModel` — типы, значения по умолчанию и ограничения `Field`.
> **Задачи:** сопоставить `str`/`int`/`list[str]`/`Literal`/`str|None`/`date`; ввести `Field` для `min_length`/`ge`/`le`; показать `default` vs `default_factory` и опасную ловушку изменяемых значений.
>
> *Пояснение для начинающих (для чайника):* поле — как строка в анкете: `age: int = Field(ge=0, le=150)` — «тут число от 0 до 150», а `tags: list[str] = Field(default_factory=list)` — «пустой список каждому, а не один на всех».
>
> ```mermaid
> flowchart LR
>   A[поле<br>аннотация] --> B{ограничение<br>Field?}
>   B -- нет --> C[тип int/str]
>   B -- да --> D[ge/le/min_length<br>default_factory]
> ```


# Поля и значения по умолчанию

```python
from datetime import date
from typing import Literal

from pydantic import BaseModel, Field, ValidationError


class Course(BaseModel):
    """Учебный курс."""

    title: str = Field(min_length=3, max_length=60)
    hours: int = Field(gt=0, le=200)
    level: Literal["базовый", "продвинутый"] = "базовый"
    tags: list[str] = Field(default_factory=list)
    started: date | None = None
    description: str | None = None
```

Разберём поля:

| Поле | Что означает | Проверки |
|---|---|---|
| `title` | название курса | длина от 3 до 60 символов |
| `hours` | часы | больше 0 и не больше 200 |
| `level` | уровень | только два допустимых значения |
| `tags` | список тегов | по умолчанию пустой список |
| `started` | дата начала | может быть `None` |
| `description` | описание | может быть `None` |

`Field` превращает тип в правило: `Field(gt=0, le=200)` — «строго больше 0 и не больше 200».
Без ограничений `int` принял бы и `-5`, и `10**9`.

> [!warning] Список по умолчанию — через `default_factory`
> В обычной функции `def f(tags=[])` и в `dataclass` изменяемое значение по умолчанию —
> ошибка: список один на всех. Pydantic от неё страхует: для нехешируемого
> значения (список, словарь) он **копирует** его каждому экземпляру, так что `tags: list[str] = []`
> здесь работает. Всё же в курсе для списков пишут `Field(default_factory=list)`: запись
> одинаково верна и в Pydantic, и в `dataclass`, и сразу видно, что список новый у каждого.
> Кроме того, `default_factory` нужен, когда значение вычисляют при создании (дату, `uuid`).

# Как это выглядит в работе

```python
course = Course(title="Инженерные практики", hours="48", tags=["python", "инженерия"])
print(course)
print("теги:", course.tags, "| уровень:", course.level, "| начали:", course.started)
```

```text
title='Инженерные практики' hours=48 level='базовый' tags=['python', 'инженерия'] started=None description=None
теги: ['python', 'инженерия'] | уровень: базовый | начали: None
```

`"48"` стало числом 48, теги сохранились, `level` получил значение по умолчанию,
необязательные поля стали `None`.

# Ошибки: все и с адресом

```python
try:
    Course(title="Пи", hours=0)
except ValidationError as exc:
    for error in exc.errors():
        print(error["loc"][0], "→", error["msg"])
```

```text
title → String should have at least 3 characters
hours → Input should be greater than 0
```

Обе ошибки пришли вместе — можно показать пользователю сразу, что не так, а не заставлять
исправлять по одной.

# Даты и другие «умные» типы

```python
course2 = Course(title="NumPy", hours=40, level="продвинутый", started="2026-09-01")
print(course2.started, type(course2.started).__name__)
```

```text
2026-09-01 date
```

Строка `"2026-09-01"` распознана как `datetime.date`. Так же работают `datetime`,
`timedelta`, `UUID`, `Decimal`, `Path` и другие типы из стандартной библиотеки:
Pydantic знает их форматы и приводит строки к объектам.

# `Literal`: только разрешённые значения

```python
try:
    Course(title="Matplotlib", hours=30, level="экспертный")
except ValidationError as exc:
    print(exc.errors()[0]["msg"])
```

```text
Input should be 'базовый' or 'продвинутый'
```

`Literal["базовый", "продвинутый"]` — способ запретить опечатки в перечислениях. Альтернатива
через `str` пропускает любое значение, а через перечисление (`enum.Enum`) удобна, когда
значения нужны ещё и в коде как константы.

# Необязательные поля: тонкость

`str | None` означает «значение может быть `None`», но **поле всё равно обязательно
при создании**, если у него нет значения по умолчанию:

```python
class Note(BaseModel):
    """Заметка: текст обязателен, подпись может отсутствовать явно."""

    text: str
    author: str | None            # обязательна, но может быть None
    comment: str | None = None    # можно вообще не передавать


print(Note(text="Проверить", author=None))
```

```text
text='Проверить' author=None comment=None
```

`Note(text="Проверить")` без `author` даст ошибку «Field required», а без `comment` — нет.
Если поле может отсутствовать, всегда пишут `field = None` (или другое значение по умолчанию).

# Как это делают в проекте

В проекте поля описывают так, чтобы модель сама была документацией и договором.

**1. Ограничение появляется только из требования.** Нет правила «часы от 1 до 200» —
не пиши `Field(le=200)`. Лишние проверки мешают, а правильные — защищают:

```python
# src/catalog/models.py
from pydantic import BaseModel, Field
from typing import Literal

class Course(BaseModel):
    """Курс каталога — договор между фронтом и бэкендом."""
    title: str = Field(min_length=3, max_length=60, description="Название на карточке")
    hours: int = Field(gt=0, le=200, description="Акад. часы")
    level: Literal["базовый", "продвинутый"] = "базовый"
    tags: list[str] = Field(default_factory=list, description="Для поиска")
    started: date | None = None

# по модели строится JSON-схема для фронта:
# print(Course.model_json_schema()["properties"]["title"]["description"])
```

`description` попадает в схему JSON и в подсказки редактора — это живая документация,
которую не нужно поддерживать отдельно.

**2. Значения по умолчанию — только для действительно необязательных данных.** Иначе
отсутствие данных маскируется:

```python
# плохо: пропустили hours — модель молча поставила 10
class CourseBad(BaseModel):
    hours: int = 10  # опасное умолчание

# хорошо: отсутствие hours — ошибка, её сразу видно
class CourseGood(BaseModel):
    hours: int = Field(gt=0)  # без default — Field required
```

**3. `list[str]` с фабрикой — привычка против общей памяти.** Ловушка из
[[11. Кортежи, списки, словари]] про изменяемые значения по умолчанию в функциях:

```python
# ловушка курса Python: def add_tag(tags=[]): tags.append(...)  → один список на все вызовы
# Pydantic: tags: list[str] = []  → копируется каждому экземпляру, безопасно
# dataclass: tags: list[str] = []  → ValueError при определении класса
# везде верно: Field(default_factory=list) → новый список каждому
```

**4. Даты хранят как `date`, а не как строку.** Хранить `"2026-09-01"` строкой и
«разобрать потом» — источник ошибок формата (`"01.09.26"` vs `"2026-09-01"`). С `date`
ошибка появляется сразу при валидации, а не через месяц при сортировке.

```python
# в модели — date, в файле — строка, в коде — объект
course = Course(title="Pydantic", hours=20, started="2026-10-01")
course.started.year  # 2026 — уже int, а не парсинг строки
```

# Подробный разбор: поле как система правил

## 1. Все параметры `Field` — шпаргалка

`Field` — не только `gt/le`, но и документация, примеры и метаданные для схемы:

```python
from pydantic import BaseModel, Field
from typing import Annotated

class Course(BaseModel):
    title: str = Field(
        min_length=3, max_length=60,
        pattern=r"^[A-Za-zА-Яа-я0-9 ]+$",   # только буквы/цифры/пробел
        description="Название на карточке каталога",
        examples=["Инженерные практики"],
        title="Заголовок",
    )
    hours: int = Field(
        gt=0, le=200, multiple_of=2,  # чётное
        strict=True,                  # без приведения "48"→48
        description="Академические часы",
    )
    price: float = Field(ge=0, le=1_000_000, json_schema_extra={"currency": "RUB"})
```

| Параметр | Для чего | Пример |
|---|---|---|
| `gt/ge/lt/le` | диапазон числа | `ge=0, le=200` |
| `multiple_of` | кратность | `multiple_of=2` |
| `min_length/max_length` | длина строки/списка | `min_length=3` |
| `pattern` | регулярка | `pattern=r"^\w+@\w+\.\w+$"` |
| `strict` | запрет приведения | `strict=True` → `"48"` ошибка |
| `description/title/examples` | документация + JSON Schema | `description="…"` |
| `deprecated` | пометка поля | `deprecated="use new_title"` |
| `json_schema_extra` | доп. ключи в схему | `{"currency":"RUB"}` |

> `Annotated[int, Field(gt=0)]` — альтернативная запись, где тип и метаданные разделены. Удобна, когда описание переиспользуется: `PositiveInt = Annotated[int, Field(gt=0)]`.

## 2. `default` vs `default_factory` — глубже, чем кажется

```python
from pydantic import BaseModel, Field
import uuid
from datetime import date

class Bad(BaseModel):
    tags: list[str] = []              # в Pydantic скопируется — работает, но в dataclass — ошибка
    uid: str = str(uuid.uuid4())      # вычислилось ОДИН раз при импорте — у всех один uid!

class Good(BaseModel):
    tags: list[str] = Field(default_factory=list)          # новый список каждому
    uid: str = Field(default_factory=lambda: str(uuid.uuid4()))  # новый uuid каждому
    today: date = Field(default_factory=date.today)        # сегодняшняя дата на момент создания

a, b = Good(), Good()
print(a.tags is b.tags, a.uid == b.uid)  # False False — разные объекты
print(Bad().uid == Bad().uid)             # True — один на всех!
```

Правило: **вычисляемое — только через `default_factory`**. Это касается `uuid`, `date.today`, `list`, `dict`. Иначе значение «застывает» при определении класса.

Ещё нюанс: `Field(default_factory=list)` можно комбинировать с ограничениями:

```python
class Course(BaseModel):
    tags: list[str] = Field(default_factory=list, min_length=0, max_length=10)
```

## 3. Весь зоопарк типов — что Pydantic приводит автоматически

| Категория | Типы | Приведение | Примечание |
|---|---|---|---|
| Примитивы | `str/int/float/bool/bytes` | `"1"→1`, `1→"1"` | `bool`: `true/1/yes/on` → `True` |
| Текст | `Literal["a","b"]` | — | только точные значения |
| Время | `date/datetime/time/timedelta` | `"2026-09-01"→date` | ISO 8601, `2026-09-01T10:00:00` |
| Сети | `AnyUrl/HttpUrl/EmailStr` | строка → url | нужен `email-validator` для EmailStr |
| Файлы | `Path/FilePath/DirectoryPath` | строка → Path | не проверяет существование без доп. |
| UUID | `UUID` | строка → UUID | |
| Деньги | `Decimal` | строка → Decimal | без потери точности |
| Контейнеры | `list[int]/set[str]/dict[str,int]/tuple[int,int]` | `("1","2")→[1,2]` | вложенные тоже приводятся |
| Объединения | `int|str`, `str|None` | пробует по порядку | `str|None` — `None` допустим |
| Перечисления | `enum.Enum` | строка → enum | |

```python
from uuid import UUID
from pathlib import Path
from decimal import Decimal
from enum import Enum

class Level(str, Enum):
    basic = "базовый"
    pro = "продвинутый"

class Demo(BaseModel):
    uid: UUID
    price: Decimal
    level: Level
    config: Path

d = Demo(uid="123e4567-e89b-12d3-a456-426614174000", price="99.90", level="базовый", config="/tmp/app")
print(type(d.uid).__name__, type(d.price).__name__, d.level, d.config)
```

## 4. `Optional` и «обязательно vs может быть None» — исчерпывающе

```python
from pydantic import BaseModel, ValidationError

class Example(BaseModel):
    a: str              # обязательно, не None
    b: str | None       # обязательно, но можно None (!)
    c: str | None = None  # необязательно, по умолчанию None
    d: str = "x"        # необязательно, по умолчанию "x"

# проверка
for kwargs in [{}, {"a": "hi"}, {"a":"hi","b":None}, {"a":"hi","b":"x","c":None}]:
    try: print(kwargs, "→", Example(**kwargs))
    except ValidationError as e: print(kwargs, "→", e.errors()[0]["type"], e.errors()[0]["loc"])
```

Вывод: `b: str|None` без `= None` всё равно **требует ключа** `b` в данных. Забыли — `missing`. Хочешь «можно не передавать» — ставь `= None`.

## 5. Конфигурация модели — `model_config`

```python
from pydantic import BaseModel, ConfigDict

class CourseStrict(BaseModel):
    model_config = ConfigDict(
        extra="forbid",        # лишние поля — ошибка, а не игнор
        str_strip_whitespace=True,  # "  Аня " → "Аня" автоматически
        str_to_lower=False,
        frozen=True,           # неизменяемая модель
        strict=True,           # глобально строгий режим
    )
    title: str
    hours: int

try: CourseStrict(title="NumPy", hours=40, extra="oops")
except ValidationError as e: print(e.errors()[0]["type"])  # extra_forbidden
```

| `ConfigDict` | Что делает |
|---|---|
| `extra="forbid"/"allow"/"ignore"` | лишние ключи — ошибка/сохранить/отбросить |
| `str_strip_whitespace` | авто-trim строк |
| `frozen=True` | `model_copy` вместо мутации |
| `strict=True` | запрещает приведение типов |

В курсе по умолчанию `extra="ignore"` — лишние поля тихо отбрасываются. Для API лучше `forbid`, чтобы опечатка `titlle` не терялась молча.

# Типичные заблуждения

| Заблуждение | Как на самом деле |
|---|---|
| «`str \| None` значит, что поле необязательно» | Обязательно, но допускает `None`; необязательность даёт `= None` |
| «`tags: list[str] = []` — общий список, как в функции» | В Pydantic значение копируется, и это безопасно; но `default_factory=list` верен везде, в том числе в `dataclass`, где `= []` запрещено |
| «Pydantic только проверяет» | Ещё и приводит типы: `"48"` → `48` |
| «Ограничения нужны везде» | Лишние проверки мешают; правила должны следовать из требований |
| «`Literal` и `str` — почти одно и то же» | `Literal` не пропустит опечатку, `str` пропустит что угодно |

# Проверь себя

1. Что делает `Field(gt=0, le=200)`?
2. Почему для списка тегов в курсе пишут `default_factory=list`, а не `= []`, хотя Pydantic копирует значение по умолчанию?
3. В чём разница между `author: str | None` и `comment: str | None = None`?
4. Что произойдёт со строкой `"2026-09-01"` в поле типа `date`?
5. Зачем нужен `Literal`, если можно написать `str`?

> [!success]- Ответы
> 1. Ограничивает число: строго больше 0 и не больше 200.
> 2. `default_factory=list` создаёт новый список каждому экземпляру и одинаково верен в
>    Pydantic и в `dataclass`; запись `= []` в Pydantic тоже сработает (значение копируется),
>    но в `dataclass` она запрещена, а в функции даёт общий список.
> 3. Первое поле обязательно (можно передать `None`), второе можно не передавать вовсе.
> 4. Будет распознана как `datetime.date(2026, 9, 1)`.
> 5. `Literal` допускает только перечисленные значения и ловит опечатки при валидации.
