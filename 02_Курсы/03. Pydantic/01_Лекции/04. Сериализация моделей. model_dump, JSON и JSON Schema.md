# 04. Сериализация моделей. model_dump, JSON и JSON Schema

> [!abstract] Цель и задачи лекции
> **Цель:** раскрыть механизмы сериализации моделей — преобразование `BaseModel` ↔ словарь / JSON и описание схемы.
> **Задачи:** сопоставить `model_dump`/`model_dump_json`/`model_validate`/`model_validate_json`; ввести `mode='json'` и `exclude_none`; показать `model_json_schema` как контракт для внешнего потребителя.
>
> *Пояснение для начинающих (для чайника):* модель — объект в памяти, `model_dump` — в словарь для кода, `model_dump_json` — в строку для файла/сети, а обратно `model_validate_json` — снова модель.
>
> ```mermaid
> flowchart LR
>   A[модель<br>Student] --> B[model_dump<br>dict]
>   B --> C[model_dump_json<br>JSON]
>   C --> D[model_validate_json<br>модель]
> ```


# Модель наружу: `model_dump` и `model_dump_json`

```python
import json
from datetime import date

from pydantic import BaseModel, Field


class Student(BaseModel):
    """Студент."""

    name: str
    average: float = Field(ge=1, le=5)
    enrolled: date
    comment: str | None = None


student = Student(name="Аня", average=4.5, enrolled="2026-09-01")
print("словарь:", student.model_dump())
print("без пустых полей:", student.model_dump(exclude_none=True))
print("JSON:", student.model_dump_json())
print("JSON без пустых:", student.model_dump_json(exclude_none=True))
```

```text
словарь: {'name': 'Аня', 'average': 4.5, 'enrolled': datetime.date(2026, 9, 1), 'comment': None}
без пустых полей: {'name': 'Аня', 'average': 4.5, 'enrolled': datetime.date(2026, 9, 1)}
JSON: {"name":"Аня","average":4.5,"enrolled":"2026-09-01","comment":null}
JSON без пустых: {"name":"Аня","average":4.5,"enrolled":"2026-09-01"}
```

Разница, которую важно заметить: в словаре дата осталась объектом `datetime.date`,
а в JSON она стала строкой `"2026-09-01"`. `model_dump_json` знает, что даты, `UUID`,
`Decimal` и другие типы не входят в стандарт JSON, и приводит их к строкам.

`exclude_none=True` убирает поля со значением `None` — удобно, когда пустые поля не нужно
передавать наружу. Есть и `exclude_unset=True` — убирает то, что не задавали явно.

# Данные внутрь: `model_validate` и `model_validate_json`

```python
text = '{"name": "Борис", "average": 3.8, "enrolled": "2026-09-02"}'
boris = Student.model_validate_json(text)
print("из JSON:", boris.name, boris.enrolled)
```

```text
из JSON: Борис 2026-09-02
```

| Задача | Метод |
|---|---|
| из словаря | `Student(**data)` или `Student.model_validate(data)` |
| из JSON-строки | `Student.model_validate_json(text)` |
| в словарь | `student.model_dump()` |
| в JSON-строку | `student.model_dump_json()` |

`model_validate_json` — не просто «`json.loads` плюс модель»: он читает и проверяет данные
сразу, без промежуточного словаря, и ошибки в JSON тоже оформляются как `ValidationError`.

> [!note] `model_validate` vs конструктор
> `Student(**data)` и `Student.model_validate(data)` делают одно и то же. Второй вариант
> удобен, когда данные — уже словарь переменной `data`, а не набор отдельных аргументов.

# Ошибки при чтении JSON

```python
from pydantic import ValidationError

broken = '{"name": "Вика", "average": 6, "enrolled": "2026-09-03"}'
try:
    Student.model_validate_json(broken)
except ValidationError as exc:
    print("ошибок:", exc.error_count(), "|", exc.errors()[0]["msg"])
```

```text
ошибок: 1 | Input should be less than or equal to 5
```

Правило `average ≤ 5` задано в модели, поэтому проверка работает одинаково для данных
из словаря, из JSON и из аргументов конструктора. А вот сломанный JSON даёт другой тип:

```python
try:
    Student.model_validate_json('{"name": "Аня" "average": 4}')
except ValidationError as exc:
    print(exc.errors()[0]["type"])  # json_invalid
```

```text
json_invalid
```

Отсюда правило: «ошибка данных» (`Input should be...`) и «ошибка разбора» (`json_invalid`)
лечатся по-разному — первую чинят правкой значения, вторую — починкой файла.

# Схема JSON

```python
print("схема (кратко):", list(Student.model_json_schema()["properties"]))
print("обязательные:", Student.model_json_schema()["required"])
```

```text
схема (кратко): ['name', 'average', 'enrolled', 'comment']
обязательные: ['name', 'average', 'enrolled']
```

`model_json_schema()` возвращает словарь-описание: какие поля есть, какие обязательны,
какие у них типы и ограничения. Эта схема:

- помогает договориться о формате данных с другой командой;
- используется FastAPI для документации API;
- может проверяться другими инструментами (генерация клиентов, форм, таблиц).

Пример схемы для курса в проекте — её можно сохранить в `schema.json` и отдать фронту:

```json
{
  "properties": {
    "title": {"type": "string", "minLength": 3},
    "hours": {"type": "integer", "exclusiveMinimum": 0, "maximum": 200}
  },
  "required": ["title", "hours"]
}
```

# Копия с изменением: `model_copy`

```python
as_dict = student.model_dump()
as_dict["average"] = 5
upgraded = Student(**as_dict)
print("после копирования:", upgraded.average, "| исходный:", student.average)
```

```text
после копирования: 5.0 | исходный: 4.5
```

Модели, как и обычные объекты, изменяемы по умолчанию — но безопаснее не менять объект
на месте, а сделать новый. Есть и короткая форма: `student.model_copy(update={"average": 5})`.

> [!warning] `model_copy` не проверяет данные
>
> ```python
> student = Student(name="Аня", average=4.5, enrolled="2026-09-01")
> bad = student.model_copy(update={"average": 99})
> print(bad.average)
> ```
>
> ```text
> 99
> ```
>
> Правило `average ≤ 5` обойдено — модель теперь содержит невозможное значение. Если нужна
> проверка, собирай модель заново: `Student.model_validate({**student.model_dump(), "average": 99})` —
> такой вызов поднимет `ValidationError`.

> [!note] Про `frozen` и неизменяемость
> Можно объявить `model_config = ConfigDict(frozen=True)` — тогда модель нельзя менять
> после создания, а `model_copy` остаётся способом получить изменённую версию. Это удобно
> для данных, которые считаются «фактом»: их не должно быть можно переписать случайно.

# Как это делают в проекте

Сериализация — граница, и на границе есть три привычки, которые экономят часы.

**1. Внутри — модели, наружу — JSON.** Код сервиса не работает со словарями:

```python
# src/catalog/service.py
import json
from pathlib import Path
from models import Student

def save_roster(path: Path, students: list[Student]) -> None:
    """Пишет список студентов в файл — одним вызовом."""
    payload = [s.model_dump(mode="json") for s in students]
    path.write_text(json.dumps(payload, ensure_ascii=False, indent=2), encoding="utf-8")

def load_roster(path: Path) -> list[Student]:
    """Читает файл и сразу проверяет."""
    text = path.read_text(encoding="utf-8")
    raw_list = json.loads(text)          # список словарей
    return [Student.model_validate(row) for row in raw_list]
```

Заметь: для записи использован `model_dump(mode="json")` — он сразу даёт строки вместо
`date`. Без `mode="json"` пришлось бы писать `json.dump(..., default=str)`, и даты
расползлись бы в разные форматы.

Анти-паттерн:

```python
# плохо: дата остаётся объектом, json.dump падает
json.dump([s.model_dump() for s in students], open("out.json","w"))
# TypeError: Object of type date is not JSON serializable
```

**2. Читают строку — сразу валидируют.** Не два шага (`json.loads` + `Student(**data)`),
а один `model_validate_json`, чтобы ошибка разбора и ошибка данных были в одном месте:

```python
# хорошо: одна точка входа, одна обработка ошибок
try:
    student = Student.model_validate_json(raw_text)
except ValidationError as exc:
    if exc.errors()[0]["type"] == "json_invalid":
        print("файл испорчен — не JSON")
    else:
        print("данные не подходят:", exc.errors()[0]["msg"])
```

**3. Схема — договор с другой командой.** В проекте мини-валидатора фронту и тестам
отдают не пример запроса, а `schema.json`:

```bash
python -c "from applications.models import Application; import json; print(json.dumps(Application.model_json_schema(), ensure_ascii=False, indent=2))" > docs/schema.json
```

Если в модели поменялось поле, схема меняется сама — и несовместимость замечают до деплоя,
а не после.

# Подробный разбор: сериализация от и до

## 1. Два режима `model_dump` — таблица преобразований

```python
from datetime import date, datetime
from decimal import Decimal
from uuid import UUID
from pathlib import Path
from pydantic import BaseModel

class Doc(BaseModel):
    title: str
    created: date
    price: Decimal
    uid: UUID
    path: Path

doc = Doc(title="Отчёт", created="2026-09-01", price="99.90", uid="123e4567-e89b-12d3-a456-426614174000", path="/tmp/x")

print("python:", doc.model_dump())
print("json  :", doc.model_dump(mode="json"))
print("json str:", doc.model_dump_json())
```

```text
python: {'title': 'Отчёт', 'created': datetime.date(2026, 9, 1), 'price': Decimal('99.90'), 'uid': UUID('...'), 'path': PosixPath('/tmp/x')}
json  : {'title': 'Отчёт', 'created': '2026-09-01', 'price': '99.90', 'uid': '123e4567-e89b-12d3-a456-426614174000', 'path': '/tmp/x'}
json str: {"title":"Отчёт","created":"2026-09-01","price":"99.90","uid":"123e4567-e89b-12d3-a456-426614174000","path":"/tmp/x"}
```

| Тип | `mode="python"` (default) | `mode="json"` |
|---|---|---|
| `date/datetime` | `date` объект | `"2026-09-01"` |
| `Decimal` | `Decimal("99.90")` | `"99.90"` (строка!) |
| `UUID` | `UUID` | `"123e..."` |
| `Path` | `PosixPath` | `"/tmp/x"` |
| `bytes` | `b"hi"` | `"aGk="` (base64, зависит) |

Правило: **внутрь программы — `python`, наружу (файл/сеть) — `json`**.

## 2. Что исключать — `exclude_*` подробно

```python
from pydantic import BaseModel

class Student(BaseModel):
    name: str
    average: float
    comment: str | None = None
    extra: str | None = None

s = Student(name="Аня", average=4.5, comment=None)  # extra не передавали

print(s.model_dump())                          # всё
print(s.model_dump(exclude_none=True))         # без None
print(s.model_dump(exclude_unset=True))        # без того, что не задавали (extra исчезнет, comment останется — его явно передали как None?)
print(s.model_dump(exclude_defaults=True))     # без значений по умолчанию
print(s.model_dump(exclude={"comment"}))       # без поля comment
print(s.model_dump(by_alias=True))             # с alias если есть
```

| Параметр | Что убирает | Когда нужен |
|---|---|---|
| `exclude_none=True` | поля `None` | API — не слать пустые |
| `exclude_unset=True` | то, что не передавали при создании | PATCH-запрос — только изменённое |
| `exclude_defaults=True` | то, что равно дефолту | экономия трафика |
| `exclude={"field"}` | конкретное поле | скрыть `password` |
| `by_alias=True` | использовать alias вместо имени | `Field(alias="camelCase")` |

> Валидаторы `exclude_*` работают и при сериализации вложенных моделей рекурсивно.

## 3. Alias — когда внешнее имя не совпадает с внутренним

API часто отдаёт `camelCase`, а в Python — `snake_case`:

```python
from pydantic import BaseModel, Field, ConfigDict

class UserIn(BaseModel):
    model_config = ConfigDict(populate_by_name=True)  # можно и так и так
    full_name: str = Field(alias="fullName")
    age: int

print(UserIn.model_validate({"fullName": "Аня", "age": 20}))
# full_name='Аня' age=20 — приняло alias
print(UserIn(full_name="Аня", age=20).model_dump(by_alias=True))
# {'fullName': 'Аня', 'age': 20} — отдало alias
```

Без `populate_by_name=True` конструктор принял бы только `fullName`, а `full_name` — нет. С ним — оба.

## 4. JSON Schema глубоко

```python
from pydantic import BaseModel, Field
from typing import Literal
import json

class Course(BaseModel):
    title: str = Field(min_length=3, description="Название")
    hours: int = Field(gt=0, le=200)
    level: Literal["базовый","продвинутый"] = "базовый"

print(json.dumps(Course.model_json_schema(), ensure_ascii=False, indent=2))
```

```json
{
  "properties": {
    "title": {"title": "Title", "description": "Название", "type": "string", "minLength": 3},
    "hours": {"title": "Hours", "type": "integer", "exclusiveMinimum": 0, "maximum": 200},
    "level": {"default": "базовый", "enum": ["базовый","продвинутый"], "title": "Level", "type": "string"}
  },
  "required": ["title","hours"],
  "title": "Course",
  "type": "object"
}
```

- `required` — поля без дефолта;
- `description/title/examples` из `Field` попадают сюда;
- `Literal` → `enum`.

Схема — договор: по ней генерят формы, клиентов, доку FastAPI. Сохраняют в `schema.json` и версионируют.

```bash
python -c "import json, models; print(json.dumps(models.Course.model_json_schema(), ensure_ascii=False, indent=2))" > docs/schema.json
```

## 5. Вложенные модели и сериализация

```python
from pydantic import BaseModel

class Author(BaseModel): name: str

class Book(BaseModel):
    title: str
    author: Author
    tags: list[str] = []

b = Book(title="Python", author={"name": "Аня"}, tags=["py"])
print(b.model_dump())              # {'title': 'Python', 'author': {'name': 'Аня'}, ...}
print(b.model_dump_json())         # вложенность сохранилась
```

Вложенность сериализуется рекурсивно, с теми же `exclude_*`.

## 6. `model_copy` vs пересоздание — когда что

| Задача | Что использовать | Проверка? |
|---|---|---|
| Изменить поле внутри доверенной зоны | `s.model_copy(update={"average":5})` | нет |
| Данные пришли извне | `Student.model_validate({**s.model_dump(), "average": raw})` | да |
| Нужна неизменяемость | `model_config=ConfigDict(frozen=True)` + `model_copy` | — |

```python
from pydantic import BaseModel, Field, ValidationError, ConfigDict

class Student(BaseModel):
    model_config = ConfigDict(frozen=True)
    name: str
    average: float = Field(ge=1, le=5)

s = Student(name="Аня", average=4.5)
# s.average = 5  # ошибка: frozen
s2 = s.model_copy(update={"average": 5})
print(s2.average)

try: Student.model_validate({**s.model_dump(), "average": 99})
except ValidationError as e: print("поймали:", e.errors()[0]["msg"])
```

# Типичные заблуждения

| Заблуждение | Как на самом деле |
|---|---|
| «`model_dump()` даёт JSON-совместимый словарь» | Даты и другие типы остаются объектами; для чистого JSON — `mode="json"` |
| «`model_validate_json` — это `json.loads`» | Это валидация с разбором: ошибки приходят структурно |
| «Схема JSON нужна только для документации» | По ней генерируют код и формы, она — контракт обмена |
| «Модель безопасно менять на месте» | Иногда да, но случайная правка «факта» — источник багов; лучше копия |
| «Ошибки JSON нужно ловить как `json.JSONDecodeError`» | Pydantic сообщает о них как `ValidationError` |
