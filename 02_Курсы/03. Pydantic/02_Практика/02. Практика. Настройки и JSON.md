# 02. Практика. Настройки и JSON

> [!abstract] О чём эта практика
> Три задачи по лекциям [[04. Сериализация и JSON]] и [[05. Настройки приложения]]:
> вывод модели в словарь и JSON, чтение и запись данных в файл, настройки приложения
> из окружения и `.env`.

> [!important] Как работать с задачей
> 1. Сначала своя попытка, разбор — потом.
> 2. Сравнивай **типы**: где дата, где строка, где словарь.
> 3. Проверяй ошибки: у данных и у формата JSON они разные.
> 4. После каждого запуска смотри, какие файлы появились в папке.

## Задача 1. Словарь и JSON

★☆☆ · `model_dump`, `model_dump_json`, `exclude_none`, `mode="json"`

**Условие.** Есть модель студента: `name`, `average` (от 1 до 5), `enrolled` (дата),
`comment` (может отсутствовать). Нужно вывести её в разных видах.

**Задание.** Для студента `Student(name="Аня", average=4.5, enrolled="2026-09-01")`:

1) получи словарь функцией `model_dump()`; 2) то же без пустых полей; 3) JSON-строку
функцией `model_dump_json()`; 4) JSON без пустых полей; 5) «JSON-совместимый словарь»
через `model_dump(mode="json")`. Объясни, чем пункт 5 отличается от пункта 1.

> [!example]- Разбор
> **Идея.** `model_dump` и `model_dump_json` — два взгляда на модель: первый для кода внутри
> программы (даты остаются датами), второй для передачи наружу (всё превращается в типы
> JSON). `exclude_none=True` убирает пустые поля, `mode="json"` делает словарь пригодным
> для `json.dump`.
>
> **Код.**
>
> ```python
> from datetime import date
>
> from pydantic import BaseModel, Field
>
>
> class Student(BaseModel):
>     """Студент: имя, средний балл, дата зачисления, комментарий."""
>
>     name: str
>     average: float = Field(ge=1, le=5)
>     enrolled: date
>     comment: str | None = None
>
>
> student = Student(name="Аня", average=4.5, enrolled="2026-09-01")
> print("словарь:", student.model_dump())
> print("только заполненные:", student.model_dump(exclude_none=True))
> print("JSON:", student.model_dump_json())
> print("JSON без пустых:", student.model_dump_json(exclude_none=True))
> print("JSON-совместимый словарь:", student.model_dump(mode="json"))
> ```
>
> **Вывод:**
>
> ```text
> словарь: {'name': 'Аня', 'average': 4.5, 'enrolled': datetime.date(2026, 9, 1), 'comment': None}
> только заполненные: {'name': 'Аня', 'average': 4.5, 'enrolled': datetime.date(2026, 9, 1)}
> JSON: {"name":"Аня","average":4.5,"enrolled":"2026-09-01","comment":null}
> JSON без пустых: {"name":"Аня","average":4.5,"enrolled":"2026-09-01"}
> JSON-совместимый словарь: {'name': 'Аня', 'average': 4.5, 'enrolled': '2026-09-01', 'comment': None}
> ```
>
> **Что здесь важно.** В обычном словаре дата — объект `datetime.date`, а в JSON и в
> `mode="json"` — строка `"2026-09-01"`. Значит, `model_dump()` без `mode="json"` нельзя
> отдавать в `json.dump`: он не знает, как записать дату.
>
> **Типичная ошибка.** Передать `model_dump()` в `json.dump` и получить
> `TypeError: Object of type date is not JSON serializable`. Лечится `mode="json"`
> или использованием `model_dump_json()`.
>
> **Граница.** `exclude_none=True` убирает только `None`: пустая строка `""` и нулевое число
> останутся. Если нужно убрать «пустоту» в другом смысле, пишут свой код.

## Задача 2. Данные из файла

★★☆ · `model_validate_json`, схема, ошибки разбора JSON

**Условие.** Данные приходят JSON-строкой: `'{"name": "Борис", "average": 3.8}'`.
Иногда строка сломана — например, содержит лишний текст.

**Задание.** 1) Прочитай студента из JSON-строки через `model_validate_json`.
2) Попробуй прочитать `'{"name": "Вика", "average": 6}'` и выведи сообщение об ошибке.
3) Попробуй прочитать строку с «мусором» в конце и определи **тип** ошибки
(`exc.errors()[0]["type"]`). 4) Выведи список полей и обязательные поля из
`model_json_schema()`. 5) Сохрани студента в файл `students.json` как список словарей
с `ensure_ascii=False` и `indent=2`.

> [!example]- Разбор
> **Идея.** `model_validate_json` сразу разбирает строку и проверяет данные; ошибка формата
> JSON и ошибка проверки — разные типы ошибок. Схема JSON показывает контракт: какие поля
> есть и какие обязательны.
>
> **Код.**
>
> ```python
> import json
>
> from pydantic import BaseModel, Field, ValidationError
>
>
> class Student(BaseModel):
>     """Студент."""
>
>     name: str
>     average: float = Field(ge=1, le=5)
>     comment: str | None = None
>
>
> text = '{"name": "Борис", "average": 3.8}'
> boris = Student.model_validate_json(text)
> print("из JSON:", boris)
>
> broken_json = '{"name": "Вика", "average": 6}'
> try:
>     Student.model_validate_json(broken_json)
> except ValidationError as exc:
>     print("ошибка данных:", exc.errors()[0]["msg"])
>
> not_json = '{"name": "Вика", "average": 4}'
> try:
>     Student.model_validate_json(not_json + "лишнее")
> except ValidationError as exc:
>     print("ошибка разбора:", exc.errors()[0]["type"])
>
> print("схема:", list(Student.model_json_schema()["properties"]))
> print("обязательные:", Student.model_json_schema()["required"])
>
> with open("students.json", "w", encoding="utf-8") as file:
>     json.dump([boris.model_dump(mode="json")], file, ensure_ascii=False, indent=2)
> ```
>
> **Вывод:**
>
> ```text
> из JSON: name='Борис' average=3.8 comment=None
> ошибка данных: Input should be less than or equal to 5
> ошибка разбора: json_invalid
> схема: ['name', 'average', 'comment']
> обязательные: ['name', 'average']
> ```
>
> Файл `students.json`:
>
> ```json
> [
>   {
>     "name": "Борис",
>     "average": 3.8,
>     "comment": null
>   }
> ]
> ```
>
> **Что здесь важно.** «Ошибка данных» (`Input should be less than or equal to 5`) и «ошибка
> разбора» (`json_invalid`) лечатся по-разному: первая — поправить значение, вторая —
> починить или спасти файл. `comment` есть в схеме, но не в списке обязательных: у него есть
> значение по умолчанию.
>
> **Типичная ошибка.** Сначала вызывать `json.loads`, потом `model_validate` — тогда ошибки
> разбора и ошибки данных смешиваются, и приходится обрабатывать два исключения. Второй
> промах — забыть `ensure_ascii=False`: русские буквы превратятся в `\u0410\u043d...`.
>
> **Граница.** `model_validate_json` не читает файлы: файл открываешь ты, а метод работает
> со строкой. Для потоковых форматов (JSON Lines) читают по строке в цикле и валидируют
> каждую независимо.

## Задача 3. Настройки с вложенным блоком

★★★ · `BaseSettings`, `env_nested_delimiter`, приоритет источников

**Условие.** Приложению нужны: название, режим отладки (по умолчанию выключен) и настройки
базы — адрес и размер пула (от 1 до 20, по умолчанию 5).

**Задание.** 1) Опиши `DatabaseSettings` и `Settings` так, чтобы вложенные переменные
читались с двойным подчёркиванием: `DATABASE__URL`, `DATABASE__POOL_SIZE`. 2) Создай `.env`
со всеми настройками и напечатай их. 3) Убедись, что без `.env` и без переменных окружения
ошибка перечисляет оба обязательных поля. 4) Проверь приоритет: значение из окружения
перекрывает `.env`. 5) Посмотри, как выглядит ошибка вложенной настройки с `pool_size=50`.

> [!example]- Разбор
> **Идея.** `BaseSettings` собирает настройки из нескольких источников, а вложенные блоки
> читаются по разделителю `__`. Модель вложенных настроек — обычная `BaseModel`: правила
> и значения по умолчанию работают как везде.
>
> **Код.**
>
> ```python
> from pydantic import BaseModel, Field, ValidationError
> from pydantic_settings import BaseSettings, SettingsConfigDict
>
>
> class DatabaseSettings(BaseModel):
>     """Настройки подключения к базе."""
>
>     url: str
>     pool_size: int = Field(default=5, ge=1, le=20)
>
>
> class Settings(BaseSettings):
>     """Настройки приложения."""
>
>     model_config = SettingsConfigDict(env_file=".env", env_nested_delimiter="__")
>
>     app_name: str
>     debug: bool = False
>     database: DatabaseSettings
>
>
> def main() -> None:
>     """Показывает настройки и одну ошибку валидации."""
>     settings = Settings()
>     print("приложение:", settings.app_name, "| debug:", settings.debug)
>     print("база:", settings.database.url, "| пул:", settings.database.pool_size)
>     print("словарь:", settings.model_dump())
>
>     try:
>         Settings(database={"url": "postgres://x", "pool_size": 50})
>     except ValidationError as exc:
>         error = exc.errors()[0]
>         print("ошибка вложенной настройки:", error["loc"], "→", error["msg"])
>
>
> if __name__ == "__main__":
>     main()
> ```
>
> Содержимое `.env`:
>
> ```text
> APP_NAME=Дневник
> DEBUG=true
> DATABASE__URL=postgres://localhost/diary
> DATABASE__POOL_SIZE=10
> ```
>
> **Вывод:**
>
> ```text
> приложение: Дневник | debug: True
> база: postgres://localhost/diary | пул: 10
> словарь: {'app_name': 'Дневник', 'debug': True, 'database': {'url': 'postgres://localhost/diary', 'pool_size': 10}}
> ошибка вложенной настройки: ('database', 'pool_size') → Input should be less than or equal to 20
> ```
>
> Без `.env`:
>
> ```text
> app_name → Field required
> database → Field required
> ```
>
> Приоритет (в окружении задано `DATABASE__POOL_SIZE=3`):
>
> ```text
> 3
> ```
>
> **Что здесь важно.** `if __name__ == "__main__":` — не формальность: без него импорт модуля
> выполняет код и создаёт настройки (именно на этом легко споткнуться, когда модуль
> импортируют тесты). Путь к ошибке во вложенной настройке — `('database', 'pool_size')`:
> видно и блок, и поле.
>
> **Типичная ошибка.** Ждать, что `DATABASE_URL` попадёт во вложенное поле: без
> `env_nested_delimiter="__"` такое имя нужно описывать отдельным полем с `alias`.
> Вторая — оставить `.env` с паролями в git.
>
> **Граница.** Вложенный разделитель можно изменить (`env_nested_delimiter="."`), но менять
> его без причины не стоит: `__` — привычное соглашение. Приоритет источников — от
> аргументов при создании (выше всего) к значениям по умолчанию.

# Что запомнить из практики

| Приём | Когда |
|---|---|
| `model_dump()` | словарь для кода внутри программы |
| `model_dump(mode="json")` | словарь для `json.dump` |
| `model_dump_json()` | готовая JSON-строка |
| `exclude_none=True` | пустые поля наружу не нужны |
| `model_validate_json` | данные приходят строкой JSON |
| `model_json_schema()` | проверить контракт: поля и обязательность |
| `BaseSettings` + `env_file` | настройки приложения |
| `env_nested_delimiter="__"` | вложенные блоки настроек |
