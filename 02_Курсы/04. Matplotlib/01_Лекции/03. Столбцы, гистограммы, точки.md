# 03. Столбцы, гистограммы, точки

> [!abstract] О чём лекция
> Линия показывает **изменение во времени**, столбцы — **сравнение категорий**, гистограмма — **распределение значений**, точки — **связь двух величин**. Выбрать правильный вид графика важнее, чем красиво его нарисовать: неправильный вид обманывает даже при честной шкале.
>
> Здесь — `bar`/`barh`, `hist` и `scatter`, подписи значений на столбцах и проверка гистограммы числами.

# Столбцы: сравнение категорий

Столбцы отвечают на вопрос «что больше» — средний балл по предметам, число посещений по месяцам:

```python
import matplotlib

matplotlib.use("Agg")
import matplotlib.pyplot as plt

subjects = ["Python", "Математика", "Физика"]
averages = [4.4, 4.1, 3.7]

fig, ax = plt.subplots(figsize=(7, 4.5))
bars = ax.bar(subjects, averages, color=["tab:blue", "tab:blue", "tab:red"])
ax.set_title("Средний балл по предметам")
ax.set_ylabel("Балл")
ax.set_ylim(0, 5)
ax.bar_label(bars, fmt="%.1f")
fig.tight_layout()
fig.savefig("bars.png", dpi=100)
```

| Приём | Зачем | Что будет, если не сделать |
|---|---|---|
| `color=[…]` списком | разный цвет столбцов: акцент на «Физика — red» | все синие — акцент теряется |
| `ax.set_ylim(0, 5)` | столбцы сравнивают величину — ось **обязана** начинаться с нуля | обрезанная ось исказит соотношение в разы |
| `ax.bar_label(bars, fmt="%.1f")` | числа прямо на столбцах: не нужно сверяться с осью | читатель гадает по высоте |
| `ax.barh(subjects, averages)` | горизонтальные столбцы — подписи длинные | вертикальные подписи наезжают |
| `ax.set_ylabel("Балл")` | единицы в подписи оси | заголовок «Баллы» без единиц непонятен |

`bars` — список прямоугольников; `bar_label` берёт их высоту и печатает `fmt="%.1f"` — один знак после запятой: `4.4`, `4.1`, `3.7`. Шириной столбцов управляет `width` (по умолчанию 0.8), интервалом между группами — `align`.

> [!warning] Столбцы без нуля на оси — грубая ошибка
> Обрезанная ось у столбцов хуже, чем у линии: столбик «4.4» и «4.1» при оси от 4 до 5 будут отличаться в 4 раза по высоте, хотя разница — 7 %. У столбцов ось значений всегда начинают с нуля, если нет отдельного предупреждения в подписи. Для линии узкая шкала иногда оправдана (см. [[02. Линии. настройка]]), для столбцов — почти никогда.

Горизонтальные столбцы удобны, когда категорий много или подписи длинные:

```python
fig, ax = plt.subplots(figsize=(7, 4.5))
ax.barh(subjects, averages, color="tab:blue")
ax.set_xlabel("Балл")
ax.set_xlim(0, 5)
ax.bar_label(ax.containers[0], fmt="%.1f")
```

# Гистограмма: распределение

Гистограмма отвечает на вопрос «сколько значений попало в каждый интервал» — распределение оценок, времени решения, размеров чеков:

```python
marks = [5, 5, 4, 5, 3, 4, 5, 2, 5, 4, 4, 5, 5, 3, 4]

fig2, ax2 = plt.subplots(figsize=(7, 4.5))
counts, edges, _ = ax2.hist(marks, bins=[1.5, 2.5, 3.5, 4.5, 5.5], color="tab:purple", rwidth=0.9)
ax2.set_title("Распределение оценок")
ax2.set_xlabel("Оценка")
ax2.set_ylabel("Число учеников")
print("границы:", edges)
print("сколько в каждом интервале:", counts)
print("сумма:", counts.sum())
```

```text
границы: [1.5 2.5 3.5 4.5 5.5]
сколько в каждом интервале: [1. 2. 5. 7.]
сумма: 15.0
```

Читается так: одна двойка, две тройки, пять четвёрок, семь пятёрок — 15 значений всего. `hist` возвращает три вещи: **числа** по интервалам (`counts`), **границы** (`edges`) и патчи (прямоугольники) — первые две полезны, чтобы проверить себя: сумма равна числу значений, границы — там, где ожидались.

| Настройка | Смысл | Пример |
|---|---|---|
| `bins=10` | 10 равных интервалов | по умолчанию |
| `bins=[1.5, 2.5, …]` | свои границы: «середины» между целыми оценками | `1.5, 2.5` → двойки отдельно от троек |
| `rwidth=0.9` | чуть уже столбиков, интервалы не сливаются | без него столбцы соприкасаются |
| `color`, `edgecolor` | заливка и обводка | `edgecolor="black"` для печати |

Число интервалов меняет картину: слишком мало — всё в одном столбце (теряется форма), слишком много — «шум» и пустые столбцы. Для учебных оценок границы по целым числам `1.5, 2.5, 3.5, 4.5, 5.5` — самый честный вариант; для времени решения границы подбирают по смыслу задачи.

> [!note] Гистограмма и `bar` — разное
> `bar` рисует столбцы по готовым категориям («Python — 4.4»), `hist` сам считает, сколько значений попало в интервалы. Путать их — значит либо считать вручную, либо потерять проверку `counts.sum()`.

# Точки: связь двух величин

Диаграмма рассеяния показывает **связь**: часы подготовки и балл, цена и спрос, рост и вес.

```python
fig3, ax3 = plt.subplots(figsize=(7, 4.5))
hours = [1, 2, 3, 4, 5, 6, 7, 8]
score = [2.5, 3.0, 3.4, 3.9, 4.1, 4.3, 4.4, 4.5]
ax3.scatter(hours, score, s=80, color="tab:orange", edgecolor="black")
ax3.set_title("Часы подготовки и балл")
ax3.set_xlabel("Часов в неделю")
ax3.set_ylabel("Балл")
ax3.set_ylim(2, 5)
ax3.grid(True, linestyle=":", alpha=0.5)
```

| Параметр | Смысл | Совет |
|---|---|---|
| `s=80` | размер точки (площадь) | 50 — мелко, 120 — крупно |
| `color`, `edgecolor` | заливка и обводка | обводка помогает на светлом фоне |
| `alpha=0.5` | прозрачность | спасает, когда точки накладываются в пятно |
| `c=values, cmap="viridis"` | цвет точки по третьей величине | так показывают три измерения на плоскости |

Если точки выстраиваются вверх — величины связаны; если облако — связи нет. Но рассеяние **не доказывает причину**: «больше часов → выше балл» на таком графике выглядит правдоподобно, но связи бывают и обратные, и случайные — причину доказывают иначе, а не картинкой из 8 точек. Для вывода нужны статистика и объём данных (см. [[00. NumPy]]).

# Что чем рисовать — шпаргалка

| Вопрос | График | Функция | Ось от нуля? |
|---|---|---|---|
| как менялось во времени | линия | `ax.plot` | по смыслу |
| что больше, что меньше (категории) | столбцы | `ax.bar`, `ax.barh` | **обязательно** |
| как распределены значения | гистограмма | `ax.hist` | да, по числу |
| связаны ли две величины | точки | `ax.scatter` | по смыслу |
| доля целого | столбцы с нормировкой | `ax.bar` (проценты) | 0–100 % |
| очень много категорий | горизонтальные столбцы | `ax.barh` | да |

> [!note] Про круговые диаграммы
> `ax.pie` существует, но читается хуже столбцов: сравнивать углы труднее, чем длины. Если задача — «показать доли», почти всегда лучше нормированные столбцы с подписями процентов. Круг оставь для 2–3 долей, когда «целое» очевидно.

# Как это делают в проекте

Выбор вида графика — решение, которое принимают до рисования, и в проекте его фиксируют функцией.

1. **Вид по вопросу, а не по привычке.** В `src/report/charts.py` — отдельная функция на каждый вопрос: `save_average_bars` (сравнение), `save_marks_hist` (распределение), `save_hours_scatter` (связь). Путать их — значит ответить не на тот вопрос.

```python
# src/report/charts.py
def save_average_bars(subjects: list[str], averages: list[float], path: Path) -> Path:
    fig, ax = plt.subplots(figsize=(7, 4.5))
    bars = ax.bar(subjects, averages, color="tab:blue")
    ax.set_ylim(0, 5)  # столбцы — всегда от нуля
    ax.bar_label(bars, fmt="%.1f")
    fig.tight_layout(); fig.savefig(path, dpi=100); plt.close(fig)
    return path

def save_hist(marks: list[int], path: Path) -> Path:
    fig, ax = plt.subplots(figsize=(7, 4.5))
    counts, edges, _ = ax.hist(marks, bins=[1.5,2.5,3.5,4.5,5.5], rwidth=0.9)
    assert counts.sum() == len(marks)  # проверка числами — не глазами
    fig.tight_layout(); fig.savefig(path, dpi=100); plt.close(fig)
    return path
```

2. **Ось столбцов — от нуля, у линии — по смыслу, и это не обсуждают каждый раз.** Константа `BAR_YLIM = (0, 5)` в одном месте, как и палитра — один источник правды.

3. **Подписи значений там, где они экономят время.** `bar_label` для отчёта — обязательно: руководитель не должен сверять высоту с осью, когда число уже на столбце.

4. **Проверяют числами, а не глазами.** `hist` возвращает `counts` и `edges`: распечатай их и убедись, что сумма равна `len(marks)` и что нет пустых интервалов там, где не должно быть. В тестах — то же: `counts, edges, _ = ax.hist(...); assert counts.sum() == 15`.

5. **Не рисуют «связь» по 8 точкам как закономерность.** В проекте рассеяние из 8 точек — иллюстрация, а не доказательство. Для вывода — статистика из [[00. NumPy]] и объём данных, а подпись к графику честно говорит «в этих данных», а не «вообще».

# Типичные заблуждения

| Заблуждение | Как на самом деле |
|---|---|
| «Столбцы и линия взаимозаменяемы» | Линия — про изменение во времени, столбцы — про сравнение категорий в один момент |
| «Оценки лучше показывать линией» | Оценки 2–5 — категории и распределение: столбцы или гистограмма, линия здесь врёт |
| «Больше интервалов — точнее гистограмма» | Слишком много интервалов даёт шум и пустые столбцы; границы — по смыслу данных |
| «Рассеяние доказывает причину» | Оно показывает связь; причину доказывают иначе и на больших данных |
| «Круговая диаграмма — универсальная для долей» | Углы читаются хуже длин; для долей чаще лучше нормированные столбцы |

# Проверь себя

1. Какой график покажет, сколько учеников получили каждую оценку, и какие `bins` взять?
2. Почему у столбцов ось значений начинают с нуля, а у линии — не всегда?
3. Что возвращает `ax.hist` и зачем проверять `counts.sum()`?
4. Когда у диаграммы рассеяния ставят `alpha=0.5` и `edgecolor="black"`?
5. Как показать динамику среднего балла по неделям — линией или столбцами?

> [!success]- Ответы
> 1. Гистограмма (`hist`) с границами `[1.5, 2.5, 3.5, 4.5, 5.5]` — по одной колонке на оценку.
> 2. Столбцы сравнивают величины: обрезанная ось искажает соотношение длин; у линии — сравнение изменения, там 0 не всегда нужен.
> 3. Числа по интервалам, границы и патчи; сумма должна равняться числу значений — проверка, что данные не потеряны.
> 4. Когда точек много и они накладываются: `alpha` показывает плотность, `edgecolor` отделяет точки от фона.
> 5. Линией (`plot`) по неделям — как в [[02. Линии. настройка]]; столбцы здесь скроют непрерывность.

# Опора на дисциплину 02

Материалы курса Python, на которые опирается лекция, и то, что она к ним добавляет:

- [[11. Кортежи, списки, словари]] — списки `subjects`, `averages` и `marks`; там их перебирали `for`, здесь они становятся высотой столбца и точкой гистограммы.
- [[07. Линейный алгоритм]] — «ввод → обработка → вывод» на схеме; выбор вида графика — обработка, а вывод теперь — картинка.
- [[08. Разветвляющийся алгоритм]] — ветвление «если вопрос — сравнение, то `bar`; если распределение, то `hist`; если связь, то `scatter`» — тот же `if`, но для визуального решения.

Что добавляет лекция: данные получают **форму**, и ошибка в выборе формы сразу видна как обманчивая картинка, а не как абстрактный неверный ответ в консоли.
