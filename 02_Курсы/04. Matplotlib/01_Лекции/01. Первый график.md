# 01. Первый график

> [!abstract] О чём лекция
> Matplotlib превращает числа в картинку: линию, столбцы, точки. Чтобы не запутаться
> в его устройстве, достаточно помнить две вещи: **фигура** — это весь лист, **оси** — область с графиком внутри него.
>
> Здесь — первый график, сохранение в файл и три настройки, которые нужны всегда: размер, разрешение и бэкенд. После неё ты сможешь с нуля построить график из списков и сохранить его так, чтобы он открылся на любом компьютере и не разъехался при печати.

# Устройство: фигура и оси

```text
Фигура (Figure) — весь лист, например 640×480 пикселей
┌──────────────────────────────────────────────┐
│  Оси (Axes) — область с сеткой и линиями     │
│  ┌────────────────────────────────────────┐  │
│  │  • заголовок, подписи осей, легенда    │  │
│  │  • сами линии/столбцы/точки            │  │
│  └────────────────────────────────────────┘  │
│  • размер фигуры, поля, сохранение         │
└──────────────────────────────────────────────┘
```

В коде это две переменные: `fig` и `ax`. Почти вся работа идёт через `ax` — он отвечает за линии, подписи и пределы осей; `fig` — за размер листа, поля и сохранение в файл. Путать их — самая частая ошибка новичка.

```python
import matplotlib
matplotlib.use("Agg")
import matplotlib.pyplot as plt

fig, ax = plt.subplots()
print(type(fig).__name__, type(ax).__name__)
print("осей на фигуре:", len(fig.axes))
```

```text
Figure Axes
осей на фигуре: 1
```

`plt.subplots()` без параметров создаёт фигуру и одну область осей. Если нужно несколько графиков, этот же вызов вернёт другую фигуру и массив осей — см. [[05. Несколько графиков]].

> [!note] Два интерфейса Matplotlib
> В документации встречаются `plt.plot(days, marks)` и `ax.plot(days, marks)`. Первое — **stateful**-интерфейс: команда рисует на «текущих» осях, которые выбирает Matplotlib сам. В маленьком скрипте это короче, но в проекте, где графиков несколько и они строятся в функциях, легко нарисовать не туда. Второе — **объектно-ориентированный** интерфейс: ты явно говоришь, на каких осях рисовать. В этом курсе почти всегда `ax.plot` — так код предсказуем и не зависит от глобального состояния.

# Самый короткий работающий пример

Возьмём баллы ученика за 5 дней и нарисуем линию с кружками, заголовком и подписями осей:

```python
import matplotlib

matplotlib.use("Agg")
import matplotlib.pyplot as plt

days = [1, 2, 3, 4, 5]
marks = [3, 4, 4, 5, 5]

fig, ax = plt.subplots()
ax.plot(days, marks, marker="o")
ax.set_title("Баллы по дням")
ax.set_xlabel("День")
ax.set_ylabel("Балл")
fig.savefig("first.png", dpi=100)

# проверка результата (Pillow устанавливается вместе с Matplotlib)
from pathlib import Path
from PIL import Image

width, height = Image.open("first.png").size
print("версия:", matplotlib.__version__)
print("бэкенд:", matplotlib.get_backend())
size = Path("first.png").stat().st_size
print(f"сохранено: first.png — {width}×{height} пикселей, {size:_} байт".replace("_", " "))
```

```text
версия: 3.11.2
бэкенд: Agg
сохранено: first.png — 640×480 пикселей, 24 282 байт
```

Файл `first.png` — ровно 640×480 пикселей, 24 282 байта для этого примера (проверено на Matplotlib 3.11.2, `dpi=100`). Числа могут отличаться на десятки байт из-за шрифтов, но порядок тот же.

Что здесь что:

| Строка | Смысл |
|---|---|
| `matplotlib.use("Agg")` | выбрать «невидимый» бэкенд: рисовать в файл, не открывая окно |
| `plt.subplots()` | создать фигуру и одну область осей |
| `ax.plot(days, marks)` | нарисовать линию через точки |
| `marker="o"` | отметить каждую точку кружком |
| `ax.set_title`, `set_xlabel`, `set_ylabel` | подписи — без них график непонятен вне контекста |
| `fig.savefig("first.png", dpi=100)` | сохранить в файл с разрешением 100 точек на дюйм |

Порядок важен: `use("Agg")` ставят **до** `import matplotlib.pyplot`: иначе Matplotlib сначала выберет оконный бэкенд, а потом переключит его, закрыв созданные фигуры.

# Зачем `Agg` и что такое бэкенд

Бэкенд — «движок отрисовки». Он зависит от окружения:

```python
import matplotlib

print("бэкенд по умолчанию:", matplotlib.get_backend())
```

```text
бэкенд по умолчанию: Agg
```

В контейнере, на сервере и в скрипте, который сохраняет картинки, окна нет — там подходит `Agg` (Anti-Grain Geometry, растровый бэкенд без окна). В интерактивной среде (Jupyter, VS Code) бэкенд другой — `inline` или `QtAgg`, и `plt.show()` показывает картинку на экране.

| Окружение | Подходит | Что использовать |
|---|---|---|
| скрипт, тесты, сервер | `Agg` | `matplotlib.use("Agg")` + `fig.savefig` |
| Jupyter Notebook | `inline` | `%matplotlib inline`, затем `plt.show()` |
| VS Code / окно с графиком | `QtAgg`, `TkAgg` | `plt.show()` |
| печать, отчёт | `Agg` + `savefig("…pdf")` | векторный формат, см. [[07. Сохранение и качество]] |

Правило курса: **скрипт и тесты — `Agg` и `savefig`; интерактивная работа — `show`.** Смешивать их в одном файле не нужно: скрипт либо сохраняет, либо показывает.

> [!warning] Импорт до выбора бэкенда
> Если написать `import matplotlib.pyplot as plt` первой строкой, а затем `matplotlib.use("Agg")`, Matplotlib всё равно переключится на `Agg` (переход на неинтерактивный бэкенд возможен всегда), но уже созданные фигуры при этом закроются, а обратно на оконный бэкенд переключиться получится не всегда. Чтобы не зависеть от этих тонкостей, бэкенд выбирают до `pyplot`. Отсюда нестандартный вид блока импортов: сначала `import matplotlib`, затем `use`, затем `import matplotlib.pyplot as plt`. В проекте это обычно делают в одном файле-настройке, а не в каждом модуле — см. [[08. Графики в проекте]].

# Размер: `figsize` и `dpi`

Размер картинки = `figsize` (в дюймах) × `dpi` (точек на дюйм):

```python
print("figsize по умолчанию:", plt.rcParams["figure.figsize"], "| dpi:", plt.rcParams["figure.dpi"])
```

```text
figsize по умолчанию: [6.4, 4.8] | dpi: 100.0
```

Отсюда 6.4 × 100 = 640 и 4.8 × 100 = 480 пикселей. Замер для одной и той же фигуры с разным разрешением (Matplotlib 3.11.2):

```python
fig, ax = plt.subplots()
ax.plot([1, 2, 3, 4], [3, 4, 4, 5], marker="o")
fig.savefig("dpi72.png", dpi=72)
fig.savefig("dpi150.png", dpi=150)
fig.savefig("tight.png", dpi=100, bbox_inches="tight")

for name in ("dpi72.png", "dpi150.png", "tight.png"):
    width, height = Image.open(name).size
    size = Path(name).stat().st_size
    print(f"{name:10} → {width}×{height} пикселей, {size:_} байт".replace("_", " "))
```

```text
dpi72.png  → 460×345 пикселей, 13 599 байт
dpi150.png → 960×720 пикселей, 33 527 байт
tight.png  → 556×413 пикселей, 20 434 байт
```

| Настройка | Что делает | Когда использовать |
|---|---|---|
| `figsize=(8, 4.5)` | меняет форму: шире — удобнее для подписей | когда подписи наезжают |
| `dpi=150` | та же картинка, но крупнее (и файл тяжелее) | для отчёта и печати — 150–300 |
| `dpi=72` | мельче и легче | для предпросмотра |
| `bbox_inches="tight"` | обрезает лишние белые поля при сохранении | почти всегда в отчётах |

> [!warning] `bbox_inches="tight"` и `tight_layout()` — разное
> `fig.tight_layout()` **внутри** фигуры распределяет место между осями, подписями и заголовком, чтобы они не наезжали друг на друга; `bbox_inches="tight"` обрезает белые поля **при сохранении**. Обычно используют оба: сначала `tight_layout()`, затем `savefig(..., bbox_inches="tight")`. В лекции [[05. Несколько графиков]] на сетке разница особенно заметна.

Простое правило: **сначала выбирай `figsize` по компоновке, затем `dpi` по назначению**. Компоновку задаёт `figsize`, чёткость и вес файла — `dpi`.

# Куда сохранять

Путь лучше держать в `pathlib`, а не строкой, и складывать картинки в одну папку:

```python
from pathlib import Path

import matplotlib
matplotlib.use("Agg")
import matplotlib.pyplot as plt

out = Path("out")
out.mkdir(parents=True, exist_ok=True)

fig, ax = plt.subplots()
ax.plot([1, 2, 3], [2, 3, 1], marker="o")
ax.set_title("Пример")
fig.tight_layout()
fig.savefig(out / "first.png", dpi=100)
plt.close(fig)
print("сохранено:", out / "first.png")
```

Папка `out/` — результат работы программы, а не исходники. Её добавляют в `.gitignore` (строка `out/`) и не коммитят: картинки легко пересобрать, а в репозитории они только раздувают историю — см. [[08. Графики в проекте]] и [[08. Git и GitHub]].

| Решение | Зачем |
|---|---|
| `Path("out") / "first.png"` | путь работает на Windows, macOS и Linux |
| `out.mkdir(exist_ok=True)` | папка создаётся сама, если её нет |
| `fig.savefig(out / "first.png")` | принимает и `Path`, и строку |
| `plt.close(fig)` | закрывает фигуру и освобождает память — важно в цикле |

# Как это делают в проекте

В учебных скриптах график — несколько строк в одном файле. В проекте рисование выносят в отдельный модуль, дают каждой картинке свою функцию и закрывают фигуры.

1. **Одна функция — одна картинка, путь — параметр.** Так функцию можно вызвать из скрипта, из отчёта и из теста, а путь `tmp_path / "line.png"` в тестах не захламляет `out/`:

```python
# src/report/charts.py
from pathlib import Path
import matplotlib.pyplot as plt

def save_line(x: list[int], y: list[int], path: str | Path, title: str = "") -> Path:
    """Строит линию и сохраняет в файл; возвращает путь."""
    fig, ax = plt.subplots()
    ax.plot(x, y, marker="o")
    if title:
        ax.set_title(title)
    ax.grid(True, linestyle=":", alpha=0.5)
    fig.tight_layout()
    target = Path(path)
    target.parent.mkdir(parents=True, exist_ok=True)
    fig.savefig(target, dpi=100)
    plt.close(fig)
    return target
```

Что здесь нового: `ax.grid(True, linestyle=":", alpha=0.5)` включает сетку пунктиром с прозрачностью 50 % (подробно — в [[02. Линии. настройка]]), а `mkdir(parents=True, exist_ok=True)` создаёт и недостающие промежуточные папки.

2. **Бэкенд настраивают один раз, в точке входа.** До импорта `pyplot` в `main.py` и в `tests/conftest.py` — а не в каждом модуле рисования. Иначе тесты откроют окно на сервере и упадут.

```python
# main.py
import matplotlib
matplotlib.use("Agg")          # до pyplot
import matplotlib.pyplot as plt
from report.charts import save_line
```

```python
# tests/conftest.py
import matplotlib
matplotlib.use("Agg")
```

3. **Размер задают явно.** В проекте `figsize` выбирают под вёрстку отчёта: узкая фигура `figsize=(8, 3)` для динамики, квадратная `(6, 6)` для рассеяния. По умолчанию оставляют только в черновиках.

4. **Всегда `plt.close(fig)` после `savefig`.** Без закрытия список открытых фигур `plt.get_fignums()` растёт, и в цикле из 50 графиков память копится:

```text
открытых фигур до: []
после 50 графиков без close: [1, 2, ..., 50]
после 50 графиков с close: []
```

5. **Не смешивают `show` и `savefig`.** Скрипт для отчёта сохраняет (`savefig`), интерактивная тетрадка показывает (`show`). Попытка делать и то и другое в одном месте приводит к пустым файлам или зависшим окнам.

# Типичные заблуждения

| Заблуждение | Как на самом деле |
|---|---|
| «`fig` и `ax` — одно и то же» | Фигура — лист, оси — область внутри; подписи и линии живут в `ax`, размер и сохранение — в `fig` |
| «`use("Agg")` можно вызвать где угодно» | Надёжно — только до импорта `pyplot`: после него смена бэкенда закрывает открытые фигуры и не всегда срабатывает |
| «`plt.plot` и `ax.plot` — одно и то же» | `plt.plot` рисует на «текущих» осях: в маленьком скрипте удобно, в проекте путает — бери `ax.plot` |
| «`dpi` влияет только на чёткость» | Он меняет и размер в пикселях, и вес файла; компоновку задаёт `figsize` |
| «Русские подписи не работают» | Шрифт по умолчанию (DejaVu Sans) их поддерживает — проверено, предупреждений нет |

# Проверь себя

1. Чем фигура отличается от осей и где живут линии и подписи?
2. Что делает `matplotlib.use("Agg")` и почему его вызывают до импорта `pyplot`?
3. Сколько пикселей будет в картинке при `figsize=(6.4, 4.8)` и `dpi=150`?
4. Чем `fig.tight_layout()` отличается от `bbox_inches="tight"` при сохранении?
5. Почему после `savefig` фигуру закрывают `plt.close(fig)`?

> [!success]- Ответы
> 1. Фигура — весь лист (размер, сохранение), оси — область с линиями и подписями; линии, заголовок, `set_xlabel` — всё в `ax`.
> 2. Выбирает бэкенд без окна: рисовать в файл. Вызов после импорта `pyplot` тоже переключит бэкенд, но закроет созданные фигуры, поэтому его делают заранее.
> 3. 960×720 (6.4 × 150 и 4.8 × 150).
> 4. `tight_layout` распределяет место внутри фигуры (чтобы подписи не наезжали), `bbox_inches="tight"` обрезает белые поля при записи файла.
> 5. Чтобы освободить память: сотни открытых фигур в цикле без `close` накапливаются, программа замедляется и может упасть.
