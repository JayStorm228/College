# 01. Первый график

> [!abstract] О чём лекция
> Matplotlib превращает числа в картинку: линию, столбцы, точки. Чтобы не запутаться
> в его устройстве, достаточно помнить две вещи: **фигура** — это весь лист, **оси** —
> область с графиком внутри него.
>
> Здесь — первый график, сохранение в файл и три настройки, которые нужны всегда:
> размер, разрешение и бэкенд.

# Устройство: фигура и оси

```text
Фигура (Figure) — весь лист, например 640×480 пикселей
┌──────────────────────────────────────────────┐
│  Оси (Axes) — область с сеткой и линиями     │
│  ┌────────────────────────────────────────┐  │
│  │  • заголовок, подписи осей, легенда    │  │
│  └────────────────────────────────────────┘  │
└──────────────────────────────────────────────┘
```

В коде это две переменные: `fig` и `ax`. Почти вся работа идёт через `ax` — он отвечает
за линии, подписи и пределы осей; `fig` — за размер, сохранение и несколько графиков сразу.

# Самый короткий работающий пример

```python
import matplotlib

matplotlib.use("Agg")
import matplotlib.pyplot as plt

days = [1, 2, 3, 4, 5]
marks = [3, 4, 4, 5, 5]

fig, ax = plt.subplots()
ax.plot(days, marks, marker="o")
ax.set_title("Баллы по дням")
ax.set_xlabel("День")
ax.set_ylabel("Балл")
fig.savefig("first.png", dpi=100)
```

```text
версия: 3.11.2
бэкенд: Agg
сохранено: first.png
```

Файл `first.png` — 640×480 пикселей, 24 282 байта (для примера выше).

Что здесь что:

| Строка | Смысл |
|---|---|
| `matplotlib.use("Agg")` | выбрать «невидимый» бэкенд: рисовать в файл, не открывая окно |
| `plt.subplots()` | создать фигуру и одну область осей |
| `ax.plot(days, marks)` | нарисовать линию через точки |
| `marker="o"` | отметить каждую точку кружком |
| `ax.set_title`, `set_xlabel`, `set_ylabel` | подписи |
| `fig.savefig("first.png", dpi=100)` | сохранить в файл |

> [!note] Порядок импортов
> `matplotlib.use("Agg")` должен стоять **до** `import matplotlib.pyplot`.
> После импорта `pyplot` бэкенд менять поздно — отсюда нестандартный вид блока импортов
> (`import matplotlib`, затем `use`, затем `import matplotlib.pyplot as plt`). В проекте
> это обычно делают в одном файле-настройке, а не в каждом модуле ([[08. Графики в проекте]]).

# Зачем `Agg` и что такое бэкенд

Бэкенд — «движок отрисовки». Он зависит от окружения:

```python
import matplotlib

print("бэкенд по умолчанию:", matplotlib.get_backend())
```

```text
бэкенд по умолчанию: agg
```

На сервере, в контейнере или в скрипте с сохранением файла окна нет — там подходит `Agg`.
Если работать в интерактивной среде (Jupyter, VS Code) и хотеть живой график, бэкенд
другой (`inline`, `QtAgg`), и `plt.show()` показывает картинку на экране.

Правило: **скрипт и тесты — `Agg` и `savefig`; интерактивная работа — `show`.**

# Размер: `figsize` и `dpi`

Размер картинки = `figsize` (в дюймах) × `dpi` (точек на дюйм):

```python
print("figsize по умолчанию:", plt.rcParams["figure.figsize"], "| dpi:", plt.rcParams["figure.dpi"])
```

```text
figsize по умолчанию: [6.4, 4.8] | dpi: 100.0
```

Отсюда 640×480 пикселей. Замер для одной и той же фигуры:

```python
fig, ax = plt.subplots()
ax.plot([1, 2, 3, 4], [3, 4, 4, 5], marker="o")
fig.savefig("dpi72.png", dpi=72)
fig.savefig("dpi150.png", dpi=150)
fig.savefig("tight.png", dpi=100, bbox_inches="tight")
```

```text
dpi72.png → (460, 345) пикселей, 15314 байт
dpi150.png → (960, 720) пикселей, 37254 байт
tight.png → (556, 434) пикселей, 22931 байт
```

| Настройка | Что делает |
|---|---|
| `figsize=(8, 4.5)` | меняет форму: шире — удобнее для подписей |
| `dpi=150` | та же картинка, но крупнее (и файл тяжелее) |
| `bbox_inches="tight"` | обрезает лишние белые поля (556×434 вместо 640×480) |

> [!warning] `bbox_inches="tight"` и `tight_layout()`
> Это разные вещи: `fig.tight_layout()` **внутри** фигуры распределяет место между осями,
> подписями и заголовком, чтобы они не наезжали друг на друга; `bbox_inches="tight"`
> обрезает белые поля при сохранении. Обычно используют оба: `tight_layout()` перед
> `savefig(..., bbox_inches="tight")`.

# Куда сохранять

Путь лучше держать в `pathlib`, а не строкой:

```python
from pathlib import Path

out = Path("out")
out.mkdir(exist_ok=True)
fig.savefig(out / "first.png", dpi=100)
```

Так картинки не разлетаются по папке проекта, а лежат в одном месте ([[09. Структура проекта и модули]]).

# Как это делают в проекте

1. **Рисуют функции, а не сценарии.** Каждая картинка — маленькая функция, которая получает
   данные и путь, а возвращает сохранённый файл ([[08. Графики в проекте]]).
2. **Размер задают явно** — `figsize`, а не «по умолчанию»: от этого зависит, поместятся
   ли подписи.
3. **Сохраняют `dpi=100…150`.** Экранный вариант — 100; для отчёта и печати — 150 и выше.
4. **Всегда закрывают фигуру** после сохранения: `plt.close(fig)` — иначе память
   накапливается (особенно в цикле по сотням графиков).
5. **Не смешивают `show` и `savefig` в одном скрипте.** Скрипт либо показывает,
   либо сохраняет.

# Типичные заблуждения

| Заблуждение | Как на самом деле |
|---|---|
| «`fig` и `ax` — одно и то же» | Фигура — лист, оси — область внутри; подписи и линии живут в `ax` |
| «`use("Agg")` можно вызвать где угодно» | Только до импорта `pyplot`, иначе не подействует |
| «`plt.plot` и `ax.plot` — одно и то же» | `plt.plot` рисует на «текущих» осях: в маленьком скрипте удобно, в проекте путает |
| «`dpi` влияет только на чёткость» | Он меняет и размер в пикселях, и вес файла |
| «Русские подписи не работают» | Шрифт по умолчанию (DejaVu Sans) их поддерживает: проверено, предупреждений нет |

# Проверь себя

1. Чем фигура отличается от осей?
2. Что делает `matplotlib.use("Agg")` и почему его вызывают до импорта `pyplot`?
3. Сколько пикселей будет в картинке при `figsize=(6.4, 4.8)` и `dpi=150`?
4. Зачем нужны `tight_layout()` и `bbox_inches="tight"`?
5. Почему после `savefig` фигуру закрывают?

> [!success]- Ответы
> 1. Фигура — весь лист (размер, сохранение), оси — область с линиями и подписями.
> 2. Выбирает бэкенд без окна: рисовать в файл. После импорта `pyplot` смена бэкенда не сработает.
> 3. 960×720 (6.4 × 150 и 4.8 × 150).
> 4. Первый убирает наложение подписей внутри фигуры, второй обрезает белые поля при сохранении.
> 5. Чтобы освободить память: сотни открытых фигур в цикле — верный способ замедлить программу.
