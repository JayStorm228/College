# 05. Несколько графиков

> [!abstract] О чём лекция
> Если линий стало больше пяти или у величин разный масштаб, один график перестаёт работать: линии сливаются, шкалы врут, легенда закрывает данные. Тогда строят **несколько областей** на одной фигуре: `plt.subplots(2, 2)` — сетку из 4 областей — или две оси Y у одной области (`twinx`).
>
> Здесь — как обращаться к областям, как сделать общий заголовок, как убрать пустую ячейку и почему «двойная ось» требует осторожности.

# Сетка областей

Сетка — когда один вопрос разбит на несколько картинок с общей логикой: успеваемость по четырём предметам, динамика по группам:

```python
import matplotlib

matplotlib.use("Agg")
import matplotlib.pyplot as plt

fig, axes = plt.subplots(2, 2, figsize=(8, 6), sharey=True)
weeks = ["1", "2", "3", "4"]

axes[0][0].plot(weeks, [3.5, 4.0, 4.5, 4.8], marker="o", color="tab:blue")
axes[0][0].set_title("Python")
axes[0][1].bar(weeks, [4.2, 4.0, 4.4, 4.6], color="tab:orange")
axes[0][1].set_title("Математика")
axes[1][0].scatter(weeks, [3.0, 3.5, 4.0, 4.2], color="tab:green")
axes[1][0].set_title("Физика")
axes[1][1].plot(weeks, [4.0, 4.1, 4.2, 4.5], marker="s", color="tab:red")
axes[1][1].set_title("Информатика")

for row in axes:
    for ax in row:
        ax.grid(True, linestyle=":", alpha=0.5)

fig.suptitle("Успеваемость по предметам")
fig.tight_layout()
fig.savefig("grid.png", dpi=100)

# проверка результата
from pathlib import Path
from PIL import Image

width, height = Image.open("grid.png").size
size = Path("grid.png").stat().st_size
print("тип axes:", type(axes).__name__, "| форма:", axes.shape, "| элементов:", axes.size, "| sharey:", axes[0][0].get_shared_y_axes().joined(axes[0][0], axes[1][1]))
print(f"файл: {size:_} байт | пиксели: {width}×{height}".replace("_", " "))
```

```text
тип axes: ndarray | форма: (2, 2) | элементов: 4 | sharey: True
файл: 45 888 байт | пиксели: 800×600
```

| Что | Значение | Запомнить |
|---|---|---|
| `plt.subplots(2, 2)` | фигура и сетка 2×2; `axes` — массив NumPy формы (2, 2) | без NumPy `axes` был бы списком списков |
| `axes[0][1]` | верхний ряд, вторая область | `[строка][столбец]`, с 0 |
| `plt.subplots(1, 3)` | форма `(3,)` — обращение `axes[0]`, `axes[1]`, `axes[2]` | одномерный массив |
| `plt.subplots(3, 1)` | форма `(3,)` — те же индексы, но вертикально | для времени с `sharex` |
| `sharey=True` | общая ось Y: графики сравнимы, метки Y не дублируются | честнее и компактнее |
| `sharex=True` | общая ось X: время одно, графики друг под другом | для динамики |
| `fig.suptitle("…")` | общий заголовок всей фигуры | а не пять одинаковых `set_title` |
| `fig.tight_layout()` | распределяет место, чтобы подписи не наезжали | обязателен для сетки |

Обход всех областей циклом — стандартный приём, чтобы не копировать настройки:

```python
for ax in axes.flat:
    ax.grid(True, linestyle=":", alpha=0.5)
    ax.set_xlabel("Неделя")
    ax.set_ylabel("Балл")
```

`axes.flat` разворачивает двумерный массив в последовательность: один и тот же настрой применяется ко всем графикам, и размер сетки не важен — `2×2` или `3×4`. Альтернатива — вложенные циклы `for row in axes: for ax in row:`, но `flat` короче.

Пределы можно синхронизировать не только при создании: `ax.set_ylim(0, 5)` вручную, но `sharey` делает это автоматически и экономит дублирование подписей.

# Пустая область

Если графиков меньше, чем ячеек, лишнюю убирают — иначе останется пустая рамка:

```python
fig3, axes3 = plt.subplots(2, 2, figsize=(8, 6))
axes3[0][0].plot([1, 2], [2, 3])
axes3[0][1].plot([1, 2], [3, 2])
axes3[1][0].hist([1, 2, 2, 3], bins=3, color="tab:blue")
fig3.delaxes(axes3[1][1])
fig3.tight_layout()
fig3.savefig("three.png", dpi=100)
print("осей на фигуре:", len(fig3.axes))
```

```text
осей на фигуре: 3
```

`fig.delaxes(ax)` удаляет область с фигуры; `fig.add_subplot()` наоборот добавляет, но в курсе это не нужно. Если пустых ячеек много, проще взять сетку другого размера: `plt.subplots(1, 3)` вместо `2×2`.

> [!note] Когда сетка хуже отдельных файлов
> Три-четыре тесно связанных графика — сетка. Шесть независимых картинок для отчёта — лучше отдельные файлы ([[07. Сохранение и качество]]): в тексте их можно поставить рядом, а одинаковые подписи не будут повторяться, и каждый файл — своя функция `save_…` с тестом на `tmp_path`.

# Две оси Y: `twinx`

Величины разного масштаба (посещения — сотни, балл — от 3 до 5) на одних осях не сравнить: одна линия «прилипнет» к нулю, другая — к верху. Их совмещают на одной области с двумя осями Y:

```python
weeks = ["1", "2", "3", "4"]
fig2, ax = plt.subplots(figsize=(7, 4))
ax.plot(weeks, [120, 150, 140, 180], marker="o", color="tab:blue")
ax.set_ylabel("посещения", color="tab:blue")
ax.tick_params(axis="y", labelcolor="tab:blue")

twin = ax.twinx()
twin.plot(weeks, [3.5, 4.0, 4.5, 4.8], marker="s", color="tab:red")
twin.set_ylabel("средний балл", color="tab:red")
twin.tick_params(axis="y", labelcolor="tab:red")
ax.set_title("Посещения и балл на одной картинке")
ax.grid(True, linestyle=":", alpha=0.5)
fig2.tight_layout()
fig2.savefig("twin.png", dpi=100)
```

| Приём | Зачем | Опасность |
|---|---|---|
| `ax.twinx()` | вторая ось Y, привязанная к той же области X | легко подогнать вывод масштабом |
| `color="tab:blue"` у `ylabel` и `tick_params(labelcolor=…)` | читатель понимает, какая ось к какой линии | без цвета — путаница |
| `ax.twiny()` | то же для второй оси X (реже нужно) | так же требует цветных подписей |
| `ax.set_zorder`, `ax.patch.set_visible(False)` | порядок наложения осей | для продвинутых случаев |

> [!warning] Двойные оси легко обманывают
> Двигая пределы второй оси `twin.set_ylim(3, 5)` против `ax.set_ylim(0, 200)`, можно сделать так, что две несвязанные линии «встретятся» или «разойдутся» и читатель решит, что они связаны. Правило: двойная ось уместна, когда у величин **общий смысл по оси X** (например, время — недели) и она **явно подписана цветом**. Если сомневаешься — делай два графика друг под другом с общей осью X: `fig, axes = plt.subplots(2, 1, sharex=True)` — это честнее, когда читателю важны обе величины по отдельности, а не их наложение.

Честная альтернатива двойной оси — два графика с общей осью X, где каждая величина в своей области, а время одно:

```python
fig, axes = plt.subplots(2, 1, figsize=(7, 5), sharex=True)
axes[0].plot(weeks, [120, 150, 140, 180], marker="o", color="tab:blue")
axes[0].set_ylabel("посещения")
axes[1].plot(weeks, [3.5, 4.0, 4.5, 4.8], marker="s", color="tab:red")
axes[1].set_ylabel("балл")
axes[1].set_xlabel("неделя")
```

# Как это делают в проекте

Сетка и двойные оси — архитектурные решения, а не «попробуем и посмотрим». В проекте их выбирают по вопросу.

1. **Один вопрос — одна область.** Разные вопросы не смешивают в одной сетке: «динамика Python» и «распределение оценок» — разные фигуры, даже если данные из одного файла. Сетка — только для сравнимых рядов (четыре предмета по неделям).

2. **`sharey`/`sharex` там, где величины сравнимы.** Для баллов 0–5 `sharey=True` делает графики сравнимыми и убирает дублирование меток — читатель не гадает, одинакова ли шкала. Это честность, а не экономия места.

3. **Общий заголовок через `suptitle`, а не пять одинаковых `set_title`.** Дублирование заголовков — признак, что сетка не нужна: достаточно отдельных файлов.

```python
# src/report/charts.py
def save_subjects_grid(weeks, data: dict[str, list[float]], path: Path) -> Path:
    fig, axes = plt.subplots(2, 2, figsize=(8, 6), sharey=True)
    for ax, (name, values) in zip(axes.flat, data.items()):
        ax.plot(weeks, values, marker="o")
        ax.set_title(name)
        ax.set_ylim(0, 5)
    fig.suptitle("Успеваемость по предметам")
    for ax in axes.flat:
        ax.grid(True, linestyle=":", alpha=0.5)
    fig.tight_layout()
    fig.savefig(path, dpi=100)
    plt.close(fig)
    return path
```

4. **Настройки циклом по `axes.flat`, а не копипастом.** Одна строка `for ax in axes.flat: ax.grid(...)` заменяет четыре. Это тот же `for` из [[09. Циклический алгоритм - цикл for]], только теперь обход матрицы осей.

5. **Двойную ось — только осознанно и с цветными подписями; иначе — два графика.** В коде это ветвление: «если величины с общим временем и нужен один слайд — `twinx` с цветом; иначе — `subplots(2,1, sharex=True)`». Логика — как в [[08. Разветвляющийся алгоритм]].

# Типичные заблуждения

| Заблуждение | Как на самом деле |
|---|---|
| «`axes[0]` — всегда первая область» | Для сетки 2×2 это целая строка; нужна `axes[0][0]` — `axes[строка][столбец]` |
| «`twinx` рисует второй график рядом» | Он добавляет вторую ось **в ту же** область, с теми же X |
| «Одинаковые заголовки в областях — нормально» | Они дублируются; хватит общего `suptitle` и подписей осей |
| «`tight_layout` нужен только при сохранении» | Он нужен всегда, когда есть сетка: иначе подписи наезжают и обрезаются |
| «Чем больше панелей, тем лучше» | 6+ панелей в одной фигуре читаются хуже, чем 6 отдельных файлов по функциям |

# Опора на дисциплину 02

Материалы курса Python, на которые опирается лекция, и то, что она к ним добавляет:

- [[13. Вложенные последовательности]] — `axes` как двумерный массив `shape (2, 2)`, доступ `axes[0][1]`; там были матрицы чисел, здесь — матрица областей для рисования.
- [[09. Циклический алгоритм - цикл for]] — `for ax in axes.flat` и `for row in axes`; цикл теперь обходит не числа, а графики.
- [[08. Разветвляющийся алгоритм]] — выбор «сетка или отдельные файлы? `twinx` или `subplots(2,1)`?» — то же ветвление, но для компоновки отчёта.

Что добавляет лекция: двумерный массив и цикл перестают быть абстракцией — они **раскладывают картинки**, и ошибка в индексе `axes[0]` сразу видна как «не та область».
