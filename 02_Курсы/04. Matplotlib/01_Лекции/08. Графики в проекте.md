# 08. Графики в проекте

> [!abstract] О чём лекция
> Пока график один и рисуется в скрипте, всё просто. В проекте их десятки: их строят
> по данным, сохраняют в папку и проверяют тестами. Здесь — как упаковать рисование
> в функции, где хранить картинки и почему тесты запускают Matplotlib без окна.

# Функция на каждый график

```python
"""Построение графиков: одна функция — одна картинка."""

from pathlib import Path

import matplotlib.pyplot as plt
import numpy as np


def save_line(x: np.ndarray, y: np.ndarray, path: str | Path, title: str = "") -> Path:
    """Сохраняет линейный график в файл и возвращает путь к нему."""
    fig, ax = plt.subplots()
    ax.plot(x, y, marker="o")
    if title:
        ax.set_title(title)
    ax.grid(True, linestyle=":", alpha=0.5)
    fig.tight_layout()
    target = Path(path)
    fig.savefig(target, dpi=100)
    plt.close(fig)
    return target
```

| Решение | Зачем |
|---|---|
| функция получает данные и путь | её можно вызвать из скрипта, теста и отчёта |
| возвращает `Path` | вызывающий код знает, что файл создан |
| `plt.close(fig)` в конце | фигуры не накапливаются: в цикле из 50 графиков список открытых фигур остаётся пустым |
| `fig, ax = plt.subplots()` внутри | функция не зависит от «текущей» фигуры — можно вызывать подряд |

# Тесты: рисуем без окна

Тест не должен открывать окно и не должен зависеть от машины. Настройка бэкенда
живёт в одном месте:

```python
"""Общие настройки тестов: без окна графиков."""

import matplotlib

matplotlib.use("Agg")
```

```python
"""Тесты графиков: рисуем в файл, изображение не открываем."""

from pathlib import Path

import numpy as np

from charts.build import save_bars, save_line


def test_save_line(tmp_path: Path) -> None:
    """Линейный график сохраняется в файл."""
    path = save_line(np.arange(1, 6), np.array([3, 4, 4, 5, 5]), tmp_path / "line.png")
    assert path.exists()
    assert path.stat().st_size > 1000


def test_save_bars(tmp_path: Path) -> None:
    """Столбцы сохраняются в файл."""
    path = save_bars(["Python", "Физика"], [4.4, 3.7], tmp_path / "bars.png")
    assert path.suffix == ".png"
    assert path.stat().st_size > 1000
```

Что проверяют такие тесты: **файл создан**, **не пустой**, расширение правильное.
Чего не проверяют: как именно выглядят линии.

> [!warning] Не сравнивайте картинки побайтово
> Тест «изображение совпадает с эталоном» ломается от другой версии Matplotlib, шрифта
> или платформы. Проверяйте то, что важно для программы: файл появился, размер разумный,
> функция не упала на краевых данных (пустой массив, одна точка).

# Где хранить картинки

```text
project/
├── src/charts/build.py     ← функции рисования
├── tests/test_build.py     ← тесты
├── data/marks.csv          ← исходные данные
├── out/                    ← готовые картинки (в .gitignore)
└── main.py                 ← сценарий: данные → картинки → отчёт
```

- `out/` создаётся программой: `out.mkdir(exist_ok=True)`.
- Картинки — **результат**, а не исходники: их не коммитят ([[08. Git и GitHub]]).
- Имена файлов — латиницей и по смыслу: `average_by_subject.png`, а не `график1.png`.
- Тесты рисуют в `tmp_path` — во временную папку, которую pytest убирает сам.

# Как это делают в проекте

1. **Рисование — отдельный модуль.** Данные, отчёты и картинки не смешивают в одном файле.
2. **Одна функция — один график**, с параметром пути и понятным именем.
3. **`plt.close(fig)` обязателен** в функциях, которые вызывают в цикле.
4. **Бэкенд настраивают в одном месте** (в `conftest.py` для тестов, в точке входа для скрипта).
5. **Тесты проверяют факт и размер файла**, а не пиксели.
6. **Картинки не коммитят**: в `.gitignore` строка `out/`.

# Типичные заблуждения

| Заблуждение | Как на самом деле |
|---|---|
| «Рисовать можно прямо в `main`» | Тогда тестировать нечего; рисование выносят в функции |
| «`plt.close` не нужен» | В цикле фигуры накапливаются и программа замедляется |
| «Тест должен проверять картинку точно» | Такие тесты хрупкие; проверяйте файл, размер и граничные случаи |
| «Настраивать бэкенд надо в каждом модуле» | Достаточно `conftest.py` и точки входа |
| «Картинки стоит закоммитить, пусть будут» | Это результат: он раздувает репозиторий и устаревает |

# Проверь себя

1. Почему рисование выносят в отдельные функции?
2. Что проверяет тест графика и почему не пиксели?
3. Зачем `tmp_path` в тестах?
4. Где настраивают бэкенд `Agg` для тестов?
5. Почему папку `out/` добавляют в `.gitignore`?

> [!success]- Ответы
> 1. Функцию можно вызвать из скрипта, теста и отчёта; логика не смешана с запуском.
> 2. Что файл создан и не пустой; побайтовое сравнение ломается от версии и шрифтов.
> 3. Это временная папка, которую pytest создаёт и убирает сам — мусор не остаётся.
> 4. В `conftest.py` (и в точке входа для скрипта), до импорта `pyplot` в тестах.
> 5. Картинки — результат работы: их не хранят в репозитории.
