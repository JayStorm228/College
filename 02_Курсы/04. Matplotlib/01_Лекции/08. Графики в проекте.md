# 08. Графики в проекте

> [!abstract] О чём лекция
> Пока график один и рисуется в скрипте, всё просто: `plt.subplots` → `plot` → `savefig`. В проекте их десятки: их строят по данным из модуля `data`, сохраняют в папку `out/` и проверяют тестами, не открывая окна. Здесь — как упаковать рисование в функции, где хранить картинки, почему тесты запускают Matplotlib без окна и как не накапливать фигуры.
>
> Лекция собирает весь курс: фигура и оси ([[01. Первый график]]), оформление ([[02. Линии: настройка]]), виды графиков ([[03. Столбцы, гистограммы, точки]]), подписи ([[04. Подписи и оси]]), сетки ([[05. Несколько графиков]]), NumPy ([[06. Графики из NumPy]]) и форматы ([[07. Сохранение и качество]]).

# Функция на каждый график

Первый шаг проекта — перестать рисовать «в `main`». Каждая картинка — маленькая функция, которая получает данные и путь, а возвращает сохранённый файл:

```python
"""Построение графиков: одна функция — одна картинка."""

from pathlib import Path

import matplotlib.pyplot as plt
import numpy as np


def save_line(x: np.ndarray, y: np.ndarray, path: str | Path, title: str = "") -> Path:
    """Сохраняет линейный график в файл и возвращает путь к нему."""
    fig, ax = plt.subplots(figsize=(7, 4.5))
    ax.plot(x, y, marker="o", color="tab:blue")
    if title:
        ax.set_title(title)
    ax.set_xlabel("X")
    ax.set_ylabel("Y")
    ax.grid(True, linestyle=":", alpha=0.5)
    fig.tight_layout()
    target = Path(path)
    target.parent.mkdir(parents=True, exist_ok=True)
    fig.savefig(target, dpi=100, bbox_inches="tight")
    plt.close(fig)
    return target


def save_bars(labels: list[str], values: list[float], path: str | Path) -> Path:
    """Столбцы с подписями значений."""
    fig, ax = plt.subplots(figsize=(7, 4.5))
    bars = ax.bar(labels, values, color="tab:blue")
    ax.set_ylim(0, max(values) * 1.2)
    ax.bar_label(bars, fmt="%.1f")
    fig.tight_layout()
    target = Path(path)
    fig.savefig(target, dpi=100, bbox_inches="tight")
    plt.close(fig)
    return target
```

| Решение | Зачем | Что ломается без него |
|---|---|---|
| функция получает `x, y, path` | её можно вызвать из `main.py`, теста и отчёта | рисует только в одном месте |
| возвращает `Path` | вызывающий код знает, что файл создан, и логирует | не проверить в тесте |
| `target.parent.mkdir(parents=True, exist_ok=True)` | папка `out/` создаётся сама | `FileNotFoundError` |
| `fig, ax = plt.subplots()` внутри | функция не зависит от «текущей» фигуры | вызов подряд рисует не туда |
| `plt.close(fig)` в конце | фигуры не накапливаются | в цикле из 50 графиков — 50 открытых фигур |
| `bbox_inches="tight"` + `tight_layout` | подписи не обрезаны | обрезанные заголовки в отчёте |

Проверка закрытия — числом открытых фигур:

```python
print("открытых фигур до:", plt.get_fignums())
for i in range(50):
    save_line(np.arange(5), np.array([3,4,4,5,5]), f"/tmp/tmp_{i}.png")
print("после 50 графиков с close:", plt.get_fignums())
```

```text
открытых фигур до: []
после 50 графиков с close: []
```

Без `close` — `[1, 2, …, 50]`, и память растёт. В отчёте с десятками графиков это не мелочь.

# Тесты: рисуем без окна

Тест не должен открывать окно и не должен зависеть от машины. Настройка бэкенда живёт в одном месте — в `tests/conftest.py`, который `pytest` выполняет до импорта тестов:

```python
"""Общие настройки тестов: без окна графиков (tests/conftest.py)."""

import matplotlib

matplotlib.use("Agg")
```

Сам тест рисует во временную папку `tmp_path`, которую `pytest` создаёт и убирает сам, и проверяет не пиксели, а **факт**:

```python
"""Тесты графиков: рисуем в файл, изображение не открываем (tests/test_build.py)."""

from pathlib import Path

import numpy as np

from report.charts import save_bars, save_line


def test_save_line(tmp_path: Path) -> None:
    """Линейный график сохраняется в файл и не пустой."""
    path = save_line(np.arange(1, 6), np.array([3, 4, 4, 5, 5]), tmp_path / "line.png")
    assert path.exists()
    assert path.stat().st_size > 1000
    assert path.suffix == ".png"


def test_save_bars(tmp_path: Path) -> None:
    """Столбцы сохраняются, даже если подпись длинная."""
    path = save_bars(["Python", "Очень длинная подпись предмета"], [4.4, 3.7], tmp_path / "bars.png")
    assert path.exists()
    assert path.stat().st_size > 1000
    assert path.suffix == ".png"
```

```text
$ PYTHONPATH=src pytest -q tests
...                                                                      [100%]
3 passed in 0.39s

$ PYTHONPATH=src mypy src tests
Success: no issues found in 4 source files

$ black --check src tests && ruff check src tests
All checks passed!
```

Что проверяют такие тесты: **файл создан**, **не пустой** (`>1000` байт), расширение правильное, функция не упала на краевых данных (пустой массив, одна точка, длинная подпись) — и всё это без окна.

> [!warning] Не сравнивайте картинки побайтово
> Тест «изображение совпадает с эталоном `expected.png`» ломается от другой версии Matplotlib, шрифта или платформы. Пиксели совпадут только на той же машине. Проверяйте то, что важно для программы: файл появился, размер разумный, функция не упала на краевых данных (пустой массив, одна точка, `NaN`). Для проверки вида — смотрите глазами `out/*.png` после `main.py`.

Точка входа при этом остаётся простой: сначала числа, затем картинки, как в мини-проекте:

```python
# main.py
import matplotlib
matplotlib.use("Agg")  # до pyplot
import matplotlib.pyplot as plt
from pathlib import Path
import logging
from report.data import MARKS_BY_SUBJECT, WEEKS
from report.charts import save_bars, save_line

logging.basicConfig(level=logging.INFO, format="%(levelname)s %(message)s")
logger = logging.getLogger("report")

def main() -> None:
    out = Path("out")
    out.mkdir(exist_ok=True)
    for name in MARKS_BY_SUBJECT:
        path = save_bars([name], [4.4], out / f"{name}.png")
        logger.info("сохранено %s, %d байт", path, path.stat().st_size)
```

# Где хранить картинки

```text
project/
├── src/report/
│   ├── __init__.py
│   ├── data.py        ← исходные данные
│   ├── summary.py     ← числа отчёта
│   └── charts.py      ← функции рисования (save_*)
├── tests/
│   ├── conftest.py    ← matplotlib.use("Agg")
│   └── test_charts.py ← тесты на tmp_path
├── data/marks.csv     ← исходные данные (если из файла)
├── out/               ← готовые картинки (в .gitignore)
├── main.py            ← сценарий: данные → числа → картинки → отчёт
└── pyproject.toml
```

- `out/` создаётся программой: `out.mkdir(exist_ok=True)` — её не создают руками.
- Картинки — **результат**, а не исходники: их не коммитят и добавляют в `.gitignore` строку `out/` (см. [[08. Git и GitHub]]).
- Имена файлов — латиницей и по смыслу: `average_by_subject.png`, `marks_hist.png`, а не `график1.png`.
- Тесты рисуют в `tmp_path` — во временную папку, которую `pytest` сам убирает; `out/` не захламляется.
- `src/report/charts.py` зависит только от `numpy` и `matplotlib`, а не от `data.py` — это внедрение зависимостей ([[07. Внедрение зависимостей]]): данные передают параметром, и функцию можно вызвать с любыми массивами.

# Как это делают в проекте

Проект с графиками — тот же инженерный проект, что и с Pydantic или NumPy, только результат — картинки.

1. **Рисование — отдельный модуль.** Данные (`data.py`), числа (`summary.py`) и картинки (`charts.py`) не смешивают в одном файле — каждый модуль делает одно дело (см. [[09. Структура проекта и модули]]).

2. **Одна функция — один график, с параметром пути и понятным именем.** `save_average_bars`, `save_marks_hist`, `save_dynamics`, `save_hours_scatter` — по имени видно, что внутри, и тесты не угадывают.

3. **`plt.close(fig)` обязателен в функциях, которые вызывают в цикле или в тестах.** Иначе `plt.get_fignums()` растёт, и отчёт с 30 графиками замедляется.

4. **Бэкенд настраивают в одном месте.** `main.py` — для запуска, `tests/conftest.py` — для тестов, до импорта `pyplot`. В самом `charts.py` `matplotlib.use` не ставят — модуль не знает, откуда его вызовут.

5. **Тесты проверяют факт и размер файла, а не пиксели.** `assert path.exists() and path.stat().st_size > 1000` — достаточно, чтобы поймать забытые `savefig` или пустую фигуру; побайтовое сравнение — хрупко.

6. **Картинки не коммитят, а данные — да.** В `.gitignore` — `out/`, `__pycache__/`, `.venv/`; в репозитории — `data.py` и `src/report/`. По логу `logger.info` видно, что графики собраны, не открывая `out/`.

# Типичные заблуждения

| Заблуждение | Как на самом деле |
|---|---|
| «Рисовать можно прямо в `main`, зачем функции» | Тогда тестировать нечего и переиспользовать нечего; рисование выносят в `save_*` |
| «`plt.close` не нужен, Python сам закроет» | В цикле из 50 графиков фигуры накапливаются — `get_fignums()` покажет 50 открытых |
| «Тест должен проверять картинку попиксельно» | Такие тесты хрупкие — ломаются от версии и шрифтов; проверяйте файл, размер и граничные случаи |
| «Настраивать бэкенд надо в каждом модуле `charts.py`» | Достаточно `conftest.py` для тестов и `main.py` для запуска — модуль рисования остаётся независимым |
| «Картинки стоит закоммитить, пусть будут в репо» | Это результат: он раздувает репозиторий и устаревает при каждом запуске `main.py` |

# Проверь себя

1. Почему рисование выносят в отдельные функции `save_*` с параметром `path`?
2. Что проверяет тест графика и почему не сравнивают пиксели `expected.png`?
3. Зачем в тестах `tmp_path`, а в `main.py` — `Path("out")`?
4. Где настраивают бэкенд `Agg` для тестов и почему до импорта `pyplot`?
5. Почему папку `out/` добавляют в `.gitignore` и что будет без `plt.close` в цикле?

> [!success]- Ответы
> 1. Функцию можно вызвать из скрипта, теста и отчёта с любыми данными и путём; логика не смешана с запуском и проверяема.
> 2. Что файл создан (`exists`), не пустой (`st_size>1000`) и с правильным расширением; побайтовое сравнение ломается от версии Matplotlib и шрифтов.
> 3. `tmp_path` — временная папка `pytest`, которая сама уберётся; `out/` — постоянная папка результата для человека, логируется.
> 4. В `tests/conftest.py` и в `main.py` до `import matplotlib.pyplot` — иначе Matplotlib уже выберет другой бэкенд.
> 5. Картинки — результат: их не хранят; без `close` 50 графиков — 50 открытых фигур и рост памяти.

- [[14. Функции и модули]] — `def save_line(x, y, path) -> Path`, `return Path`, `if __name__ == "__main__"`; там функции считали числа, здесь — сохраняют файлы, но устройство то же.
