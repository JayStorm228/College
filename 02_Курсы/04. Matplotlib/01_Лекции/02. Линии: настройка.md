# 02. Линии: настройка

> [!abstract] О чём лекция
> Линия — самый частый график: динамика по времени, сравнение нескольких наборов, поведение величины. Одна линия показывает **изменение**, несколько — **сравнение**.
>
> Здесь — как сделать линию понятной: цвет, толщина, стиль, маркеры, легенда, сетка и — самое важное — **честные пределы осей**. После лекции линии перестанут быть «синими по умолчанию» и станут читаемыми и в цвете, и в чёрно-белой печати.

# Несколько линий на одних осях

```python
import matplotlib

matplotlib.use("Agg")
import matplotlib.pyplot as plt

weeks = ["1 нед", "2 нед", "3 нед", "4 нед"]
python_marks = [3.5, 4.0, 4.5, 4.8]
math_marks = [4.2, 4.0, 4.4, 4.6]

fig, ax = plt.subplots(figsize=(7, 4.5))
ax.plot(weeks, python_marks, marker="o", linestyle="-", color="tab:blue", label="Python")
ax.plot(weeks, math_marks, marker="s", linestyle="--", color="tab:orange", label="Математика")
ax.set_title("Средний балл по неделям")
ax.set_xlabel("Неделя")
ax.set_ylabel("Балл")
ax.set_ylim(0, 5)
ax.grid(True, linestyle=":", alpha=0.6)
ax.legend(loc="lower right")
fig.tight_layout()
fig.savefig("lines.png", dpi=100)
```

```text
файл: 41 186 байт | осей: 1 | линий: 2 | легенда: 2 элемента
```

Разница с лекцией [[01. Первый график]] — два вызова `ax.plot` на **одних** осях. Каждая линия получает свой `label`, и только после этого `ax.legend()` знает, что подписывать.

| Параметр | Значения (самые нужные) | Когда менять |
|---|---|---|
| `color` | `"tab:blue"`, `"tab:orange"`, `"red"`, `"#3366cc"` | всегда — цвет по смыслу |
| `linestyle` | `"-"` сплошная, `"--"` пунктир, `":"` точки, `"-."` штрихпунктир | когда график уйдёт в печать без цвета |
| `marker` | `"o"` круг, `"s"` квадрат, `"^"` треугольник, `"*"` звезда, `"D"` ромб | чтобы различить линии без цвета |
| `linewidth` | 1 — тонко, 1.5 — по умолчанию, 2–3 — акцент | когда нужно выделить одну линию |
| `alpha` | 0.3 — почти прозрачно, 1 — непрозрачно | для фона или перекрывающихся линий |
| `label` | имя для легенды | для каждой линии, если линий больше одной |

Правило: **каждая линия — свой `label`, иначе легенда её не покажет.** А если линия одна, легенда не нужна: подпись оси `ax.set_ylabel("Балл")` сообщает то же самое короче.

# Цвета: что выбрать

- `tab:blue`, `tab:orange`, `tab:green`, `tab:red`, `tab:purple` — «фирменная» палитра Matplotlib (Tableau). Она различается и в чёрно-белой печати, и при большинстве форм дальтонизма лучше резких `red`/`green` парами.
- Один цвет на один смысл: если Python везде синий, не делайте его в другом графике зелёным — читатель привыкает к цвету как к названию.
- Не больше 5–6 линий на осях: больше — уже не читается, нужны отдельные графики или сетка ([[05. Несколько графиков]]).

```python
# Палитра проекта: константы, а не строки в каждом plot
COLORS = {"Python": "tab:blue", "Математика": "tab:orange", "Физика": "tab:green"}
ax.plot(weeks, python_marks, color=COLORS["Python"], label="Python")
```

Словарь цветов — маленький реестр (см. [[06. Проектирование - фабрики и реестры]]): один источник правды для всех графиков.

# Стиль линии и маркеры — для печати и скриншотов

Если график попадёт в чёрно-белый отчёт, различия только по цвету пропадут. Поэтому в пару к цвету берут **стиль линии и маркер**: сплошная с кружками против пунктира с квадратами различимы всегда, даже после ксерокса.

```python
ax.plot(weeks, [3.0, 3.5, 4.0, 4.2], marker="^", linestyle=":", color="tab:green", label="Физика")
ax.plot(weeks, [4.0, 4.1, 4.2, 4.5], marker="D", linestyle="-.", color="tab:red", label="Информатика")
```

| Комбинация | Узнаваемость без цвета |
|---|---|
| `"-", "o"` | сплошная с кружками |
| `"--", "s"` | пунктир с квадратами |
| `":", "^"` | точки с треугольниками |
| `"-.", "D"` | штрихпунктир с ромбами |

В отчёте, где графики копируют в слайды и печатают, это не украшение — это требование читаемости. Толщину тоже используют как акцент: главная линия `linewidth=2`, остальные `linewidth=1`.

# Легенда и сетка

```python
ax.legend(loc="lower right")          # положение: upper left, lower center, best и другие
ax.legend(loc="lower right", ncol=2) # две колонки, если линий 4
ax.grid(True, linestyle=":", alpha=0.6)
ax.grid(True, axis="y", linestyle=":", alpha=0.5) # только горизонтальные линии
```

- `loc="best"` — Matplotlib сам ищет свободное место; `"lower right"` — предсказуемо и удобно в отчётах, не закрывает рост в правом верхнем углу.
- `ncol=2` — когда линий 4, легенда в две колонки занимает меньше высоты.
- Сетка помогает читать значения, но не должна спорить с данными: `alpha=0.5…0.6` и точечный стиль `":"` — стандарт.
- Есть `ax.legend(title="Предмет")`, если линий много и подпись объясняет группу.

Легенду ставят там, где она не закрывает данные. Если график всё равно перегружен, лучше вынести легенду наружу (`bbox_to_anchor`) или сделать отдельные графики.

# Главная ловушка: обрезанные оси

```python
ax.set_ylim(0, 5)   # честно для баллов от 0 до 5
ax.set_ylim(3, 5)   # «драматично» для тех же данных
```

Один и тот же набор `Python = [3.5, 4.0, 4.5, 4.8]` на разных шкалах — два разных впечатления:

| Пределы | Что видит читатель | На сколько % высоты приходится рост 3.5→4.8 (+1.3) |
|---|---|---|
| `set_ylim(0, 5)` | честная картина: график вырос примерно на четверть высоты | 26 % |
| `set_ylim(3, 5)` | «драма»: рост кажется огромным, половина высоты | 65 % |

Правило: **если ось обрезана — это должно быть осознанным решением и объяснено подписью или статьёй.** По умолчанию Matplotlib подбирает пределы сам и обычно близок к честному варианту, но с точками данных может ошибиться и показать «от минимума до максимума».

Для баллов честная шкала — 0–5, для процентов — 0–100, для посещений — «0 до чуть выше максимума». Исключение: когда сравнивают два близких метода и оба «в диапазоне 4.0–4.2» — тогда узкую шкалу подписывают: «Шкала 4.0–4.2 для сравнения методов».

> [!warning] Сглаживание и обрезанные оси вместе
> Самая нечестная картинка — «масштаб от минимума до максимума» плюс сглаживание: разница в 2 % выглядит как катастрофа. Такие графики встречаются в новостях и рекламе; в отчёте так делать не нужно. См. [[06. Графики из NumPy]] про сглаживание.

# Как это делают в проекте

В проекте линии — не «быстрый plot в ноутбуке», а функция, которая принимает данные, знает палитру и не обманывает шкалой.

1. **Палитра — константа, а не строки в каждом вызове.** Один словарь на весь модуль — как реестр цветов:

```python
# src/report/charts.py
COLORS = {"Python": "tab:blue", "Математика": "tab:orange", "Физика": "tab:green"}
STYLES = {"Python": ("-", "o"), "Математика": ("--", "s"), "Физика": (":", "^")}
def save_dynamics(weeks, data: dict[str, list[float]], path: Path) -> Path:
    fig, ax = plt.subplots(figsize=(8, 4.5))
    for name, values in data.items():
        style, marker = STYLES[name]
        ax.plot(weeks, values, label=name, color=COLORS[name], linestyle=style, marker=marker)
    ax.set_ylim(0, 5)  # честная шкала для баллов — в одном месте, а не в каждой задаче
    ax.legend(loc="lower right")
    ax.grid(True, linestyle=":", alpha=0.5)
    fig.tight_layout()
    fig.savefig(path, dpi=100)
    plt.close(fig)
    return path
```

2. **Граница честности — одна.** Пределы осей выбирают по смыслу величины (баллы 0–5, проценты 0–100), а не по данным. Это та же идея, что и валидация на границе в Pydantic: правило в одном месте.

3. **Тест проверяет вид, а не пиксели.** В `tests/test_charts.py` вызывают функцию с двумя наборами, передавая `tmp_path / "dyn.png"`, и проверяют, что файл появился и весит >10 КБ — так ловят отсутствие `legend` или `savefig` без `tmp_path`:

```python
def test_dynamics(tmp_path: Path):
    path = save_dynamics(["1","2"], {"Python":[3.5,4.0],"Математика":[4.0,4.2]}, tmp_path/"d.png")
    assert path.exists() and path.stat().st_size > 10_000
```

4. **Логи уровня `INFO` после сохранения.** `logger.info("сохранено %s, %d байт", path, path.stat().st_size)` — по логу видно, что график не пустой и куда попал, не открывая файл.

5. **Стиль и маркер — обязательная пара для линий в отчётах.** Даже если сейчас график цветной, завтра его распечатают. Код сразу закладывает различимость без цвета — это дешевле, чем переделывать отчёт.

# Типичные заблуждения

| Заблуждение | Как на самом деле |
|---|---|
| «Чем больше линий, тем информативнее» | После 5–6 линий график перестаёт читаться — нужна сетка или отдельные файлы |
| «Цвета хватит, чтобы различить» | В чёрно-белой печати цвет пропадёт; нужен стиль или маркер |
| «Обрезать ось — приём для наглядности» | Это приём для искажения; обрезайте осознанно и предупреждайте читателя |
| «Легенда всегда нужна» | Для одной линии она дублирует подпись оси и только загромождает |
| «Сетка — для красоты» | Сетка помогает читать значения; без неё график хуже, но и слишком яркая мешает — держите `alpha=0.5` |

# Проверь себя

1. Как подписать линию для легенды и когда легенда не нужна?
2. Почему в отчётах лучше не различать линии только цветом?
3. Чем опасен `set_ylim(3, 5)` для данных от 3.5 до 4.8?
4. Где в подписи оси указывать единицы измерения и как быть с `ncol=2`?
5. Когда стоит рисовать не одну фигуру с линиями, а сетку графиков?

> [!success]- Ответы
> 1. Через `label="…"` в `ax.plot` и затем `ax.legend()`; для одной линии легенда дублирует `ylabel` и не нужна.
> 2. График могут распечатать в ч-б: цвет пропадёт — нужны разные стили и маркеры.
> 3. Он усиливает разницу: рост 1.3 на шкале 2 (3–5) — 65 % высоты, на шкале 5 (0–5) — только 26 %.
> 4. В `ax.set_ylabel("Температура, °C")`; `ncol=2` — для 4 линий, чтобы легенда не росла в высоту.
> 5. Когда линий больше 5–6 или у них разный масштаб — см. [[05. Несколько графиков]].

# Опора на дисциплину 02

Материалы курса Python, на которые опирается лекция, и то, что она к ним добавляет:

- [[11. Кортежи, списки, словари]] — списки `weeks`, `python_marks` и словари `{"Python": [...]}` с данными; там списки только перебирались циклом, здесь они становятся координатами точек.
- [[07. Линейный алгоритм]] — шаги «данные → обработка → вывод»; линия — визуальный вывод того же алгоритма, где предобработка — выбор `set_ylim`.
- [[03. Разветвляющийся алгоритм — общий вид]] — условие «если линий >1, нужна легенда; если ось обрезана, нужно предупреждение»; ветвление теперь — выбор вида оформления.

Что добавляет лекция: список и словарь перестают быть абстракцией — они **рисуются**, и неверный выбор шкалы сразу виден как искажение, а не как абстрактная «ошибка в формуле».
