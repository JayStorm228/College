# 10. Моделирование — от допущений до численного эксперимента

> [!abstract] О чём лекция
> Программа может без ошибок считать неправильную идею. Чтобы компьютер помог исследовать
> реальный процесс, сначала нужно сформулировать цель и допущения, описать модель, реализовать
> её, проверить, затем провести контролируемый эксперимент и аккуратно интерпретировать вывод.
>
> **Зачем это нужно.** Модель не «истина в компьютере». Она упрощает оригинал ради определённого
> вопроса. Проверка кода сама по себе не доказывает, что выбранное упрощение подходит реальности.
>
> **После лекции ты сможешь:** назвать компоненты и тип модели, пройти цикл моделирования,
> отличить верификацию от валидации, реализовать пошаговую модель свободного падения на C++20,
> сравнить её с аналитическим решением, рассмотреть влияние шага и сформулировать границы вывода.

## Оригинал, модель и цель

**Оригинал** — реальный объект, процесс или система: падающий шар, очередь, заказ в магазине,
учёт посещаемости.

**Модель** — упрощённое представление оригинала, которое сохраняет только свойства, важные
для выбранной **цели**. Карта метро отвечает на вопрос «как добраться», а не «какое расстояние
между зданиями в метрах». Отсутствие деталей — не недостаток модели, а причина, по которой
модель вообще полезна.

**Моделирование** — построение модели и исследование оригинала с её помощью. **Анализ** —
исследование самой модели: соответствует ли она описанию, насколько точна, как реагирует на
изменение входов и что происходит на границах.

**Программа — реализация модели, а не сама модель.** Можно написать две разные программы,
реализующие одни и те же правила; и можно написать безупречную с точки зрения компилятора
программу, которая реализует неподходящую модель.

### Какие стороны системы можно описать программой

В информационных системах модель может описывать не только формулы:

| Сторона модели | Что задаётся | Пример |
|---|---|---|
| Данные | Какие сведения хранятся и как связаны | Заказ: номер, дата и список блюд. |
| Поведение | Какие действия допустимы и как меняется состояние | Статусы заказа: создан → подтверждён → доставлен. |
| Вычисления | Какие формулы или алгоритмы превращают вход в результат | Площадь поверхности шара по радиусу. |

Один проект часто объединяет все три стороны: хранит данные, задаёт правила переходов и считает
результаты. Выбор важного зависит от цели; модель не обязана включать каждую подробность оригинала.

## Из чего состоит модель

| Часть | Что это | Пример падения шара |
|---|---|---|
| Цель | Какой вопрос задаём | Сколько времени падает шар с заданной высоты? |
| Входные данные/параметры | Изменяемые данные | Начальная высота `h₀` в метрах |
| Константы | Принятые фиксированные величины | `g = 9.81 м/с²` |
| Допущения | Что считаем несущественным | Нет сопротивления воздуха, ускорение постоянно |
| Правила/связи | Формулы или алгоритм | `y(t) = h₀ − g·t²/2` |
| Выходные данные | Что нас интересует | Время до поверхности |
| Область применимости | Где выводу можно доверять | Вертикальное падение при малой скорости и принятом приближении `g` |

Допущения определяют, **где** модели можно доверять. Формула для падения без сопротивления
воздуха не подходит для пера с большой высоты; реальная траектория, рельеф и вращение Земли
тоже игнорируются в простом примере.

## Виды моделей: несколько независимых признаков

| Признак | Виды | Пример |
|---|---|---|
| Форма | Материальная; словесная; графическая; математическая; компьютерная | Макет; описание; UML-диаграмма; формула; C++-симуляция |
| Изменение во времени | Статическая; динамическая | Объём шара по радиусу; падение тела |
| Случайность | Детерминированная; стохастическая | Площадь по радиусу; модель длины очереди со случайным потоком людей |
| Время | Непрерывное; дискретное | Непрерывная формула движения; расчёт с шагом `dt` |

Эти оси сочетаются. Например, наша аналитическая модель падения математическая, динамическая,
детерминированная и непрерывная. Компьютерная пошаговая версия динамическая, детерминированная,
но дискретная по времени.

**Имитационная модель** воспроизводит изменение состояния системы шаг за шагом. Для многих
систем точной простой формулы нет; тогда компьютер многократно применяет правила перехода
состояния. Пошаговость приносит погрешность и требует осмысленного выбора шага.

## Семь этапов моделирования

```text
1. Постановка задачи → 2. Концептуальная модель → 3. Формализация →
4. Реализация → 5. Проверка → 6. Эксперимент → 7. Выводы
                         ↑                         │
                         └──── уточнение модели ──┘
```

| Этап | Главный вопрос | Пример |
|---|---|---|
| 1. Постановка задачи | Что и зачем нужно узнать? | Найти время падения с высоты в метрах. |
| 2. Концептуальная модель | Что существенно, какие допущения принимаем? | Игнорируем сопротивление воздуха; стартуем из покоя. |
| 3. Формализация | Какими формулами/правилами описываем? | Выбираем точное уравнение и пошаговую схему. |
| 4. Реализация | Как записать правила кодом? | Функции C++, типы, цикл. |
| 5. Проверка | Соответствует ли программа правилам и оригиналу? | Тесты, аналитическая формула, измерения. |
| 6. Эксперимент | Что будет при разных входах и параметрах? | Меняем начальную высоту и `dt`. |
| 7. Выводы | Что можно заключить и где границы вывода? | Меньший `dt` меняет точность данного численного метода. |

Если проверка не сходится, пересмотри и реализацию, и формализацию, и допущения. Не надо
«подгонять» выход программы к желаемому ответу не выяснив причину.

## Сверху вниз: точное уравнение

Пусть тело начинает падать без начальной скорости с высоты `h₀`, ось `y` направлена вверх,
поверхность находится на `y = 0`, ускорение свободного падения постоянно и равно `g > 0`.
Тогда положение в момент `t`:

```text
y(t) = h₀ − (g · t²) / 2
```

При достижении земли `y(t) = 0`, поэтому время падения:

```text
t = √(2 · h₀ / g)
```

В C++ для квадратного корня используем `std::sqrt` из `<cmath>`. Если `h₀ < 0` или `g <= 0`,
вход нарушает физические допущения: формулу нельзя применять молча.

## Пошаговая модель: метод Эйлера

В модели по времени с шагом `dt > 0` пересчитываем скорость и высоту. Для выбранных осей:

```text
v(next) = v(current) − g · dt
y(next) = y(current) + v(next) · dt
```

Это один из вариантов явной пошаговой схемы (semi-implicit Euler): сначала обновляется скорость,
затем положение использует уже новую скорость. Если поменять порядок, получится другая численная
схема и иная ошибка. Мы явно записываем правило, а не маскируем его под точную физику.

Когда один шаг пересекает поверхность, высота в точке шага может стать отрицательной. Земля
не уходит под ноль в нашей модели: это значит, что между двумя шагами было пересечение. Для
учебного примера линейно оценим точку пересечения между последней положительной и первой
неположительной высотой. Это приближение, а не дополнительный закон природы.

## Полная программа C++20: проверяем вход и сравниваем модели

```cpp
#include <cmath>
#include <iomanip>
#include <iostream>

// Предусловия: initial_height >= 0, gravity > 0, dt > 0.
double exact_fall_time(double initial_height, double gravity) {
    return std::sqrt(2.0 * initial_height / gravity);
}

// Полунеявная схема Эйлера и линейная оценка пересечения поверхности.
double euler_fall_time(double initial_height, double gravity, double dt) {
    double height{initial_height};
    double velocity{};  // скорость вниз хранится отрицательной при оси y вверх
    double time{};

    while (height > 0.0) {
        const double previous_height{height};
        const double previous_time{time};

        velocity -= gravity * dt;
        height += velocity * dt;
        time += dt;

        if (height <= 0.0) {
            const double fraction{previous_height / (previous_height - height)};
            return previous_time + fraction * dt;
        }
    }

    return 0.0;  // тело уже на поверхности: initial_height == 0
}

void report(double initial_height, double gravity, double dt) {
    const double exact_time{exact_fall_time(initial_height, gravity)};
    const double simulated_time{euler_fall_time(initial_height, gravity, dt)};
    std::cout << "dt = " << dt
              << " s; simulated = " << simulated_time
              << " s; signed error = " << simulated_time - exact_time << " s\n";
}

int main() {
    constexpr double gravity{9.81};
    double initial_height{};

    std::cout << "Initial height in metres (0..1000): ";
    if (!(std::cin >> initial_height) || !std::isfinite(initial_height) ||
        initial_height < 0.0 || initial_height > 1000.0) {
        std::cerr << "Enter a finite height from 0 to 1000 metres.\n";
        return 1;
    }

    std::cout << std::fixed << std::setprecision(6);
    std::cout << "Analytical result: "
              << exact_fall_time(initial_height, gravity) << " s\n";
    report(initial_height, gravity, 0.1);
    report(initial_height, gravity, 0.01);
    report(initial_height, gravity, 0.001);
    return 0;
}
```

Собери, например, так:

```bash
g++ -std=c++20 -Wall -Wextra -Wpedantic -g fall_model.cpp -o fall_model
./fall_model
```

Введи `20`. Вывод округлён до шести знаков и зависит от платформы на последних десятичных
разрядах. Ожидаемая аналитическая оценка — около `2.019275` секунды; численные результаты
должны быть близки, а в этой модели и для этих шагов ошибка обычно уменьшается вместе с `dt`.
Проверь также `0` (падение уже завершено), `-1`, `1001` (недопустимые значения), `1000`
(верхняя допустимая граница) и `abc` (ошибка чтения). Диапазон `0..1000` м — явное ограничение
этого учебного запуска: он не даёт случайно запросить неограниченно длинную симуляцию. Это
операционное ограничение примера, а не утверждение, что модель без сопротивления воздуха
физически точна на всём этом диапазоне.

### Что измеряет эксперимент

- Входной параметр — `initial_height`; константа — `gravity`; численный параметр алгоритма — `dt`.
- Сравниваем два вычислительных подхода: формулу и численное приближение.
- **Погрешность** здесь — разность численного и аналитического времени. Она не является
  расстоянием между моделью и реальным экспериментом.
- При меньшем `dt` выполняется больше итераций. Для фиксированной длительности процесса число
  шагов примерно обратно пропорционально `dt`.
- Для нашего простого уравнения аналитический ответ доступен. В более сложной задаче точную
  формулу может быть невозможно получить; тогда используют независимые контрольные данные,
  альтернативные методы и проверку на реальных наблюдениях.

## Верификация и валидация — два разных вопроса

| Вопрос | Название | Что проверяем | Пример |
|---|---|---|---|
| «Правильно ли мы построили модель по заданным правилам?» | **Верификация** | Код соответствует формулам/алгоритму, а вычисления реализованы правильно | Сравнить Euler с точной формулой, изменить шаг и проверить поведение. |
| «Ту ли модель мы построили для задачи и оригинала?» | **Валидация** | Допущения и выходы подходят реальной системе и цели | Измерить падение шара в заданных условиях и сравнить с моделью. |

Верификация: «правильно ли строим модель?»; валидация: «правильно ли выбрали модель?». Это
разные проверки. Код может верно реализовать уравнение без сопротивления воздуха, но уравнение
может оказаться неподходящим для пера.

**Тест программы** отвечает на вопросы о конкретных путях исполнения. Он помогает верификации,
но сам по себе не подтверждает валидацию. **Контрольное значение** — вход, ответ для которого
известен заранее, например высота `0` даёт время `0` в обеих моделях.

## Вычислительный эксперимент без самообмана

При сравнении `dt` меняй именно его, оставляя постоянными другие параметры. Запиши таблицу:

| Начальная высота, м | `g`, м/с² | `dt`, с | Число шагов/время | Оценка ошибки |
|---:|---:|---:|---:|---:|
| 20 | 9.81 | 0.1 | измерить | сравнить |
| 20 | 9.81 | 0.01 | измерить | сравнить |
| 20 | 9.81 | 0.001 | измерить | сравнить |

Если одновременно менять высоту, шаг и алгоритм, будет трудно объяснить, почему изменился
результат. Сохраняй единицы измерения, формат округления и описание версии модели. Для
воспроизводимости записывай компилятор/версию и точные входы, когда точность имеет значение.

## Модели в разработке программ

Моделирование встречается не только в физике:

| Модель в разработке ПО | Что упрощает | Как проверяют |
|---|---|---|
| Модель предметной области | Понятия и правила организации | Сверяют с владельцами процесса и требованиями. |
| UML-диаграмма | Один аспект структуры или поведения системы | Проверяют, что показанный аспект согласован с требованиями и соседними диаграммами. |
| Модель жизненного цикла ПО | Этапы и порядок работ команды | Сравнивают с реально выполняемым процессом и ограничениями проекта. |
| Вычислительная модель | Существенные параметры и правила процесса | Верификация, валидация, анализ чувствительности. |

Любая такая модель имеет оригинал, цель и допущения. Диаграмма состояний может описывать только
основные переходы и опускать пользовательский интерфейс; модель предметной области может
упрощать организацию ради автоматизируемого процесса.

## Как это делают в проекте

Перед написанием кода ответь письменно:

1. Какой конкретный вопрос должен получить ответ?
2. Каковы входы, выходы и единицы измерения?
3. Какие допущения включены и где заканчивается область применимости?
4. Какая точная формула/правило переводит вход в выход?
5. Что будет независимым ориентиром для проверки?
6. Какие значения и параметры изменю в эксперименте?

После реализации проверь корректность кода и модели раздельно. В отчёте формулируй вывод
только в пределах сделанных допущений: «эта программа доказала падение настоящего шара» —
слишком сильное утверждение; «в модели без сопротивления воздуха время при высоте 20 м
приблизительно равно…» — точнее.

## Типичные заблуждения

| Заблуждение | Как на самом деле |
|---|---|
| «Чем подробнее модель, тем она лучше» | Детали оправданы только если помогают цели; модель должна быть управляемым упрощением. |
| «Программа запустилась, значит модель верна» | Запуск говорит только о выполнении; нужны верификация и валидация. |
| «Сверка с формулой — это валидация реального мира» | Она проверяет вычислительную реализацию/численный метод; реальность требует наблюдений и измерений. |
| «Компьютер может считать непрерывное время буквально» | Программа работает конечными шагами; дискретизация создаёт погрешность. |
| «Уменьшение шага всегда только улучшает результат» | Для данной схемы и выбранного примера ошибка уменьшается, но цена счёта растёт; для сложных систем поведение надо исследовать, а не предполагать. |
| «Отрицательная высота просто означает, что формула работает» | Это выход за область применимости; входные условия должны быть проверены, пересечение поверхности обработано явно. |

## Ключевые термины

| Термин | Объяснение |
|---|---|
| Оригинал | Реальная система/процесс, который пытаются исследовать. |
| Модель | Упрощённое представление оригинала для конкретной цели. |
| Допущение | Условие, которое сознательно упрощает описание оригинала. |
| Область применимости | Условия, в которых результат модели полезен и допустим. |
| Аналитическая модель | Модель, в которой ответ получают формулой/символьным решением. |
| Численная модель | Модель, которая приближённо рассчитывает ответ конечными шагами/операциями. |
| Имитационная модель | Компьютерное воспроизведение изменения состояния системы во времени. |
| Метод Эйлера | Пошаговый метод приближённого интегрирования дифференциальных уравнений. |
| Шаг `dt` | Интервал времени между соседними шагами дискретной симуляции. |
| Погрешность | Разность или иная мера расхождения приближённого и ориентирного результата. |
| Верификация | Проверка, правильно ли реализована/построена модель по заданному описанию. |
| Валидация | Проверка, соответствует ли выбранная модель оригиналу и цели. |
| Вычислительный эксперимент | Серия расчётов с контролируемым изменением входных данных или параметров. |
