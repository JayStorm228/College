# 13. Стандартная библиотека — алгоритмы, итераторы и сложность

> [!abstract] О чём лекция
> Стандартная библиотека C++ предоставляет не только контейнеры, но и алгоритмы, которые
> работают с диапазонами элементов. Изучим итераторы, полуоткрытый диапазон `[begin, end)`,
> поиск/сортировку/суммирование, простую лямбда-функцию и асимптотическую сложность.
>
> **Зачем это нужно.** Повторно реализовывать проверенный поиск или сортировку — риск ошибки и
> лишняя работа. Правильный стандартный алгоритм обычно яснее цикла, а понимание сложности помогает
> оценить масштаб задачи до того, как программа станет медленной.
>
> **После лекции ты сможешь:** выбрать `find`, `count_if`, `sort` или `accumulate`, объяснить
> роль `begin`/`end`, понять требования алгоритма, оценить простую операцию как `O(1)`, `O(n)`
> или `O(n log n)` и учесть компромисс времени/памяти.

## Что называют STL и стандартной библиотекой

В разговоре часто говорят **STL** об инфраструктуре контейнеров, итераторов и алгоритмов.
Формально стандарт C++ определяет стандартную библиотеку, а привычное слово STL исторически
относится к части её идей и компонентов. Для нас практическое правило важнее названия:
сначала проверь, есть ли готовый стандартный контейнер/алгоритм, который точно выражает задачу.

## Итератор — обобщённый способ пройти по элементам

**Итератор** — объект, который обозначает позицию в последовательности и даёт алгоритму способ
читать/перемещаться по элементам. У `std::vector` вызовы `begin()` и `end()` обозначают начало
и границу диапазона. Короткие блоки без `main` ниже — фрагменты: операторы нужно поместить
в тело функции, а переменные `values`/`scores` объявить заранее. Для фрагментов используются
`<vector>`, `<iostream>`, `<algorithm>` или `<numeric>` — нужный заголовок будет указан рядом.
Полная самостоятельная программа приведена далее.

```cpp
std::vector<int> values{10, 20, 30};
auto first{values.begin()};
auto last{values.end()};
```

Это фрагмент тела функции; подключи `<vector>`. Следующий цикл использует объявленные здесь
`first` и `last` и дополнительно требует `<iostream>`.

`end()` указывает **за последним элементом**, не на последний элемент. Поэтому стандартные
алгоритмы часто принимают полуоткрытый диапазон `[first, last)`: первая граница включена,
последняя исключена. Пустой диапазон можно представить так, что `first == last`.

```cpp
for (auto position{first}; position != last; ++position) {
    std::cout << *position << '\n';
}
```

`*position` читает текущий элемент. В повседневном простом обходе предпочитай range-based `for`,
а итератор используй, когда алгоритм или границы диапазона делают код яснее.

### Возможности итераторов

| Возможность | Пример | Где встречается |
|---|---|---|
| Однопроходное чтение | Читать следующий элемент | Потоки и некоторые диапазоны. |
| Прямой многократный проход | Повторно начать и идти вперёд | `forward_list`, многие диапазоны. |
| Движение вперёд и назад | `++it`, `--it` | `std::list`, `std::set`. |
| Произвольный доступ | `it + n`, разность итераторов | `std::vector`, `std::array`, строка. |

Не любой алгоритм подходит к любому контейнеру. `std::sort` требует итераторы произвольного
доступа, поэтому он подходит `vector` и `array`, но не `std::list`. Для списка есть собственный
`list.sort()`.

## Найти элемент: `std::ranges::find`

```cpp
#include <algorithm>
#include <iostream>
#include <vector>

int main() {
    const std::vector<int> scores{73, 88, 91, 64};
    const auto found{std::ranges::find(scores, 91)};

    if (found != scores.end()) {
        std::cout << "Found: " << *found << '\n';
    } else {
        std::cout << "Not found\n";
    }
}
```

Алгоритм ищет первое равное значение. Если не нашёл, результат равен `end()`. Проверяй этот
результат **до** разыменования. Для обычного неотсортированного `vector` поиск просматривает
элементы по очереди, то есть в худшем случае время растёт линейно с числом элементов `n`.

## Подсчёт по условию: `std::ranges::count_if`

Самостоятельная программа подсчитывает оценки не ниже 60. Нужны `<algorithm>` для алгоритма,
`<vector>` для контейнера и `<iostream>` для вывода:

```cpp
#include <algorithm>
#include <iostream>
#include <vector>

int main() {
    const std::vector<int> scores{73, 88, 91, 64};
    const auto passing_count{std::ranges::count_if(
        scores,
        [](int score) { return score >= 60; }
    )};

    std::cout << "Passing: " << passing_count << '\n';
    return 0;
}
```

Второй аргумент — **лямбда**: небольшая функция без отдельного имени, созданная прямо в месте
вызова. Здесь она получает оценку и возвращает `true`, если оценка не ниже 60. `count_if`
вызывает её для каждого элемента и считает положительные ответы.

Лямбда `[](int score) { ... }` ничего не захватывает из внешней области (`[]` пусто). Объявление
типа и синтаксис достаточно прочитать здесь; сложные captures и generic lambdas будут частью
последующей практики шаблонов.

## Сортировка: `std::ranges::sort`

Это фрагмент тела функции; подключи `<algorithm>` и `<vector>`:

```cpp
std::vector<int> scores{73, 88, 91, 64};
std::ranges::sort(scores);  // по возрастанию
```

`std::ranges::sort` сортирует диапазон на месте. Он меняет исходный порядок. Если нужно оставить
исходные данные, создай копию и отсортируй её. Для собственного порядка можно передать функцию-
сравнение, которая задаёт **строгое слабое упорядочение**: сравнение должно быть согласованным
и не противоречить самому себе. На старте используй стандартный порядок, если его достаточно.

Сортировка сравнительным алгоритмом обычно требует порядка `O(n log n)` сравнений. Гарантия
точного числа сравнений/скорости зависит от стандарта/реализации, но асимптотическая оценка
описывает рост масштаба.

## Суммирование: `std::accumulate`

```cpp
#include <iostream>
#include <numeric>
#include <vector>

int main() {
    const std::vector<double> measurements{18.5, 20.0, 19.5};
    const double total{std::accumulate(
        measurements.begin(), measurements.end(), 0.0
    )};

    std::cout << "Total: " << total << '\n';
    return 0;
}
```

`std::accumulate` объявлен в `<numeric>`. Начальное значение `0.0` задаёт тип результата
`double`; если передать `0`, тип накопителя может быть целым, даже когда элементы дробные.
Тип начального значения — часть смысла алгоритма.

## Пример: сводка и поиск

```cpp
#include <algorithm>
#include <iostream>
#include <numeric>
#include <vector>

int main() {
    const std::vector<int> scores{73, 88, 91, 64};
    if (scores.empty()) {
        std::cout << "No scores\n";
        return 0;
    }

    const auto total{std::accumulate(scores.begin(), scores.end(), 0LL)};
    const double average{static_cast<double>(total) / scores.size()};
    const auto passing{std::ranges::count_if(
        scores, [](int score) { return score >= 60; }
    )};

    std::cout << "Average: " << average << '\n';
    std::cout << "Passing: " << passing << '\n';
    return 0;
}
```

Код можно собрать с параметрами курса `g++ -std=c++20 -Wall -Wextra -Wpedantic`. `0LL` расширяет
начальный накопитель до `long long`; при реальных ограничениях проверь, что диапазона достаточно.
Пустой набор обрабатывается до деления.

## Сложность — рост объёма работы

Обозначим число входных элементов как `n`. **Асимптотическая сложность** описывает, как
увеличивается число операций/объём памяти при росте `n`, не предсказывая точное время на одном
компьютере.

| Оценка | Пример | Интуиция |
|---|---|---|
| `O(1)` | Обращение к `vector[index]` при корректном индексе | Число операций примерно не зависит от `n`. |
| `O(log n)` | Поиск в отсортированном диапазоне пополам | На каждом шаге область поиска резко сокращается. |
| `O(n)` | `find` в неотсортированном массиве, сумма элементов | В худшем случае проверяется каждый элемент. |
| `O(n log n)` | Сравнительная сортировка | Растёт быстрее линейного, значительно медленнее квадратичного. |
| `O(n²)` | Для каждой пары перебрать все `n` элементов | При удвоении `n` работа примерно возрастает в четыре раза. |

Это оценки порядка роста, обычно опускающие константы и менее значимые слагаемые. `O(n)` не
означает одну операцию; `O(1)` не всегда означает «мгновенно».

### Быстрый обзор стоимости операций

| Структура/операция | Типичная оценка | Уточнение |
|---|---|---|
| `vector` индекс | `O(1)` | Индекс должен быть допустимым. |
| Добавить в конец `vector` | Амортизированно `O(1)` | Иногда происходит расширение/перенос, отдельное добавление может стоить `O(n)`. |
| Вставить в середину `vector` | `O(n)` | Последующие элементы часто сдвигаются. |
| Линейный поиск в `vector` | `O(n)` | Если значение на последнем месте или отсутствует. |
| Упорядоченная ассоциативная map/set | `O(log n)` поиск/вставка | Обычно сбалансированное дерево. |
| `unordered_map` | Среднее `O(1)` | Худший случай может быть `O(n)`; порядок обхода не гарантирован. |
| Сортировка `vector` | `O(n log n)` | Меняет порядок элементов. |

Оценки — стандартный ориентир, а не гарантия точной задержки: реальные характеристики зависят
от контейнера, компилятора, данных, кэшей и операций.

## Почему сортировка помогает поиску

Если данные уже упорядочены, алгоритм бинарного поиска может за `O(log n)` сужать половину
оставшегося диапазона. Но он **требует отсортированных данных** по тому же порядку. Если данных
мало или поиск выполняется один раз, сначала сортировать дороже, чем просто просмотреть.
Алгоритм выбирают с учётом набора операций, а не одного привлекательного числа сложности.

## Сложность по памяти и инвалидирование

Важен и объём дополнительной памяти. Один алгоритм может быть быстрее, но хранить копию данных;
другой — менять исходный контейнер. У `vector` добавление способно перераспределить хранилище,
из-за чего итераторы/ссылки/указатели на его элементы могут стать недействительными.

Не меняй размер контейнера во время прохода, если не знаешь правила алгоритма и операции.

## Как это делают в проекте

Перед самописным циклом проверь четыре вопроса:

1. Есть ли стандартный алгоритм, имя которого прямо описывает задачу?
2. Какие свойства диапазона/итератора он требует?
3. Меняет ли он исходные данные, и как обозначает отсутствие результата?
4. Насколько растёт работа/память при максимальном входе из требований?

Стандартный алгоритм не отменяет понимание контракта: `sort` не знает, что оценка должна быть
в диапазоне 0–100, а `find` не проверит, что контейнер содержит уникальные элементы.

## Типичные заблуждения

| Заблуждение | Как на самом деле |
|---|---|
| «`end()` указывает на последний элемент» | Это граница за последним; её нельзя разыменовывать. |
| «Бинарный поиск быстрее для любого контейнера» | Он требует отсортированного диапазона и подходящих итераторов; подготовка данных тоже стоит времени. |
| «`O(1)` значит ровно одно действие» | Это означает, что число операций асимптотически не зависит от `n`. |
| «После сортировки исходный порядок сохранён» | `sort` переставляет элементы на месте. |
| «Любой алгоритм STL подходит к `list` и `vector`» | Алгоритм требует определённых возможностей итераторов. |
| «`unordered_map` всегда гарантирует O(1)» | Это средняя оценка; худший случай может быть линейным. |
| «Лямбда — особый оператор алгоритма» | Это обычный вызываемый объект-функция, который можно передать алгоритму. |

## Ключевые термины

| Термин | Объяснение |
|---|---|
| Стандартный алгоритм | Готовая функция библиотеки для операции над диапазоном данных. |
| Итератор | Обобщённое средство указать позицию/проход в последовательности. |
| Диапазон `[first, last)` | Полуоткрытая последовательность: начало включено, граница `last` не включена. |
| Лямбда | Локально определяемый объект-функция, часто передаваемый алгоритму. |
| Сложность времени | Рост объёма вычислений с размером входа. |
| Сложность памяти | Рост дополнительной памяти с размером входа. |
| `O(1)`, `O(log n)`, `O(n)`, `O(n log n)` | Классы асимптотического роста. |
| Амортизированная сложность | Средняя оценка серии операций, распределяющая редкие дорогие операции. |
| Компаратор | Вызываемый объект, который задаёт отношение порядка для алгоритма. |
| Инвалидирование | Потеря действительности итератора/ссылки/указателя после изменения контейнера. |
