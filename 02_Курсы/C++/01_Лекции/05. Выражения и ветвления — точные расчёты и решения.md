# 05. Выражения и ветвления — точные расчёты и решения

> [!abstract] О чём лекция
> Из значений строятся выражения, выражения позволяют вычислять, а условные операторы
> выбирают следующий шаг. Научимся учитывать типы, приоритет операций, логические условия
> и крайние случаи.
>
> **Зачем это нужно.** Компилятор может принять формулу с неправильным смыслом: например,
> целочисленное деление в вычислении среднего или условие, которое забывает ровно граничное
> значение. Хорошее ветвление опирается на точное условие и тесты, а не на догадку.
>
> **После лекции ты сможешь:** построить арифметическое выражение, расставить скобки,
> использовать `if`/`else`/`switch`, применять `&&`, `||`, `!` и проверить область допустимых
> значений без незащищённого деления на ноль.

## Выражение — вычисление со значением

**Выражение** — комбинация значений, переменных, операторов и вызовов, которая даёт результат.
Например, `width * height` — выражение, а `area = width * height;` — оператор присваивания,
заканчивающийся `;`.

Операторы, которые понадобятся сейчас:

| Оператор | Значение | Пример |
|---|---|---|
| `+` | сложение | `a + b` |
| `-` | вычитание или унарная смена знака | `a - b`, `-a` |
| `*` | умножение | `a * b` |
| `/` | деление | `distance / time` |
| `%` | остаток целочисленного деления | `17 % 5` даёт `2` |
| `=` | присваивание | `total = 0;` |
| `+=` | прибавить к текущему значению и сохранить | `total += value;` |
| `++` | увеличить на единицу | `++count;` |
| `--` | уменьшить на единицу | `--count;` |
| `-=`, `*=`, `/=` | выполнить операцию и сохранить результат | `total -= value;` |

`total += value` означает «прибавить `value` к `total` и сохранить». Операторы `-=`, `*=`, `/=`
работают по той же схеме; для целого `total /= 2` выполняет целочисленное деление.

У инкремента есть префиксная форма `++count` и постфиксная `count++`: обе увеличивают `count`
на единицу, но как выражения дают соответственно новое и прежнее значение. Уменьшение `--`
устроено аналогично. Когда нужно только изменить счётчик, пиши отдельный оператор (`++count;`);
не прячь инкремент внутри сложного выражения — так проще читать порядок действий.

У `*` и `/` приоритет выше, чем у `+` и `-`, а операции одного уровня в общем случае
группируются слева направо. Но читателю не нужно угадывать приоритет: ставь скобки, если они
показывают структуру расчёта.

> [!note] Как читать короткие примеры
> Если в блоке нет `int main()`, это фрагмент для тела функции, а не самостоятельный `.cpp`.
> Имена, например `total`, `count` или `temperature`, обозначают уже объявленные значения;
> соответствующие типы и необходимые заголовки названы рядом с примером.

Пусть до этого фрагмента объявлены `int total{17}; int count{4};`, причём `count != 0`:

```cpp
const double average{total / count};
```

Это не обязательно считает дробное среднее, если `total` и `count` — целые. Сделай типы
операндов явными:

```cpp
const double average{static_cast<double>(total) / count};
```

Так мы сначала преобразовали числитель, затем деление стало вещественным. При `count == 0`
делить нельзя: правильное решение — проверить предусловие до формулы, а не надеяться на вывод.

## Приоритет и скобки

Скобки должны объяснять формулу. В примере `width`, `height` и `radius` уже объявлены как
`double`; для `std::numbers::pi` подключи `<numbers>`:

```cpp
const double rectangle_area{width * height};
const double circle_area{std::numbers::pi * radius * radius};
```

Во втором выражении нужна директива `#include <numbers>` и C++20. Для краткой записи `radius * radius`
мы не используем `pow`: возведение в квадрат — два умножения, и смысл ясен.

Избегай цепочек сложных преобразований внутри одной строки. Промежуточная переменная с именем
вроде `area_before_discount` помогает объяснить расчёт и поставить breakpoint.

## Сравнения дают `bool`

| Оператор | Значение |
|---|---|
| `==` | равно |
| `!=` | не равно |
| `<`, `>` | меньше, больше |
| `<=`, `>=` | меньше или равно, больше или равно |
| `&&` | логическое И: оба условия истинны |
| `||` | логическое ИЛИ: хотя бы одно условие истинно |
| `!` | логическое НЕ |

Важное отличие: `=` присваивает, `==` сравнивает. Ошибка `if (x = 5)` может изменить значение
вместо проверки. Обычные предупреждения компилятора и аккуратное имя условия помогают найти
такую ошибку.

Например, до фрагмента объявлены `int age{20};`, `double minimum{0.0};`,
`double value{5.0};` и `double maximum{10.0};`:

```cpp
const bool is_adult{age >= 18};
const bool is_valid{minimum <= value && value <= maximum};
```

Диапазон включительно читается как `minimum <= value && value <= maximum`.
Запись `minimum <= value <= maximum` не является математической цепочкой сравнений в C++:
сначала вычислится `minimum <= value` и даст `bool`, затем этот `bool` сравнят с `maximum`.
Всегда соединяй два сравнения `&&`.

## Короткое замыкание — безопасная проверка слева направо

`&&` и `||` вычисляются слева направо и останавливаются, если результат уже известен.
Для следующего фрагмента предполагаются объявленные `int numerator{10}; int denominator{2};`
и `int limit{3};`, а в начале файла подключён `<iostream>`:

```cpp
if (denominator != 0 && numerator / denominator > limit) {
    std::cout << "Large quotient\n";
}
```

Если `denominator == 0`, правая часть `&&` не выполняется, и деления на ноль нет. Это называют
**коротким замыканием**. Порядок важен: размести безопасную проверку слева от операции,
которая требует этой проверки.

Логические таблицы истинности:

| `a` | `b` | `a && b` | `a || b` |
|---|---|---|---|
| `false` | `false` | `false` | `false` |
| `false` | `true` | `false` | `true` |
| `true` | `false` | `false` | `true` |
| `true` | `true` | `true` | `true` |

Не записывай сложную формулу в `if` только потому, что она помещается в строку. Назови её.
Перед фрагментом уже объявлены `int age{20};` и `bool has_permission{true};`:

```cpp
const bool is_eligible{age >= 18 && has_permission};
if (is_eligible) {
    // ...
}
```

## Выбор ветви: `if`, `else if`, `else`

В следующем фрагменте предполагаются `double temperature{0.0};` и заголовок `<iostream>`:

```cpp
if (temperature < 0) {
    std::cout << "Below freezing\n";
} else if (temperature == 0) {
    std::cout << "At freezing point\n";
} else {
    std::cout << "Above freezing\n";
}
```

Условие в круглых скобках должно иметь логический смысл. Код между `{}` выполняется, только
если соответствующее условие истинно. В цепочке `else if` выбирается первая подходящая ветвь;
`else` срабатывает, если предыдущие не подошли.

Даже для одной строки оставляй фигурные скобки: так добавление второй строки не изменит
неожиданно объём ветки.

## Несколько вариантов с `switch`

`switch` подходит, когда одно целочисленное или перечислимое значение выбирает один из
фиксированных вариантов. Здесь перед фрагментом объявлено `int menu_choice{1};`, подключён
`<iostream>`:

```cpp
switch (menu_choice) {
case 1:
    std::cout << "New file\n";
    break;
case 2:
    std::cout << "Open file\n";
    break;
case 0:
    std::cout << "Exit\n";
    break;
default:
    std::cout << "Unknown choice\n";
    break;
}
```

- `case` задаёт значение варианта.
- `break` выходит из `switch`; без него выполнение обычно продолжится в следующую ветку
  (fall-through).
- `default` обрабатывает остальные значения; он необязателен, но полезен для меню.

`switch` не заменяет `if` для произвольных диапазонов, строк или вещественных значений.
Если ветви формулируются как `score >= 90`, `else if` подходит лучше.

## Целочисленный остаток и границы

Для целых положительных чисел `n % 2 == 0` проверяет чётность. Остаток `%` не является
процентом. Для отрицательных операндов знак остатка может удивить; не используй его как
«математический mod» для круговых индексов без нормализации.

Целочисленные переполнения тоже опасны: стандартный знаковый `int` не имеет гарантированного
циклического перехода от максимума к минимуму. Если значение выходит за представимый диапазон,
результат не является безопасным способом продолжить вычисление. Для задач сначала проверь
ограничения и диапазон типа; о более широком выборе и сложных численных моделях поговорим позже.

## Из условия задачи — в проверяемые ветви

Пример: определить, попадает ли целое число в закрытый диапазон от 1 до 100. Здесь уже
объявлены `int score{85};` и подключён `<iostream>`:

```cpp
const bool is_valid_score{score >= 1 && score <= 100};
if (!is_valid_score) {
    std::cout << "Score must be from 1 to 100\n";
} else {
    std::cout << "Score accepted\n";
}
```

Прежде чем писать условие, сформулируй его словами:

1. Каково минимально допустимое значение? Включается ли оно?
2. Каково максимальное допустимое значение? Включается ли оно?
3. Что происходит ровно на каждой границе?
4. Что происходит ниже минимума и выше максимума?

Этот список превращается в тесты `0`, `1`, `100`, `101`.

## Как это делают в проекте

Условие — это решение, которое желательно назвать как бизнес-правило (`is_valid_score`), а не
случайный набор сравнений. Формула отвечает за расчёт, условие — за допустимость/выбор действия;
разделяй их, если это упрощает тестирование. Перед делением, индексированием или чтением поля
проверь предпосылку, от которой безопасность операции зависит.

## Типичные заблуждения

| Заблуждение | Как на самом деле |
|---|---|
| «`=` и `==` делают почти одно и то же» | `=` присваивает, `==` сравнивает и возвращает `bool`. |
| «Цепочка `a < x < b` читается как математика» | В C++ это две операции по порядку, а не связанная математическая цепочка. |
| «Сначала можно разделить, потом проверить делитель» | Делитель проверяют до деления; короткое замыкание помогает только при правильном порядке. |
| «`switch` сам остановится после выбранного `case`» | Обычно нужен `break`, иначе управление провалится в следующую ветвь. |
| «Компилируемый расчёт обязательно точный» | Типы и порядок операций могут потерять дробь, выйти за диапазон или дать приближение. |
| «Одна проверка посередине доказывает диапазон» | Проверяй минимальную, максимальную и соседние недопустимые границы. |

## Ключевые термины

| Термин | Объяснение |
|---|---|
| Выражение | Фрагмент программы, который вычисляет значение или выполняет действие. |
| Оператор присваивания | Действие записи значения в объект, например `total = 0`. |
| Сравнение | Выражение, результат которого имеет тип `bool`. |
| Условие | Логическое выражение, от которого зависит выбор пути выполнения. |
| Короткое замыкание | Пропуск вычисления правой части `&&`/`||`, когда итог уже известен. |
| Ветвление | Выбор кода для выполнения в зависимости от условия. |
| `switch` fall-through | Продолжение выполнения следующего `case`, если управление не остановили. |
| Инвариант | Свойство, которое должно быть истинно в определённой точке алгоритма; позже применим к циклам. |
| Граничный случай | Значение на границе или рядом с ней, которое проверяет условие. |
