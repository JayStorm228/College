# 11. Свои типы и классы — данные с правилами

> [!abstract] О чём лекция
> Встроенные типы описывают числа, символы и логические значения, но предметная область
> состоит из смысловых сущностей. Создадим собственный тип из нескольких значений, затем
> защитим его состояние закрытыми полями и публичными операциями.
>
> **Зачем это нужно.** Если код оперирует несвязанными `double`, `int` и `string`, трудно
> отличить радиус от температуры, а корректность приходится проверять в каждом месте отдельно.
> Класс объединяет данные и правила их использования.
>
> **После лекции ты сможешь:** определить `struct` и `class`, создать конструктор, закрыть
> детали через `private`, описать инвариант, добавить `const`-методы, выбрать композицию вместо
> неуместного наследования и использовать стандартные типы так, чтобы не управлять памятью вручную.

## Когда встроенных типов недостаточно

Допустим, модель хранит координаты точки. Два `double` в отдельных переменных не объясняют,
какой из них `x`, а какой `y`. Можно описать их собственным типом:

```cpp
struct Point {
    double x{};
    double y{};
};

const Point origin{};
const Point target{3.0, 4.0};
```

`Point` — новый тип данных. Экземпляры `origin` и `target` хранят оба координатных значения;
через `.` обращаются к полю (`target.x`). Для простых записей с открытыми данными `struct`
удобен.

> [!warning] Набросок, не универсальная геометрия
> Такой тип допускает любые координаты — в том числе `NaN` и бесконечность. Если задача требует
> ограничений, их надо ввести интерфейсом и проверками. Тип не становится корректным лишь
> потому, что у него красивое имя.

## `struct` и `class`

Оба ключевых слова объявляют пользовательский тип и умеют содержать поля, функции, конструкторы
и другие типы. Важные различия по умолчанию:

| Свойство | `struct` | `class` |
|---|---|---|
| Доступ к членам по умолчанию | `public` | `private` |
| Наследование по умолчанию | публичное | закрытое |

В этом курсе используем `struct` для прозрачной записи с данными, а `class` — когда объект
должен защищать состояние и поддерживать правила. Это соглашение стиля, не ограничение языка.

## Класс с инвариантом: `Rectangle`

У прямоугольника ширина и высота неотрицательны и конечны. Если хранить значения открытыми,
любая часть программы могла бы записать `-10`. Спрячем поля и проверим конструктор:

```cpp
#include <cmath>
#include <stdexcept>

class Rectangle {
public:
    Rectangle(double width, double height)
        : width_{width}, height_{height} {
        if (!std::isfinite(width_) || !std::isfinite(height_) ||
            width_ < 0.0 || height_ < 0.0) {
            throw std::invalid_argument("rectangle dimensions must be finite and non-negative");
        }
    }

    double width() const {
        return width_;
    }

    double height() const {
        return height_;
    }

    double area() const {
        return width_ * height_;
    }

    double perimeter() const {
        return 2.0 * (width_ + height_);
    }

private:
    double width_{};
    double height_{};
};
```

Разбираем структуру:

- `public:` — часть интерфейса, доступная вызывающему коду.
- `private:` — состояние, которое напрямую снаружи менять нельзя.
- `Rectangle(...)` — **конструктор**; его имя совпадает с классом, возвращаемого типа не пишут.
- `: width_{width}, height_{height}` — список инициализации членов. Поля получают аргументы
  при создании, до выполнения тела конструктора.
- Проверка отвергает отрицательные и нечисловые размеры. `throw std::invalid_argument(...)`
  сигнализирует, что аргумент нарушает контракт; подробный перехват исключений разберём
  в лекции [[16. Ошибки, файлы и отладка — инженерный рабочий цикл]].
- Методы `width`, `height`, `area`, `perimeter` — публичные действия/запросы к объекту.
- `const` после скобок означает, что метод обещает не менять состояние объекта.
- Имена полей со `_` в конце — распространённый стиль, помогающий различать поле и параметр.

> [!note] Конечные входы не гарантируют конечный результат
> Проверка размеров гарантирует, что `width` и `height` — конечные и неотрицательные значения,
> но для очень больших конечных `double` произведение в `area()` или сумма/удвоение в
> `perimeter()` могут переполниться до бесконечности. Если предметная область требует конечных
> результатов, задай более узкие допустимые границы и/или отдельно проверяй вычисление.

Полная демонстрация использования:

```cpp
#include <iostream>
#include <stdexcept>

// Вставь сюда определение класса Rectangle из предыдущего примера.

int main() {
    try {
        const Rectangle panel{3.0, 4.0};
        std::cout << "Area: " << panel.area() << '\n';
        std::cout << "Perimeter: " << panel.perimeter() << '\n';
    } catch (const std::invalid_argument& error) {
        std::cerr << "Invalid rectangle: " << error.what() << '\n';
        return 1;
    }
    return 0;
}
```

В примере класс опущен из второго блока, чтобы не дублировать определение; для компиляции
объедини его с первым фрагментом и оставь по одному комплекту `#include`.

## Инвариант и инкапсуляция

**Инвариант класса** — свойство, которое должно сохраняться для каждого корректного объекта.
У `Rectangle` оба измерения конечны и неотрицательны. Конструктор проверяет начальные значения,
поля закрыты, а публичных изменяющих методов пока нет — значит, после создания некорректное
состояние нельзя случайно внести извне.

**Инкапсуляция** объединяет состояние и операции и контролирует доступ к ним. Она не означает
«прятать всё подряд»: публичный интерфейс должен давать именно те операции, которые понятны
пользователю типа.

Если позже появится `resize`, он должен сохранить инвариант: проверить новые размеры до того,
как объект примет их. Метод-проверка возвращает `bool`; метод, который отвергает значение,
может сообщить об этом через исключение или другой явный результат. Выбирай политику и документируй её.

## Композиция: объект состоит из объектов

Тип может содержать уже готовые стандартные типы или другие собственные типы:

```cpp
#include <string>
#include <vector>

struct StudentRecord {
    std::string name{};
    std::vector<int> scores{};
};
```

`StudentRecord` **содержит** строку и набор оценок. Это композиция: сложный объект строится
из частей. Для большинства моделей это проще и безопаснее, чем объявлять наследование.

Стандартные контейнеры управляют своей памятью. Не добавляй `int* scores` с ручным `new[]`
только ради динамического списка оценок — `std::vector<int>` уже решает эту задачу.

## `const`-методы и чтение объекта

```cpp
const Rectangle panel{2.0, 5.0};
std::cout << panel.area() << '\n';
```

Этот вызов допустим, потому что `area()` объявлен `const`. Запрос, который не меняет объект,
обычно следует объявлять `const`: тогда им можно пользоваться с константным объектом и читателю
видно намерение.

Методы, изменяющие состояние, не объявляют `const`. Для простых значений предпочтительны
неизменяемые объекты и результаты, если изменение не является частью задачи.

## `explicit` и неявное создание

Конструктор с одним параметром может участвовать в неявном преобразовании. `explicit` запрещает
часть случайных преобразований:

```cpp
class UserId {
public:
    explicit UserId(int value) : value_{value} {}

private:
    int value_{};
};

UserId id{42};       // намеренное создание
auto other = UserId{7};
// void load(UserId); load(42); // неявный вызов запрещён из-за explicit
```

`UserId` — только эскиз типа; настоящему идентификатору нужны правила допустимых значений.
`explicit` особенно полезен для одноаргументных конструкторов, когда преобразование не очевидно.

## Где заканчивается ответственность класса

Класс не обязан выполнять ввод с клавиатуры, печатать каждое поле и сохранять данные в файл.
Хранение предметного состояния, расчёт и интерфейс ввода/вывода часто лучше разделять. Например,
функция `area()` вычисляет результат, а `main` решает, как попросить пользователя размеры и как
показать площадь.

У класса может быть несколько конструкторов, перегруженные методы и операции, но добавляй их,
когда пользователь типа действительно в них нуждается. Хороший тип делает допустимые операции
очевидными и уменьшает число способов собрать противоречивое состояние.

## Правило нуля для ресурсов

Когда полями объекта являются `std::string`, `std::vector`, `std::unique_ptr` и другие RAII-типы,
они сами освобождают принадлежащие ресурсы. Обычно не нужно самостоятельно писать деструктор,
конструктор копирования и оператор присваивания. Этот подход называют **Rule of Zero**:
проектируй типы на основе типов, которые уже правильно управляют временем жизни.

Класс `Rectangle` не выделяет ресурс, поэтому ему не нужны пользовательские деструкторы.
Управление ресурсами и причина осторожно относиться к `new`/`delete` подробно рассмотрены
в [[12. Ссылки, указатели и время жизни — безопасное владение]].

## Как это делают в проекте

Перед созданием класса спроси:

1. Какие понятия предметной области повторяются и должны быть типом?
2. Какие состояния объекта разрешены?
3. Как класс не позволит получить неразрешённое состояние?
4. Какие запросы и команды входят в публичный интерфейс?
5. Можно ли собрать тип из `string`, `vector` и других готовых компонентов?

Не превращай каждую переменную в класс. Иногда простая структура данных — наиболее ясное решение.

## Типичные заблуждения

| Заблуждение | Как на самом деле |
|---|---|
| «`struct` и `class` — разные механизмы» | Оба объявляют тип; основная языковая разница — доступ по умолчанию. |
| «Закрытое поле само гарантирует корректность» | Инвариант должны поддерживать конструкторы и все изменяющие методы. |
| «Класс — это обязательно наследование» | Большинство полезных классов обходятся полями, методами и композицией. |
| «Метод `const` делает объект физически неизменяемым навсегда» | Он ограничивает изменение через этот интерфейс; сам объект может быть неконстантным и иметь другие операции. |
| «Нужно вручную написать деструктор для каждого класса» | Стандартные RAII-типы часто позволяют следовать Rule of Zero. |
| «Конструктор может молча принять любые данные» | Если значения нарушают контракт, их нужно отвергнуть явно; иначе объект не поддерживает заявленный инвариант. |

## Ключевые термины

| Термин | Объяснение |
|---|---|
| Пользовательский тип | Тип, объявленный программистом для предметного понятия. |
| `struct` | Пользовательский тип с публичным доступом по умолчанию. |
| `class` | Пользовательский тип с закрытым доступом по умолчанию. |
| Поле / член-данные | Значение, которое хранит объект типа. |
| Метод / функция-член | Функция, связанная с типом и имеющая доступ к его интерфейсу. |
| Конструктор | Специальная функция, которая создаёт и инициализирует объект. |
| Список инициализации | Часть определения конструктора, которая инициализирует поля и базовые классы. |
| Инвариант класса | Условие, истинное для каждого корректного состояния объекта. |
| Инкапсуляция | Организация состояния и операций с контролируемым публичным интерфейсом. |
| Композиция | Построение объекта из других объектов («имеет/содержит»). |
| `explicit` | Ключевое слово, блокирующее нежелательные неявные преобразования через конструктор/оператор. |
| Rule of Zero | Проектировать типы так, чтобы управление ресурсами делегировалось готовым RAII-членам. |
