# 12. Ссылки, указатели и время жизни — безопасное владение

> [!abstract] О чём лекция
> C++ позволяет передавать доступ к существующим объектам и управлять ресурсами. Это мощно,
> но ошибка во времени жизни даёт висячие ссылки и трудноуловимые дефекты. Разберём ссылки,
> указатели, `nullptr`, время жизни, RAII и умные указатели C++.
>
> **Зачем это нужно.** Вручную управлять каждой областью памяти трудно и опасно. Профессиональный
> C++ старается ясно отвечать на два вопроса: **кто владеет ресурсом** и **как долго он живёт?**
>
> **После лекции ты сможешь:** передать значение по ссылке или `const&`, проверить nullable
> указатель, не вернуть ссылку на локальный объект, описать владение через `unique_ptr` и
> объяснить, почему сырые `new`/`delete` не являются обычным инструментом начинающего.

## Передача по значению и ссылка

Обычный параметр копирует значение. Для `int` это обычно недорого; копировать большой
`std::string` может быть лишней работой.

```cpp
#include <iostream>
#include <string>

void print_name(const std::string& name) {
    std::cout << name << '\n';
}

void add_one(int& number) {
    ++number;
}
```

> [!note] Контекст следующих примеров
> Блоки без собственного `main` ниже — фрагменты. Для запуска помещай инструкции в `main`;
> функции оставляй на уровне файла. Примеры с `std::cout` требуют `<iostream>`, а функции
> со `std::string` — `<string>`; эти заголовки уже показаны выше, но не повторяются в каждом
> фрагменте. Вызов `invalid_name()` намеренно не нужен: он демонстрирует опасное возвращение ссылки.

`std::string& name` — **ссылка**: второе имя для существующего объекта. Ссылка должна быть
привязана при создании, не может быть «пустой» и после инициализации не переназначается на другой
объект.

- `const std::string&` даёт доступ без копии, но запрещает менять строку через это имя.
- `int&` позволяет функции изменить переменную вызывающей стороны; применяй только когда
  изменение — явная часть контракта.
- Для маленьких скалярных значений вроде `int` обычно передавай по значению.
- Для результата нового объекта чаще возвращай значение: компилятор умеет устранять лишние
  копии, а возвращённый объект принадлежит вызывающей стороне.

Ссылка не продлевает время жизни произвольного объекта так, чтобы он стал вечным. Вызвавший код
должен передать живой объект, который переживёт использование ссылки.

## Указатель: адрес и возможное отсутствие объекта

```cpp
int score{87};
int* score_observer{&score};  // адрес объекта score

if (score_observer != nullptr) {
    std::cout << *score_observer << '\n';  // разыменовать: получить объект по адресу
}

score_observer = nullptr;     // теперь указатель не указывает на объект
```

- `&score` в выражении получает адрес `score`.
- `int*` — тип указателя на `int`.
- `*score_observer` разыменовывает указатель.
- `nullptr` — значение указателя, которое означает «не указывает на объект».

Символ `*` в `int* pointer` объявляет тип указателя, в `*pointer` означает разыменование,
а в `a * b` — умножение. Смысл задаёт контекст.

Разыменовывать можно только ненулевой указатель, который действительно указывает на живой
объект подходящего типа. `nullptr` проверить легко; **устаревший адрес** проверить так нельзя.

## `const` и указатели

| Запись | Можно изменить объект через указатель? | Можно перенаправить указатель? |
|---|---|---|
| `int* p` | Да | Да |
| `const int* p` | Нет | Да |
| `int* const p` | Да | Нет |
| `const int* const p` | Нет | Нет |

Для чтения часто достаточно `const T*` или `const T&`. Квалификатор описывает доступ через это
имя; он не сообщает, кто владеет объектом.

## Время жизни важнее типа адреса

Каждый объект существует в определённый период. **Время жизни** — участок исполнения от начала
жизни объекта до её конца. Имя может выйти из области видимости; объект/его ресурс перестанет
существовать, а сохранённый адрес станет недействительным.

```cpp
int* bad_pointer{};
{
    int local_score{90};
    bad_pointer = &local_score;
}  // local_score перестал существовать

// *bad_pointer здесь разыменовывать нельзя: указатель висячий.
```

Пример намеренно неправильный. `bad_pointer != nullptr` не доказывает, что адрес всё ещё жив.
После выхода из блока указатель не обнулился автоматически.

### Не возвращай ссылку на локальный объект

```cpp
const std::string& invalid_name() {
    const std::string local{"temporary"};
    return local;  // ошибка: после return local уничтожается
}
```

Возвращённая ссылка будет висячей. Верни значение:

```cpp
std::string make_name() {
    std::string result{"safe value"};
    return result;
}
```

Современный компилятор обычно строит результат прямо в месте вызова или перемещает его;
не заменяй безопасный возврат по значению ссылкой ради воображаемой оптимизации.

## Область видимости, автоматическое и динамическое хранилище

- Локальный объект, созданный в блоке, обычно имеет **автоматическую длительность хранения**:
  он живёт до выхода из области.
- Глобальный объект или `static`-объект имеет **статическую длительность**: живёт в течение
  соответствующей части программы.
- Динамически выделенный объект живёт до освобождения ресурса.

Часто динамическую память связывают со словом «куча», локальные переменные — со «стеком».
Это полезная схема для первого знакомства, но физическая организация зависит от реализации;
главное правило языка — время жизни и владение, а не адрес в конкретной аппаратной области.

Не создавай динамический объект без необходимости. `std::string`, `std::vector` и многие другие
типы сами владеют своим хранилищем и корректно освобождают его.

## RAII: ресурс следует за временем жизни владельца

**RAII** (Resource Acquisition Is Initialization) связывает ресурс с объектом-владельцем:
объект получил ресурс при создании и освобождает его, когда заканчивается время жизни объекта.
`std::vector` владеет памятью элементов, `std::ifstream` владеет файловым дескриптором,
`std::unique_ptr` — динамическим объектом.

```cpp
#include <iostream>
#include <memory>

int main() {
    auto owner{std::make_unique<int>(42)};
    std::cout << *owner << '\n';
    // При выходе owner уничтожится и освободит принадлежащий int.
    return 0;
}
```

Не надо вызывать `delete`: он выполняется через деструктор `unique_ptr`. Это защищает от части
ошибок: забыть освобождение, освободить дважды или освободить ресурс при раннем выходе.

## `unique_ptr`: один владелец

`std::unique_ptr<T>` выражает **исключительное владение**: один умный указатель отвечает за
ресурс. Его нельзя скопировать, но можно передать новому владельцу:

```cpp
#include <iostream>
#include <memory>
#include <utility>

int main() {
    auto first_owner{std::make_unique<int>(42)};
    auto second_owner{std::move(first_owner)};

    if (!first_owner) {
        std::cout << "first_owner is empty\n";
    }
    std::cout << *second_owner << '\n';
    return 0;
}
```

`std::move` **сам не перемещает память**; он превращает выражение в форму, по которой функция
может выбрать перемещающий конструктор/операцию. Конкретно `unique_ptr` передаёт владение,
после чего `first_owner` пуст. Используй moved-from объект только в разрешённых операциях
(например, присвоить новое значение или проверить/уничтожить его); не считай, что у него
сохранился старый ресурс.

В повседневном коде `std::unique_ptr` нужен только когда динамическое время жизни действительно
необходимо, например для полиморфной коллекции. Если достаточно локального `Rectangle`,
`std::vector<Rectangle>` или возвращаемого значения, не оборачивай всё в указатель.

## `shared_ptr`: совместное владение — исключение, не режим по умолчанию

`std::shared_ptr<T>` использует совместный подсчёт владельцев: ресурс освобождается, когда
заканчивается последний сильный владелец. Это удобно только если несколько частей программы
действительно владеют одним объектом и их жизненные циклы независимы.

Совместное владение добавляет учёт, может скрыть ответственность и образовать циклы. Для
обычного владения сначала рассматривай значение/контейнер или `unique_ptr`. `std::weak_ptr`
может разорвать цикл наблюдателя и владельца, но это отдельная тема продвинутого управления
графом объектов.

## Сырой указатель — обычно наблюдатель, не владелец

В современном C++ выражение `T*` часто обозначает необязательный **невладеющий доступ** к объекту.
Владелец может быть обычным объектом или smart pointer. Направленный к чужому ресурсу raw
pointer не должен освобождать его, если контракт владения явно не говорит обратного.

Сырые `new` и `delete` существуют, но прямое управление ими приводит к утечкам и двойному
освобождению. В учебном и профессиональном прикладном коде используй RAII-контейнеры и
умные указатели, а ручное управление оставь специальным слоям, где есть веская причина.

## Инвалидирование адресов контейнера

`std::vector` может переместить элементы, когда увеличивает внутреннее хранилище. Ссылка,
указатель или итератор на старый адрес после такой операции может стать недействительным.
Не сохраняй адрес элемента и не добавляй элементы, а затем продолжай пользоваться адресом,
если не изучил правила конкретной операции.

## Как это делают в проекте

При проектировании функции сначала выбирай простую семантику:

1. Маленькое значение — передача по значению.
2. Большое значение только для чтения — обычно `const T&`.
3. Функция должна изменить объект вызывающего кода — `T&` и явно указать это в контракте.
4. Объект необязателен — ссылка не подходит; рассмотри указатель-обозреватель или
   `std::optional<T>` в зависимости от интерфейса.
5. Функция возвращает результат — обычно возвращай по значению.
6. Нужен динамический владелец — предпочти `std::unique_ptr`; совместное владение проектируй
   только с объяснением, кому оно действительно нужно.

И для каждого адреса спроси: «Кто владеет объектом? Будет ли он жив, пока я им пользуюсь?»

## Типичные заблуждения

| Заблуждение | Как на самом деле |
|---|---|
| «Ссылка — безопасный указатель, который никогда не бывает висячим» | Ссылка не может быть null, но всё равно может пережить объект, на который ссылается. |
| «Ненулевой указатель всегда валиден» | Он может указывать на уже уничтоженный объект. |
| «`std::move` перемещает объект сам по себе» | Это преобразование категории выражения; перемещение происходит, если выбран соответствующий конструктор/операция. |
| «Всё надо выделять через `new`, чтобы не потерялось» | Локальные объекты и контейнеры управляют временем жизни проще; динамическое владение выбирают под задачу. |
| «`shared_ptr` — самый безопасный умный указатель» | Он безопасен только при реальном совместном владении; для одного владельца яснее `unique_ptr`. |
| «`const&` гарантирует, что объект вообще не изменится» | Оно запрещает изменение через данную ссылку, но другой доступ к неконстантному объекту может существовать. |

## Ключевые термины

| Термин | Объяснение |
|---|---|
| Ссылка | Объявленное имя-алиас для существующего объекта. |
| Указатель | Значение, которое хранит адрес объекта или `nullptr`. |
| Разыменование | Получение объекта, на который указывает корректный указатель. |
| `nullptr` | Специальное пустое значение указателя. |
| Время жизни | Период, когда объект существует и к нему разрешён доступ. |
| Висячая ссылка/указатель | Доступ, который пережил объект и больше не может безопасно использоваться. |
| Владение | Ответственность за срок жизни и освобождение ресурса. |
| RAII | Связь получения/освобождения ресурса с жизненным циклом объекта-владельца. |
| `std::unique_ptr` | Умный указатель с одним владельцем. |
| `std::shared_ptr` | Умный указатель с совместным владением и подсчётом сильных владельцев. |
| Перемещение | Передача ресурса/состояния из объекта без обязательного копирования. |
| Инвалидирование | Ситуация, когда сохранённый итератор/указатель/ссылка становится недействительным после операции. |
