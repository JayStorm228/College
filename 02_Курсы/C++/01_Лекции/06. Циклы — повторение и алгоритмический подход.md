# 06. Циклы — повторение и алгоритмический подход

> [!abstract] О чём лекция
> Цикл повторяет действие, пока выполняется условие. Учимся выбирать `while`, `for` и
> `do-while`, считать сумму и количество, замечать бесконечный цикл и доказывать, что повторение
> продвигается к завершению.
>
> **Зачем это нужно.** Компьютер хорошо повторяет точные действия, но не понимает «остановись,
> когда достаточно». Условие и изменение состояния должны быть связаны с целью задачи.
>
> **После лекции ты сможешь:** построить цикл с ясным условием остановки, подобрать цикл для
> известного/неизвестного числа повторов, проследить значения по итерациям, найти off-by-one
> ошибку и сформулировать простой инвариант накопления.

> [!note] Контекст коротких примеров
> Блоки без собственного `int main()` — фрагменты для тела `main`; если в них есть `std::cout`,
> подключи `<iostream>` и оберни фрагмент фигурными скобками функции. Имена-плейсхолдеры вроде
> `should_continue` и `should_stop` означают условие, которое программа должна вычислять сама;
> некоторые блоки показывают форму алгоритма, а не законченный запускаемый файл.

## Задача цикла

Без цикла, чтобы вывести числа от 1 до 5, пришлось бы написать пять похожих команд. Цикл
описывает повторяющийся шаблон один раз и меняет значение, которое участвует в следующем шаге.

У каждого корректного цикла есть три части:

1. **Начальное состояние** — с чего начинаем.
2. **Продвижение** — что меняется за итерацию.
3. **Условие остановки** — когда повторять больше не нужно.

Если хотя бы одной части нет или она не связана с другими, цикл может выполниться неверное число
раз или никогда не закончиться.

## `while`: повторять, пока условие истинно

```cpp
int count{1};
while (count <= 5) {
    std::cout << count << '\n';
    ++count;
}
```

Перед каждым проходом проверяется `count <= 5`. Когда `count` становится `6`, тело больше
не выполняется. Если условие ложно до первого прохода, цикл может сделать **ноль** итераций.
Это удобно, если заранее неизвестно, сколько раз придётся повторять действие.

Проследим таблицей:

| Проверка | Условие | Вывод тела | Значение после `++count` |
|---:|---|---:|---:|
| 1 | `1 <= 5` — true | 1 | 2 |
| 2 | `2 <= 5` — true | 2 | 3 |
| 3 | `3 <= 5` — true | 3 | 4 |
| 4 | `4 <= 5` — true | 4 | 5 |
| 5 | `5 <= 5` — true | 5 | 6 |
| 6 | `6 <= 5` — false | тело пропущено | — |

Эта ручная трассировка — простой и мощный способ понять код до запуска.

## `for`: число повторений видно рядом

Если нужно пройти счётчик по диапазону, `for` объединяет начало, условие и изменение:

```cpp
for (int number{1}; number <= 5; ++number) {
    std::cout << number << '\n';
}
```

Схема записи (это обозначения частей синтаксиса, а не готовая программа):

```text
for (инициализация; условие; шаг) {
    тело цикла
}
```

- Инициализация выполняется один раз.
- Условие проверяется перед каждой итерацией.
- Шаг выполняется после тела, если условие было истинно.

`number` живёт только внутри цикла. Это желательное ограничение: счётчик не случайно не меняется
после завершения `for`.

Сравниваем `i < limit` (ровно `limit` повторов для нуля до `limit-1`) и `i <= limit`
(включительно до `limit`). Выбор зависит от условия, а не от привычки.

## `do-while`: тело хотя бы один раз

```cpp
do {
    std::cout << "Enter 1 to continue, 0 to stop: ";
    // запрос и чтение команды
} while (should_continue);
```

У `do-while` сначала выполняется тело, потом условие; после закрывающей скобки нужна точка
с запятой. Он полезен, если первый запрос должен появиться обязательно. Для чтения и проверки
потоков ввода нужен отдельный разговор, поэтому пока не используй этот шаблон для бесконечного
«пока ввод корректен».

## Сумма и инвариант цикла

Задача: вычислить сумму целых чисел от 1 до `n`. Демонстрация ниже намеренно использует
небольшое `n = 5`:

```cpp
long long n{5};
long long total{};
for (long long value{1}; value <= n; ++value) {
    total += value;
}
```

После окончания `total` равен `15`. Если обобщаешь пример на большой пользовательский `n`,
нужны явные ограничения: итоговая сумма должна помещаться в тип, и счётчик должен безопасно
достичь значения после последней итерации. Сам факт, что `n` помещается в тип, ещё не гарантирует,
что и сумма помещается. Чтобы обосновать результат, опиши **инвариант** — свойство, которое
верно после каждого завершённого шага:

> Перед обработкой `value` переменная `total` содержит сумму чисел от 1 до `value - 1`.

В начале `value == 1`, поэтому уже накоплена пустая сумма `0`. На шаге к ней добавляется
текущее `value`; затем счётчик увеличивается. Когда `value == n + 1`, весь диапазон уже
обработан. Такой разбор помогает проверить границы и объяснить, почему цикл считает именно то,
что требуется.

> [!warning] Диапазон и переполнение
> Пример выше показывает идею. Для большого `n` накопленная сумма может переполнить тип,
> даже если само `n` в него помещается; счётчик также может переполниться при попытке сделать
> шаг после последнего значения. Проверяй ограничения и выбирай безопасный диапазон для всех
> промежуточных результатов.

## Посчитать минимум и максимум

Нельзя брать `values[0]`, пока не доказано, что элементов хотя бы один. Для будущей коллекции
алгоритм будет выглядеть так:

```cpp
// Предусловие: значения непусты.
int minimum{values[0]};
for (int index{1}; index < count; ++index) {
    if (values[index] < minimum) {
        minimum = values[index];
    }
}
```

Пока массива и `vector` ещё нет: этот фрагмент иллюстрирует ход алгоритма, но его нельзя
скомпилировать без объявления `values` и `count`. Мы реализуем такой обход после блока
[[08. Строки и коллекции — string, vector, array]]. Главное наблюдение: первое значение служит
начальным кандидатом; мы не придумываем магическое число вроде `999999`.

## Бесконечный цикл, `break` и `continue`

```cpp
while (true) {
    // тело
    if (should_stop) {
        break;
    }
}
```

`break` немедленно выходит из ближайшего цикла. `continue` пропускает остаток тела и начинает
следующую итерацию. Оба инструмента могут быть уместны, но если остановка скрыта в нескольких
вложенных местах, алгоритм сложнее прочитать. Для первых задач предпочитай условие цикла,
которое прямо объясняет, когда работа завершится.

Бесконечный цикл не всегда ошибка — сервер может постоянно обслуживать запросы, пока его не
остановят. Но в консольной учебной программе цикл должен иметь явно запланированный выход.

## Вложенные циклы

Для таблицы умножения внешний цикл выбирает строку, внутренний — столбец:

```cpp
for (int row{1}; row <= 3; ++row) {
    for (int column{1}; column <= 3; ++column) {
        std::cout << row * column << ' ';
    }
    std::cout << '\n';
}
```

Внутреннее тело выполняется для каждой пары `(row, column)`. Если оба диапазона имеют длину `n`,
число действий растёт примерно как `n * n`. Формальную оценку сложности разберём в блоке 17.

## Метод ручной трассировки

Перед запуском сложного цикла выпиши:

1. Значение счётчика и накопителя до первой проверки.
2. Условие, которое проверяется.
3. Изменения в теле.
4. Изменение счётчика.
5. Состояние сразу после последней итерации.

Для ловли ошибки «на один раз» проверь маленький вход: `n = 0`, `n = 1`, затем обычный пример.
Если цикл должен обработать 1..n, отдельно проверь, что он не пропустил `n` и не обработал `n+1`.

## Частые причины бесконечного цикла

- счётчик не меняется;
- он меняется в неправильном направлении: `value` уменьшается, а условие требует `value <= n`;
- условие проверяет другую переменную, не связанную с прогрессом;
- изменение переполняет тип и не может безопасно достичь условия остановки.

Когда программа «зависла», не нажимай случайные клавиши в цикле. Останови её, найди проверку,
запиши начальное состояние и посмотри, какое значение меняется.

## Как это делают в проекте

Цикл полезен, когда повторяется один алгоритмический шаг. Переменные внутри него часто имеют
три роли: **счётчик**, **накопитель** (сумма, количество) и **текущий элемент/состояние**.
Дай каждой роли ясное имя. До реализации опиши, сколько элементов должно быть обработано и
каково условие выхода. После реализации трассируй самый маленький и пограничный пример.

## Типичные заблуждения

| Заблуждение | Как на самом деле |
|---|---|
| «Тело `while` выполняется хотя бы один раз» | Условие проверяется первым; при ложном условии будет ноль проходов. |
| «`for` всегда лучше `while`» | `for` удобен для счётчика; `while` лучше отражает неизвестное число повторов. |
| «`i <= n` и `i < n` почти одно и то же» | Разница ровно в граничном элементе; выбери сравнение по диапазону задачи. |
| «Сумму можно начать с первой добавляемой переменной без значения» | Накопитель должен иметь осмысленное начальное значение, обычно ноль. |
| «Бесконечный цикл всегда компилятор распознает и исправит» | Компилятор не знает намеренную точку остановки задачи; её надо спроектировать. |
| «Внутренний цикл — просто ещё один проход» | Его тело повторяется для каждого шага внешнего; объём работы быстро растёт. |

## Ключевые термины

| Термин | Объяснение |
|---|---|
| Итерация | Один проход тела цикла. |
| Счётчик | Переменная, которая обычно обозначает текущий шаг или число повторений. |
| Накопитель | Переменная, которая объединяет результаты многих шагов, например сумму. |
| Инвариант цикла | Свойство, которое сохраняется на выбранной границе каждой итерации. |
| Off-by-one | Ошибка границы: выполнить на один шаг больше или меньше нужного. |
| Вложенный цикл | Цикл внутри тела другого цикла. |
| Бесконечный цикл | Цикл, который не достигает условия выхода; может быть намеренным или ошибочным. |
| Трассировка | Ручная запись значений и состояний программы по порядку выполнения. |
