# 01. Среда разработки и Visual Studio

> [!abstract] О чём лекция
> Настраиваем **Microsoft Visual Studio на Windows** и разбираемся, из каких инструментов
> состоит рабочее место программиста. Пока не считаем кнопку Build объяснением компиляции:
> до привычной сборки в IDE мы отдельно соберём программу через g++ и увидим этапы.
>
> **Зачем это нужно.** Если не установлена нужная рабочая нагрузка или создан не тот проект,
> IDE либо не найдёт C++-компилятор, либо создаст приложение другого типа. Настроенная среда
> убирает лишнюю неопределённость, но не заменяет понимание языка и сборки.
>
> **После лекции ты сможешь:** отличить Visual Studio от Visual Studio Code, выбрать нужные
> компоненты, создать консольный C++-проект, найти файл исходного кода и настройки языка,
> объяснить, что именно пока не следует принимать за «магическую сборку».

## Сначала разберём названия

- **Visual Studio** — полноценная IDE для Windows. В ней есть редактор, управление проектом,
  интеграция с компиляторами и отладчик.
- **Visual Studio Code** — отдельный лёгкий редактор. Расширение C/C++ добавляет подсказки
  и отладочные возможности, но само по себе не устанавливает компилятор и не превращает
  VS Code в Visual Studio. В этом курсе нужен **Visual Studio**, не VS Code.
- **IDE** (интегрированная среда разработки) объединяет редактор, сборку и отладчик в одном
  приложении. IDE помогает вызывать инструменты; она не является языком C++.
- **Компилятор** проверяет и переводит исходный код; **компоновщик** объединяет части
  программы; **отладчик** позволяет останавливать программу и проверять её состояние.
  Как это связано в реальной сборке, разберём в следующей лекции на g++.

## Установка Visual Studio на Windows

Инструкция зависит от текущего установщика, поэтому за сверкой интерфейса переходи к
[официальной инструкции Microsoft](https://learn.microsoft.com/en-us/cpp/build/vscpp-step-0-installation?view=msvc-170).

1. Открой официальный [раздел загрузок Visual Studio](https://visualstudio.microsoft.com/downloads/)
   и скачай актуальный установщик редакции **Community**, если её лицензионные условия подходят
   для твоего использования.
2. Запусти Visual Studio Installer. На шаге выбора функций отметь рабочую нагрузку
   **Desktop development with C++** (в русской локализации — «Разработка классических
   приложений на C++» или близкое название).
3. Проверь, что в установке выбран современный **MSVC C++ build tools** и **Windows SDK**.
   Если название или расположение компонентов изменились, сверься с текущей инструкцией
   Microsoft, а не включай неизвестные пункты наугад.
4. Установи IDE и открой Visual Studio. Для этой программы не нужно дополнительно ставить
   Visual Studio Code, расширения VS Code или сторонний «компилятор для Visual Studio».
5. Если Visual Studio уже установлена, открой Visual Studio Installer → **Modify** и добавь
   только недостающую рабочую нагрузку.

> [!warning] Не путай установщик IDE с языковым стандартом
> Наличие Visual Studio не означает автоматически, что каждый проект собирается в режиме C++20.
> Версию стандарта задают настройкой конкретного проекта. Мы проверим её ниже и позже сравним
> результат с командой g++.

## Создаём консольный проект

Официальный маршрут Microsoft: [создание C++ console app](https://learn.microsoft.com/en-us/cpp/build/vscpp-step-1-create?view=msvc-170).

1. Выбери **File → New → Project**.
2. Найди шаблон **Console App** с языком C++ и платформой Windows. Если его нет, вернись
   в Visual Studio Installer и проверь `Desktop development with C++`.
3. Назови проект `HelloCpp`. Для учебной работы используй простое имя без точек и не клади
   исходник в случайную папку загрузок.
4. В Solution Explorer найди созданный файл `.cpp`. Это текст программы. Solution — контейнер
   для проекта или нескольких проектов; проект хранит настройки сборки и список файлов.
5. Открой **Project → Properties → C/C++ → Language** и выбери стандарт ISO C++20
   (`/std:c++20`), если установленный MSVC предлагает эту настройку. Выбери одну конфигурацию
   и платформу и проверь её в селекторах окна Properties: свойства могут различаться для
   Debug/Release и x64/Win32.
6. В **C/C++ → General** посмотри настройку уровня предупреждений. В учебной работе оставь
   предупреждения включёнными; не выключай диагностику только ради исчезновения сообщения.

На этом шаге мы **создали и изучили проект, но ещё не делаем IDE единственным способом сборки**.
В уроке 02 сначала увидим запуск того же простого кода из терминала через g++.

## Что ты видишь в IDE

| Элемент | Простое объяснение | Что он не означает |
|---|---|---|
| Редактор | Место, где открыт текст `.cpp` | Он не запускает код сам по себе |
| Solution Explorer | Дерево проектов и файлов решения | Папка в дереве не всегда равна папке на диске |
| Build | Просит выбранную систему сборки собрать проект | Build не гарантирует, что программа логически верна |
| Error List / Output | Диагностика компилятора, компоновщика и системы сборки | Сообщения разных инструментов надо различать |
| Debug / Start | Запускает процесс; с отладчиком может остановить его на breakpoint | Отладчик не доказывает правильность алгоритма |
| Properties | Настройки стандарта, компилятора, путей и формата программы | Это настройки проекта, а не «настройки всего языка C++» |

## Как это делают в проекте

Перед сборкой разработчик проверяет: **какой проект, какая конфигурация, какой стандарт,
какие исходные файлы и какие предупреждения выбраны?** Это помогает не отлаживать случайный
проект или не ту версию программы.

Когда появится код, мы будем пользоваться привычным циклом:

1. Сохранить файл.
2. Собрать проект и прочитать первое сообщение об ошибке сверху.
3. Исправить причину, а не случайную последующую ошибку.
4. Запустить без отладчика или под отладчиком.
5. Сравнить фактический результат с ожидаемым тестом.

## Типичные заблуждения

| Заблуждение | Как на самом деле |
|---|---|
| «Visual Studio и VS Code — два названия одного приложения» | Это разные продукты; этот курс использует Visual Studio на Windows. |
| «Раз появился шаблон C++, компилятор точно установлен» | Проверь рабочую нагрузку `Desktop development with C++` и MSVC build tools. |
| «Проект и исходный файл — одно и то же» | Проект хранит настройки и объединяет файлы; `.cpp` содержит код. |
| «Если IDE собрала приложение, алгоритм правильный» | Компилятор проверяет правила языка и часть ошибок; логическая ошибка может компилироваться успешно. |
| «Предупреждение можно всегда убрать кнопкой Suppress» | Сначала прочитай его и исправь причину; подавляй только с обоснованием и узкой областью действия. |

## Ключевые термины

| Термин | Объяснение |
|---|---|
| IDE | Программа, которая объединяет инструменты редактирования, сборки и отладки. |
| Visual Studio | Полноценная среда разработки Microsoft для Windows; используется в курсе. |
| Visual Studio Code | Отдельный редактор, не выбранный основной средой этого курса. |
| Solution | Контейнер Visual Studio, который может объединять проекты. |
| Project | Набор исходных файлов и настроек, по которым система собирает приложение. |
| Конфигурация | Набор параметров сборки, обычно Debug или Release. |
| Windows SDK | Заголовки и инструменты для разработки под Windows. |
| MSVC | Компилятор C++ и связанный набор инструментов Microsoft. |
