# 08. Строки и коллекции — `string`, `vector`, `array`

> [!abstract] О чём лекция
> Реальная программа обрабатывает не одно число, а набор элементов и текст. Разберём
> `std::string`, динамический контейнер `std::vector`, контейнер фиксированного размера
> `std::array`, индексы, обход элементов и безопасную проверку пустого набора.
>
> **Зачем это нужно.** Несколько отдельных переменных не образуют удобный набор данных.
> Контейнер хранит элементы одного типа, а цикл позволяет обработать их единообразно.
>
> **После лекции ты сможешь:** создать строку и последовательность значений, добавить элемент
> в vector, пройти по контейнеру, не выйти за границу индекса, вычислить простую сводку и объяснить,
> почему число элементов и последняя позиция — разные величины.

## Строка — последовательность текста

`std::string` объявлен в `<string>` и хранит строку:

```cpp
#include <iostream>
#include <string>

int main() {
    std::string title{"C++ course"};
    std::cout << title << '\n';
    std::cout << "Characters/bytes reported by size: " << title.size() << '\n';
    return 0;
}
```

Следующий блок — фрагмент для тела функции, не отдельный файл. В программе подключи `<string>`;
если хочешь увидеть результат, выведи `greeting` через `std::cout` из `<iostream>`.

Частые операции:

```cpp
std::string first_name{"Pavel"};
std::string greeting{"Hello, "};
greeting += first_name;
greeting += '!';
```

- `size()` возвращает количество хранимых кодовых единиц (для `std::string` обычно байтов),
  а не гарантированное число видимых букв.
- `empty()` проверяет, пуста ли строка.
- `+=` добавляет текст/символ к строке.
- `find("course")` ищет подстроку. Если совпадения нет, результат равен `std::string::npos`.

В UTF-8 русская буква часто занимает несколько байтов. Поэтому `name.size()` может быть больше
числа видимых символов. Для первых задач обрабатывай ASCII-символы или используй строку как
непрозрачный пользовательский текст; корректная работа с Unicode-графемами требует отдельной
библиотеки и правил.

## Контейнер хранит набор однородных элементов

**Контейнер** — объект стандартной библиотеки, который управляет коллекцией элементов. Два
последовательных контейнера:

- `std::array<T, N>` — количество элементов фиксировано в типе `N`;
- `std::vector<T>` — последовательность, которая может увеличиваться и уменьшаться во время
  выполнения.

Элементы одного `vector` имеют один тип `T`. Пример:

```cpp
#include <iostream>
#include <vector>

int main() {
    std::vector<int> scores{};
    scores.push_back(82);
    scores.push_back(95);
    scores.push_back(71);

    std::cout << "Count: " << scores.size() << '\n';
    return 0;
}
```

`push_back` добавляет значение в конец, а `size()` сообщает количество элементов.
`vector` управляет памятью самостоятельно; в обычном коде не нужно вручную выделять память
через `new` или освобождать через `delete`.

## Скобки при создании `vector`

Два похожих объявления **внутри функции** имеют разный смысл. Следующие блоки — фрагменты:
включи `<vector>` и помести объявления внутрь `main` или другой функции.

```cpp
std::vector<int> five_zeros(5);   // пять элементов со значением 0
std::vector<int> one_five{5};     // один элемент со значением 5
```

Это частая ловушка синтаксиса. При нулевой/пустой коллекции удобна запись `std::vector<int> values{};`,
затем добавляй элементы через `push_back`. При фиксированном наборе значений `{}` может выступать
списком элементов:

```cpp
std::vector<int> small_scores{82, 95, 71};
```

## `std::array`: размер известен заранее

```cpp
#include <array>
#include <iostream>

int main() {
    std::array<int, 3> weekday_counts{};
    weekday_counts[0] = 20;
    weekday_counts[1] = 18;
    weekday_counts[2] = 22;

    std::cout << weekday_counts[0] << ' '
              << weekday_counts[1] << ' '
              << weekday_counts[2] << '\n';
    return 0;
}
```

Размер `3` является частью типа. В этом примере `[0]`, `[1]`, `[2]` — позиции; последняя
позиция равна `size() - 1`, если коллекция непуста.

`std::array<int, 3> counts{}` создаёт три значения `0`. Нельзя добавить четвёртый элемент:
размер контейнера фиксирован.

## Размер и индексы — не одно и то же

Если в контейнере `n` элементов, допустимые индексы: `0` до `n - 1` включительно. При `n == 0`
допустимого индекса нет.

> [!note] Фрагменты обхода
> Следующие три блока — фрагменты тела `main`, не отдельные программы. Они предполагают, что
> `scores` — уже объявленный `std::vector<int>`; для этого раздела нужны `<vector>` и `<iostream>`.
> В цикле с `std::size_t` явно подключи также `<cstddef>`.

```cpp
if (!scores.empty()) {
    std::cout << scores[0] << '\n';
}
```

`operator[]` (`scores[index]`) не проверяет границу. Выйти за неё — ошибка программы с
неопределённым поведением. `scores.at(index)` проверяет границу и при неверном индексе
выбрасывает исключение; это не заменяет проектирование корректного диапазона, но помогает
диагностике.

Правильная граница цикла:

```cpp
for (std::size_t index{}; index < scores.size(); ++index) {
    std::cout << scores[index] << '\n';
}
```

`std::size_t` — беззнаковый тип, которым стандартные контейнеры представляют размер и индекс.
Условие `index < scores.size()` даёт ровно существующие позиции. В блоке про ссылки/время жизни
рассмотрим безопасный обход без индекса.

## Range-based `for`: пройти все элементы

Для многих задач индекс вообще не нужен:

```cpp
for (const int score : scores) {
    std::cout << score << '\n';
}
```

`const int score` получает копию каждого значения; для простого `int` это недорого.
`const` предотвращает случайное изменение локальной копии и показывает, что мы только читаем.
Если для тяжёлых объектов копирование нежелательно, позже применим `const T&`.

При обходе контейнера не меняй его размер без понимания правил инвалидирования итераторов и
ссылок: добавление элементов может переместить хранилище vector. Подробно разберём это после
темы времени жизни.

## Пример: среднее по измерениям

```cpp
#include <iostream>
#include <vector>

int main() {
    const std::vector<double> measurements{18.5, 20.0, 19.5};

    if (measurements.empty()) {
        std::cout << "No measurements\n";
        return 0;
    }

    double total{};
    for (const double value : measurements) {
        total += value;
    }

    const double average{total / static_cast<double>(measurements.size())};
    std::cout << "Average: " << average << '\n';
    return 0;
}
```

Проверка пустоты важна: нельзя делить на количество `0`, а вывод «среднее равно нулю» был бы
неверным для набора без измерений. Преобразование `size()` к `double` здесь написано явно,
потому что мы хотим вещественное деление и не сравниваем число с произвольной размерностью.
Для больших реальных выборок надо также рассмотреть диапазон и точность суммы.

## Строка тоже обходится по элементам

В следующем отдельном фрагменте цикл находится внутри функции; подключи `<iostream>` и `<string>`:

```cpp
const std::string word{"code"};
for (const char symbol : word) {
    std::cout << symbol << '\n';
}
```

Для ASCII это ожидаемо: каждый байт представляет один символ. Для UTF-8 многобайтовый символ
будет показан несколькими `char`, поэтому этот цикл не является универсальным Unicode-обходом.

## `vector`, массив и `string` — какой выбрать?

| Если задача просит | Обычно начни с |
|---|---|
| Изменяемую последовательность однотипных значений неизвестной длины | `std::vector<T>` |
| Последовательность фиксированного размера, известного при компиляции | `std::array<T, N>` |
| Текст | `std::string` |
| Одиночное число/флаг | Соответствующий скалярный тип, например `int` или `bool` |

Не нужно самостоятельно придумывать связанный список или динамический массив, пока стандартный
контейнер решает задачу яснее и безопаснее.

## Как это делают в проекте

Сначала выясни: **какие элементы храним, сколько их может быть, нужен ли динамический размер,
важен ли индекс?** После выбора контейнера проверь пустую последовательность и верхнюю границу.
Для простого чтения предпочитай range-based `for`; индекс вводи, когда задача действительно
опирается на позицию.

## Типичные заблуждения

| Заблуждение | Как на самом деле |
|---|---|
| «У vector размера `n` индексы от 1 до `n`» | Индексация с нуля: позиции `0` … `n-1`. |
| «`scores[3]` — четвёртый элемент при любом размере» | Он существует, только когда контейнер содержит не менее четырёх элементов. |
| «`std::vector<int> values{5}` — это пять нулей» | Это один элемент со значением `5`; пять элементов создаёт `values(5)`. |
| «`reserve(100)` создаёт 100 элементов» | `reserve` меняет вместимость, но не размер; здесь пока просто не нужен. |
| «`string.size()` всегда считает буквы» | Для UTF-8 он обычно сообщает число байтов/кодовых единиц. |
| «Можно удалить/добавить элемент во время любого обхода» | Модификация vector может переместить данные и сделать текущие ссылки/итераторы недействительными. |

## Ключевые термины

| Термин | Объяснение |
|---|---|
| Контейнер | Объект стандартной библиотеки, который хранит коллекцию элементов. |
| `std::string` | Стандартный контейнер текста, основанный на последовательности `char`. |
| `std::vector<T>` | Последовательный контейнер переменного размера с элементами типа `T`. |
| `std::array<T, N>` | Последовательный контейнер фиксированного размера `N`. |
| Индекс | Числовая позиция элемента; у последовательных контейнеров начинается с нуля. |
| `size()` | Число элементов контейнера, не индекс последнего элемента. |
| Range-based `for` | Цикл, проходящий элементы коллекции без явного счётчика индексов. |
| `std::size_t` | Беззнаковый тип, используемый стандартной библиотекой для размеров. |
| Вместимость | Сколько элементов контейнер может хранить без перераспределения; это не его текущий размер. |
| Неопределённое поведение | Ситуация, для которой стандарт не задаёт гарантированного поведения; выход за границы `[]` — опасный пример. |
