# 02. Консоль и g++ — путь от исходника до запуска

> [!abstract] О чём лекция
> Устанавливаем Linux внутри Windows через WSL2, учимся читать приглашение терминала и
> прослеживаем, что происходит между файлом `.cpp` и работающей программой. Впервые
> собираем маленькую программу через g++ и отдельно рассматриваем этапы сборки.
>
> **Зачем это нужно.** Если IDE сообщает «linker error», «не найден файл» или «команда не
> распознана», понимание терминала и стадий сборки помогает определить, на каком этапе проблема.
>
> **После лекции ты сможешь:** отличить PowerShell от Bash, перейти в папку проекта,
> посмотреть файлы, установить g++ в Ubuntu WSL, собрать и запустить программу, объяснить
> разницу препроцессора, компиляции, ассемблирования и компоновки.

## Что такое консоль, терминал и оболочка

Представь, что компьютер — исполнитель, который ждёт точные инструкции. **Терминал** — окно,
в которое вводят текстовые команды. **Оболочка** (shell) разбирает строку и запускает указанную
программу. В WSL мы используем Bash. Окно Windows Terminal может отображать и PowerShell,
и Bash, но команды зависят от выбранного профиля.

**Командная строка** — текст команды с параметрами, например:

```text
pwd
```

Терминал не переводит C++ сам. Он помогает перейти к файлу и запустить инструмент `g++`.

**Linux** — семейство Unix-подобных систем на базе ядра Linux. Для обычной работы устанавливают
**дистрибутив** — ядро, системные программы и пакетный менеджер. В курсе это Ubuntu внутри WSL2;
в Ubuntu для установки программ используется `apt`. Другие дистрибутивы могут выбрать другой
пакетный менеджер, хотя базовые команды оболочки часто похожи.

## Почему для маршрута выбраны C++ и Linux

C++ — компилируемый статически типизированный язык: компилятор проверяет многие правила до
запуска, а результат обычно становится нативной программой. Это помогает изучить типы,
сборку и контроль над ресурсами, но не гарантирует ни правильный алгоритм, ни автоматическое
превосходство по скорости — результат зависит от задачи и реализации. C++ используют в разных
областях, включая симуляции и программы с ограничениями по производительности; это не значит,
что он нужен для каждого проекта.

Ubuntu в WSL2 нужна здесь как удобное Linux-окружение с g++, gdb и настоящей оболочкой Bash.
Многие серверы и автоматизированные сборки работают в Linux, а консоль показывает команды,
которые IDE часто выполняет скрыто. Это дополнение к начальной Visual Studio на Windows, а не
требование отказываться от Windows или переходить на настольный Linux.

> [!note] «В Linux всё есть файл» — полезное, но неточное сокращение
> У многих ресурсов ввода-вывода — например, терминала, канала-потока или устройства — есть
> файловый интерфейс: программа может работать с ними через схожие операции чтения и записи.
> Но это не значит, что буквально каждый объект системы является обычным файлом. На этом этапе
> достаточно различать файлы, каталоги и процессы; файловый ввод/вывод C++ будет отдельной темой.

## Устанавливаем WSL2 и Ubuntu

Инструкция относится к Windows 10/11 с поддержкой WSL. Перед изменением компонентов Windows
проверь актуальные требования и [официальное руководство Microsoft](https://learn.microsoft.com/en-us/windows/wsl/install).

1. Открой PowerShell **от имени администратора**.
2. Если WSL ещё не установлен, выполни:

   ```powershell
   wsl --install
   ```

3. Перезагрузи компьютер, если Windows этого потребует. При первом запуске Ubuntu создай
   Linux-имя пользователя и пароль. При наборе пароля символы могут не отображаться — это
   обычное поведение терминала.
4. Из PowerShell проверь версию дистрибутива:

   ```powershell
   wsl --list --verbose
   ```

   Новые установки обычно используют WSL2. Если команда сообщает, что `wsl --install` уже
   установлен, сначала просмотри `wsl --help` и актуальные варианты команды на странице Microsoft.
5. Открой **Ubuntu** из меню Пуск. Следующие команды выполняются в Ubuntu/Bash, не в PowerShell:

   ```bash
   sudo apt update
   sudo apt install g++ gdb
   g++ --version
   ```

   `sudo` просит выполнить установку с правами администратора внутри Linux; `apt` — пакетный
   менеджер Ubuntu; `gdb` — отладчик для терминала. Если система сообщает, что пакет или сеть
   недоступны, не повторяй команды вслепую: сохрани сообщение об ошибке и проверь сеть/инструкцию.

> [!warning] PowerShell и Bash — разные оболочки
> `wsl --install` вводится в PowerShell; `sudo apt install ...` — в Bash внутри Ubuntu.
> Если вставить Linux-команду в PowerShell, она может не распознаться. Сначала посмотри
> название профиля терминала и приглашение строки.

## Первые команды Bash

Открой Ubuntu и попробуй по одной. В начале строки обычно видно приглашение вроде
`alex@computer:~$`: `alex` — имя пользователя, `computer` — имя среды, `~` — домашний каталог,
а `$` показывает обычные права пользователя. Символ приглашения вводить не нужно. Если видишь
`#`, проверь, не работаешь ли ты случайно от имени администратора/root.


| Команда | Что делает | Пример или наблюдение |
|---|---|---|
| `pwd` | Печатает текущий каталог | Посмотри, в какой папке ты находишься. |
| `ls` | Показывает файлы и папки | `ls -la` дополнительно показывает скрытые файлы. |
| `cd имя` | Переходит в папку | `cd projects`; команда меняет текущий каталог оболочки. |
| `cd ..`, `cd ~`, `cd -` | Переходит выше, домой или возвращает в предыдущую папку | `..` — родительский каталог, `~` — домашний. |
| `mkdir cpp-start` | Создаёт папку | `mkdir -p lab01/src` также создаёт недостающие родительские папки. |
| `touch hello.cpp` | Создаёт пустой файл | Открой файл редактором или создай его в Visual Studio и сохрани в доступную папку. |
| `cat hello.cpp` | Печатает содержимое файла | Удобно проверить, что сохранился именно тот код, который собираешь. |
| `cp a.cpp b.cpp` | Копирует файл | `cp -r src/ backup/` копирует папку с содержимым. |
| `mv old new` | Перемещает или переименовывает | Сначала проверь оба пути. |
| `rm file` | Удаляет файл | `rm -r dir/` удаляет папку с содержимым; сначала проверь путь. |
| `man команда` | Открывает руководство | Закрой просмотр клавишей `q`; `команда --help` часто показывает краткую справку. |

> [!warning] Удаление в терминале
> `rm` обычно не перемещает файл в графическую корзину. `rm -r` удаляет каталог рекурсивно,
> а `rm -rf` дополнительно подавляет запросы и сообщения. Не выполняй `rm -rf` с неизвестным
> путём или подстановкой `*`; перед Enter перечитай команду целиком.

### Пути: где искать файлы

Linux организует файлы в единое дерево от `/`. У каталогов есть общие назначения:

```text
/
├── home/      домашние каталоги пользователей, например /home/alex
├── etc/       системные настройки
├── usr/bin/   многие установленные программы
├── tmp/       временные файлы
└── var/       журналы и другие изменяемые системные данные
```

Это обзор, а не полный перечень; детали и ссылки между каталогами зависят от дистрибутива.
`~` — домашняя папка текущего Linux-пользователя, `.` — текущая папка, `..` — родительская.

- Абсолютный путь начинается от `/`, например `/home/alex/cpp-start/hello.cpp`.
- Относительный путь считается от текущего места, например `cpp-start/hello.cpp`.
- `pwd` отвечает на вопрос «где я?», а `ls` — «что здесь лежит?».
- Имена в Linux чувствительны к регистру: `Hello.cpp` и `hello.cpp` могут быть разными файлами.

Для первых занятий храни учебную папку в домашнем каталоге Ubuntu, чтобы не путать Linux-путь
с Windows-путём. Доступ к файлам Windows из WSL существует, но разберём его только если он
понадобится для передачи проекта.

## Исходник — не исполняемая программа

Файл `hello.cpp` — текст для людей и компилятора. Он ещё не содержит готового для процессора
исполняемого файла. Сначала создадим короткий пример:

```cpp
#include <iostream>

int main() {
    std::cout << "Hello, world!\n";
    return 0;
}
```

Сохрани его как `hello.cpp` в папке `cpp-start`. В Ubuntu перейди в эту папку и проверь содержимое:

```bash
cd ~/cpp-start
pwd
ls
cat hello.cpp
```

Теперь собери программу одной командой:

```bash
g++ -std=c++20 -Wall -Wextra -Wpedantic -g hello.cpp -o hello
```

Разберём слева направо:

- `g++` — драйвер набора инструментов GNU для C++; он подбирает нужные стадии обработки и подключает стандартную C++-библиотеку согласно настройкам.
- `-std=c++20` просит проверять программу в режиме C++20.
- `-Wall -Wextra -Wpedantic` включают полезные предупреждения. «Wall» не значит буквально
  «все предупреждения»; это имя набора опций GCC.
- `-g` добавляет отладочную информацию, чтобы отладчик мог связать машинный код с исходником.
- `hello.cpp` — входной исходник.
- `-o hello` задаёт имя результата. На Linux это исполняемый файл `hello`, а не `hello.exe`.

Если команда завершилась без диагностики, запусти файл из текущей папки:

```bash
./hello
```

Результат:

```text
Hello, world!
```

`./` означает «запустить файл `hello` из текущего каталога». Имя без `./` оболочка обычно
ищет среди системных команд в `PATH`, а наша учебная папка к этому списку не относится.

## Что g++ делает под капотом

GCC описывает сборку как последовательность до четырёх стадий; в обычной команде g++ запускает
их нужную цепочку автоматически. Названия и внутренние детали отличаются между toolchain,
но полезная модель такова:

```text
hello.cpp
   ↓ препроцессор: обрабатывает #include и условные директивы текст после препроцессора
   ↓ компилятор: проверяет правила C++ и переводит код в инструкции/ассемблер hello.s или внутреннее представление
   ↓ ассемблер: создаёт объектный файл hello.o
   ↓ компоновщик: соединяет объектные файлы и библиотеки
hello — исполняемая программа
```

1. **Препроцессор** обрабатывает директивы вроде `#include <iostream>` до основной проверки
   C++-кода. Заголовок сообщает объявления стандартной библиотеки; включение текста — часть
   модели классических заголовков.
2. **Компилятор** разбирает исходный текст, проверяет синтаксис и типы, переводит его
   в низкоуровневое представление. Ошибки вроде «ожидался `;`» обычно возникают здесь.
3. **Ассемблер** превращает текст ассемблера в объектный файл. Объектный файл ещё не обязан
   быть самостоятельной запускаемой программой.
4. **Компоновщик** соединяет объектные файлы и необходимые библиотеки. Если объявление найдено,
   а определение функции потеряно, компоновщик может сообщить об unresolved/undefined reference.

В реальной реализации компилятор может использовать промежуточные форматы и дополнительные
инструменты. Схема — модель того, **какую работу нужно выполнить**, а не обещание, что на диске
обязательно появится каждый промежуточный файл.

### Посмотри на стадии сам

Эти команды каждый раз читают исходник и останавливают обработку на указанном этапе:

```bash
g++ -std=c++20 -E hello.cpp -o hello.ii   # только препроцессинг

g++ -std=c++20 -S hello.cpp -o hello.s    # компиляция, остановка до ассемблера

g++ -std=c++20 -c hello.cpp -o hello.o    # объектный файл, без компоновки

g++ hello.o -o hello                      # компоновка объектного файла
```

- `-E` показывает большой обработанный текст; он может быть намного длиннее файла, потому
  что в него вошли заголовки.
- `-S` сохраняет ассемблерный текст. Не нужно учить его команды наизусть.
- `-c` создаёт `.o` и **не** запускает компоновщик.
- Последняя команда просит драйвер выполнить компоновку объекта. `-std=c++20` при простой
  компоновке отдельно не нужен, потому что исходник уже перевели на прошлом шаге.

> [!note] Не делай вывод по одному расширению
> `.cpp`, `.s`, `.o` и файл `hello` — типичные имена в этой демонстрации. Настоящий формат
> определяется toolchain и платформой; Windows, Linux и macOS не обязаны создавать одинаковые
> расширения или одинаковые исполняемые форматы.

## GCC/g++ и MSVC — не один компилятор

После этого блока можно понять, почему IDE «быстро собирает» проект:

- В WSL мы вызвали драйвер `g++`, который использует GCC, инструменты Linux и стандартную
  библиотеку `libstdc++`.
- В нативном проекте Visual Studio сборку обычно выполняет MSVC через систему проектов
  Visual Studio/MSBuild.
- Это разные реализации стандарта C++. Они должны согласованно реализовывать выбранный
  стандарт, но у них могут отличаться сообщения, расширения, предупреждения и ещё не поддержанные
  экспериментальные возможности.
- В следующем цикле мы используем Visual Studio как более удобную оболочку: она управляет
  исходниками и параметрами, вызывает инструменты, показывает ошибки и подключает отладчик.
  Это не отменяет четыре понятия: preprocess, compile, assemble, link.

## Отдельно о тексте в терминале

Пример использует только ASCII-символы и поэтому не зависит от настроек отображения кириллицы.
Русские строки в программе дополнительно зависят от кодировки исходника и терминала.
`windows.h`, `SetConsoleOutputCP` и `SetConsoleCP` — Windows API, а не часть стандартного C++;
не добавляй их по привычке в переносимый код. Условный Windows-пример и разницу между кодировкой исходника и кодовой страницей консоли см. в [[03. Первая программа — main, ввод и вывод]].

## Ошибки: на каком этапе искать

| Симптом | Вероятное место | Первый вопрос |
|---|---|---|
| `g++: command not found` | Установка или `PATH` | Ты сейчас в Ubuntu/WSL? Установлен ли пакет `g++`? |
| `No such file or directory` для `hello.cpp` | Рабочий каталог или имя файла | Что показывают `pwd` и `ls`? Совпадает ли регистр имени? |
| `expected ';'` | Компиляция | Какую первую строку диагностики показывает компилятор? |
| `undefined reference` | Компоновка | Скомпилированы ли определения всех вызванных функций и переданы ли объекты/библиотеки? |
| `Permission denied` при `./hello` | Запуск/права/файл | Действительно ли это исполняемый файл, созданный текущей командой? |
| Программа запускается, но ответ неверен | Логика во время выполнения | Какой вход и промежуточные значения дали этот результат? |

Не исправляй десять последних сообщений, пока не прочитал самое первое: одна синтаксическая
ошибка часто порождает каскад последующих сообщений.

## Как это делают в проекте

В проекте из нескольких файлов каждый `.cpp` компилируется в отдельный объектный файл;
затем компоновщик собирает их в программу. Именно поэтому позже мы изучим объявления, определения
и отдельную компоновку. Для первых задач достаточно одной команды g++, чтобы понять весь цикл,
не настраивая пока систему сборки.

## Типичные заблуждения

| Заблуждение | Как на самом деле |
|---|---|
| «Терминал — это и есть Linux» | Терминал — окно; Bash — оболочка; Ubuntu — дистрибутив; WSL — способ запускать Linux-среду в Windows. |
| «`g++` сразу исполняет исходник» | Сначала он собирает программу; только отдельный запуск `./hello` её запускает. |
| «Если компиляция прошла, решение правильное» | Компилятор проверяет правила языка, но не смысл условия задачи. |
| «Файл `.o` можно запустить» | Обычно это объектный файл для следующей стадии, а не конечная программа. |
| «Visual Studio внутри пользуется g++» | Нативный Windows-проект обычно собирается MSVC; g++ мы запускаем в Ubuntu/WSL. |
| «`-Wall` включает абсолютно все предупреждения» | Это историческое имя набора. Другие флаги и компиляторы имеют собственные списки. |

## Ключевые термины

| Термин | Объяснение |
|---|---|
| Терминал | Окно для ввода команд и чтения их вывода. |
| Shell / оболочка | Программа, которая разбирает команду; здесь используется Bash в Ubuntu. |
| Текущий каталог | Папка, относительно которой оболочка разрешает относительные пути. |
| Препроцессор | Первая стадия обработки директив `#include`, макросов и условной компиляции. |
| Компилятор | Инструмент, который проверяет программу и переводит C++ в низкоуровневое представление. |
| Ассемблер | Инструмент, который создаёт объектный код из ассемблерного представления. |
| Объектный файл | Результат компиляции отдельной единицы трансляции, который обычно нужно скомпоновать. |
| Компоновщик / linker | Инструмент, связывающий объектные файлы и библиотеки. |
| Сборка / build | Весь путь от исходных файлов и настроек до полученной программы. |
| WSL2 | Среда Linux, запускаемая рядом с Windows; используется в курсе для Ubuntu и g++. |
| GCC / g++ | GCC — семейство инструментов GNU; `g++` — его драйвер для C++, который выбирает нужную цепочку обработки. |
