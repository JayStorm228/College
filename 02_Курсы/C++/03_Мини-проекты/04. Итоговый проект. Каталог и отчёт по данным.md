# 04. Итоговый проект. Каталог и отчёт по данным

> [!abstract] Цель проекта
> Создать небольшое C++20-приложение, которое читает каталог из текстового файла, проверяет
> записи, хранит сущности в собственных типах, строит сводные отчёты, обрабатывает ошибки,
> применяет алгоритмы STL и даёт проверяемый интерфейс расширения. Это интеграционный проект
> блоков 13–17; соревновательный трек не требуется.

## Предметная область

В каталоге хранятся позиции:

```text
id;name;category;quantity;unit_price_cents
P-001;Notebook;Stationery;24;18900
P-002;Pen;Stationery;50;2500
P-003;Bottle;Travel;0;1299
```

Правила проекта (явные допущения для учебного формата):

- поля разделены `;`; экранированные `;` внутри поля не поддерживаются;
- `id` уникален; имя и категория не пусты;
- `quantity` — неотрицательный `std::int64_t`;
- `unit_price_cents` — неотрицательный `std::int64_t` в целых сотых долях валюты (для рублёвого
  отчёта это копейки); суммы и промежуточные произведения должны оставаться в том же целочисленном
  масштабе;
- число, не помещающееся в `std::int64_t`, отклоняется при разборе;
- испорченная запись получает номер строки и причину; приложение не считает её валидной;
- отчёт показывает количество позиций, общий запас, стоимость запаса и категории;
- стоимость считается целыми копейками; округление не требуется.

Если хочешь изменить одно из правил, зафиксируй новое требование и добавь тест.

## Обязательные функции продукта

1. Прочитать `catalog.csv` и отличить «файл не найден» от «строка некорректна».
2. Проверить дубликаты `id`.
3. Хранить записи в типе `Product` с приватными данными/инвариантом или в валидируемой структуре,
   если ты аргументировал решение.
4. Сформировать отчёт:
   - число валидных позиций;
   - число ошибок;
   - суммарное количество единиц на складе;
   - суммарную стоимость `quantity × unit_price_cents`;
   - список категорий в детерминированном порядке.

Перед добавлением каждой строки сначала безопасно вычисли её стоимость через
`checked_multiply_nonnegative`, затем проверь сложение с накопленной суммой через
`checked_add_nonnegative`; аналогично проверь суммарное количество.
5. Отсортировать копию каталога по имени или цене стандартным алгоритмом, сохранив исходный порядок
   для другого отчёта.
6. Поддержать как минимум текстовый и CSV-отчёт через общий интерфейс.
7. Проверить алгоритмы автоматическими тестами/проверками и запустить с разными файлами.

Расширения файлов — соглашение; важны ясные границы. Система сборки не обязательна: для данного
размера достаточно одной проверенной команды g++ и проекта Visual Studio, включающего нужные
`.cpp`.

## Архитектура решения

### 1. Тип предметной области

Создай `Product` с `id`, `name`, `category`, `quantity`, `unit_price_cents`. Договорись о
способе отклонять некорректный объект и не оставляй публичный setter, который обходит правило.
Методы чтения объявляй `const`. Проверь возможность использовать готовые `std::string`/значения
по Rule of Zero.

### 2. Чтение и разбор

`catalog_io` отвечает за файл и текстовую запись. Раздели этапы:

- открыть поток и проверить его;
- прочитать заголовок/строки;
- выделить поля;
- разобрать целые значения;
- проверить предметные ограничения и уникальность ключа;
- передать только валидные данные в каталог;
- сохранить диагностику с номером строки.

Не смешивай парсинг с печатью всего отчёта. Если файл не открылся, не утверждай, что получен
пустой каталог: это разные состояния.

#### Безопасная денежная арифметика: переполнение проверяют до операции

Переполнение **знакового** целого в C++ — неопределённое поведение. Нельзя сначала вычислить
`quantity * unit_price_cents`, а потом проверить, что ответ «стал отрицательным»: ошибка могла
произойти уже при умножении. Сначала проверь границы, затем выполняй операцию:

```cpp
#include <cstdint>
#include <limits>

bool checked_multiply_nonnegative(
    std::int64_t left,
    std::int64_t right,
    std::int64_t& result
) {
    if (left < 0 || right < 0) {
        return false;
    }

    const auto max_value{std::numeric_limits<std::int64_t>::max()};
    if (right != 0 && left > max_value / right) {
        return false;
    }

    result = left * right;  // безопасно только после проверки выше
    return true;
}

bool checked_add_nonnegative(
    std::int64_t current,
    std::int64_t value,
    std::int64_t& result
) {
    if (current < 0 || value < 0) {
        return false;
    }

    const auto max_value{std::numeric_limits<std::int64_t>::max()};
    if (value > max_value - current) {
        return false;
    }

    result = current + value;
    return true;
}
```

Обе функции меняют выходной параметр только при успехе. Перед умножением уже должны быть
проверены отрицательные входы; деление `max_value / right` выполняется только если `right != 0`.
Ту же `checked_add_nonnegative` применяй к общему количеству и сумме стоимости. Если хотя бы
одна строка не помещается, выбери и запиши политику (отклонить строку или весь отчёт), но не
печатай частичный итог как полный.

Для проверки протестируй: `0 × max`, `1 × max`, `2 × max` (последнее должно быть отклонено),
а также сложение `max + 0` и `max + 1`. Не вычисляй ожидаемое переполнение в самом тесте.

### 3. Выбор контейнеров и алгоритмов

- `std::vector<Product>` — последовательность записей.
- `std::map<std::string, std::size_t>` — детерминированная сводка по категориям.
- `std::ranges::sort` — сортированная копия каталога.
- `std::ranges::find_if` или `count_if` — поиск/подсчёт по условию.
- Перед каждым алгоритмом запиши, что он меняет и какую сложность ожидать.

### 4. Полиморфные форматы

Создай базовый `Report` с виртуальным деструктором и `render(...) const`, затем `TextReport` и
`CsvReport`. Точка входа владеет выбранной реализацией через `std::unique_ptr<Report>` и вызывает
одну операцию через интерфейс. Сначала проверь, действительно ли два формата оправдывают
runtime-интерфейс; если достаточно простого `switch`, обоснуй выбор и сравни варианты.

### 5. Шаблон с concept

Добавь небольшой действительно общий helper, например суммирование контейнера целых значений.
Ограничь его concept-ом `std::integral`/собственным `requires` и тестируй только типы, для которых
арифметика безопасна по диапазону. Важно: `std::integral` проверяет категорию типа, но **не**
предотвращает переполнение и не доказывает, что сумма помещается в `T`. Для денежного отчёта
используй проверенные операции выше; generic-helper не должен молча обходить их. Не обобщай
`Product`/предметную логику без причины.

### 6. Ошибки, тесты, отладка

- Отдельно тестируй parser на корректной, пустой, повреждённой и граничной строке.
- Проверь файл без заголовка/без доступа/пустой файл.
- Проверь повторный `id` и цену/остаток вне диапазона.
- Используй `assert` или небольшой test runner для чистых функций; для полного проекта укажи
  ограничения такого набора и что автоматизировано.
- Собери с `-Wall -Wextra -Wpedantic -g`; при наличии попробуй ASan/UBSan.
- Для логической ошибки воспроизведи минимальный CSV и пройди её в gdb/Visual Studio Debugger.

или контрольные версии, если используешь Git.

## Тестовая матрица

| Сценарий | Ожидаемое поведение |
|---|---|
| Файл содержит 3 корректные записи | 3 позиции попадают в отчёт |
| Пустой файл | Понятный отчёт «нет данных» или ошибка формата по принятой спецификации |
| Не существует путь | Диагностика открытия, без ложного успешного отчёта |
| Неверное число в `quantity` | Строка пропущена/отвергнута с номером и причиной |
| Отрицательный `unit_price_cents` | Нарушение контракта |
| Повторный `id` | Дубликат обнаружен, политика записана |
| Нулевой остаток | Общая стоимость этой позиции равна нулю |
| Один товар/одна категория | Min/max/сортировка и сводка работают |
| Непустой каталог | Text и CSV дают одинаковые предметные итоги |
| Сортированный выход | Исходный vector не изменён, если сортируется копия |
| `quantity=2`, `unit_price_cents=std::numeric_limits<std::int64_t>::max()` | Произведение отклонено до умножения; нет signed overflow. |
| Накопленная стоимость равна `INT64_MAX`, добавляется `1` | Сложение отклонено до операции; отчёт не выдаёт частичный итог как полный. |
| Очень большая цена/количество | Проверены диапазоны произведения и суммы; переполнение не происходит молча. |

## Критерии приёмки

- ☐ Проект собирается g++ C++20 и MSVC C++20 либо отмечены конкретные различия компиляторов.
- ☐ Заголовки/исходники разделены осмысленно; нет `#include` `.cpp` и случайных определений.
- ☐ Валидные и ошибочные строки различаются; номер строки и причина доступны.
- ☐ Денежная величина хранится целыми минимальными единицами.
- ☐ Вектор, map/другая структура и стандартные алгоритмы выбраны по операциям.
- ☐ Полиморфизм использован только для общего контракта форматов или заменён обоснованным вариантом.
- ☐ Шаблон ограничен и тестируется для разрешённых типов.
- ☐ Пустые данные, повторный ключ, ошибочный файл и числовые границы протестированы.
- ☐ README объясняет сборку, входной формат, выходные отчёты и известные ограничения.

## Если застрял

| Симптом | Проверь |
|---|---|
| `undefined reference` | Переданы ли все `.cpp`; совпали ли объявления/определения. |
| Повторный ключ теряется | Явно ли выбрана политика дубликатов; не перезаписал ли `map[id]` молча. |
| Стоимость стала отрицательной/неверной | Диапазон умножения и накопителя; знаковый тип и проверка переполнения. |
| CSV строка «съехала» | Количество полей, разделитель, пустые значения, предполагаемая кодировка. |
| Сортировка изменила основной отчёт | Сортируй копию, если исходный порядок нужен далее. |
| Template error слишком длинная | Проверь concept, фактические типы и каждую требуемую операцию с малым примером. |
