# 03. Мини-проект. Симулятор движения с разбором модели

> [!abstract] Задача проекта
> Разработать небольшую многофайловую программу, которая симулирует вертикальное движение
> объекта, записывает состояния по шагам и сравнивает приближённый результат с аналитическим.
> Проект соединяет блоки 09–12: интерфейсы файлов, собственные типы, модель и безопасное
> управление жизненным циклом данных.

## Цель и допущения

**Вопрос:** сколько времени падает объект с высоты `h₀`? Модель изолирует численный расчёт.

- Ось координаты направлена вверх; земля — `height = 0`.
- Начальная скорость равна нулю.
- Ускорение `g` постоянно, сопротивление воздуха не учитывается.
- Высота задаётся в метрах, время — в секундах, шаг `dt` положителен.
- Модель не описывает столкновение/отскок, размер объекта и реальные погодные условия.

Не формулируй результат как измеренное время настоящего шарика: это вывод модели при указанных
допущениях.

## Архитектура

```text
motion-simulator/
├── simulation.h       # структуры состояния и объявления функций
├── simulation.cpp     # расчёт шагов и аналитического времени
└── main.cpp           # выбор входов, запуск и отчёт
```

Заголовок описывает интерфейс; реализация не печатает в консоль. `main` собирает эксперимент.

## Модель данных

Создай типы:

```cpp
struct SimulationConfig {
    double initial_height{};
    double gravity{9.81};
    double time_step{0.01};
};

struct Sample {
    double time{};
    double height{};
    double velocity{};
};
```

Добавь объявление функции, которая принимает `const SimulationConfig&` и возвращает
`std::vector<Sample>`, а также функцию точного решения. Объявления помести в `simulation.h`
под include guard.

Для ограниченного учебного эксперимента зафиксируй контракт конфигурации: все три числа должны
быть конечными; `0 <= initial_height <= 1000`, `0.1 <= gravity <= 20` и
`0.001 <= time_step <= 1`. Проверяй это до создания samples и до цикла. При этих границах
даже самая долгая из разрешённых симуляций делает меньше 150 000 шагов; объясни, что границы
ограничивают вычислительную нагрузку этого проекта и не задают универсальные физические пределы.

## Алгоритм

1. Начать с `height = initial_height`, `velocity = 0`, `time = 0`.
2. Записать начальное состояние в vector.
3. Пока тело выше поверхности: сохранить `previous_height` и `previous_time`, обновить скорость
   `v -= g * dt`, затем положение `h += v * dt`, продвинуть время и записать новое состояние.
4. При первом `height <= 0` отметить пересечение с землёй; отрицательную высоту не трактовать
   как физическое движение под поверхностью.
5. Оцени время пересечения линейной интерполяцией. Пусть `h_prev > 0` — высота до шага,
   `h_next <= 0` — после него, `t_prev` — время до шага. Тогда
   `fraction = h_prev / (h_prev - h_next)` и `t_cross = t_prev + fraction * dt`.
   Знаменатель положителен из-за условий пересечения; при `h0 == 0` верни время `0` без цикла.
6. Аналитический ориентир для старта из покоя: `sqrt(2 * h0 / g)`.

Проверяй входные ограничения до вызова функции. Для эксперимента используй ограниченный набор
тестовых конфигураций `h0=20`, `g=9.81`, `dt` `0.1`, `0.01`, `0.001`.

## Лабораторные этапы

### Этап 1. Один файл, один пример

Сначала реализуй и собери расчёт в `main.cpp`, чтобы проверить знак скорости и направление оси.

### Этап 2. Собственные типы

Перенеси `SimulationConfig` и `Sample` в заголовок. Запиши инварианты: `gravity > 0`, `time_step > 0`,
`initial_height >= 0`. Определи, где каждое ограничение проверяется.

### Этап 3. Несколько файлов

Перемести расчётные функции в `simulation.cpp`, объявления оставь в `simulation.h`, включи заголовок
в оба `.cpp`. Собери:

```bash
g++ -std=c++20 -Wall -Wextra -Wpedantic -g main.cpp simulation.cpp -o motion_simulator
```

### Этап 4. Численный эксперимент

Прогони три шага, выпиши число шагов и расхождение с формулой. Уменьшение `dt` должно улучшать
приближение в рамках данной схемы; время/память на samples при этом растут.

### Этап 5. Тесты модели

Проверь `h0=0`, `h0=1000`, отрицательную высоту, `h0=1001`, `dt=0`, отрицательный `dt`,
`dt=0.001`, `dt=1`, `dt<0.001`, `dt>1`, `g=0`, `g=0.1`, `g=20` и `g` вне диапазона.
Добавь `NaN`/бесконечность, если тестовый способ позволяет создать такие значения. Недопустимые
входы должны быть отвергнуты до цикла. Для граничных тестов опиши ожидаемое поведение, не
вызывай функцию с нарушенным предусловием. При разрешённых границах убедись, что samples не
превышает 150 001 записей (начальное состояние плюс максимум шагов).

## Инженерные требования

- Заголовок имеет include guard; каждый `.cpp` включает нужные объявления.
- Функции расчёта возвращают данные, а не печатают результат.
- `std::vector` владеет последовательностью samples; raw `new[]` не используется.
- Время и координаты имеют документированные единицы.
- В отчёте различаются верификация численного метода и валидация реального процесса.

## Дополнительный шаг по времени жизни

Если добавишь наблюдателя на последний sample, не сохраняй указатель/ссылку через последующие
`push_back`: vector может перераспределить память. Предпочти индекс или получай ссылку после
окончания записи, когда структура больше не меняется.

## Критерии приёмки

- ☐ Сборка проходит одной командой из нескольких `.cpp`.
- ☐ Ошибочные параметры отклоняются до симуляционного цикла.
- ☐ Начальное и конечное состояния видны в отчёте.
- ☐ Аналитический и численный результаты сравниваются.
- ☐ Изменение `dt` объяснено и измерено.
- ☐ Все допущения и границы применимости записаны.
