# C++ с нуля — от консоли до самостоятельной программы

> [!abstract] О чём курс
> Это последовательный курс C++ для человека, который **ещё не программировал**. Мы начнём с
> установки инструментов и простых команд, выясним, что именно делает компилятор, напишем первую программу, а затем шаг за шагом научимся превращать условия задач в ясный, проверяемый код.
> Цель — не выучить набор команд, а уметь понять новую задачу, разбить её на части, выбрать
> подходящие типы и алгоритм, проверить границы и объяснить, почему решение работает.
>
> **Предварительные знания:** не требуются. Читатель может быть незнаком с программированием,
> терминалом и английскими техническими терминами. Все необходимые понятия вводятся до того,
> как на них опираются задания.
>
> **Дополнительная дорожка:** иногда встречаются свёрнутые сравнения с Python. Их можно пропустить:
> основное объяснение и весь маршрут курса не требуют Python. У каждой такой врезки указано,
> какие знания дисциплины 02 нужны для сравнения.

## Как проходить

1. Иди по лекциям по порядку. Термины вводятся ровно перед тем, как становятся нужны.
2. После каждой лекции сделай обе практики: сперва разборную с опорой на шаги и образец,
   затем самостоятельную. Не открывай свёрнутые решения до собственной попытки.
3. После нескольких блоков собери накопительный мини-проект. Он соединяет несколько уже
   изученных понятий; новые конструкции нельзя добавлять в проект раньше их объяснения.
4. Каждый пример запускай. Для C++20 основная командная строка курса —
   `g++ -std=c++20 -Wall -Wextra -Wpedantic -g source.cpp -o app`.
5. Visual Studio настраивается первой, как просил владелец, но сначала мы **видим работу сборки
   через g++ в терминале**. После этого IDE используется как ускоритель редактирования,
   сборки и отладки, а не как «волшебная кнопка».

### Два способа увидеть одну программу

- **Сначала настрой Visual Studio на Windows** — установи рабочую нагрузку Desktop development
  with C++ и создай консольный проект. На этом этапе познакомься с окнами и настройками, но не
  считай автоматическую сборку объяснением того, как создаётся программа.
- **Затем WSL2 + Ubuntu + g++:** выполни команды в Bash, отдельно посмотри препроцессор,
  компиляцию, ассемблирование и компоновку, собери и запусти тот же минимальный пример.
- **После этого сравни с Visual Studio/MSVC:** посмотри, где находятся исходный код,
  конфигурация и сообщения сборки, как поставить точку останова и пройти программу по шагам.
  GCC и MSVC — разные реализации; одинаковый C++20-код следует проверять, а не считать
  их диагностические сообщения и расширения взаимозаменяемыми.

> [!note] Среда, версии и переносимость
> Основной язык курса — стандартный C++20. В командах используется `-std=c++20`; в MSVC
> соответствующая настройка — `/std:c++20`. На дату подготовки курс прогнан на g++ 12.2.0
> в Linux. Конкретные версии Visual Studio, Ubuntu и компиляторов со временем меняются:
> следуй актуальным официальным установщикам и проверяй поддержку возможностей перед тем,
> как переносить их в проект. C++23/26, экспериментальные возможности и модули не являются
> требованием этого базового маршрута.

## Как устроены сравнения с Python

> [!example]- Для тех, кто уже знает Python: имя и тип переменной
> **Предварительно:** переменные и присваивание из курса Python дисциплины 02.
> В Python тип привязан к объекту, а в C++ объявление указывает тип переменной, например
> `int count{3};`. Это сравнение — подсказка для переноса знакомой идеи, не объяснение,
> необходимое новичку.

Такой формат используется редко, когда он помогает увидеть различие. Ни одна задача не
требует писать на Python или знать синтаксис Python.

## Инженерные правила, которые проходят через весь курс

- Имена объясняют смысл (`distance_m`, а не `x1`); инициализируй переменную при объявлении.
- Явно подключай каждый используемый стандартный заголовок; в заголовках не пиши
  `using namespace std;`.
- Сначала выбери подходящие стандартные типы и контейнеры; не начинай с `new`/`delete`.
- Проверяй ввод, пустые данные, ноль, край диапазона и максимальный размер.
- Пиши функцию, которая вычисляет и **возвращает** значение; вывод и запрос ввода оставляй
  вызывающему коду, если нет причины связать их.
- Используй `const` для значения, которое не должно меняться; не скрывай преобразования,
  которые влияют на смысл вычисления.
- Читай предупреждения компилятора и исправляй причину, а не подавляй диагностику.
- Проверяй поведение примерами, тестами и отладчиком; «скомпилировалось» не означает
  «решение верно».

Это учебные правила для общего портативного C++20. Существуют исключения и специальные
задачи — они вводятся с объяснением причины, а не как случайный стиль.
