# 30. Практика. Ограничиваем шаблон concept

> [!abstract] Цель практики
> Спроектировать обобщённую функцию не для «всех типов», а для типов, которые соответствуют
> конкретному контракту. Сверить успешную компиляцию с намеренно неподходящим типом.

## Задача 1 ★☆☆. Ограничить упорядочиваемый тип

Напиши функцию `choose_larger`, которая использует только `<` и возвращает один аргумент.
Сравни шаблон без ограничений с вариантом:

```cpp
template <std::totally_ordered T>
T choose_larger(T left, T right);
```

Подключи `<concepts>`, проверь `int`, `double`, `std::string`.

## Задача 2 ★★☆. Собственный `Printable`

Нужна функция, которая печатает переданное значение. Определи concept через requires-expression:

```cpp
template <typename T>
concept Printable = requires(std::ostream& out, const T& value) {
    { out << value } -> std::same_as<std::ostream&>;
};
```

Затем создай `print_line(const T&)`, ограниченный `Printable`. Подключи `<concepts>` и `<iostream>`.
Проверь `int` и `std::string`.

> [!example]- Возможный разбор функции
> ```cpp
> template <Printable T>
> void print_line(const T& value) {
>     std::cout << value << '\n';
> }
> ```
> Проверка `std::same_as<std::ostream&>` подтверждает, что `out << value` возвращает поток,
> как ожидает цепочка вывода.

## Задача 3 ★★☆. Проверить ошибку контракта

Создай тип `struct NotPrintable { };` без оператора вывода и вызови `print_line(NotPrintable{})`.

1. Сохрани первую полезную строку диагностики.
2. Найди в ней constraint/concept.
3. Объясни, почему функция отвергла тип до запуска.
4. Не реализуй оператор вывода, пока не зафиксировал причину.

## Задача 4 ★★★. Сделать concept, выражающий смысл

Определи concept `AddableToSelf`, который требует выражение `value += value`.
Используй его в шаблоне, который удваивает значение. Для `int` проверь результат; для
`std::string` проверь, что строка удвоилась конкатенацией.

Обсуди: является ли это математическим «умножением на два» для строк? Concept подтверждает
допустимость синтаксиса, но не смысл операции.

## Задача 5 ★★★. Где должен находиться шаблон?

Раздели `print_line` на `template_utils.h` и `main.cpp`. Объясни, почему тело шаблона должно
быть видно при инстанцировании и почему один только прототип обычно недостаточен.
Добавь include guard.

## Критерии готовности

- ☐ Concept называет требования к типу, а не скрывает их внутри тела.
- ☐ Хорошие типы принимаются; плохой тип даёт полезное ограничение в диагностике.
- ☐ `static_assert` проверяет compile-time свойство, а не подменяет runtime-тест.
- ☐ Понимаю, что синтаксис не доказывает бизнес-смысл.
- ☐ Определение шаблона доступно там, где его используют.
