# 28. Практика. Полиморфная обработка объектов

> [!abstract] Цель практики
> Создать абстрактный контракт фигуры, два разных наследника и единый проход, который вызывает
> виртуальный метод без знания конкретного класса.

## Задание

Реализуй интерфейс:

```cpp
class Shape {
public:
    virtual ~Shape() = default;
    virtual double area() const = 0;
};
```

Добавь `Circle` и `Rectangle`, каждый переопределяет `area()` с `override`.
Предусловие размеров — конечные неотрицательные значения; для этой практики допустимо явно
зафиксировать тестовые константы без пользовательского ввода.

## Лабораторные шаги

1. Подключи `<numbers>`, `<memory>`, `<vector>`, `<iostream>`.
2. Определи базовый `Shape`.
3. Определи `Circle final : public Shape` с радиусом и методом площади.
4. Определи `Rectangle final : public Shape` с шириной/высотой.
5. Создай `std::vector<std::unique_ptr<Shape>>`.
6. Добавь `std::make_unique<Circle>(2.0)` и `std::make_unique<Rectangle>(3.0, 4.0)`.
7. Обойди коллекцию `for (const auto& shape : shapes)` и напечатай `shape->area()`.
8. Скомпилируй C++20, проверь значения около `12.5664` и `12`.

> [!example]- Эскиз производного типа
> ```cpp
> class Circle final : public Shape {
> public:
>     explicit Circle(double radius) : radius_{radius} {}
>     double area() const override {
>         return std::numbers::pi * radius_ * radius_;
>     }
> private:
>     double radius_{};
> };
> ```
> Для полноценного типа добавь проверку предусловия радиуса; здесь повторяем структуру virtual API.

## Задача 2. Изменить набор

Добавь вторую фигуру каждого типа. Не меняй код цикла обработки: он должен работать для всех
объектов через один контракт.

## Задача 3. Найти ошибки проектирования

1. Удали `virtual` перед `area`; что перестало соответствовать контракту?
2. Удали `override`; какой класс ошибок теперь компилятор может не заметить?
3. Удали виртуальный деструктор и объясни, почему `unique_ptr<Shape>` требует корректного
   уничтожения производного объекта.
4. Попробуй создать `Shape` напрямую. Почему это запрещено?
5. Не создавай `std::vector<Shape>`; абстрактный объект нельзя инстанцировать, а конкретные
   значения по значению могут срезаться.

## Критерии готовности

- ☐ У базового класса есть публичный виртуальный деструктор.
- ☐ Метод `area` чисто виртуальный и константный.
- ☐ Все наследники используют `override`.
- ☐ Владение объектами явно находится в `unique_ptr`.
- ☐ Цикл вызывает одну и ту же операцию через базовый интерфейс.
