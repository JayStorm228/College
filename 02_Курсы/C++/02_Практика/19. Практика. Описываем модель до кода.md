# 19. Практика. Описываем модель до кода

> [!abstract] Цель практики
> До реализации зафиксировать цель, оригинал, входы/выходы, единицы измерения, допущения,
> класс модели, формулу и способ проверки. Эта лабораторная намеренно начинается без кода.

## Вариант A. Падающий предмет

Цель: оценить время падения небольшого стального шарика с высоты `h₀`.

Заполни карточку:

| Поле | Твоё описание |
|---|---|
| Оригинал | … |
| Конкретный вопрос | … |
| Вход и единицы | … |
| Выход и единицы | … |
| Константа | … |
| Допущения | … |
| Что игнорируем | … |
| Аналитическое правило | … |
| Область применимости | … |
| Контрольный случай | … |
| Возможное измерение для валидации | … |

Назови модель по четырём признакам: форма, статическая/динамическая, детерминированная/
стохастическая, непрерывная/дискретная.

> [!example]- Возможный разбор
> Оригинал — реальное падение шарика; вопрос — время до поверхности; вход — высота в метрах,
> выход — секунды; константа — `g ≈ 9.81 м/с²`. Для аналитической модели принимаются
> постоянное `g`, нулевая начальная скорость и отсутствие сопротивления воздуха. Игнорируются
> вращение, рельеф, размер тела и ветер. Формула `t = sqrt(2 h0 / g)`. Модель математическая,
> динамическая, детерминированная, непрерывная. `h0=0` даёт контрольный ответ 0; валидации
> помогают реальные измерения при описанных условиях.

## Вариант B. Отчёт по оценкам

Для консольной программы, которая считает средний балл группы, опиши модель предметной области:

- какие данные входят;
- какие значения считаются допустимыми;
- что означает «средний балл» при пустой группе;
- округляется ли результат и по какому правилу;
- можно ли считать учащихся с одинаковым именем одним человеком;
- что программа должна сообщить, если один файл не читается.

Не выдумывай политику: неизвестные правила запиши как вопросы заказчику/преподавателю.

## Сравнение верификации и валидации

Для каждого утверждения поставь букву V (verification) или A (validation):

1. Сравнить вычисление с формулой, где точный ответ известен.
2. Сравнить результат с секундомером в реальном эксперименте.
3. Проверить, что код использует формулу из спецификации.
4. Проверить, подходят ли допущения для пера.

> [!example]- Ответ
> 1 — верификация; 2 — валидация; 3 — верификация; 4 — валидация.

## Задание на эксперимент

Составь план измерения зависимости численной ошибки от `dt`:

- какие значения `dt` сравнивать;
- что оставить неизменным;
- какую величину записывать;
- где взять ориентир для ошибки;
- сколько запусков и при каких высотах;
- как не перепутать ошибку интегратора с измерительной ошибкой.
