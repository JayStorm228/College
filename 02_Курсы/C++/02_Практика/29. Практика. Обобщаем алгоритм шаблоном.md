# 29. Практика. Обобщаем алгоритм шаблоном

> [!abstract] Цель практики
> Заменить несколько одинаковых функций одним шаблоном, проверить вывод типа и затем назвать
> ограничения, которые делает алгоритм.

## Задача 1 ★☆☆. Найти больший

Напиши шаблон `larger`, который принимает два значения одного типа и возвращает большее.
Проверь на `int` и `double`; запиши, что должно уметь сравниваться у `T`.

```cpp
template <typename T>
T larger(T left, T right) {
    return left < right ? right : left;
}
```

Сначала попробуй понять функцию без компиляции, затем проверь тестами.

## Задача 2 ★★☆. Квадрат и compile-time проверка

Создай шаблон функции `square` для типов, которые можно перемножать, и добавь:

```cpp
static_assert(square(4) == 16);
```

В отдельной копии попробуй `square(std::string{"text"})`. Зафиксируй диагностическое сообщение;
тип не поддерживает умножение строки на строку.

> [!example]- Возможный C++20-разбор
> ```cpp
> #include <concepts>
>
> template <typename T>
> concept Multipliable = requires(T left, T right) {
>     { left * right } -> std::convertible_to<T>;
> };
>
> template <Multipliable T>
> constexpr T square(T value) {
>     return value * value;
> }
>
> static_assert(square(4) == 16);
> ```
> Concept проверяет требуемую операцию, `static_assert` — конкретное условие при компиляции.

## Задача 3 ★★☆. Сравнить разные типы

Примени `larger` к строкам `"alpha"` и `"beta"`. Объясни, что компилятор синтаксически
может сравнить их, но порядок строки не становится человеческой локализованной сортировкой.

Затем попробуй смешать аргументы `int` и `double`. Запиши, почему простой вывод единого `T`
может не получиться и какие варианты API возможны: одинаковые аргументы, явное преобразование
или отдельный обобщённый интерфейс.

## Задача 4 ★★★. Вывести тип как контракт

Напиши в отчёте шаблонную сигнатуру, которая принимает `std::vector<T>` для любого `T` и
печатает его размер. Укажи, почему внутри функции не требуется знать, как выводить сам `T`.
Затем измени алгоритм так, чтобы он печатал все элементы, и сформулируй новое требование:
`T` должен поддерживать `operator<<`.

## Критерии готовности

- ☐ Один шаблон заменил дублирующиеся варианты функции.
- ☐ Понимаю, что `T` разрешается во время компиляции.
- ☐ Назвал операции, которые требует тело шаблона.
- ☐ Провёл тест на подходящий и неподходящий тип.
- ☐ Определение доступно при компиляции места вызова.
