# 21. Практика. Проектируем тип записи

> [!abstract] Цель практики
> Описать предметную сущность собственным типом, выбрать поля по смыслу и отделить данные
> записи от операций подсчёта. Начинаем с прозрачного `struct`, не добавляя лишнюю иерархию.

## Задание 1 ★☆☆. Запись студента

Для учебного отчёта нужны имя и несколько целочисленных оценок. Определи:

```cpp
struct StudentRecord {
    std::string name{};
    std::vector<int> scores{};
};
```

1. Подключи `<string>` и `<vector>`.
2. Создай запись с именем `"Alex Kim"` и оценками `{90, 84, 100}`.
3. Напечатай имя, размер списка и каждую оценку.
4. Объясни, зачем список оценок — `vector<int>`, а не три отдельных поля `score1`, `score2`, `score3`.

## Задание 2 ★★☆. Инварианты предметных данных

Уточни для каждой сущности допустимость и представление:

| Сущность | Поле | Вопрос к контракту |
|---|---|---|
| Студент | `name` | Может ли имя быть пустым? Разрешены ли пробелы? |
| Оценка | `scores` | Каков диапазон баллов? Что означает пустой список? |
| Товар | `price_cents` | Может ли цена быть отрицательной? Какой тип покрывает диапазон? |
| Заявка | `status` | Нужны ли фиксированные варианты состояния? |

Отдели подтверждённые требования от открытых вопросов. Не выдумывай правила учебной группы.

> [!example]- Возможный разбор
> Для записи студента явно указаны имя и динамическое число оценок. Нормы пустого имени,
> шкалы оценок и смысла пустого списка условием не заданы: их нужно согласовать/документировать.
> Цена в копейках хранится целым достаточного диапазона; фиксированный набор статусов позднее
> удобно моделировать `enum class`.

## Задание 3 ★★☆. Функция над типом

Напиши `double average_score(const StudentRecord& student)`, которая возвращает средний балл.
Сформулируй предусловие для пустого `scores` и выбери, как вызывающий код узнает о пустом
списке. Для базового решения проверь пустоту в `main` до вызова.

## Задание 4 ★★★. Модель отчёта

Создай ещё `struct CourseRecord`, содержащий название курса и `vector<StudentRecord>`.
Напиши программу с двумя студентами и обходом списка. Определи, какие вычисления должны быть
функциями, а какие — только данными. Не печатай данные из конструктора/типа самопроизвольно.

## Критерии

- ☐ Поля объединены вокруг одной предметной сущности.
- ☐ Тип поля выбран с учётом переменного числа значений.
- ☐ Имена не кодируют случайный порядок (`score1`, `score2`, ...).
- ☐ Допущения и открытые вопросы записаны явно.
- ☐ Код разделяет хранение и вывод/расчёт.
