# 32. Практика. Файл, сбойный ввод и автоматические проверки

> [!abstract] Цель практики
> Прочитать один целый счётчик в строке, отдельно обработать ошибочные строки, проверить
> открытие файла и закрепить исправления простыми автоматическими тестами.

## Задание

Создай в своей лабораторной папке `numbers.txt`:

```text
10
-3
not-a-number
42 extra
0
```

Напиши программу, которая:

- открывает файл через `std::ifstream`;
- сообщает об ошибке, если файл не открылся;
- читает файл построчно через `std::getline`;
- принимает только строку с одним целым числом `std::int64_t` и пробелами вокруг;
- для плохой строки печатает номер и продолжает;
- суммирует принятые числа только после проверки переполнения;
- отдельно проверяет `input.bad()` после цикла.

Для данных выше принимаются `10`, `-3`, `0`; сумма равна `7`. `not-a-number` и `42 extra`
считаются ошибками, так как формат задачи — одно число на строку. Если сумма не помещается в
`std::int64_t`, останови обработку с явной ошибкой и не называй частичный итог полной суммой.

## Лабораторные шаги

1. Реализуй `bool parse_integer_line(const std::string&, std::int64_t&)`.
2. Внутри функции разбирай строку через `std::istringstream` в локальное `std::int64_t candidate{}`.
3. Если чтение числа не удалось или после числа нашёлся непробельный `char extra`, верни `false`.
4. Только при успехе присвой `candidate` выходной ссылке и верни `true`; при ошибке выходное значение не меняется.
5. Прочитай файл через `while (std::getline(input, line))`; увеличивай номер строки.
6. Плохие строки запиши в отчёт, а не передавай в арифметику.
7. Суммируй через `checked_add`: сначала вычисли во временную переменную, затем обнови итог;
   при переполнении останови обработку без ложного «полного» отчёта.
8. Запусти с файлом, затем временно переименуй файл и проверь обработку отсутствия.
9. Верни файл и пересобери программу.

> [!example]- Возможный разбор `parse_integer_line`
> ```cpp
> #include <cstdint>
> #include <sstream>
> #include <string>
>
> bool parse_integer_line(const std::string& line, std::int64_t& output) {
>     std::istringstream parser{line};
>     std::int64_t candidate{};
>     char extra{};
>     if (!(parser >> candidate) || (parser >> extra)) {
>         return false;
>     }
>     output = candidate;
>     return true;
> }
> ```
> Выходной аргумент меняется только после успешной проверки. Парсер принимает ` 10 `, отклоняет
> пустую строку, целое вне диапазона `int64_t` и `10 items`.

## Проверка сложения до операции

Даже если каждый `int64_t` прочитан успешно, сумма многих значений может переполниться.
Знаковое переполнение в C++ — неопределённое поведение, поэтому границу проверяют до `+`:

```cpp
#include <cstdint>
#include <limits>

bool checked_add(
    std::int64_t left,
    std::int64_t right,
    std::int64_t& result
) {
    const auto min_value{std::numeric_limits<std::int64_t>::min()};
    const auto max_value{std::numeric_limits<std::int64_t>::max()};

    if ((right > 0 && left > max_value - right) ||
        (right < 0 && left < min_value - right)) {
        return false;
    }

    result = left + right;
    return true;
}
```

В цикле сначала вычисли кандидата, а только после успеха обновляй накопитель:

```cpp
#include <iostream>

std::int64_t next_total{};
if (!checked_add(total, value, next_total)) {
    std::cerr << "Sum is outside int64_t range.\n";
    return 1;
}
total = next_total;
```

После неуспешного вызова нельзя выполнять `total = next_total`; выйди из обработки с явным
сообщением. В production-коде оформи этот путь явно, не используй `assert` для проверки внешнего файла.

## Автоматические проверки ★★☆

Проведи эти проверки в тестовом `main` (функции `parse_integer_line` и `checked_add` определены
выше или подключены из тестируемого модуля):

```cpp
#include <cassert>
#include <cstdint>
#include <limits>

int main() {
    std::int64_t result{};

    const bool parsed_ten{parse_integer_line("10", result)};
    assert(parsed_ten);
    assert(result == 10);

    const bool parsed_negative{parse_integer_line("  -3  ", result)};
    assert(parsed_negative);
    assert(result == -3);

    const std::int64_t previous{result};
    const bool parsed_words{parse_integer_line("words", result)};
    assert(!parsed_words);
    assert(result == previous);  // при ошибке output не изменился

    const bool parsed_extra{parse_integer_line("42 extra", result)};
    assert(!parsed_extra);
    const bool parsed_empty{parse_integer_line("", result)};
    assert(!parsed_empty);
    const bool parsed_too_large{parse_integer_line("9223372036854775808", result)};
    assert(!parsed_too_large);

    const auto max_value{std::numeric_limits<std::int64_t>::max()};
    std::int64_t sum{};
    const bool reached_max{checked_add(max_value - 1, 1, sum)};
    assert(reached_max);
    assert(sum == max_value);

    const bool overflowed{checked_add(max_value, 1, sum)};
    assert(!overflowed);
    assert(sum == max_value);  // при ошибке result не меняется

    const auto min_value{std::numeric_limits<std::int64_t>::min()};
    const bool reached_min{checked_add(min_value + 1, -1, sum)};
    assert(reached_min);
    assert(sum == min_value);
    const bool underflowed{checked_add(min_value, -1, sum)};
    assert(!underflowed);
    assert(sum == min_value);
    return 0;
}
```

Каждый вызов функции выполняется **до** `assert`: если сборка определяет `NDEBUG`, выражение
внутри макроса исчезает. Для этой лабораторной собирай тестовый запуск без `-DNDEBUG`, чтобы
проверки оставались активными. В рабочем приложении проверяй внешний ввод обычной логикой, а не
`assert`.

## Задача ★★★. Сбои и частичный отчёт

Реши, должен ли отчёт печатать сумму принятых строк, если некоторые строки плохие. Зафиксируй
это как требование и выводи число ошибок рядом с суммой. Если после чтения возник I/O-сбой,
не сообщай, что файл обработан полностью.

## Критерии

- ☐ Файл открывается и проверяется до чтения.
- ☐ Строки читаются до успешного EOF, а не через `while (!eof())`.
- ☐ Ошибка формата строки не превращается в неинициализированное значение.
- ☐ Сумма вычисляется только по валидным числам.
- ☐ Проверки покрывают валидное число, пробелы, пустую строку, текст и лишний токен.
- ☐ Ошибки файла и данные отделены от предметного алгоритма.
