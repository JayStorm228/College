# 08. Практика. Данные без скрытых преобразований

> [!abstract] Цель практики
> Самостоятельно выбрать типы и объяснить каждое преобразование. Задачи идут от чтения кода
> и ручному прогнозу к небольшой программе-конвертеру.

## Часть 1. Предскажи результат

Не запускай до заполнения:

```cpp
const int first{7 / 2};
const double second{7.0 / 2};
const double third{static_cast<double>(7 / 2)};
const double fourth{static_cast<double>(7) / 2};
```

Запиши все четыре результата. Затем собери маленькую программу и сравни.

> [!example]- Самопроверка
> `first == 3`; `second == 3.5`; `third == 3.0`, потому что целочисленное деление уже
> отбросило остаток; `fourth == 3.5`, потому что числитель преобразован до деления.

## Часть 2. Деньги в целых единицах

Задача: программа получает цену товара в копейках и количество. Выбери типы и вычисли общую
стоимость в копейках.

1. Запиши верхние ожидаемые границы цены/количества.
2. Выбери целый тип, покрывающий и цену, и произведение.
3. Инициализируй переменные, прочитай тест `1250` копеек и `3` штуки.
4. Выведи итоговое число копеек.
5. Отдельно объясни, почему `double price{12.50};` не является автоматически точным денежным форматом.

Не дели и не округляй денежную сумму в этой задаче: здесь исследуем выбор хранения, а не
налоговые правила.

## Часть 3. Конвертер километров в мили

Известно, что 1 километр ≈ 0.621371 мили. Напиши программу, которая:

- хранит множитель в `constexpr double` с именем `miles_per_kilometer`;
- читает `double kilometers{}`;
- вычисляет расстояние отдельной переменной `miles`;
- печатает исходное и пересчитанное значения;
- не использует `int` для расстояния.

Тесты: `0`, `1`, `12.5`. Результат приблизительный — укажи это в комментарии/подписи.

## Часть 4. Проверь точность

Создай `double sum{0.1 + 0.2};`, выведи его с 17 значащими цифрами через `<iomanip>` и
`std::setprecision(17)`. Сравни вывод с `0.3`. Напиши в отчёте: «Какое решение допустимо
для измерений и почему тест `sum == 0.3` может быть плохим?»

> [!example]- Самопроверка
> Для двоичного `double` большинство десятичных дробей приближённые; значение может быть около
> `0.30000000000000004`. Для измерений выбери допустимую погрешность и сравни отклонение с ней;
> для точных сумм минимальных денежных единиц храни целые копейки. Не округляй результат просто
> потому, что печать показывает много цифр.
