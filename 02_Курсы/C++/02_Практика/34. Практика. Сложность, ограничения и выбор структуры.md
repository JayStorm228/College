# 34. Практика. Сложность, ограничения и выбор структуры

> [!abstract] Цель практики
> Сопоставить требования и размер входа с алгоритмом/структурой данных, оценить время и память,
> а затем объяснить компромиссы без обещаний абсолютной производительности.

## Задача 1 ★☆☆. Оценить рост

Укажи Big-O числа сравнений:

```cpp
for (int i = 0; i < n; ++i) { /* constant work */ }
```

```cpp
for (int i = 0; i < n; ++i) {
    for (int j = 0; j < n; ++j) { /* constant work */ }
}
```

Как примерно меняется работа при удвоении `n`? Не считай точную миллисекундную длительность.

> [!example]- Самопроверка
> Первый цикл — `O(n)`, при удвоении входа работы примерно вдвое. Двойной проход — `O(n²)`,
> примерно вчетверо. Константные факторы и кэш всё ещё могут отличать реальные замеры.

## Задача 2 ★★☆. Операции диктуют контейнер

Выбери и аргументируй:

1. Часто получать элемент по индексу, преимущественно добавлять в конец.
2. Часто получать минимум и максимум/обходить все элементы по порядку, вставлять редко.
3. Уникальные ключи с упорядоченным отчётом.
4. Много проверок наличия, порядок вывода не важен.
5. Часто получать первый пришедший запрос.
6. Всегда извлекать задание с наибольшим приоритетом.

Сопоставь с `vector`, `set`/`map`, `unordered_set`/`unordered_map`, `queue` и `priority_queue`.

## Задача 3 ★★☆. Честно сравнить два алгоритма

Есть `n` строк и одна проверка наличия ключа:

- линейный поиск в vector — `O(n)`;
- построить `unordered_set`, затем искать — среднее `O(n)` на построение плюс среднее `O(1)` на запрос, но дополнительная память и стоимость хеширования.

При одном поиске постройка хеш-таблицы может не окупиться. Если запросов много, преимущество
может измениться. Запиши, какие реальные данные и число запросов нужны для обоснованного выбора.

## Задача 4 ★★★. Объём данных и ограничения

Для алгоритма с двойным циклом оцени операции при `n=10`, `1000`, `100000` (порядок, не
точное число наносекунд). Сравни с сортировкой `O(n log n)` и линейным проходом `O(n)`.

Затем ответь:

- какой максимум `n` разрешён задачей;
- сколько памяти хранит исходный массив;
- сколько памяти добавит копия для сортировки;
- можно ли изменить исходный порядок;
- какие структуры дают детерминированный порядок обхода?

## Задача 5 ★★★. Проверить гипотезу измерением

Составь план простого benchmark:

1. однаковый набор входных данных для обоих вариантов;
2. сборка в сопоставимом режиме;
3. несколько прогонов и одинаковая среда;
4. проверка, что оба алгоритма выдают одинаковый ответ;
5. измерение после валидации результата;
6. запись версии компилятора/размера входа.

Не заявляй скорость по одному случайному замеру. В реальном проекте используй подходящий
benchmark/profiler вместо `std::cout` в горячем цикле.

## Итоговая заметка

Для каждой структуры укажи: какие операции важны, стоимость, память, порядок, допустимые
ограничения и недостатки. Отдельно напиши, почему «наименьшее Big-O» не автоматически означает
лучший дизайн для небольшого набора.
