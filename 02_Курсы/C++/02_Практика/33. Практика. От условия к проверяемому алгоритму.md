# 33. Практика. От условия к проверяемому алгоритму

> [!abstract] Цель практики
> Решить небольшую прикладную задачу полным циклом: уточнить требования, выбрать структуру,
> написать алгоритм, обосновать корректность инвариантом, оценить сложность и создать тесты.

## Условие

Дан набор кодов аудиторий, например:

```text
B-12, A-03, B-12, C-01, A-03, B-12
```

Нужно получить число появлений каждого кода и вывести их по ключу в лексикографическом порядке.

## Шаг 1. Уточнить контракт

Запиши ответы:

- Может ли список быть пустым?
- Чувствителен ли код к регистру (`B-12` и `b-12`)?
- Что считается одинаковым ключом?
- Как трактовать пустой элемент между двумя запятыми?
- Нужно ли сохранять порядок первого появления или вывести сортированный отчёт?
- Как сообщить о повреждённой записи?

В этой лабораторной принимаем: список уже разобран на строки, пустых кодов нет, сравнение
чувствительно к регистру, результат сортируется по `std::string`.

## Шаг 2. Выбрать структуру

Пусть `n` — количество входных кодов, `k` — число уникальных. Выбери `std::map<std::string,
std::size_t>`:

- один проход обновляет частоту;
- map хранит ключи в порядке сравнения;
- память пропорциональна `k`;
- время — примерно `O(n log k)`.

## Шаг 3. Написать код

```cpp
#include <cstddef>
#include <iostream>
#include <map>
#include <string>
#include <vector>

int main() {
    const std::vector<std::string> room_codes{
        "B-12", "A-03", "B-12", "C-01", "A-03", "B-12"
    };

    std::map<std::string, std::size_t> frequency;
    for (const std::string& code : room_codes) {
        ++frequency[code];
    }

    for (const auto& entry : frequency) {
        std::cout << entry.first << ": " << entry.second << '\n';
    }
    return 0;
}
```

Ожидаемый результат:

```text
A-03: 2
B-12: 3
C-01: 1
```

Собери с `-std=c++20 -Wall -Wextra -Wpedantic`. Здесь `.first`/`.second` используется
вместо structured bindings, чтобы не отвлекаться на дополнительный синтаксис.

## Шаг 4. Обосновать корректность

Сформулируй инвариант перед обработкой i-го кода:

> Для каждого ключа, встреченного среди первых `i` элементов, map содержит точное число
> его появлений в этой обработанной части.

Проверь начало (`i=0`), один шаг (увеличивается только выбранный ключ) и завершение (обработаны
все коды). Это аргумент, почему итоговый результат верен.

## Шаг 5. Добавить тесты

| Вход | Ожидаемый результат |
|---|---|
| `{}` | пустой отчёт |
| `{"A-1"}` | `A-1: 1` |
| `{"A-1", "A-1"}` | `A-1: 2` |
| `{"B", "A"}` | сначала `A`, затем `B` |
| `{"B", "b"}` | две разные записи при выбранной чувствительности к регистру |

## Усложнение ★★★

Перепиши подсчёт на `std::unordered_map`. Затем для отчёта собери ключи в `std::vector`,
отсортируй их стандартным алгоритмом и выведи детерминированно. Сравни:

- что стало с порядком обхода;
- какова средняя сложность обновлений;
- где добавилась память/работа;
- почему нельзя утверждать, что хеш-таблица всегда быстрее.

## Что сдать

Код, таблицу тестов, инвариант, оценку времени и памяти, выбранные допущения и вывод о том,
какой формат вывода соответствует условию.
