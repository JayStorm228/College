# 07. Практика. Выбираем тип и проверяем ввод

> [!abstract] Цель практики
> Для каждого значения выбрать тип по смыслу и диапазону, инициализировать его, а затем
> по состоянию потока определить, было ли чтение успешным. Ветвление пока не требуется:
> `std::cin.fail()` выводим как `true`/`false`.

## Задание 1. Подобрать тип

Заполни таблицу. В последней колонке укажи, почему выбран этот тип.

| Значение | Подходящий стартовый тип | Обоснование |
|---|---|---|
| число попыток входа | … | … |
| стоимость в целых копейках | … | … |
| средняя температура `19.5` | … | … |
| включён/выключен флаг | … | … |
| имя с пробелами | … | … |
| один ASCII-символ команды | … | … |

Подсказка: тип отражает смысл значения, а не только примерное количество цифр.

> [!example]- Самопроверка
> Подойдут соответственно `int`, целое достаточного диапазона (`long long`, если требуется),
> `double`, `bool`, `std::string`, `char`. Для копеек проверь верхнюю границу целого типа;
> не используй `double` как точное хранилище денег без отдельной политики округления.

## Задание 2. Инициализировать и проверить поток

Напиши программу, которая просит целое количество занятий, читает его и печатает введённое
значение и признак ошибки потока:

```cpp
#include <iostream>

int main() {
    int lesson_count{};
    std::cout << "Number of lessons: ";
    std::cin >> lesson_count;
    std::cout << std::boolalpha
              << "Read failed: " << std::cin.fail() << '\n'
              << "Stored value: " << lesson_count << '\n';
    return 0;
}
```

Запусти программу два раза:

- введи `12`;
- введи `twelve`.

Запиши, что изменилось. `lesson_count` инициализирован нулём; не делай вывода о корректности
числа только по тому, что в переменной лежит какое-то значение.

## Задание 3. Увидеть сужение

Попробуй отдельно скомпилировать:

```cpp
int whole{2.5};
```

Компилятор должен отвергнуть list-initialization: преобразование потеряло бы дробную часть.
Теперь сформулируй осознанное преобразование:

```cpp
int whole{static_cast<int>(2.5)};
```

Запиши результат и объясни, почему `static_cast` не проверяет диапазон по смыслу задачи.

## Задание 4. Проверить диапазоны типов

Напиши программу с `<limits>`, которая печатает минимальное и максимальное значение `int` и
`long long`. Не записывай в ответе «это всегда ровно столько-то байт»: результат относится
к текущей реализации компилятора.

## Критерии готовности

- ☐ Имена отражают смысл.
- ☐ Все локальные переменные имеют начальное значение.
- ☐ Дробные измерения хранятся не в целом типе.
- ☐ Неудачное чтение замечено через состояние потока.
- ☐ Сужение обнаружено фигурными скобками.
- ☐ Границы типов проверены на текущем компиляторе.
