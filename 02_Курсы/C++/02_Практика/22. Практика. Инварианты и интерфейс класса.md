# 22. Практика. Инварианты и интерфейс класса

> [!abstract] Цель практики
> Спроектировать класс, чьё допустимое состояние проверяется при создании, поля закрыты,
> а публичные операции не позволяют случайно нарушить контракт.

## Задача 1 ★☆☆. Объявить класс

Создай класс `Percentage`, который хранит конечное число от 0 до 100 включительно.
Публичный интерфейс:

- конструктор `Percentage(double value)`;
- `double value() const`;
- `double fraction() const`, возвращающий значение от 0 до 1.

Поля должны быть `private`. Имена полей — например, `value_`.

## Лабораторные шаги

1. Подключи `<cmath>` для `std::isfinite` и `<stdexcept>` для `std::invalid_argument`.
2. Инициализируй поле в списке инициализации конструктора.
3. В теле конструктора отвергни NaN, бесконечность, числа ниже 0 и выше 100.
4. Добавь `const` к методам чтения.
5. Напиши тесты для `0`, `12.5`, `100`, `-1`, `101`, `infinity`.
6. Используй `try/catch` в `main`, чтобы ошибочное создание не завершило программу без сообщения.

> [!example]- Возможный разбор
> ```cpp
> #include <cmath>
> #include <stdexcept>
>
> class Percentage {
> public:
>     explicit Percentage(double value) : value_{value} {
>         if (!std::isfinite(value_) || value_ < 0.0 || value_ > 100.0) {
>             throw std::invalid_argument("percentage must be finite and in [0, 100]");
>         }
>     }
>
>     double value() const { return value_; }
>     double fraction() const { return value_ / 100.0; }
>
> private:
>     double value_{};
> };
> ```
> Инвариант хранится одним объектом: после успешного конструктора `value_` конечен и находится
> в `[0,100]`. Нет публичного setter, который позволил бы обойти проверку.

## Задача 2 ★★☆. Публичный метод с изменением

Добавь `void set_value(double value)`, который сохраняет инвариант:

- сначала проверить новый аргумент;
- если он недопустим — выбросить исключение, старое состояние не менять;
- если допустим — заменить поле.

Проверь, что после неудачной попытки `set_value(150)` объект всё ещё хранит прежнее значение.

## Задача 3 ★★★. Дизайн-ревью

Для классов `StudentRecord`, `Rectangle`, `Percentage` ответь:

1. Какие данные публичны/закрыты и почему?
2. Где проверяется каждое ограничение?
3. Есть ли состояние, которое можно изменить только одним корректным способом?
4. Нужен ли пользовательский деструктор? Почему?
5. Какая часть является интерфейсом, а какая — реализацией?

## Критерии готовности

- ☐ Поля не доступны для произвольной записи.
- ☐ Проверка охватывает конечность и обе границы.
- ☐ Ошибка сообщает о нарушенном контракте.
- ☐ Читающие методы объявлены `const`.
- ☐ Новая операция сохраняет инвариант при успехе и не повреждает его при отказе.
- ☐ Управление стандартными значениями не требует ручного `new`/`delete`.
