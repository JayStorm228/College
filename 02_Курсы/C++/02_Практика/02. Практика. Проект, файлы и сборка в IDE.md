# 02. Практика. Проект, файлы и сборка в IDE

> [!abstract] Цель практики
> Научиться читать структуру Solution/Project и не путать `.cpp` с проектом. Проверим настройки
> стандарта/предупреждений, найдём источник и выходные папки, но пока не считаем автоматическую кнопку Build объяснением того, как получается исполняемый файл.

## Задание 1. Карта проекта

Открой проект из [[01. Практика. Первое знакомство с Visual Studio]] и заполни таблицу:

| Объект | Где он виден в Visual Studio? | Что он описывает? |
|---|---|---|
| Solution | … | … |
| Project | … | … |
| Исходный `.cpp` | … | … |
| Configuration (`Debug`/`Release`) | … | … |
| Platform (`x64` и т. п.) | … | … |
| C++ Language Standard | … | … |
| Warning Level | … | … |

Не удаляй `.sln`, `.vcxproj`, `.vcxproj.filters` и похожие файлы только потому, что их код
не похож на C++. Это файлы описания/настроек проекта.

## Задание 2. Проверить режимы

1. Открой свойства проекта, выбери Debug и проверь язык C++20.
2. Выбери Release и проверь тот же параметр. Убедись, что ты понимаешь, какая конфигурация
   сейчас выбрана.
3. Запиши настройки предупреждений и стандарт.
4. Вернись на `All Configurations` и исправь различия, если это требуется.
5. Не отключай предупреждения и не меняй платформу, если не знаешь, зачем она нужна.

## Задание 3. Различить файлы

В Solution Explorer найди `.cpp`; затем через контекстное меню посмотри его реальное место
на диске. Ответь:

1. Может ли один Solution содержать несколько Projects?
2. Может ли один Project содержать несколько `.cpp`?
3. Где хранятся настройки компилятора: в тексте `main.cpp` или в параметрах Project?
4. Почему папка, показанная в Solution Explorer, не всегда является полным отражением каталога?

> [!example]- Самопроверка
>1. Да. Solution — контейнер для одного или нескольких проектов; 
>2. проект объединяет исходные файлы и параметры сборки. 
>3. Настройки C++20 и MSVC — параметры проекта/конфигурации, не команды в `main.cpp`. 
>4. Solution Explorer показывает логическую структуру, а некоторые файлы могут быть исключены или отображаться по фильтрам; сверяй с расположением на диске.

## Задание 4. Осмотреть сборку, не делая из неё «чёрный ящик»

Найди меню Build и Output. Пока можно узнать, где IDE покажет результаты и ошибки. Не меняй
командную строку компилятора, не задавай случайные пути и не копируй сторонние настройки.

Запиши:
- какую конфигурацию/платформу показывает IDE;
- где отобразится список операций сборки;
- где появится `.exe` после первой настоящей сборки;
- какие четыре стадии сборки мы увидим в лекции про g++.

Сами стадии пока называем предварительно; полный разбор будет в лекции
[[02. Консоль и g++ — путь от исходника до запуска]].

## Контрольный чек-лист

- ☐ Могу объяснить разницу Solution, Project и `.cpp`.
- ☐ Могу найти исходник и папку проекта на диске.
- ☐ Знаю, какая Configuration и Platform выбрана.
- ☐ C++20 задан для используемых конфигураций.
- ☐ Warning Level включён.
- ☐ Не добавил в проект случайных файлов/путей и не отключил диагностику.
- ☐ Могу назвать будущие четыре стадии: препроцессор, компилятор, ассемблер, компоновщик.

## Что сдать

Таблицу проекта и краткое объяснение: «Что Visual Studio хранит помимо исходного текста?»
Не сдавай `.sln`/скриншоты с путями к личным данным без необходимости.
