# 17. Практика. Разделяем программу на файлы

> [!abstract] Цель практики
> Создать модуль геометрии из заголовка и реализации, затем собрать его вместе с `main.cpp`.
> На практике увидеть: `#include` сообщает объявления каждой единице трансляции, а компоновщик
> соединяет объектный код.

## Задача

Раздели программу про площадь круга на три файла:

```text
circle-lab/
├── circle.h
├── circle.cpp
└── main.cpp
```

Пользователь вводит радиус; программа показывает площадь. Предусловие — радиус неотрицательный.
Используй `std::numbers::pi`, стандарт C++20.

## Шаг 1. Напиши заголовок `circle.h`

Заголовок должен содержать include guard и объявления:

```cpp
#ifndef COLLEGE_CIRCLE_LAB_CIRCLE_H
#define COLLEGE_CIRCLE_LAB_CIRCLE_H

double circle_area(double radius);

#endif  // COLLEGE_CIRCLE_LAB_CIRCLE_H
```

Проверь, что имена макросов в `#ifndef` и `#define` совпадают посимвольно.

## Шаг 2. Реализуй `circle.cpp`

```cpp
#include "circle.h"

#include <numbers>

double circle_area(double radius) {
    return std::numbers::pi * radius * radius;
}
```

Файл включает собственный интерфейс первым, затем заголовок стандартной библиотеки, которую
использует тело.

## Шаг 3. Используй интерфейс в `main.cpp`

```cpp
#include "circle.h"

#include <iostream>

int main() {
    double radius{};
    std::cout << "Radius (0 or greater): ";
    if (!(std::cin >> radius) || radius < 0.0) {
        std::cerr << "Invalid radius.\n";
        return 1;
    }

    std::cout << "Area: " << circle_area(radius) << '\n';
    return 0;
}
```

`main.cpp` использует объявление из заголовка и не знает формулу реализации.

## Шаг 4. Собери все `.cpp`

Из `circle-lab` выполни:

```bash
g++ -std=c++20 -Wall -Wextra -Wpedantic -g main.cpp circle.cpp -o circle_app
./circle_app
```

Проверь радиус `1`: площадь близка к `3.14159`. Затем проверь `0` и `-1`.

Для эксперимента собери раздельно:

```bash
g++ -std=c++20 -Wall -Wextra -Wpedantic -g -c main.cpp -o main.o
g++ -std=c++20 -Wall -Wextra -Wpedantic -g -c circle.cpp -o circle.o
g++ main.o circle.o -o circle_app
```

## Вопросы

1. Почему `circle.h` не передаётся g++ как `.cpp`?
2. Что произойдёт, если убрать `circle.cpp` из первой команды?
3. Где находится объявление, а где определение?
4. Зачем каждый `.cpp` подключает используемый интерфейс?
5. Что именно делает include guard?

> [!example]- Самопроверка
> Заголовок включается препроцессором в соответствующие единицы трансляции; отдельно обычно
> компилируются `.cpp`. Объявление находится в `.h`, тело — в `circle.cpp`. Без `circle.cpp`
> `main.cpp` скомпилируется, но линковщик не найдёт определение `circle_area`. Guard не даёт
> повторно включить этот текст внутри одной единицы трансляции, но не собирает реализацию.

## Критерии готовности

- ☐ Созданы ровно три файла с указанными ролями.
- ☐ Каждый `.cpp` отдельно компилируется с правильными заголовками.
- ☐ Команда линковки включает оба `.o`/`.cpp`.
- ☐ `main.cpp` не содержит формулу площади.
- ☐ Проверены положительный, нулевой и отрицательный радиусы.
