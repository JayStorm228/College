# 24. Практика. Владение ресурсом и RAII

> [!abstract] Цель практики
> Передать ответственность за динамический объект через `std::unique_ptr`, проследить, кто
> владеет ресурсом после перемещения, и объяснить, почему RAII безопаснее пары `new`/`delete`.

## Задача 1 ★☆☆. Создать одного владельца

Создай `std::unique_ptr<int>` через `std::make_unique<int>(42)` и напечатай значение через
разыменование. Проверь, что подключён `<memory>`. Не пиши raw `new`.

> [!example]- Минимальный пример
> ```cpp
> #include <iostream>
> #include <memory>
>
> int main() {
>     auto owner{std::make_unique<int>(42)};
>     std::cout << *owner << '\n';
> }
> ```
> При выходе из `main` владелец уничтожается; ресурс освобождается автоматически.

## Задача 2 ★★☆. Передать владение

1. Создай `first_owner`.
2. Передай его в `second_owner` через `std::move` из `<utility>`.
3. Выведи, что `first_owner` пуст (`!first_owner`).
4. Прочитай ресурс через `second_owner`.
5. Объясни: `std::move` само не освобождает и не копирует ресурс; `unique_ptr` передаёт владение.

## Задача 3 ★★☆. Наблюдатель не владеет

Пусть `auto owner{std::make_unique<int>(10)};` и `int* observer{owner.get()};`.

- Пока `owner` жив, прочитай `*observer`.
- Не вызывай `delete observer`.
- Объясни, почему `observer` становится недействительным после уничтожения `owner`.
- Объясни, почему `observer != nullptr` не гарантирует действительное время жизни.

## Задача 4 ★★★. Массив значений или динамический владелец?

Для каждого сценария выбери лучшее начало и объясни:

| Сценарий | Выбор |
|---|---|
| В функции локально хранить три оценки | `std::array` или `std::vector` |
| Количество оценок читается из файла | `std::vector` |
| Одна функция должна вернуть новое сообщение | `std::string` по значению |
| В коллекции хранятся разные реализации абстрактной базы | `std::vector<std::unique_ptr<Base>>` (после блока 14) |

Умный указатель оправдан там, где есть динамическое владение/полиморфизм; не оборачивай
каждое локальное число в `unique_ptr`.

## Задача 5 ★★★. Найди ручную ошибку управления

Не запускай и не копируй в рабочий проект:

```cpp
int* pointer{new int{5}};
delete pointer;
delete pointer;
```

Отметь double delete. Перечисли две альтернативы на основе стандартного C++: обычный объект
по значению, если динамическое время жизни не нужно; `std::unique_ptr`, если нужно.

## Итоговый чек-лист

- ☐ На один динамический ресурс есть один явный владелец.
- ☐ Копирование `unique_ptr` не используется; владение передаётся через move.
- ☐ Сырой указатель рассматривается как невладеющий только при таком контракте.
- ☐ Ни одна ссылка/указатель не переживает ресурс.
- ☐ Выбраны контейнеры/RAII-типы, а не ручные массивы без причины.
