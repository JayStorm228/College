# 18. Практика. Исправляем include guards и компоновку

> [!abstract] Цель практики
> По симптому установить, проблема ли это повторного включения, компиляции отдельного `.cpp`
> или компоновки. Каждый дефект исправляется в изолированной папке; не меняй системные файлы.

## Сценарий A ★☆☆. Повторное включение в одном `.cpp`

`settings.h`:

```cpp
const int retry_limit{3};
```

`main.cpp`:

```cpp
#include "settings.h"
#include "settings.h"

int main() {
    return retry_limit == 3 ? 0 : 1;
}
```

1. Предскажи, почему два подключения могут привести к переопределению.
2. Добавь include guard с уникальным именем.
3. Повтори сборку.

> [!example]- Возможный guard
> ```cpp
> #ifndef COURSE_PRACTICE_SETTINGS_H
> #define COURSE_PRACTICE_SETTINGS_H
> inline constexpr int retry_limit{3};
> #endif
> ```
> В учебном примере константа помечена `inline`, чтобы избежать отдельных вопросов о внешнем
> связывании констант в разных единицах; основной урок сфокусирован на include guard.

## Сценарий B ★★☆. Undefined reference

Есть объявление `double circle_area(double);` и вызов из `main.cpp`, а определение лежит
в `circle.cpp`.

1. Собери только `main.cpp`.
2. Сохрани сообщение линкера.
3. Добавь `circle.cpp` в команду сборки.
4. Собери снова и объясни, на каком этапе исчезла ошибка.

Ожидаемый симптом при отсутствии определения: `undefined reference to circle_area(double)`
или близкая диагностика, формат зависит от версии GCC.

## Сценарий C ★★☆. Сигнатура расходится

Заголовок объявляет:

```cpp
double distance(double first, double second);
```

В реализации написано:

```cpp
double distance(int first, int second) { return first - second; }
```

Найди несовпадение параметров. Объясни, почему определение `distance(int,int)` не является
определением `distance(double,double)`. Исправь определение или объявление так, чтобы контракт
был один.

## Сценарий D ★★★. Multiple definition

Опиши в `common.h` обычное определение функции с телом, подключи заголовок в двух `.cpp`, затем
собери оба файла. Объясни, почему include guards не спасли от двух отдельных определений.

Исправь структуру: в заголовке оставь объявление, единственное тело положи в один `.cpp`.
В шаблонных/`inline` исключениях пока не упражняйся.

## Таблица диагностики

| Симптом | Наиболее вероятная стадия | Что проверить первым |
|---|---|---|
| повторное объявление в одном `.cpp` | препроцессинг/компиляция | include guard |
| `undefined reference` | компоновка | тело функции и перечень исходных файлов |
| `multiple definition` | компоновка | где определена функция и сколько раз собрана реализация |
| типы параметров не совпадают | компиляция/компоновка | сигнатуры объявления и определения |
| нет `main` | компоновка | включён ли файл точки входа |

## Что сдать

Для каждого сценария приложи: минимальные файлы, точную команду, первую диагностику,
классификацию стадии и исправление. Не оставляй в `main` случайные копии функций из `.cpp`.
