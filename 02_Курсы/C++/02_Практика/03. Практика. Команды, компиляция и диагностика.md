# 03. Практика. Команды, компиляция и диагностика

> [!abstract] Цель практики
> Выполнить полный лабораторный маршрут в Bash/Ubuntu: определить текущую папку, создать
> исходник, собрать его g++, посмотреть промежуточные стадии и по диагностике определить,
> где остановилась сборка. Выполняй команды **по одной** и читай ответ терминала.

## Часть A. Подготовить рабочую папку

Открой Ubuntu/WSL, не PowerShell, и введи:

```bash
pwd
mkdir -p ~/cpp-course/lab02
cd ~/cpp-course/lab02
pwd
```

Ожидается путь внутри домашней папки Linux, например `/home/pavel/cpp-course/lab02`.
Имя пользователя у тебя может быть другим.

Проверь инструменты:

```bash
g++ --version
gdb --version
```

Если g++ отсутствует, установи пакет только в Ubuntu:

```bash
sudo apt update
sudo apt install g++ gdb
```

Если Ubuntu ещё не установлена, сначала пройди системную часть лекции; не запускай команды `apt`
в PowerShell.

## Часть B. Создать и прочитать файл

Создай `hello.cpp` любым понятным редактором (можно Visual Studio, если файл сохранён в папке,
доступной WSL) со следующим содержимым:

```cpp
#include <iostream>

int main() {
    std::cout << "Hello from g++!\n";
    return 0;
}
```

Проверь местоположение и текст:

```bash
ls -la
cat hello.cpp
```

В `ls` должен быть файл `hello.cpp`, а `cat` должен показать именно сохранённый исходник.

## Часть C. Полная сборка и запуск

```bash
g++ -std=c++20 -Wall -Wextra -Wpedantic -g hello.cpp -o hello
./hello
```

Ожидаемый запуск:

```text
Hello from g++!
```

Ответь: какая команда создала исполняемый файл, а какая запустила его? Почему перед именем
стоит `./`?

## Часть D. Остановить обработку на разных стадиях

```bash
g++ -std=c++20 -E hello.cpp -o hello.ii
wc -l hello.ii

g++ -std=c++20 -S hello.cpp -o hello.s
ls -l hello.s

g++ -std=c++20 -c hello.cpp -o hello.o
ls -l hello.o

g++ hello.o -o hello_from_object
./hello_from_object
```

Заполни:

| Команда/флаг | Полученный файл | Что уже произошло? |
|---|---|---|
| `-E` | `.ii` | … |
| `-S` | `.s` | … |
| `-c` | `.o` | … |
| `hello.o -o ...` | исполняемый файл | … |

`hello.ii` содержит много кода из заголовков — это ожидаемо. Не нужно вручную править `.ii`,
`.s` или `.o`.

## Часть E. Безопасно вызвать диагностические ошибки

Работай только в своей лабораторной папке.

1. Временно переименуй `hello.cpp` в `greeting.cpp`, затем попробуй собрать `hello.cpp`.
   Прочитай сообщение о пути. Верни имя файла и повтори сборку.
2. В отдельной копии `broken.cpp` убери точку с запятой после `std::cout << "Broken\n"`.
   Собери `broken.cpp` и запиши **первое** сообщение компилятора. Верни `;`, пересобери.
3. Запусти `g++ hello.o -o hello_from_object`. Объясни, почему здесь не требуется повторно
   передавать `.cpp`.
4. Не запускай `rm -rf`, не удаляй домашнюю папку и не экспериментируй с системными файлами.

> [!example]- Самопроверка
> `-E` завершает работу после препроцессинга; `-S` создаёт ассемблерное представление;
> `-c` создаёт объектный код без компоновки; последний шаг связывает `.o` в программу.
> Отсутствующий файл — проблема пути/имени. Пропущенная `;` — ошибка компиляции. Если ошибка
> уже исправлена в `hello.cpp`, объект `hello.o` всё ещё относится к предыдущей версии, пока
> ты не соберёшь его заново.
