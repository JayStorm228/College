# 26. Практика. Поиск, сортировка и контейнеры

> [!abstract] Цель практики
> Выбрать структуру по набору операций, оценить время и память, а затем объяснить, почему один
> алгоритм не является лучшим для каждой входной последовательности.

## Задача 1 ★☆☆. Найти цену

Дано `vector<int>` с `n` несортированными ценами. Нужно один раз найти наличие цены `target`.

1. Выбери алгоритм.
2. Оцени время в худшем случае.
3. Укажи, нужна ли дополнительная память.
4. Проверь случаи: первый элемент, последний, отсутствует, пустой vector.

Ожидаемая отправная точка — `std::ranges::find`, время `O(n)`.

## Задача 2 ★★☆. Много запросов к упорядоченным данным

Входной вектор отсортирован. Пользователь задаёт много запросов наличия числа.
Сравни:

- каждый раз выполнять линейный `find`;
- для уже отсортированного `vector` использовать `std::ranges::binary_search` из `<algorithm>`.

Поясни предпосылку: бинарный поиск верен, только если диапазон упорядочен согласно тому же
правилу сравнения. Если нужно отсортировать один раз, учти стоимость сортировки `O(n log n)`.

## Задача 3 ★★☆. Посчитать частоты

Для последовательности идентификаторов нужно узнать количество появлений каждого ключа.
Выбери между `std::map` и `std::unordered_map`:

| Требование | Выбор и объяснение |
|---|---|
| Отчёт должен идти по ключу в установленном порядке | … |
| Порядок отчёта не важен, в среднем важны быстрые обновления | … |
| Нужно гарантировать воспроизводимый обход | … |

Напиши оба фрагмента подсчёта, если успеваешь. Для `unordered_map` не обещай стабильный порядок.

> [!example]- Самопроверка
> Для упорядоченного отчёта обычно уместна `std::map` с `O(log k)` обновлением.
> `std::unordered_map` даёт среднее `O(1)` на операцию, но порядок не гарантирован и худший
> случай линейный. Если требуется отсортированный вывод, придётся отдельно упорядочить ключи.

## Задача 4 ★★★. Выбрать приоритетную очередь

Есть список задач с приоритетом; нужно каждый раз брать задачу с максимальным приоритетом.
Почему `std::priority_queue` может быть лучше полного `std::sort` после каждого добавления?
Запиши операции в алгоритм-карточку: создание, добавление, извлечение, чтение вершины. Не
путай очередь приоритетов с очередью FIFO.

## Задача 5 ★★★. Сложность и реальные измерения

Для циклов по `n` элементам определи порядок операций:

```cpp
for (int i = 0; i < n; ++i) { /* O(1) */ }
```

```cpp
for (int i = 0; i < n; ++i)
    for (int j = 0; j < n; ++j) { /* O(1) */ }
```

Оцени рост при удвоении `n`. Затем назови две причины, почему реальные замеры могут отличаться
от одного только `O(...)`.
