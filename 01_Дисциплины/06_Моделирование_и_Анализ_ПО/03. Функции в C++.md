# Функции в C++

> [!abstract] О чём эта лекция
> До сих пор программы курса писались сплошным текстом внутри `main`. Эта лекция вводит **функции** — главный инструмент декомпозиции: большая задача распадается на маленькие именованные куски, каждый из которых можно написать, проверить и использовать отдельно.
>
> **Зачем это нужно.** Любая модель дисциплины — формулы, расчёты, обработка данных — собирается именно из функций. Без них код быстро превращается в нечитаемую стену инструкций внутри `main`.
>
> **Что ты должен уметь после лекции:** написать функцию с параметрами и возвращаемым значением; отличить объявление от определения и понять, почему компилятор требует объявление раньше использования; пользоваться математическими функциями и константами из `<cmath>` и `<numbers>`; построчно объяснить программу про шар; записать ту же функцию на Python и Rust.

# Зачем нужны функции

**Функция** — именованный блок кода, который принимает аргументы, что-то делает и, возможно, возвращает значение.

Четыре причины раскладывать программу на функции:

1. **Декомпозиция.** Задача «вычислить объём шара» превращается в одну строку `sphereVolume(radius)`, если функция уже есть. Большое распадается на маленькое и решаемое.
2. **Повторное использование.** Написанную один раз функцию вызывают сколько угодно раз и откуда угодно. Это прямое применение принципа DRY — не дублируй код ([[06. Принципы качественного кода и технический долг|лекция про технический долг]]).
3. **Абстракция.** Вызывая `pow(x, 2)`, ты не обязан знать, как возведение в степень устроено внутри. Функция — «чёрный ящик» с понятным контрактом: имя, параметры, результат.
4. **Проверяемость.** Маленькую функцию легко проверить на известных значениях: `sphereVolume(1)` должен дать примерно `4.189`. Стену кода внутри `main` проверить так уже не получится.

# Анатомия функции

```cpp
double sphereArea(double radius) {                        // 1 — сигнатура
    double area = std::numbers::pi * 4 * pow(radius, 2);  // 2 — тело
    return area;                                          // 3 — возврат значения
}
```

- **Возвращаемый тип** (`double`) — что функция отдаёт наружу. Если функция ничего не возвращает — `void`.
- **Имя** (`sphereArea`) — подчиняется тем же правилам, что и имена переменных.
- **Параметры** (`double radius`) — локальные переменные, в которые при вызове попадают значения аргументов.
- **Тело** — блок операторов внутри `{}`.
- **`return`** — завершает функцию и передаёт значение вызывающему коду. Тип значения должен быть совместим с возвращаемым типом.

## Вызов

```cpp
double s = sphereArea(2.0);   // аргумент 2.0 копируется в параметр radius
```

При вызове **аргументы копируются в параметры** — это называется **передачей по значению**. Что бы функция ни делала с копиями, переменные вызывающего кода не меняются:

```cpp
void addTen(int x) { x = x + 10; }   // меняет только копию

int a = 5;
addTen(a);
// a по-прежнему 5
```

# Объявление и определение

Компилятор читает файл сверху вниз. Чтобы он разрешил вызов, он должен увидеть **хотя бы сигнатуру** функции раньше места вызова.

- **Определение** — сигнатура плюс тело. То, что написано выше.
- **Объявление (прототип)** — только сигнатура, с точкой с запятой: `double sphereArea(double radius);`

Два правильных способа организовать программу:

```cpp
// Способ 1: функции определены до main
double sphereArea(double radius) { ... }
int main() { sphereArea(2.0); }

// Способ 2: сначала прототип, определение — позже
double sphereArea(double radius);          // объявление
int main() { sphereArea(2.0); }
double sphereArea(double radius) { ... }   // определение
```

Если не сделано ни то ни другое, компилятор выдаст ошибку о неизвестном имени.

# Математика: `<cmath>` и `<numbers>`

Функции вроде `pow` не встроены в ядро языка — они живут в заголовке `<cmath>`:

| Функция | Что делает |
|---|---|
| `pow(x, n)` | x в степени n |
| `sqrt(x)` | Квадратный корень |
| `fabs(x)` | Модуль дробного числа |
| `sin(x)`, `cos(x)` | Тригонометрия (аргумент в радианах) |
| `atan2(y, x)` | Угол по координатам |
| `log(x)`, `exp(x)` | Натуральный логарифм и экспонента |

Константы со стандарта C++20 живут в `<numbers>`: `std::numbers::pi` (π), `std::numbers::e` (e). При компиляции это нужно включить флагом: `g++ -std=c++20 main.cpp -o main`.

> [!warning] `pow` без `<cmath>` — дефект исходного кода
> В исходном примере дисциплины `pow()` вызывалась **без подключённого `<cmath>`**. На MSVC такой код мог собраться благодаря транзитивным включениям, но формально заголовка не хватало. В программе ниже дефект исправлен. Вывод: заголовок с используемыми функциями подключается всегда и явно.

# Разбор программы «площадь и объём шара»

Вторая программа дисциплины из [[01. Введение в предмет|лекции 01]] — первый пример программы, собранной из функций:

```cpp
#include <iostream>
#include <string>
#include <windows.h>     // консоль Windows; в Linux не нужен
#include <numbers>       // std::numbers::pi
#include <cmath>         // pow — добавлено при исправлении исходного дефекта

double sphereArea(double radius) {
    double area = std::numbers::pi * 4 * pow(radius, 2);        // S = 4πR²
    return area;
}
double sphereVolume(double radius) {
    double volume = std::numbers::pi * 4 / 3 * pow(radius, 3);  // V = (4/3)πR³
    return volume;
}

int main() {
    SetConsoleOutputCP(CP_UTF8);   // кириллица в консоли (только Windows)
    SetConsoleCP(CP_UTF8);

    double radius;
    std::cout << "Введите радиус: ";
    std::cin >> radius;

    double volume = sphereVolume(radius);   // вызовы с аргументом от пользователя
    double area = sphereArea(radius);

    std::cout << "Площадь: " << area << std::endl;
    std::cout << "Объём: " << volume << std::endl;

    return 0;
}
```

Что здесь важно:

- **Формулы вынесены в две функции.** `main` не знает, как считается площадь, — он просто вызывает функцию и печатает результат. Это и есть декомпозиция в действии.
- **В `std::numbers::pi * 4 / 3` нет ловушки целочисленного деления.** Операции выполняются слева направо: `pi * 4` уже дробное число, поэтому деление на `3` ничего не отбрасывает. Напиши `4 / 3 * pi` — и получилось бы `1 * pi`.
- `std::cin >> radius` читает `double`: пользователь может ввести и `2.5`.
- Функции определены **до** `main`, поэтому прототипы не нужны — см. раздел выше.

> [!example] Проверка результата
> Для радиуса 1: площадь = 4π ≈ 12.566, объём = (4/3)π ≈ 4.189. Если программа выдаёт другие числа — в модели ошибка. Простые контрольные значения — самый дешёвый способ проверить модель, и в курсе он будет использоваться постоянно.

# Аналогии: та же функция в Python и Rust

```python
import math

def sphere_area(radius):          # типы не объявляются
    return math.pi * 4 * radius ** 2
```

```rust
fn sphere_area(radius: f64) -> f64 {      // типы параметра и возврата обязательны
    std::f64::consts::PI * 4.0 * radius.powi(2)
}   // последнее выражение тела возвращается без слова return
```

| Свойство | C++ | Python | Rust |
|---|---|---|---|
| Объявление | Тип возврата перед именем | Ключевое слово `def` | Ключевое слово `fn` |
| Типы параметров | Обязательны | Необязательны | Обязательны |
| Возвращаемый тип | Обязателен (`void`, если нет) | Не объявляется | Обязателен |
| Константа π | `std::numbers::pi` (C++20) | `math.pi` | `std::f64::consts::PI` |
| Возведение в степень | `pow(x, 2)` | `x ** 2` | `x.powi(2)` |

C++ и Rust здесь почти зеркальны — оба требуют типов; Python платит за краткость тем, что ошибки типов всплывают только при запуске.

# Ключевые термины

| Термин | Определение |
|---|---|
| Функция | Именованный блок кода, принимающий аргументы и, возможно, возвращающий значение |
| Сигнатура | Возвращаемый тип, имя и список параметров функции |
| Параметр | Локальная переменная в объявлении функции, принимающая значение аргумента |
| Аргумент | Конкретное значение, передаваемое в функцию при вызове |
| Передача по значению | Аргумент копируется в параметр; переменная вызывающего кода не меняется |
| Возвращаемое значение | То, что `return` передаёт вызывающему коду |
| Объявление (прототип) | Сигнатура функции без тела, завершённая `;` |
| Определение | Сигнатура плюс тело функции |
| Декомпозиция | Разбиение задачи на маленькие независимые подзадачи |

# Типичные заблуждения

- ❌ «Функция меняет переменную, которую ей передали». При передаче по значению изменяется только копия. (Передача по ссылке существует, но это отдельная тема.)
- ❌ «`return` просто завершает функцию». Он ещё и возвращает значение; код после `return` в том же блоке никогда не выполнится.
- ❌ «Функции можно писать в любом порядке». Компилятор должен увидеть хотя бы объявление функции раньше места вызова.
- ❌ «Константа `M_PI` есть в стандарте». `M_PI` — нестандартное расширение; стандартный способ с C++20 — `std::numbers::pi`.
- ❌ «`pow` работает без `<cmath>`». Только пока везёт с транзитивными включениями; заголовок подключается явно.
