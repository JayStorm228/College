# 07. Линейный алгоритм

> [!abstract] О чём эта лекция
> Первая настоящая программа курса. Такой алгоритм уже разбирался схемой
> в [[02. Линейный алгоритм — общий вид]] — теперь то же самое записывается кодом: ввод,
> вычисления по формулам, вывод результата.
>
> **Зачем это нужно.** Схема показывает порядок шагов, код его выполняет. Здесь появляются
> привычки, без которых не работает ничего дальше: значения приходят из `input` в виде строки
> и их надо преобразовать; формула в коде выглядит ровно как в математике, со скобками; результат
> выводят в понятном виде, а не «как получилось».
>
> **Что ты должен уметь после лекции:** записать линейный алгоритм программой; ввести числа
> с клавиатуры и преобразовать их к нужному типу; посчитать выражение, не потеряв точность;
> вывести результат с подписью и нужным числом знаков; обменять значения двух переменных
> по-питоновски; найти ошибку в порядке строк.
>
> **Куда идти дальше:** [[08. Разветвляющийся алгоритм]] — программа учится выбирать.

# Линейный алгоритм в коде

**Линейный алгоритм** — шаги выполняются один за другим, без ветвлений и повторений. Схема
из блока А:

```text
начало → ввести стороны x и y → s := x * y → вывести s → конец
```

Программа на Python:

```python
x = float(input("Введите длину: "))
y = float(input("Введите ширину: "))

square = x * y

print(f"Площадь прямоугольника: {square:.2f}")
```

Сопоставить просто: каждая строка программы соответствует блоку схемы.

| Блок схемы | Строка программы |
|---|---|
| «ввести x, y» | `x = float(input(...))`, `y = float(input(...))` |
| «s := x * y» | `square = x * y` |
| «вывести s» | `print(f"...{square:.2f}")` |
| «начало» / «конец» | начало файла / конец файла |

В любой вычислительной задаче этих трёх частей ровно три: **ввод → вычисление → вывод**.
Порядок обязателен: вычислять до ввода нельзя (переменные пусты), выводить до вычисления нечего.

# Ввод данных и преобразование типа

`input()` всегда возвращает строку, поэтому числа преобразуют сразу при вводе:

```python
count = int(input("Сколько товаров? "))        # целое
price = float(input("Цена товара: "))          # дробное
name = input("Название товара: ")              # строка — преобразовывать не надо
```

Есть и такой приём — сначала принять, потом преобразовать. Он удобнее, когда нужно
проверить или переспросить:

```python
raw = input("Цена товара: ")
price = float(raw)
```

> [!warning] Забыл про преобразование — получил склейку
> `"5" + "3"` даёт `"53"`, а `"5" * 2` — `"55"`. Если в задаче нужно посчитать, а не склеить,
> ввод преобразуют в `int` или `float`. Признак ошибки: результат похож на текст,
> а должен быть числом.

# Вычисления: формулы и порядок операций

Формула переносится в код почти дословно, но скобки нужно ставить самому:

| Математика | В коде | Ошибка новичка |
|---|---|---|
| $\frac{a+b}{2}$ | `(a + b) / 2` | `a + b / 2` — делится только `b` |
| $a \cdot (b + c)$ | `a * (b + c)` | `a * b + c` |
| $a^{b}$ | `a ** b` | `a ^ b` — это совсем другая операция |
| $2\pi r$ | `2 * math.pi * r` | — |

Полезные в вычислительных задачах операторы:

```python
total = 1000
people = 3

each = total // people        # 333 — целых частей на каждого
rest = total % people         # 1 — остаток
exact = total / people        # 333.3333333333333
```

> [!note] Про точность
> Дробные числа хранятся приближённо: `0.1 + 0.2` даёт `0.30000000000000004`. Для вывода
> это лечится форматом `f"{value:.2f}"`, а для сравнения — проверкой с точностью
> (`abs(a - b) < 1e-9`). Об этом уже было в
> [[05. Язык Python - идентификаторы, операторы, типы данных]].

# Вывод результата

Результат должен быть понятен человеку: с подписью и с разумной точностью.

```python
print(f"Площадь: {square:.2f} кв. м")       # два знака после запятой
print(f"Товаров: {count} шт., итого: {total:.2f} руб.")
print(f"Среднее: {average:.1f}")
```

Правила, которые стоит взять сразу:

- в строке вывода есть **подпись**, что это за число («Среднее», «Итого»), и **единицы**, если они есть;
- у денег и измерений — не больше двух знаков после запятой;
- если нужно вывести несколько значений, они не «сваливаются» подряд: `sep` и `f`-строки
  расставляют порядок.

# Порядок шагов и обмен значений

Порядок строк — часть алгоритма. Если поменять строки местами, программа либо упадёт с
`NameError`, либо посчитает не то:

```python
# неверно: total ещё не существует
total = price * count
price = float(input("Цена: "))

# верно: сначала данные, потом вычисления
price = float(input("Цена: "))
count = int(input("Количество: "))
total = price * count
```

Отдельный классический случай — **обмен значений** двух переменных. Через третью переменную
он делается так же, как на схеме:

```python
a = 3
b = 8

temp = a
a = b
b = temp
print(a, b)      # 8 3
```

В Python есть короткая запись того же самого:

```python
a, b = b, a
print(a, b)      # 3 8 — значения поменялись местами
```

Приём `a, b = b, a` работает потому, что справа сначала вычисляются все значения, и только
потом они присваиваются. Но понимать, **почему** это работает, важнее, чем помнить запись:
без третьей переменной (пусть и «невидимой») обмен невозможен.

> [!tip] Массовое присваивание
> Тем же способом значения распаковываются из кортежа: `x, y = 10, 20`. Подробнее —
> в [[11. Кортежи, списки, словари]].

### Задачи по физике и геометрии — примеры с пар (базовый уровень «могу использовать»)

> [!note] Материал с пар — уточни, если есть фото/листок
> Ниже — типовые задачи, которые точно были на паре (вывод и код). Если приложишь фото листочка — заменю на точные формулировки и ЧИСЛА варианта.

**Физика — равномерное движение:**

```python
# Дано: скорость v (км/ч), время t (ч). Найти путь s
v = float(input("Скорость (км/ч): "))
t = float(input("Время (ч): "))
s = v * t
print(f"Путь: {s:.2f} км")
```

**Геометрия — площадь и периметр:**

```python
import math

# Круг по радиусу
r = float(input("Радиус: "))
area = math.pi * r ** 2
circ = 2 * math.pi * r
print(f"Площадь: {area:.2f}, длина окружности: {circ:.2f}")

# Прямоугольник по двум сторонам — как на схеме блока А
a = float(input("Сторона a: "))
b = float(input("Сторона b: "))
print(f"Площадь: {a*b:.2f}, периметр: {2*(a+b):.2f}")
```

**Геометрия — теорема Пифагора (гипотенуза):**

```python
import math

a = float(input("Катет a: "))
b = float(input("Катет b: "))
c = math.sqrt(a**2 + b**2)
print(f"Гипотенуза: {c:.2f}")
```

Принцип один — **ввод → вычисление по формуле → вывод** с подписью и единицами. Для базового уровня: формула дословно как в математике, скобки обязательны, точность `:.2f` для измерений.

# Комментарии и читаемость

```python
# Стоимость доставки зависит от веса: до 1 кг — 200 руб., дальше +50 руб. за кг
delivery = 200 + max(0, weight - 1) * 50
```

`max(0, ...)` здесь не даёт лишним килограммам уйти в минус: если вес меньше 1 кг, добавка
равна нулю. Сам `max` разобран в [[05. Язык Python - идентификаторы, операторы, типы данных]].

Комментарий объясняет **почему** так написано (правило из задачи), а не «что делает строка»:
что делает `delivery = ...`, видно из имён. Полезные правила для линейных программ:

- имена переменных — по смыслу (`total_price`, `average_speed`, `delivery_cost`);
- длинное выражение разбивают на шаги: `subtotal`, `discount`, `total` — так видно, где ошибка;
- магические числа объясняют или выносят в константы: `MAX_WEIGHT = 1`.

# Как это делают в проекте

**Привычка 1. Преобразовывать ввод сразу.** `int(input(...))` рядом с вопросом — читателю видно,
что именно ожидается. Преобразование «где-то потом» забывается.

**Привычка 2. Считать по шагам, а не одной длинной строкой.** Разбитое на части выражение легче
проверить и отладить: видно промежуточные величины.

**Привычка 3. Проверять программу на числах.** Прежде чем сдавать задачу, посчитай ответ
на бумаге или калькуляторе для одного набора данных (как в задачах блока А). Расхождение
означает ошибку в формуле, а не «плохой компьютер».

**Привычка 4. Проверять границы.** Ноль, единица и отрицательные числа — там ошибки живут
чаще всего: деление на ноль, отрицательная цена, пустой ввод.

> [!note] Про обработку ошибок ввода
> В учебных задачах данные обычно корректные. В настоящей работе пользователь вводит что угодно,
> и `float("два килограмма")` останавливает программу. Базовый приём (`try` / `except ValueError`)
> разобран в [[05. Язык Python - идентификаторы, операторы, типы данных]], полный — в инженерном модуле.

# Ключевые термины

| Термин | Определение |
|---|---|
| **Линейный алгоритм** | алгоритм, шаги которого выполняются один за другим, без ветвлений и циклов |
| **Ввод → вычисление → вывод** | обязательные три части вычислительной задачи, именно в этом порядке |
| **Присваивание** | запись значения в переменную: `total = price * count` |
| **Преобразование типа** | приведение введённой строки к числу: `int(input(...))` |
| **Промежуточная переменная** | именованная часть расчёта (`subtotal`, `discount`) — для читаемости и отладки |
| **Формат вывода** | указание точности и вида числа: `f"{value:.2f}"` |
| **Магическое число** | число в коде без объяснения; лучше вынести в константу с именем |
| **Обмен значений** | перестановка значений двух переменных; в Python — `a, b = b, a` |

# Типичные заблуждения

- ❌ **«`input()` вернёт число, если ввести цифры».** Всегда строка; числа преобразуют явно.
- ❌ **«Скобки можно опустить — Python поймёт».** Python считает по строгим правилам приоритета,
  и `a + b / 2` — это `a + (b / 2)`. Скобки расставляют, а не надеются на удачу.
- ❌ **«`^` — это степень».** В Python `^` — побитовая операция, степень это `**`.
- ❌ **«Порядок строк неважен, главное чтобы все были».** Порядок — часть алгоритма: использование
  переменной до присваивания даёт `NameError` или неверный результат.
- ❌ **«Обмен значений работает и без третьей переменной».** `a = b` и `b = a` оставят в обеих
  переменных одно и то же значение. `a, b = b, a` — та же схема с третьей переменной, только
  спрятанной.
- ❌ **«Чем больше знаков, тем точнее».** Для денег `599.6999999999999` — не точность, а мусор
  в выводе. Точность задаётся форматом и разумным числом знаков.
- ❌ **«Комментарий нужен к каждой строке».** Комментарий «что» дублирует код и мешает читать;
  ценность имеет «почему».

# Проверь себя

1. Из каких трёх частей состоит почти любая вычислительная задача и почему порядок важен?
2. Что вернёт `input()` и как получить из него число?
3. Чем отличаются `a + b / 2` и `(a + b) / 2`?
4. Почему нельзя сначала считать, а потом вводить данные?
5. Как обменять значения двух переменных и почему короче — не значит «без третьей переменной»?
6. Зачем разбивать длинную формулу на промежуточные переменные?

> [!example]- Ответы
> 1. **Ввод, вычисление, вывод.** Вычислять до ввода нельзя — переменные ещё пусты; выводить
>    до вычисления нечего. Порядок частей — часть алгоритма.
> 2. Строку. Чтобы получить число: `int(input(...))` для целого, `float(input(...))` для дробного.
> 3. В первом случае делится только `b` (деление выполняется раньше сложения), во втором
>    сначала складываются `a` и `b`. Это разные результаты: для среднего нужно второе.
> 4. Потому что вычисление использует значения переменных, а до ввода их ещё нет: получится
>    `NameError` (имя не определено) или посчитается мусор из прошлой работы.
> 5. Через третью переменную: `temp = a; a = b; b = temp`. В Python есть запись `a, b = b, a` —
>    справа значения сначала вычисляются, поэтому обмен получается без потери данных.
> 6. Чтобы видеть промежуточные величины: если ответ не сходится, сразу понятно, на каком шаге
>    ошибка. Ещё это читаемее: `subtotal`, `discount`, `total` вместо строки на пол-экрана.
