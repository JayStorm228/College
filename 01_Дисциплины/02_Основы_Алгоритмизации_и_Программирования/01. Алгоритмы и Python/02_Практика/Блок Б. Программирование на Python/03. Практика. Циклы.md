# 03. Практика. Циклы

> [!abstract] О чём эта практика
> Три задачи по лекциям [[09. Циклический алгоритм - цикл for]] и
> [[10. Циклический алгоритм - цикл while]]: счётчик и накопитель в цикле `for`, таблица
> значений функции с поиском максимума и цикл `while`, который работает, пока член
> последовательности не станет слишком маленьким.
>
> Общее у всех трёх задач одно: в теле цикла что-то **накапливается** — количество,
> сумма, лучший результат. Накопитель заводится до цикла, иначе он потеряется.

> [!important] Как работать с задачей
> 1. Прочитай условие и **не открывай разбор**.
> 2. Напиши программу и запусти её на тех данных, что указаны в задании.
> 3. Проверь, что цикл **заканчивается**, и что накопитель получает начальное значение
>    до цикла.
> 4. Сверься с разбором. Если ответ разошёлся, сначала проверь, сколько раз выполнился цикл.
>
> Общий чек-лист — в [[00. Обзор практик блока Б]].

## Задача 1. Сколько температур ниже нуля

★☆☆ · цикл `for`, счётчик, ввод в цикле

**Условие.** Сначала вводится количество измерений `N`, затем `N` значений температуры.
Нужно посчитать, сколько из них отрицательные.

**Задание.** 1) Заведи счётчик **до** цикла и реши, чему он равен сначала. 2) Напиши программу.
3) Прогони на пяти значениях `3.5`, `-2`, `0`, `-7.5`, `-1` — ответ должен быть 3.
4) Проверь отдельно случай, когда отрицательных нет, и случай с одним значением.

> [!example]- Разбор
> **Идея.** Нужен один накопитель — количество. До цикла он равен нулю, а внутри цикла
> увеличивается на единицу, если выполнилось условие. Считать заранее, сколько таких
> значений будет, нельзя: они вводятся по одному.
>
> **Код.**
>
> ```python
> count = int(input("Сколько температур? "))
>
> negative = 0
> for i in range(count):
>     temperature = float(input(f"Температура {i + 1}: "))
>     if temperature < 0:
>         negative += 1
>
> print(f"Отрицательных температур: {negative}")
> ```
>
> **Пример запуска**:
>
> ```text
> Сколько температур? 5
> Температура 1: 3.5
> Температура 2: -2
> Температура 3: 0
> Температура 4: -7.5
> Температура 5: -1
> Отрицательных температур: 3
> ```
>
> **Что здесь важно.** `range(count)` даёт ровно `count` повторений — это форма «повторить
> известное число раз» из [[09. Циклический алгоритм - цикл for]]. Номер `i` используется
> только в подсказке ввода: без него непонятно, какое значение спрашивают.
>
> **Типичная ошибка.** Сбрасывать счётчик внутри цикла (`negative = 0` в теле) — тогда
> в ответе всегда будет 0 или 1. Накопитель заводится один раз, до цикла.
>
> **Граница.** Если ввести `N = 0`, цикл не выполнится ни разу и ответ будет «0 отрицательных
> температур» — это верно. А если ввести отрицательное `N`, `range` не даст ни одного
> повторения, и программа молча ответит нулём: проверка ввода — тема инженерного модуля.

## Задача 2. Таблица значений и максимум

★★☆ · `for` с шагом, таблица, поиск максимума

**Условие.** Функция `y = 3·cos²(2x + 1)` рассматривается на отрезке от `−π` до `π`
с шагом `π/8`. Нужно вывести таблицу «x — y» и найти наибольшее значение `y` и `x`,
при котором оно достигается.

**Задание.** 1) Посчитай, сколько точек попадёт в таблицу (отрезок делится на шаги —
вспомни правило счётчика из лекции 09). 2) Напиши программу. 3) Обрати внимание, как
считается очередной `x`: умножением шага на номер, а не прибавлением шага к предыдущему.
Объясни, почему так надёжнее.

> [!example]- Разбор
> **Идея.** Отрезок от `−π` до `π` разбит на 16 шагов по `π/8`, значит точек — 17
> (начало, все промежуточные и конец). Значение `x` на шаге `i` считается как
> `начало + i · шаг` — так погрешность дробных чисел не накапливается, в отличие
> от `x += шаг`. Максимум ищется накопителем: «лучшее из увиденного», начальное значение —
> результат в первой точке.
>
> **Код.**
>
> ```python
> import math
>
> start = -math.pi
> step = math.pi / 8
> steps = 16
>
> best_x = start
> best_y = 3 * math.cos(2 * start + 1) ** 2
>
> for i in range(steps + 1):
>     x = start + i * step
>     y = 3 * math.cos(2 * x + 1) ** 2
>     print(f"x = {x:7.4f}   y = {y:.6f}")
>     if y > best_y:
>         best_x, best_y = x, y
>
> print(f"Максимум: y = {best_y:.6f} при x = {best_x:.4f}")
> ```
>
> **Пример запуска** (первые строки таблицы и итог):
>
> ```text
> x = -3.1416   y = 0.875780
> x = -2.7489   y = 0.136054
> x = -2.3562   y = 2.124220
> x = -1.9635   y = 2.863946
> x = -1.5708   y = 0.875780
> ...           ...
> Максимум: y = 2.863946 при x = 1.1781
> ```
>
> **Что здесь важно.** Начальное значение максимума берётся **из данных**, а не из нуля:
> здесь `y` не бывает отрицательным, но в общем случае ноль — плохая отправная точка
> (максимум может быть отрицательным). Это правило из [[04. Циклический алгоритм — общий вид]].
>
> **Типичная ошибка.** Писать `x += step` в цикле. Тогда к концу таблицы `x` накопит
> погрешность дробных чисел, и «красивые» точки вроде `0` или `π` перестанут быть ровными.
> Сравни с осторожностью из [[04. Циклический алгоритм — общий вид]]: с дробным шагом
> работают аккуратно.
>
> **Замечание про максимум.** Функция симметрична, и одинаковые значения встречаются
> в нескольких точках сетки. Программа вывела `x = 1.1781`, потому что в этой точке
> значение оказалось на `2·10⁻¹⁵` больше, чем в точке `x = −1.9635` — чистая случайность
> приближённой арифметики. Если важно «первое из равных», сравнивают с точностью:
> `if y > best_y + 1e-9`.

## Задача 3. Члены последовательности больше порога

★★★ · цикл `while`, рекуррентная формула, условие выхода

**Условие.** Дана последовательность `x, x²/2!, x³/3!, …, xⁿ/n!` при `x = 0.2`.
Нужно вывести все её члены, которые **больше** `0.001`.

**Задание.** 1) Объясни, почему здесь подходит `while`, а не `for`: сколько членов
попадёт в ответ, заранее неизвестно. 2) Считай очередной член **из предыдущего**
по правилу `следующий = предыдущий · x / n` — так не понадобится считать факториал
заново. 3) Напиши программу и покажи, на каком члене цикл остановился.

> [!example]- Разбор
> **Идея.** Член последовательности `xⁿ/n!` связан с предыдущим:
> `xⁿ/n! = (xⁿ⁻¹/(n−1)!) · x / n`. Это **рекуррентное соотношение** — оно считается
> одним умножением и одним делением вместо факториала. Условие цикла — «текущий член
> больше порога», а внутри счётчик `n` растёт, поэтому цикл обязательно закончится:
> множитель `x / n` со временем становится меньше единицы.
>
> **Код.**
>
> ```python
> x = 0.2
> threshold = 0.001
>
> n = 1
> term = x
> while term > threshold:
>     print(f"n = {n}: {term:.6f}")
>     n += 1
>     term = term * x / n
>
> print(f"Следующий член уже меньше порога: n = {n}")
> ```
>
> **Пример запуска**:
>
> ```text
> n = 1: 0.200000
> n = 2: 0.020000
> n = 3: 0.001333
> Следующий член уже меньше порога: n = 4
> ```
>
> **Что здесь важно.** В теле цикла есть строка, которая меняет условие (`n += 1`
> и пересчёт `term`) — это ответ на вопрос «почему цикл закончится» из
> [[10. Циклический алгоритм - цикл while]]. Порядок строк тоже важен: сначала выводим
> текущий член, потом переходим к следующему.
>
> **Типичная ошибка.** Прибавлять к `n` единицу, но не пересчитывать `term`: условие
> никогда не станет ложным, и программа зациклится. Признак — она «висит» и ничего
> не печатает после нескольких строк.
>
> **Граница.** При `x = 1` последовательность убывает медленнее, и членов будет больше;
> при `x = 0` в ответ попадёт только первый член `0` — но он не больше порога, поэтому
> ответ будет пустым. Проверять такие значения полезно: программа не должна падать
> или зацикливаться ни на одном из них.
