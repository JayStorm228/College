# 02. Практика. Ветвления

> [!abstract] О чём эта практика
> Три задачи по лекции [[08. Разветвляющийся алгоритм]]: программа выбирает вариант
> по условию. Сначала одна развилка с границами, потом кусочно заданная функция из трёх
> веток, затем задача, где вариантов больше и нужно аккуратно разложить случай `a = 0`.
>
> Ветвление — первое место в курсе, где программа может «пойти не туда»: условие написано
> верно, но порядок проверок или граница закрыты не полностью. Поэтому в каждой задаче
> есть пункт «проверь на границах».

> [!important] Как работать с задачей
> 1. Прочитай условие и **не открывай разбор**. Разбор свёрнут (`> [!example]-`).
> 2. Напиши программу и **прогони** её на всех числах, которые указаны в задании.
> 3. Отдельно прогони на границах: ровно на границе диапазона и чуть-чуть рядом.
> 4. Сверься с разбором и разберись, если решения разошлись.
>
> Общий чек-лист — в [[00. Обзор практик блока Б]].

## Задача 1. Холодно, умеренно или жарко

★☆☆ · `if` / `elif` / `else`, границы диапазона

**Условие.** Известна средняя температура за неделю. Программа должна сообщить:

- «Холодно!», если температура меньше 10;
- «Жарко!», если температура больше 25;
- «Умеренно» — во всех остальных случаях.

**Задание.** 1) Определи, какие значения попадают в каждую из трёх групп, и что произойдёт
при температуре ровно 10 и ровно 25. 2) Напиши программу с одним `if`, одним `elif`
и `else`. 3) Проверь её на 7, 10, 12, 25, 30.

> [!example]- Разбор
> **Идея.** Три варианта — это одна конструкция `if / elif / else`, а не три отдельных `if`.
> Условия расставлены так, что каждое значение попадает ровно в одну ветку: сначала проверяем
> «меньше 10», потом «больше 25», а всё, что осталось, — умеренная температура между ними,
> включая сами границы 10 и 25.
>
> **Код.**
>
> ```python
> temperature = float(input("Средняя температура за неделю: "))
>
> if temperature < 10:
>     print(f"Холодно! {temperature:.0f}°C")
> elif temperature > 25:
>     print(f"Жарко! {temperature:.0f}°C")
> else:
>     print(f"Умеренно. {temperature:.0f}°C")
> ```
>
> **Пример запуска** (для 7, 12 и 30):
>
> ```text
> Средняя температура за неделю: 7
> Холодно! 7°C
> Средняя температура за неделю: 12
> Умеренно. 12°C
> Средняя температура за неделю: 30
> Жарко! 30°C
> ```
>
> **Что здесь важно.** `else` работает как «всё остальное» — именно поэтому он закрывает
> диапазон целиком. Если вместо `elif` написать второй `if`, ветки начнут пересекаться.
>
> **Типичная ошибка.** Записать первые два случая двумя отдельными `if`, а `else` оставить
> только при втором. Тогда для температуры 7 программа напечатает **и** «Холодно!»,
> **и** «Умеренно»: для второго `if` условие «больше 25» ложно, и `else` срабатывает.
> Проверка на 7 сразу показывает эту ошибку.
>
> **Границы.** 10 и 25 попадают в «умеренно» — это следует из условия: строго меньше и строго
> больше. Прогон на границах — привычка из [[08. Разветвляющийся алгоритм]].

## Задача 2. Кусочно заданная функция

★★☆ · три ветки, `math`, сравнение дробных чисел

**Условие.** Функция задана по-разному на трёх участках:

- при `x < 1.3`: `y = π·x² − 7 / x²`;
- при `x = 1.3`: `y = a·x³ + 7·√x`;
- при `x > 1.3`: `y = ln(x + 7·√x)`.

Значения `a` и `x` вводятся с клавиатуры.

**Задание.** 1) Напиши программу с двумя `elif`. 2) Прогони её на `x = 1.3` и на `x = 5`
(при `a = 2`). 3) Проверь, что при `x = 0` программа падает, и объясни, почему — какую
проверку стоит добавить в условие?

> [!example]- Разбор
> **Идея.** Кусочная функция — это буквально схема с ромбами из блока А: три ветки, каждая
> со своей формулой. Порядок проверок здесь важен: сначала `x < 1.3`, потом точное равенство,
> потом «всё остальное» — то есть `x > 1.3`, потому что других значений у `x` не бывает.
>
> **Код.**
>
> ```python
> import math
>
> a = float(input("Введите a: "))
> x = float(input("Введите x: "))
>
> if x < 1.3:
>     y = math.pi * x ** 2 - 7 / x ** 2
> elif x == 1.3:
>     y = a * x ** 3 + 7 * math.sqrt(x)
> else:
>     y = math.log(x + 7 * math.sqrt(x))
>
> print(f"f({x}) = {y:.4f}")
> ```
>
> **Пример запуска** (для `a = 2`, `x = 1.3` и `x = 5`):
>
> ```text
> Введите a: 2
> Введите x: 1.3
> f(1.3) = 12.3752
> Введите a: 2
> Введите x: 5
> f(5.0) = 3.0278
> ```
>
> **Что здесь важно.** `math.sqrt(x)` — квадратный корень, `math.log(...)` — натуральный
> логарифм из [[05. Язык Python - идентификаторы, операторы, типы данных]]. Каждая ветка
> возвращает одно и то же имя `y`, поэтому вывод один для всех трёх случаев.
>
> **Типичная ошибка.** Проверять `x > 1.3` третьим `elif` и не оставить `else`. Программа
> работает одинаково, но читается хуже: `else` честно говорит «других вариантов нет», а лишнее
> условие заставляет читателя проверять, не забыт ли ещё один случай.
>
> **Про `x == 1.3`.** Дробные числа хранятся приближённо, и сравнивать их через `==` почти
> всегда плохая идея. Здесь это допустимо по смыслу задачи: пользователь ввёл ровно `1.3`,
> и в обе записи — ввод и литерал — попадает одно и то же ближайшее число. В задачах,
> где значение считается, сравнение делают с точностью:
> `abs(x - 1.3) < 1e-9` (см. «Типичные заблуждения» в [[05. Язык Python - идентификаторы, операторы, типы данных]]).
>
> **Граница.** При `x = 0` первая ветка пытается делить на ноль и программа падает
> с `ZeroDivisionError`. Правильное решение — добавить в условие проверку ввода:
> `if x <= 0` → сообщить, что функция не определена. Такие проверки разбираются
> в инженерном модуле.

## Задача 3. Квадратное уравнение

★★★ · вложенные условия, порядок случаев, граничный случай `a = 0`

**Условие.** Даны коэффициенты `a`, `b`, `c`. Нужно решить уравнение `a·x² + b·x + c = 0`.

Случаи:

- `a = 0` — это не квадратное уравнение, решать его этой формулой нельзя;
- `D > 0` — два корня;
- `D = 0` — один корень;
- `D < 0` — корней нет.

**Задание.** 1) Напиши программу с проверкой случая `a = 0` **до** вычисления дискриминанта.
2) Прогони её на четырёх наборах: `(1, −5, 6)`, `(1, 2, 1)`, `(1, 0, 1)`, `(0, 2, 3)`.
3) Объясни, почему проверку `a = 0` нельзя убрать: что произойдёт без неё?

> [!example]- Разбор
> **Идея.** Задача с четырьмя исходами — это не четыре независимых условия, а вложенная
> развилка: сначала отделяем «не квадратное» (`a = 0`), потом смотрим на дискриминант.
> Так каждая проверка опирается на предыдущую, и ни один случай не теряется.
>
> **Код.**
>
> ```python
> import math
>
> a = float(input("a = "))
> b = float(input("b = "))
> c = float(input("c = "))
>
> if a == 0:
>     print("Это не квадратное уравнение: a должно быть не равно нулю")
> else:
>     d = b ** 2 - 4 * a * c
>     if d > 0:
>         x1 = (-b + math.sqrt(d)) / (2 * a)
>         x2 = (-b - math.sqrt(d)) / (2 * a)
>         print(f"Два корня: x1 = {x1:.4f}, x2 = {x2:.4f}")
>     elif d == 0:
>         x = -b / (2 * a)
>         print(f"Один корень: x = {x:.4f}")
>     else:
>         print("Корней нет: дискриминант отрицательный")
> ```
>
> **Пример запуска** (для трёх наборов):
>
> ```text
> a = 1
> b = -5
> c = 6
> Два корня: x1 = 3.0000, x2 = 2.0000
>
> a = 1
> b = 2
> c = 1
> Один корень: x = -1.0000
>
> a = 0
> b = 2
> c = 3
> Это не квадратное уравнение: a должно быть не равно нулю
> ```
>
> **Что здесь важно.** Порядок проверок — часть алгоритма: случай `a = 0` проверяется
> **раньше** дискриминанта, потому что формула корней делит на `a`. Это тот же принцип,
> что «проверь делитель до деления» из блока А.
>
> **Типичная ошибка.** Писать четыре `if` подряд и забыть `else` у дискриминанта: тогда
> при `D = 0` программа напечатает и «один корень», и «корней нет». Лестница условий
> останавливается на первом истинном — на этом и держится аккуратность.
>
> **Граница.** Если `a` очень близко к нулю, но не ноль, деление формально проходит,
> и корни получаются огромными. Это уже не ошибка, а свойство метода — и повод вспомнить,
> что проверять нужно не «приятные» значения, а границы.
