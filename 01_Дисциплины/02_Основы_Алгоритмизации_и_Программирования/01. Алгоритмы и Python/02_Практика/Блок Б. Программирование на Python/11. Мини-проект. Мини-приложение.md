# 11. Мини-проект. Мини-приложение

> [!abstract] Что за работа
> Последняя работа блока Б и всего курса. Нужно собрать маленькое приложение «Библиотека»:
> книги описываются классом, каталог книг — вторым классом, а общение с пользователем —
> меню в цикле. Это первый проект, где ты **сам решаешь**, из каких сущностей состоит
> программа, а не выполняешь пошаговое условие.
>
> Готового решения нет. Под спойлером — **пример-аналог из другой темы**: такой же
> по устройству склад товаров, но не библиотека. Он показывает уровень и структуру,
> ответа на задачу не даёт.
>
> **Когда делать:** после лекции 16. Это следующий шаг после практики «Классы» — и последний
> перед инженерным модулем и Django.

# Что должно получиться

Программа `library.py` (если захочешь — с модулем, как в предыдущем проекте), в которой:

1. есть класс **`Book`** — книга: название, автор, год издания, число страниц;
2. есть класс **`EBook`** — электронная книга: то же самое плюс размер файла в мегабайтах;
3. есть класс **`Library`** — каталог: список книг и действия над ним;
4. есть меню, которое работает, пока пользователь не выберет выход;
5. при выходе программа печатает короткий итог: сколько книг в каталоге.

Вот пример работы (набор действий и тексты — твои, но смысл должен быть такой):

```text
Библиотека. Команд: 1 добавить, 2 показать, 3 найти по автору, 4 удалить, 5 итог, 0 выход
Команда: 1
Название: Муму
Автор: Тургенев
Год: 1852
Страниц: 96
Добавлено: «Муму» — Тургенев, 96 с.

Библиотека. Команд: 1 добавить, 2 показать, 3 найти по автору, 4 удалить, 5 итог, 0 выход
Команда: 4
Название для удаления: Война и мир
Такой книги нет

Библиотека. Команд: 1 добавить, 2 показать, 3 найти по автору, 4 удалить, 5 итог, 0 выход
Команда: 0
Книг в каталоге: 1. Было выполнено команд: 2
```

# Требования

| # | Требование | Что тренируется |
|---|---|---|
| 1 | `Book`: данные в `__init__`, проверка страниц **при создании объекта** | инкапсуляция и `raise ValueError` |
| 2 | `Book.__str__` печатает книгу понятно, а не адрес объекта | специальные методы из [[16. Объектно-ориентированное программирование]] |
| 3 | `EBook(Book)`: добавляет размер файла, вызывает `super().__init__(...)`, переопределяет `__str__` | наследование и `super()` |
| 4 | У книги есть вычисляемое свойство (`@property`), например «толстая книга» или страниц в день | `@property` вместо поля |
| 5 | `Library` хранит список книг и умеет: добавить, показать все, найти по автору, удалить по названию | список объектов внутри объекта |
| 6 | У каталога есть свойство-статистика: сколько книг, среднее число страниц или самая старая книга | `@property` + проверка пустого каталога |
| 7 | Меню в цикле `while`: неизвестная команда — сообщение, работа продолжается | цикл из [[10. Циклический алгоритм - цикл while]] |
| 8 | Счётчик выполненных команд и итог при выходе | накопитель со значением до цикла |
| 9 | Ошибки данных не роняют программу: страницы `0` или год из будущего — понятное сообщение | `try` / `except ValueError` |
| 10 | Docstring у модуля, классов и методов; код по PEP 8 | привычка из [[14. Функции и модули]] |

**Дополнительно, если хочется больше:** сохранять каталог в `catalog.json` при выходе
и загружать при запуске; искать книги по части названия; вывести список книг, отсортированный
по году. Это те же приёмы из [[15. Работа с файлами]], и они уместны — но сначала сдай
основную часть.

# Как идти к результату

1. **Сформулируй сущности словами.** Две строки на бумаге: «книга — это …, каталог — это …,
   что каталог умеет делать». Действия каталога и станут его методами. Не начинай с кода:
   неудачное деление на классы потом дорого переделывать.
2. **Сделай `Book`.** Поля, проверка в `__init__`, `__str__`. Проверь в консоли: создай
   книгу, напечатай её, попробуй создать книгу с нулём страниц и поймай `ValueError`.
   Этот шаг должен работать полностью, прежде чем идти дальше.
3. **Сделай `EBook` и убедись, что наследование работает.** Создай электронную книгу
   и напечатай её: в строке должны оказаться и общие поля, и размер файла.
   Если `__str__` родителя приходится копировать целиком — используй `super().__str__()`.
4. **Сделай `Library` с двумя методами.** Пока только «добавить» и «показать все»,
   и проверь их в консоли тремя книгами. Каталог должен печатать книги через `print(book)`,
   то есть через `__str__`, а не собирать строку вручную.
5. **Добавь поиск и удаление.** Поиск по автору возвращает **список** книг (их может быть
   несколько). Удаление ищет книгу по названию и сообщает, если её нет: `return True`
   при успехе и `False`, если не нашёл, — пусть решение, что печатать, принимает меню.
6. **Добавь свойство-статистику.** Например, `average_pages`. Обязательно реши, что вернуть
   на пустом каталоге: `0.0` или `None`, — и напиши, почему ты выбрал именно это.
7. **Собери меню.** Функция `main()` с циклом, ввод команды, разбор вариантов через
   `if` / `elif` / `else`, ввод данных для книги — можно отдельными функциями
   `read_book()` и `read_ebook()`. Ошибку `ValueError` от класса лови в меню и печатай
   сообщение.
8. **Доведи до отчёта.** Счётчик команд, аккуратные пустые строки, итог при выходе.
9. **Проверь по таблице ниже** и только после этого сдавай.

> [!example]- Пример-аналог из другой темы: склад товаров
> **Задача другая:** товары и склад, а не книги и библиотека. Устройство то же: два класса,
> наследник, вычисляемые свойства, каталог с методами, меню. Показываю не всё приложение,
> а его костяк — на таком объёме видно, как классы связаны между собой.
>
> ```python
> """Склад: классы и наследник."""
>
>
> class Product:
>     """Товар: название, цена за единицу, количество на складе."""
>
>     def __init__(self, name, price, quantity):
>         if price <= 0:
>             raise ValueError("цена должна быть положительной")
>         if quantity < 0:
>             raise ValueError("количество не может быть отрицательным")
>         self.name = name
>         self.price = price
>         self.quantity = quantity
>
>     @property
>     def total_cost(self):
>         """Стоимость всей партии этого товара."""
>         return self.price * self.quantity
>
>     def __str__(self):
>         return f"{self.name}: {self.quantity} шт. по {self.price:.2f} руб."
>
>
> class Perishable(Product):
>     """Скоропортящийся товар: то же самое плюс срок годности."""
>
>     def __init__(self, name, price, quantity, expiry_date):
>         super().__init__(name, price, quantity)
>         self.expiry_date = expiry_date
>
>     def __str__(self):
>         return f"{super().__str__()} (годен до {self.expiry_date})"
>
>
> class Storage:
>     """Склад: список товаров, поиск и статистика."""
>
>     def __init__(self):
>         self.products = []
>
>     def add(self, product):
>         """Добавляет товар на склад."""
>         self.products.append(product)
>
>     def find(self, name):
>         """Товар с указанным названием или None."""
>         for product in self.products:
>             if product.name == name:
>                 return product
>         return None
>
>     @property
>     def total_cost(self):
>         """Стоимость всего, что лежит на складе."""
>         total = 0.0
>         for product in self.products:
>             total += product.total_cost
>         return total
> ```
>
> Здесь показаны только классы. Чтобы увидеть их в работе, добавь короткую `main()`:
> она создаёт склад, кладёт в него три товара (в том числе один `Perishable`) и печатает
> список, количество позиций и стоимость, — и вызывай её под условием
> `if __name__ == "__main__":`, как в примере к проекту «Свой модуль».
>
> **Как это выглядит в работе:**
>
> ```text
> На складе:
>   Болт: 100 шт. по 12.50 руб.
>   Гайка: 250 шт. по 8.00 руб.
>   Йогурт: 12 шт. по 45.00 руб. (годен до 2026-10-01)
> Всего позиций: 3
> Стоимость склада: 3790.00 руб.
> Найдено: Гайка: 250 шт. по 8.00 руб.
> ```
>
> **Что здесь стоит перенять.**
>
> - **Проверки стоят в `__init__`**: объекта с ценой `0` или количеством `-5` не существует.
>   Проверено: `Product("Соль", 0, 10)` → `ValueError: цена должна быть положительной`.
> - **Наследник не копирует родителя.** `Perishable.__init__` вызывает `super().__init__(...)`
>   и добавляет одно своё поле; `__str__` приклеивает срок годности к строке родителя.
> - **Каталог ничего не знает о происхождении товаров.** `Storage.add(product)` принимает
>   готовый объект — поэтому в него можно положить и `Product`, и `Perishable`. Кто и откуда
>   их создаёт — забота программы, а не склада.
> - **Свойство `total_cost`** есть и у товара, и у склада: у склада оно складывает стоимости
>   партий, а не повторяет умножение. Так одна и та же формула не живёт в двух местах.
> - **Поиск возвращает `None`, когда ничего не нашлось**, и решение «что печатать»
>   принимает вызывающий код: у склада нет ни одного `print`. Это пригодится и в меню
>   твоей библиотеки.
>
> **Чего в примере нет:** меню и проверок ввода (они в примере к проекту «Калькулятор»),
> сохранения на диск (оно в примере к проекту «Свой модуль»), удаления товара. В твоём
> проекте всё это будет — на этот раз твой черед собрать части вместе.

# Как проверить свою работу

| # | Что проверяю | Как именно |
|---|---|---|
| 1 | Данные проверяются при создании | книга с `0` страниц и книга с отрицательным годом → ошибка, объект не создан |
| 2 | `__str__` у обеих сущностей | `print(book)` и `print(ebook)` печатают читаемые строки, не адреса |
| 3 | Наследник использует родителя | в `EBook` есть `super().__init__`, и общие поля не дублируются |
| 4 | `@property` без скобок | `library.average_pages`, а не `library.average_pages()` |
| 5 | Пустой каталог | статистика не падает с `ZeroDivisionError`: выбранное тобой поведение |
| 6 | Поиск по автору | два автора и один из них с двумя книгами → находятся именно они |
| 7 | Удаление | существующая книга удаляется один раз; повторное удаление — «такой книги нет» |
| 8 | Неизвестная команда меню | сообщение и продолжение работы |
| 9 | Ошибка в данных книги | `abc` в страницах или `0` в году → сообщение и возврат в меню |
| 10 | Выход | итог печатается, счётчик команд верный, программа завершается |
| 11 | Смешанный каталог | в списке лежат и `Book`, и `EBook`; печать и статистика работают для обоих |
| 12 | Читаемость | `python3 -m py_compile library.py` без ошибок; docstring у каждого класса и метода |

Проверку 11 сделай специально: положи в каталог одну электронную книгу и убедись, что
и печать, и статистика её учитывают. Именно здесь чаще всего выясняется, что программа
написана «под печатные книги».

> [!tip] Если застрял
> - **`TypeError: __init__() takes 4 positional arguments but 5 were given`.** У наследника
>   свой набор полей — проверь порядок аргументов и то, что `super().__init__` зовётся
>   с нужными тремя.
> - **`AttributeError: 'EBook' object has no attribute ...`.** В `super().__init__(...)`
>   переданы не все поля родителя.
> - **Печатается адрес вида `<__main__.Book object at 0x...>`.** Не определён `__str__`.
> - **Статистика падает на пустом каталоге.** Сначала проверка длины, потом деление.
> - **Удаление удаляет не ту книгу.** Два одинаковых названия — решай явно: удалять первую
>   или все; и проверь это случаем с двумя одинаковыми названиями.
> - **Методы каталога начинают печатать.** Признак путаницы ролей: пусть каталог возвращает
>   значения, печатает меню. Так и проверять проще, и менять потом.
> - **Слишком много команд** — сделай две: «добавить» и «показать». Доведи до конца
>   маленькое приложение, потом добавляй поиск, удаление и итог.

# Что сдать

1. Файл `library.py`, который запускается и проходит проверки 1–12.
2. Короткий разбор своего проекта (5–7 пунктов): какие сущности ты выделил и почему,
   какие свойства сделал вычисляемыми, что возвращает статистика на пустом каталоге,
   какие границы не предусмотрел.
3. Демонстрацию: ты запускаешь программу, кто-то другой диктует команды и данные —
   и приложение не падает. Это ровно та проверка, которая ждёт в Django, где данные
   приходят не от тебя.

**Куда идти дальше.** Блок Б закончен: ты умеешь описать задачу, собрать её из функций
и классов, работать с данными из файла и проверять ввод. Дальше — инженерный модуль
(тесты, типизация, отладка, структура проекта) и 2026-2027 год с Django. В Django модель —
это почти `Book` из этой работы, представления — функции и классы, а ORM-запросы — коллекции
и генераторы, знакомые по этому курсу.

# Частые ошибки

| Ошибка | Как выглядит | Как правильно |
|---|---|---|
| Класс без проверок | книга с `-5` страниц существует | проверки в `__init__`, `raise ValueError` |
| Наследник копирует родителя | поля продублированы, правки в двух местах | `super().__init__(...)` |
| `@property` вызывают как метод | `library.average_pages()` → `TypeError` | свойство читается без скобок |
| Статистика без проверки | пустой каталог → `ZeroDivisionError` | проверка `len(self.books) > 0` |
| Каталог печатает вместо возврата | нельзя переиспользовать, трудно проверять | методы возвращают, меню печатает |
| Удаление без сообщения | «ничего не произошло» | вернуть `True` / `False`, а решает меню |
| Список книг как атрибут класса | книги «переживают» создание второго каталога | `self.books = []` в `__init__` |
| Строки собираются вручную | склейка через `+` и `str(...)` | f-строки и `__str__` |
