# 06. Практика. Функции и файлы

> [!abstract] О чём эта практика
> Три задачи по лекциям [[14. Функции и модули]] и [[15. Работа с файлами]]: свои функции
> с параметрами и `return`, модуль из двух файлов и работа с данными на диске через
> `pathlib` и JSON.
>
> Здесь меняется главное: программа перестаёт быть одним куском кода. Сначала расчёт
> отделяется от ввода и вывода (функции), потом код разносится по файлам (модули),
> а данные начинают переживать закрытие программы (файлы).

> [!important] Как работать с задачей
> 1. Прочитай условие и **не открывай разбор**.
> 2. Напиши программу и проверь её на нескольких наборах данных.
> 3. Спроси себя: «эту функцию можно проверить отдельно от `input`?» Если нет — передай
>    данные в функцию аргументами, а результат верни через `return`.
> 4. Сверься с разбором.
>
> Общий чек-лист — в [[00. Обзор практик блока Б]].

## Задача 1. Медианы треугольника

★☆☆ · свои функции, `return`, проверка данных

**Условие.** Известны длины сторон треугольника `a`, `b`, `c`. Медиана, проведённая
к стороне `a`, считается по формуле `m = √(2b² + 2c² − a²) / 2`. Аналогично считаются
медианы к сторонам `b` и `c`.

Нужно вывести все три медианы. Треугольника с введёнными сторонами может и не быть —
в этом случае программа должна сообщить об этом, а не считать «как получится».

**Задание.** 1) Напиши функции `read_side`, `exists` и `median`. 2) Функция `exists`
возвращает `True` или `False`; функция `median` возвращает число. 3) Проверь программу
на сторонах `3, 4, 5` и на наборе `1, 2, 10`.

> [!example]- Разбор
> **Идея.** Три маленькие функции вместо одной большой программы: `read_side` отвечает
> за ввод, `exists` — за проверку, `median` — за формулу. Каждая функция делает одно дело
> и не печатает: ввод и вывод остаются в основной части. Это привычка из
> [[14. Функции и модули]] — «функция считает и возвращает».
>
> **Код.**
>
> ```python
> import math
>
>
> def read_side(prompt):
>     """Читает число и повторяет запрос, пока ввод не станет числом."""
>     while True:
>         try:
>             return float(input(prompt))
>         except ValueError:
>             print("Нужно ввести число, например 3 или 4.5")
>
>
> def exists(a, b, c):
>     """Проверяет, что стороны положительные и неравенство треугольника выполнено."""
>     return a > 0 and b > 0 and c > 0 and a + b > c and a + c > b and b + c > a
>
>
> def median(a, b, c):
>     """Медиана к стороне a: половина корня из 2b² + 2c² − a²."""
>     return math.sqrt(2 * b ** 2 + 2 * c ** 2 - a ** 2) / 2
>
>
> a = read_side("Сторона a: ")
> b = read_side("Сторона b: ")
> c = read_side("Сторона c: ")
>
> if not exists(a, b, c):
>     print("Треугольника с такими сторонами не существует")
> else:
>     print(f"Медиана к стороне a: {median(a, b, c):.4f}")
>     print(f"Медиана к стороне b: {median(b, a, c):.4f}")
>     print(f"Медиана к стороне c: {median(c, a, b):.4f}")
> ```
>
> **Пример запуска** (для `3, 4, 5` и для `1, 2, 10`):
>
> ```text
> Сторона a: 3
> Сторона b: 4
> Сторона c: 5
> Медиана к стороне a: 4.2720
> Медиана к стороне b: 3.6056
> Медиана к стороне c: 2.5000
>
> Сторона a: 1
> Сторона b: 2
> Сторона c: 10
> Треугольника с такими сторонами не существует
> ```
>
> **Что здесь важно.** Медиана к стороне `b` считается вызовом `median(b, a, c)` — функция
> одна, а сторону, к которой строится медиана, задаёт первый аргумент. Так формула
> не повторяется три раза: ошибку в ней придётся исправлять в одном месте.
>
> **Типичная ошибка.** Печатать результат внутри функции (`print` вместо `return`). Тогда
> функцию нельзя использовать в расчётах и трудно проверить: значение уходит на экран,
> а не возвращается в программу.
>
> **Граница.** Ввод с клавиатуры может быть чем угодно, и `read_side` повторяет вопрос,
> пока не получит число, — приём с `try` / `except` из
> [[05. Язык Python - идентификаторы, операторы, типы данных]]. Проверка «существует ли
> треугольник» выполняется **до** вычислений: формула на «невозможных» сторонах даст
> отрицательное число под корнем и `ValueError`.

## Задача 2. Свой модуль для списка

★★☆ · модуль, импорт, чистые функции

**Условие.** Нужно написать маленький «статистический» модуль из четырёх функций
и программу, которая им пользуется:

- `make_list(size)` — список чисел, введённых с клавиатуры;
- `average(numbers)` — среднее арифметическое;
- `maximum(numbers)` — наибольший элемент;
- `only_positive(numbers)` — новый список из положительных чисел.

**Задание.** 1) Разложи функции в файл `stats.py`. 2) Напиши `main.py`, который импортирует
модуль и выводит все четыре результата. 3) Запусти программу для чисел `5`, `−2`, `3.5`, `8`.
4) Что должны вернуть `average` и `maximum` для пустого списка?

> [!example]- Разбор
> **Идея.** Модуль — это обычный файл с функциями ([[14. Функции и модули]]). Функции
> не читают данные сами: список приходит в аргументе, результат возвращается через `return`.
> Поэтому их легко переиспользовать и проверять.
>
> **Код. `stats.py`**
>
> ```python
> """Функции для работы со списком чисел."""
>
>
> def make_list(size):
>     """Список из size чисел, введённых с клавиатуры."""
>     numbers = []
>     for i in range(size):
>         numbers.append(float(input(f"Число {i + 1}: ")))
>     return numbers
>
>
> def average(numbers):
>     """Среднее арифметическое; None, если список пуст."""
>     if len(numbers) == 0:
>         return None
>     return sum(numbers) / len(numbers)
>
>
> def maximum(numbers):
>     """Наибольший элемент; None, если список пуст."""
>     if len(numbers) == 0:
>         return None
>     best = numbers[0]
>     for number in numbers:
>         if number > best:
>             best = number
>     return best
>
>
> def only_positive(numbers):
>     """Новый список из положительных чисел."""
>     result = []
>     for number in numbers:
>         if number > 0:
>             result.append(number)
>     return result
> ```
>
> **Код. `main.py`**
>
> ```python
> import stats
>
> size = int(input("Сколько чисел? "))
> numbers = stats.make_list(size)
>
> print(f"Введено: {numbers}")
> print(f"Среднее: {stats.average(numbers):.4f}")
> print(f"Максимум: {stats.maximum(numbers)}")
> print(f"Положительные: {stats.only_positive(numbers)}")
> ```
>
> **Пример запуска**:
>
> ```text
> Сколько чисел? 4
> Число 1: 5
> Число 2: -2
> Число 3: 3.5
> Число 4: 8
> Введено: [5.0, -2.0, 3.5, 8.0]
> Среднее: 3.6250
> Максимум: 8.0
> Положительные: [5.0, 3.5, 8.0]
> ```
>
> **Что здесь важно.** Оба файла лежат **в одной папке**: `import stats` ищет модуль рядом
> с `main.py`. Именно поэтому в VS Code проект открывают папкой, а не отдельным файлом
> ([[06. Среды разработки и виртуальное окружение]]): иначе редактор не видит модули.
>
> **Типичная ошибка.** Считать статистику в `main.py` «по месту», скопировав первые
> программы курса. Тогда при второй задаче код придётся писать заново: модуль нужен
> именно для того, чтобы им пользоваться много раз.
>
> **Граница.** Для пустого списка среднее не определено — функция возвращает `None`
> и не падает с `ZeroDivisionError`. В `main.py` в этом случае формат `:.4f`
> не сработает, поэтому проверка «есть ли данные» — обязанность вызывающего кода:
> `if len(numbers) > 0:`.

## Задача 3. Список чисел в JSON-файле

★★★ · `pathlib`, `json`, запись и чтение файла, изменение данных

**Условие.** Программа работает со списком чисел `[3.5, 1.25, 9.0, 4.75, 2.0, 8.25]`:

1. записывает его в файл `numbers.json` в виде `{"numbers": [...]}`;
2. читает файл обратно и выводит список;
3. удаляет из списка максимальный и минимальный элементы;
4. записывает результат в тот же файл вторым ключом `without_edges`.

**Задание.** 1) Построй путь к файлу от файла программы (`Path(__file__)`), а не строкой
`"numbers.json"`. 2) Запиши данные в UTF-8 и не забудь `ensure_ascii=False`. 3) Проверь,
что после второго запуска файл не «сломался» и содержит оба ключа.

> [!example]- Разбор
> **Идея.** Файл — это данные, которые переживают закрытие программы
> ([[15. Работа с файлами]]). Путь строится от местоположения самого скрипта
> (`Path(__file__).resolve().parent`), поэтому программа работает из любой папки.
> Данные хранятся в JSON: список чисел превращается в строку через `json.dumps`
> и возвращается назад через `json.loads`.
>
> **Код.**
>
> ```python
> import json
> from pathlib import Path
>
> folder = Path(__file__).resolve().parent
> file_path = folder / "numbers.json"
>
> first = [3.5, 1.25, 9.0, 4.75, 2.0, 8.25]
> file_path.write_text(
>     json.dumps({"numbers": first}, ensure_ascii=False, indent=2), encoding="utf-8"
> )
>
> data = json.loads(file_path.read_text(encoding="utf-8"))
> numbers = data["numbers"]
> print(f"Было: {numbers}")
>
> biggest = max(numbers)
> smallest = min(numbers)
>
> without_edges = []
> for number in numbers:
>     if number != biggest and number != smallest:
>         without_edges.append(number)
>
> data["without_edges"] = without_edges
> file_path.write_text(
>     json.dumps(data, ensure_ascii=False, indent=2), encoding="utf-8"
> )
> print(f"Стало: {without_edges}")
> print(f"Файл: {file_path.name}")
> ```
>
> **Пример запуска**:
>
> ```text
> Было: [3.5, 1.25, 9.0, 4.75, 2.0, 8.25]
> Стало: [3.5, 4.75, 2.0, 8.25]
> Файл: numbers.json
> ```
>
> **Содержимое файла после запуска:**
>
> ```json
> {
>   "numbers": [3.5, 1.25, 9.0, 4.75, 2.0, 8.25],
>   "without_edges": [3.5, 4.75, 2.0, 8.25]
> }
> ```
>
> **Что здесь важно.** Файл читается и записывается как **словарь**: в него можно добавлять
> новые ключи, не теряя старые. Путь собран через оператор `/` у `Path` — так же, как
> в [[15. Работа с файлами]], и это защищает от «программа работает только из своей папки».
>
> **Типичная ошибка.** Писать `open("numbers.json")` без пути: программа создаст файл там,
> откуда её запустили, и в следующий раз его не найдёт. Второй вариант ошибки — забыть
> `encoding="utf-8"`; на русских буквах это сразу даёт «кракозябры», а иногда
> и `UnicodeDecodeError`.
>
> **Граница.** Если максимум и минимум совпадают (все числа одинаковые, например
> `[7, 7, 7]`), из списка удалятся **все** элементы, и результат будет пустым. Это стоит
> проверять: данные в условии могут быть любыми. Ещё один граничный случай — максимум
> встречается дважды: `number != biggest` уберёт оба вхождения — и это в большинстве задач
> именно то, что нужно.
