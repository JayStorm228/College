# 15. Работа с файлами

> [!abstract] О чём эта лекция
> До сих пор всё, что программа считала, исчезало после её закрытия. **Файл** — способ сохранить
> данные: настройки, результаты, тексты, таблицы. Здесь разбираются три вещи: как открыть
> и закрыть файл, как правильно собрать путь к нему и как хранить в файле структурированные
> данные (JSON).
>
> **Зачем это нужно.** Программа, которая не читает и не пишет файлы, умеет только разговаривать
> с человеком через консоль. Файлы — это данные между запусками и обмен с другими программами.
> И почти все «загадочные» ошибки здесь родом из двух мест: неверный путь (программа запущена
> из другой папки) и неверная кодировка.
>
> **Что ты должен уметь после лекции:** прочитать файл целиком и построчно; записать и дописать
> текст; не забывать про `with`; собрать путь через `pathlib` так, чтобы он работал после
> переноса проекта; сохранить словарь в JSON и прочитать его назад; прочитать сообщение
> `FileNotFoundError` и понять, где искать файл.
>
> **Куда идти дальше:** [[16. Объектно-ориентированное программирование]] — последняя тема курса.

# Три шага работы с файлом

Любая работа с файлом состоит из трёх шагов:

1. **открыть** файл — `open(...)`, указав путь и режим;
2. **прочитать или записать** данные;
3. **закрыть** файл — иначе данные могут не сохраниться, а файл останется занятым.

```python
file = open("notes.txt", "r", encoding="utf-8")
text = file.read()
file.close()
print(text)
```

Так писать можно, но почти никто так не пишет: легко забыть про `close()`. Для этого есть
**контекстный менеджер** `with` — он закрывает файл в любом случае.

```python
with open("notes.txt", "r", encoding="utf-8") as file:
    text = file.read()

print(text)      # файл уже закрыт
```

> [!important] Почему `with` лучше ручного `close()`
> `with` закрывает файл не только при обычном завершении, но и **при ошибке внутри блока**:
> если чтение упадёт на середине, файл всё равно будет закрыт. Ручная запись `open` … `close`
> этого не гарантирует — исключение проскочит мимо `close()`, и файл останется открытым.
> Правило: **любая работа с файлом — через `with`**.

# Режимы открытия

| Режим | Что делает | Если файла нет | Что происходит с содержимым |
|---|---|---|---|
| `"r"` | чтение | ошибка `FileNotFoundError` | — |
| `"w"` | запись | файл создаётся | **старое содержимое стирается** |
| `"a"` | дозапись | файл создаётся | старое остаётся, новое пишется в конец |
| `"r+"` | чтение и запись | ошибка | содержимое меняется по месту |

Буква `b` добавляет «бинарный» режим: `"rb"`, `"wb"`, `"ab"`. В нём данные читаются и пишутся
байтами — это нужно для картинок, архивов, готовых форматов. Текст читают и пишут **без** `b`.

> [!warning] `"w"` уничтожает файл
> Открыть файл в режиме `"w"` — значит стереть его содержимое сразу, ещё до первой записи.
> Если нужен журнал, который дополняется, — режим `"a"`. Если боишься потерять данные —
> сначала копия.

# Чтение данных

```python
# весь файл одной строкой
with open("data.txt", "r", encoding="utf-8") as file:
    text = file.read()

# список строк (в каждой строке остаётся \n)
with open("data.txt", "r", encoding="utf-8") as file:
    lines = file.readlines()

# построчно, без загрузки всего файла в память — так делают для больших файлов
with open("data.txt", "r", encoding="utf-8") as file:
    for line in file:
        print(line.rstrip())
```

`line.rstrip()` убирает перевод строки справа — без него между строками вывода будет пустая
строка (ведь в конце каждой строки файла уже есть `\n`).

Обычно строку из файла сразу разбирают:

```python
# строка вида "Аня;17;Калининград"
for line in file:
    name, age, city = line.strip().split(";")
    print(f"{name} ({age}) — {city}")
```

# Запись данных

```python
with open("result.txt", "w", encoding="utf-8") as file:
    file.write("Отчёт\n")
    file.write(f"Строк: {count}\n")
```

Запомни две вещи:

- `write()` **не добавляет** перевод строки — `\n` пишут руками;
- `write()` принимает только строку: число нужно преобразовать (`str(count)`), а удобнее —
  f-строка, она делает это сама.

Для списка строк есть `writelines()`, но имена обманывают: переводы строк он тоже не добавляет.

```python
lines = [f"{name}: {score}\n" for name, score in results]
with open("report.txt", "w", encoding="utf-8") as file:
    file.writelines(lines)
```

> [!note] Кодировка — указывать всегда
> `encoding="utf-8"` — стандарт для текста, и в нём русские буквы не превращаются в «кракозябры».
> Без указания кодировки Python берёт системную, и на другой машине файл может прочитаться
> неправильно. Одно исключение: `open(..., "rb")` — бинарный режим, там кодировки нет.

# Пути: `pathlib` вместо строк

Первый источник «непонятных» ошибок — путь. Запись `open("data.txt")` ищет файл
в **текущем рабочем каталоге** (current working directory), а он зависит от того, откуда
запущена программа: в редакторе это папка проекта, а из терминала — папка, из которой запустили.

Правильный способ — строить путь **от файла программы**, а не от текущего каталога:

```python
from pathlib import Path

BASE_DIR = Path(__file__).resolve().parent          # папка, где лежит сам скрипт
DATA_DIR = BASE_DIR / "data"                        # оператор / склеивает пути
file_path = DATA_DIR / "result.txt"

with file_path.open("w", encoding="utf-8") as file:
    file.write("Отчёт готов\n")
```

`Path(__file__)` — путь к самому файлу программы, `.parent` — его папка. Такой путь не зависит
от того, откуда запустили программу, и работает на любой операционной системе: склейка через
`/` сама подставит нужный разделитель.

Полезные методы `Path`:

| Метод | Что делает |
|---|---|
| `path.exists()` | существует ли путь |
| `path.is_file()` / `path.is_dir()` | это файл / это папка |
| `path.mkdir(parents=True, exist_ok=True)` | создать папку (и родителей, не падая, если уже есть) |
| `path.read_text(encoding="utf-8")` | прочитать текст одной строкой кода |
| `path.write_text(text, encoding="utf-8")` | записать текст одной строкой |
| `path.name`, `path.suffix`, `path.parent` | имя, расширение, родительская папка |
| `path.resolve()` | абсолютный путь |

```python
from pathlib import Path

path = Path("data/result.txt")
print(path.name)        # result.txt
print(path.suffix)      # .txt
print(path.parent)      # data
print(path.exists())    # False, если файла ещё нет
```

> [!warning] Не собирай пути строками
> `"data" + "/" + "result.txt"` ломается на другой системе и неверно склеивается, если
> у папки есть завершающий слэш. `Path("data") / "result.txt"` — правильный способ.

# JSON: данные со структурой

Текст в файле хранить удобно, но что делать со словарём или списком? Превратить его в текст —
это называется **сериализация**. Самый распространённый формат — **JSON**, и у Python есть
для него встроенный модуль `json`.

```python
import json

data = {
    "name": "Аня",
    "scores": [5, 4, 5],
    "city": "Калининград",
}

# словарь → строка JSON
text = json.dumps(data, ensure_ascii=False, indent=2)
print(text)
```

```json
{
  "name": "Аня",
  "scores": [5, 4, 5],
  "city": "Калининград"
}
```

Работа с файлом получается в две строки:

```python
from pathlib import Path
import json

path = Path("student.json")

# запись
with path.open("w", encoding="utf-8") as file:
    json.dump(data, file, ensure_ascii=False, indent=2)

# чтение
with path.open("r", encoding="utf-8") as file:
    loaded = json.load(file)

print(loaded["name"])       # Аня
print(loaded["scores"])     # [5, 4, 5]
```

| Функция | С чем работает |
|---|---|
| `json.dumps(obj)` / `json.loads(text)` | со **строкой** в памяти |
| `json.dump(obj, file)` / `json.load(file)` | с **файлом** |

Параметры, которые стоит указывать: `ensure_ascii=False` (чтобы русские буквы остались буквами,
а не `\u0410`-последовательностями) и `indent=2` (чтобы файл читался человеком).

> [!note] Что JSON умеет хранить
> Словари, списки, строки, числа, `true` / `false` / `null`. Кортеж при записи станет списком,
> а произвольный объект записать не получится — «JSON умеет только простые данные».
> Как сохранить в JSON информацию о своих объектах, разбирается в
> [[16. Объектно-ориентированное программирование]].

> [!warning] Бинарные форматы Python (продвинутое)
> В модулях `pickle` и `shelve` можно сохранить почти любой объект Python «как есть» — это
> удобно для кэшей и временных файлов. Но: файл `pickle` может выполнить произвольный код
> при чтении, поэтому **чужие** такие файлы открывать нельзя, и для обмена данными их
> не используют. Подробно — в инженерном модуле; для обмена данными есть JSON.

# Ошибки при работе с файлами

| Ошибка | Что случилось | Что делать |
|---|---|---|
| `FileNotFoundError` | файла по пути нет (или путь считается от другой папки) | проверить путь; печатать его при отладке; строить от `__file__` |
| `PermissionError` | нет прав на запись (файл открыт в другой программе, системная папка) | закрыть файл в другой программе, выбрать рабочую папку |
| `UnicodeDecodeError` | файл прочитан не в той кодировке | указать `encoding="utf-8"` (или ту, в которой файл реально сохранён) |
| `IsADirectoryError` | в `open` попала папка, а не файл | проверить путь: возможно, потеряно имя файла в конце |

Приём отладки, который экономит время: **напечатать путь и проверить его существование**
перед чтением.

```python
path = BASE_DIR / "data" / "result.txt"
print(path, path.exists())      # видно, какой именно путь получился
```

# Как это делают в проекте

**Привычка 1. `with` — всегда.** Ни одна работа с файлом не должна оставлять его открытым.

**Привычка 2. Кодировка указывается явно.** `encoding="utf-8"` для любого текстового файла.

**Привычка 3. Пути строятся от файла программы.** `Path(__file__).resolve().parent / "data"` —
тогда программа работает независимо от того, откуда её запустили.

**Привычка 4. Данные — в JSON, а не в самодельном тексте.** Если сохраняешь структуру
(словарь, список), JSON даст понятный человеку файл и готовый разбор.

**Привычка 5. Файл создают до записи, если так задумано.** `path.parent.mkdir(parents=True,
exist_ok=True)` перед записью избавляет от ошибки «папки нет» на чистой машине.

# Ключевые термины

| Термин | Определение |
|---|---|
| **Файл** | именованная область на диске, где данные хранятся между запусками программы |
| **`open(path, mode, encoding)`** | открыть файл в нужном режиме |
| **Режимы** | `"r"` чтение, `"w"` запись (стирает), `"a"` дозапись, `b` — бинарный |
| **Контекстный менеджер `with`** | гарантирует закрытие файла, в том числе при ошибке |
| **`read`, `readline`, `readlines`** | прочитать всё / одну строку / список строк |
| **`write`, `writelines`** | записать строку / список строк (переводы строк не добавляются) |
| **Кодировка** | правило отображения символов в байты; для текста — `utf-8` |
| **Текущий рабочий каталог** | папка, от которой считаются относительные пути; зависит от запуска |
| **`pathlib.Path`** | объект для работы с путями; `/` склеивает пути, методы читают и пишут файлы |
| **Сериализация / десериализация** | превращение данных в текст/байты и обратно |
| **JSON** | текстовый формат обмена данными; в Python — модуль `json` |
| **`json.dump` / `json.load`** | запись и чтение JSON в файл (без «s» — со строкой) |

# Типичные заблуждения

- ❌ **«Можно не закрывать файл».** После записи данные могут остаться в буфере и не попасть
  на диск; файл остаётся занятым. Решение — всегда `with`.
- ❌ **«`with` нужен, чтобы файл быстрее работал».** Он нужен для надёжности: закрывает файл
  и при ошибке тоже.
- ❌ **«`"w"` добавляет в конец».** `"w"` стирает содержимое. Добавление — режим `"a"`.
- ❌ **«`write()` сам добавит перевод строки».** Не добавит: `\n` пишется явно.
- ❌ **«Путь `data.txt` найдётся всегда».** Он ищется от текущего рабочего каталога, который
  зависит от запуска. Надёжно — строить путь от `__file__`.
- ❌ **«Кодировку Python подберёт».** Подберёт системную, и она может не совпасть с той, в которой
  файл сохранён. Явное `encoding="utf-8"` снимает вопрос.
- ❌ **«JSON сохранит любой объект».** Только простые данные: словари, списки, строки, числа,
  `true` / `false` / `null`. Кортеж превратится в список, свой объект — не сохранится.
- ❌ **«`json.dumps` — то же, что `json.dump`».** `dumps`/`loads` работают со строкой,
  `dump`/`load` — с файлом.

# Проверь себя

1. Зачем нужен `with` и что произойдёт, если обойтись без него?
2. Чем `"w"` отличается от `"a"` и какие у этого последствия?
3. Почему путь `"data.txt"` может «не найтись», хотя файл есть?
4. Как надёжно построить путь к файлу рядом с программой?
5. Какие параметры стоит указывать при записи JSON и зачем?
6. Что означает `UnicodeDecodeError` и как его исправить?

> [!example]- Ответы
> 1. `with` гарантированно закрывает файл — и при обычном окончании, и при ошибке внутри блока.
>    Без него нужно помнить про `close()`; при исключении файл останется открытым, а данные
>    могут не записаться на диск.
> 2. `"w"` стирает содержимое файла сразу при открытии и пишет с начала; `"a"` сохраняет старое
>    и дописывает в конец. Для журналов и накопления данных нужен `"a"`; `"w"` — когда файл
>    перезаписывается целиком.
> 3. Потому что относительный путь считается от **текущего рабочего каталога**, а он зависит
>    от того, откуда запущена программа (из редактора — одно, из другой папки в терминале —
>    другое).
> 4. Через `pathlib`: `BASE_DIR = Path(__file__).resolve().parent`, дальше
>    `BASE_DIR / "data" / "result.txt"`. Такой путь не зависит от места запуска.
> 5. `ensure_ascii=False`, чтобы русский текст остался читаемым, и `indent=2`, чтобы файл был
>    отформатирован для человека. Плюс `encoding="utf-8"` при открытии файла.
> 6. Файл прочитан в кодировке, которая не совпадает с той, в которой он сохранён. Исправление:
>    открывать с нужной кодировкой — обычно `encoding="utf-8"`.
