# 14. Функции и модули

> [!abstract] О чём эта лекция
> Программа растёт: один и тот же расчёт нужен в трёх местах, код начинает дублироваться, и всё труднее
> понять, что где. Решение — **функции**: именованные блоки кода, которые можно вызывать
> сколько нужно раз. А когда функций становится много, их раскладывают по **модулям** — файлам.
>
> **Зачем это нужно.** До этой лекции вся программа была «сверху вниз». Функции — граница между
> «код, который пишут один раз» и «код, которым пользуются»: они дают имена действиям, убирают
> копипаст и позволяют проверять части по отдельности. Дальше весь курс строится на них:
> в Django каждая страница — это функция или метод.
>
> **Что ты должен уметь после лекции:** написать функцию с параметрами и возвратом значения;
> понять разницу между аргументами по порядку и по имени; не наступить на ловушку изменяемого
> значения по умолчанию; объяснить, почему `global` — плохая привычка; вынести функции в модуль
> и импортировать их; защитить модуль от выполнения при импорте.
>
> **Куда идти дальше:** [[15. Работа с файлами]].

> [!tip] Что нужно знать заранее
> [[09. Циклический алгоритм - цикл for]], [[11. Кортежи, списки, словари]],
> [[13. Вложенные последовательности]] — функции принимают и возвращают любые значения,
> чаще всего коллекции. [[06. Среды разработки и виртуальное окружение]] — модули и запуск кода.

# Зачем нужны функции

Представь: в программе трижды нужно посчитать среднее значение, и в каждом месте написан
одинаковый код. Проблемы начинаются сразу:

- **дублирование.** Нашли ошибку в формуле — надо исправить в трёх местах и не забыть про четвёртое;
- **нет имени.** `(a + b) / 2` не говорит, что это «среднее»; смысл держится в голове автора;
- **нечего проверять.** Нельзя протестировать «среднее» отдельно от остальной программы;
- **программа не читается.** Страница кода без единого имени действия — это набор операций.

**Функция** решает всё это сразу: у действия появляется имя, код живёт в одном месте,
и его можно вызвать из любого количества мест.

```python
def average(first, second):
    """Возвращает среднее арифметическое двух чисел."""
    return (first + second) / 2


mark_a = average(5, 4)      # 4.5
mark_b = average(3, 2)      # 2.5
print(f"Средние: {mark_a} и {mark_b}")
```

# Как устроена функция

```python
def average(first, second):
    """Возвращает среднее арифметическое двух чисел."""
    return (first + second) / 2
```

| Часть | Что это |
|---|---|
| `def` | «объявляю функцию» |
| `average` | имя функции — обычно глагол или «что она считает» |
| `first, second` | **параметры**: имена, под которыми внутри функции видны данные |
| `"""..."""` | **docstring** — описание: что функция делает, что принимает, что возвращает |
| `return` | вернуть результат туда, откуда функцию вызвали |

**Аргументы** — значения, которые передаются при вызове: в `average(5, 4)` это `5` и `4`.
При вызове значения попадают в параметры по порядку: `first = 5`, `second = 4`.

`return` делает две вещи: возвращает значение и **заканчивает** функцию.

```python
def describe(score):
    """Возвращает текстовую оценку по баллам."""
    if score >= 90:
        return "отлично"
    if score >= 60:
        return "хорошо"
    return "нужно доработать"
```

Здесь несколько `return`, но срабатывает всегда только первый подходящий: как только функция
что-то вернула, она завершилась. Такая запись называется «ранний выход» и читается лучше,
чем вложенная лестница `if` … `else`.

> [!important] Функция без `return` возвращает `None`
> Если `return` не написать (или написать `return` без значения), функция вернёт `None` —
> «ничего». Это не ошибка, но если результат хотели получить, а он «пустой», — ищите забытый
> `return`.

# Аргументы по порядку и по имени

```python
def delivery_cost(weight, urgent=False):
    """Считает стоимость доставки: базовая цена плюс надбавка за вес и срочность."""
    cost = 200 + max(0, weight - 1) * 50
    if urgent:
        cost += 300
    return cost


print(delivery_cost(2))                     # 250 — по порядку
print(delivery_cost(weight=2))              # 250 — по имени
print(delivery_cost(2, urgent=True))        # 550 — первый по порядку, второй по имени
```

- **Позиционные аргументы** — передаются по порядку;
- **Именованные (ключевые)** — `weight=2`: видно, что чему соответствует; удобно, когда
  параметров много;
- **Значения по умолчанию** — `urgent=False`: если аргумент не указан, берётся это значение.

> [!warning] Изменяемое значение по умолчанию — ловушка
> Значение по умолчанию вычисляется **один раз**, при объявлении функции. Поэтому список
> или словарь в роли «пустого по умолчанию» будут общими для всех вызовов:
>
> ```python
> def add_item(item, items=[]):        # так нельзя
>     items.append(item)
>     return items
>
> print(add_item("яблоко"))            # ['яблоко']
> print(add_item("груша"))             # ['яблоко', 'груша'] — вот это сюрприз
> ```
>
> Правильно — «пустое» значение `None`, а контейнер создавать внутри:
>
> ```python
> def add_item(item, items=None):
>     """Добавляет элемент в список и возвращает его."""
>     if items is None:
>         items = []
>     items.append(item)
>     return items
> ```

# Область видимости: что видно внутри функции

Переменные, созданные внутри функции, снаружи не видны, и наоборот:

```python
def double(number):
    """Возвращает удвоенное число."""
    result = number * 2          # result существует только внутри функции
    return result


print(double(5))                 # 10
# print(result)                  # NameError: name 'result' is not defined
```

Данные передаются в функцию **через аргументы**, а возвращаются **через `return`**. Это главное
правило: функция — маленькая программа со своим входом и выходом.

```python
# плохо: функция меняет чужие переменные снаружи
total = 0

def add_to_total(value):
    global total                 # так писать не надо
    total += value

# хорошо: данные приходят в аргументах, результат возвращается
def add(total, value):
    """Возвращает сумму двух чисел."""
    return total + value

total = add(total, 5)
```

> [!important] Почему `global` — плохая привычка
> Функция, которая меняет глобальные переменные, ведёт себя по-разному в зависимости от того,
> что было раньше в программе. Её невозможно проверить отдельно и трудно понять. Правило:
> всё нужное — в параметрах, всё полученное — в `return`.

# Функции, которые легко проверить

Функция, которая только считает и возвращает результат (не печатает и не меняет файлы),
называется **чистой**. Её легко проверить и переиспользовать.

```python
# трудно проверить: результат ушёл на экран, использовать его больше нигде нельзя
def print_average(first, second):
    print((first + second) / 2)

# легко проверить и использовать: результат вернулся
def average(first, second):
    """Возвращает среднее арифметическое двух чисел."""
    return (first + second) / 2

result = average(5, 4)
print(f"Среднее: {result:.1f}")
```

Совет простой: **функция считает и возвращает, а печатает пусть тот, кто её вызвал.**
В будущем такие функции превращаются в автотесты почти без переделки — этим займёмся
в инженерном модуле.

# Модули: функции в отдельном файле

Когда функций много, их раскладывают по файлам. В Python **модуль** — это обычный файл `.py`.

```text
src/
├── geometry.py      # модуль: здесь функции
└── main.py          # программа: здесь их используют
```

```python
# geometry.py
"""Расчёты для геометрических фигур."""

import math


def circle_area(radius):
    """Возвращает площадь круга по радиусу."""
    return math.pi * radius ** 2


def rectangle_area(width, height):
    """Возвращает площадь прямоугольника."""
    return width * height
```

```python
# main.py
from geometry import circle_area, rectangle_area


def main():
    """Точка входа программы."""
    print(f"Площадь круга: {circle_area(2):.2f}")
    print(f"Площадь прямоугольника: {rectangle_area(3, 4)}")


if __name__ == "__main__":
    main()
```

Разбор импорта:

| Запись | Что делает |
|---|---|
| `import geometry` | подключает модуль целиком: `geometry.circle_area(2)` |
| `from geometry import circle_area` | подключает только нужную функцию: `circle_area(2)` |
| `import geometry as geo` | подключает с коротким именем: `geo.circle_area(2)` |

Расширение `.py` при импорте не пишут: `import geometry`, а не `import geometry.py`.
Модуль должен лежать **рядом** с программой (или в папке проекта) — иначе Python его не найдёт.

> [!important] `if __name__ == "__main__":`
> При импорте модуля Python выполняет **весь** его код сверху вниз. Значит, если в модуле есть
> вызовы функций «просто так», они сработают при импорте — и чужой код начнёт что-то печатать
> или считать.
>
> ```python
> # плохо: при импорте это выполнится и что-то напечатает
> print(circle_area(2))
>
> # хорошо: код запускается только при прямом запуске файла
> def main():
>     ...
>
> if __name__ == "__main__":
>     main()
> ```
>
> `__name__` — служебная переменная: она равна `"__main__"` при прямом запуске файла
> и имени модуля при импорте. Условие читается как «если этот файл — главная программа,
> выполни `main()`».

**Пакеты.** Папка, в которой лежат модули, называется **пакетом**: например, `src/geometry/`
с файлами `circle.py`, `rectangle.py`. Импорт тогда длиннее: `from geometry.circle import circle_area`.
Это удобно в больших проектах; в учебных задачах хватает одного-двух модулей.

> [!note] `*args` и `**kwargs` (продвинутое)
> Иногда функция должна принимать «сколько угодно аргументов»: `*args` соберёт позиционные
> в кортеж, `**kwargs` — именованные в словарь. В прикладном коде это встречается редко
> (чаще в библиотеках), поэтому подробности — в инженерном модуле. Пока достаточно знать,
> что звёздочки означают «любое количество».

# Как это делают в проекте

**Привычка 1. Одна функция — одна задача.** Если описание функции начинается с «и», это две
функции: «считать среднее **и** напечатать отчёт». Разделив их, каждую легко проверить.

**Привычка 2. Имя функции — глагол.** `count_words()`, `find_max()`, `is_valid()` — по имени
видно, что функция делает. Проверка на «плохое имя»: если из имени непонятно, что вернётся, —
переименуй.

**Привычка 3. Функция помещается на экран.** Если для чтения нужно прокручивать, функцию пора
разделить. Это не жёсткое правило, но ориентир полезный.

**Привычка 4. Docstring — одна строка о сути.** Что принимает, что возвращает. Не описывать
построчно код: его видно рядом.

**Привычка 5. Не повторяться.** Скопированный в третий раз код — сигнал, что нужна функция.
Это правило называют DRY (Don't Repeat Yourself).

# Ключевые термины

| Термин | Определение |
|---|---|
| **Функция** | именованный блок кода, который можно вызывать с разными данными |
| **Параметр** | имя данных внутри функции (`first`, `second`) |
| **Аргумент** | значение, переданное при вызове (`average(5, 4)`) |
| **`return`** | вернуть результат и завершить функцию |
| **`None`** | «ничего»; функция без `return` возвращает `None` |
| **Значение по умолчанию** | значение параметра, если аргумент не передан: `urgent=False` |
| **Именованный аргумент** | аргумент с именем параметра: `weight=2` |
| **Область видимости** | где переменная существует: локальные внутри функции, глобальные снаружи |
| **Чистая функция** | только считает и возвращает результат, не меняя ничего снаружи |
| **Docstring** | описание функции в тройных кавычках сразу под `def` |
| **Модуль** | файл `.py` с функциями и данными, подключается через `import` |
| **Пакет** | папка с модулями |
| **`if __name__ == "__main__":`** | защита: код выполняется при запуске файла, но не при импорте |

# Типичные заблуждения

- ❌ **«Функция нужна только для больших задач».** Функция нужна для **повторяющегося** и для
  **именованного**: даже три строки стоит вынести, если они используются дважды или имеют смысл.
- ❌ **«`return` и `print` — почти одно и то же».** `print` показывает значение человеку
  и ничего не возвращает; `return` отдаёт значение программе, и его можно использовать дальше.
- ❌ **«Значение по умолчанию можно задавать списком».** Можно, но список общий для всех
  вызовов — это классическая ошибка. Для «пустого» значения используют `None`.
- ❌ **«Переменные, созданные в функции, видны снаружи».** Нет: они локальные. Данные передают
  через аргументы и `return`.
- ❌ **«`global` упрощает код».** Упрощает запись, но ломает понятность: функцию нельзя проверить
  отдельно, а результат зависит от состояния всей программы.
- ❌ **«Модуль — это что-то особенное».** Модуль — обычный файл `.py`. Особенность одна:
  при импорте выполняется весь код файла.
- ❌ **«Импортировать можно только установленные библиотеки».** Свой модуль импортируется так же:
  важно, чтобы файл лежал рядом или в папке проекта.
- ❌ **«Расширение нужно указать: `import geometry.py`».** Нет, только имя модуля без `.py`.

# Проверь себя

1. Чем параметр отличается от аргумента?
2. Что вернёт функция, в которой нет `return`?
3. Почему `def add_item(item, items=[])` — плохое решение и как исправить?
4. Как передать данные в функцию и как получить результат, если не использовать `global`?
5. Зачем нужен `if __name__ == "__main__":`?
6. Почему функция, которая возвращает результат, лучше функции, которая печатает его?

> [!example]- Ответы
> 1. **Параметр** — имя внутри функции, объявленное при её создании: `def average(first, second)`.
>    **Аргумент** — конкретное значение, переданное при вызове: `average(5, 4)`.
> 2. `None` — «ничего». Если результат нужен, надо написать `return`.
> 3. Значение по умолчанию вычисляется один раз при объявлении, поэтому один и тот же список
>    будет использоваться всеми вызовами и «накапливать» чужие элементы. Правильно: параметр
>    `items=None`, а пустой список создавать внутри функции (`if items is None: items = []`).
> 4. Данные передаются **аргументами**, результат возвращается через **`return`**. Тогда функция
>    не зависит от состояния программы: что дали — то и посчитала.
> 5. Чтобы код «просто запуска» выполнялся только при прямом запуске файла, а при импорте модуля
>    — нет. Иначе импорт чужой программы начнёт печатать и считать лишнее.
> 6. Результат можно использовать дальше (сложить, записать в файл, вывести красиво) и легко
>    проверить: сравнить возвращённое значение с ожидаемым. Печать — действие «наружу», её
>    нельзя использовать как значение.
