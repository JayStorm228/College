# 08. Разветвляющийся алгоритм

> [!abstract] О чём эта лекция
> В [[03. Разветвляющийся алгоритм — общий вид]] развилка разбиралась ромбами на схеме. Здесь
> она записывается кодом: `if`, `else`, `elif` — и вместе с ними появляется то, чего не было
> в линейном алгоритме: программа сама выбирает, какая ветка выполнится.
>
> **Зачем это нужно.** Развилка — первое место, где ошибка не роняет программу, а тихо портит
> ответ: «хорошо» вместо «отлично», «не сдано» вместо «удовлетворительно». Такие ошибки ловятся
> не запуском, а проверкой границ — и этой привычке посвящена половина лекции.
>
> **Что ты должен уметь после лекции:** записать неполную, полную и многозначную развилку;
> соединить условия через `and`, `or`, `not`; расставить условия в правильном порядке;
> объяснить, почему в Python отступы — часть языка; проверить развилку на граничных значениях
> и найти потерянный случай.
>
> **Куда идти дальше:** [[09. Циклический алгоритм - цикл for]] — повторение шагов.

# Условие в коде

**Условие** — вопрос, на который есть ответ «да» или «нет». В коде на него отвечает выражение
типа `bool`: `True` или `False`.

```python
age = int(input("Возраст: "))

if age >= 18:
    print("Вход разрешён")
```

Читается ровно как схема: «если возраст не меньше 18 — выполнить действие».
Обратите внимание на три детали записи:

1. после условия стоит **двоеточие** `:`;
2. действие на следующей строке сдвинуто вправо — это **отступ**;
3. отступ в Python — не украшение, а часть языка.

> [!important] Отступ = «что входит в ветку»
> Все строки с одинаковым отступом после `if` — это его тело. Как только отступ заканчивается,
> заканчивается и ветка:
>
> ```python
> if age >= 18:
>     print("Вход разрешён")     # внутри ветки
>     print("Билет полный")      # тоже внутри ветки
> print("Следующий посетитель")  # уже вне ветки — выполнится всегда
> ```
>
> По стандарту PEP 8 отступ — **четыре пробела**, не табуляция. Смешивать пробелы и табы
> в одном файле нельзя: Python выдаст `TabError`.

# Три формы развилки

**Неполная** — действие только на ветке «да». Если условие ложно, ничего не происходит:

```python
if temperature < 0:
    print("На улице мороз — наденьте шапку")
```

**Полная** — есть обе ветки, «если — иначе»:

```python
if temperature < 0:
    print("На улице мороз")
else:
    print("Мороза нет")
```

**Многозначная (лестница условий)** — вариантов больше двух; проверки идут одна за другой,
пока какая-нибудь не окажется истинной:

```python
score = int(input("Баллы: "))

if score >= 90:
    mark = 5
elif score >= 60:
    mark = 4
elif score >= 40:
    mark = 3
else:
    mark = 2

print(f"Оценка: {mark}")
```

`elif` — сокращение от `else if`: «иначе, если…». В лестнице выполняется **первое истинное**
условие, все следующие пропускаются. `else` необязателен, но в развилке с ним надёжнее: он
забирает все случаи, которые не подошли ни под одно условие.

# Составные условия

Простые условия соединяются операторами:

| Оператор | Значит | Истинно, когда |
|---|---|---|
| `and` | и | истинны **оба** условия |
| `or` | или | истинно **хотя бы одно** |
| `not` | не | условие ложно |

```python
if height >= 140 and age >= 12:
    print("Можно на аттракцион")

if is_student or is_pensioner:
    print("Есть скидка")

if not is_closed:
    print("Магазин открыт")
```

В Python можно писать цепочки сравнений — это читается как в математике:

```python
if 0 <= score <= 100:
    print("Балл в допустимых пределах")
```

> [!warning] Отрицание «и» — это «или»
> `not (a and b)` — то же самое, что `not a or not b`. Проверка на «не подходит» превращается
> в «или»: «не пускать, если рост меньше 140 **или** возраст меньше 12».
> Перепутать `and` и `or` легко, а цена — неверное решение по каждому второму случаю.

# Вложенные развилки и порядок условий

Развилку можно поместить внутрь другой развилки — так записывают зависимые проверки:

```python
if has_ticket:
    if age >= 18:
        print("Проходите в зал")
    else:
        print("Нужно сопровождение взрослого")
else:
    print("Сначала купите билет")
```

То же самое можно записать составным условием, и часто это читается лучше:

```python
if has_ticket and age >= 18:
    print("Проходите в зал")
elif has_ticket:
    print("Нужно сопровождение взрослого")
else:
    print("Сначала купите билет")
```

**Порядок условий — часть алгоритма.** В лестнице проверки идут от самого строгого условия
к самому мягкому:

```python
# верно: 95 баллов попадут в «отлично»
if score >= 90:
    ...

# неверно: 95 баллов получат «хорошо», до проверки >= 90 дело не дойдёт
if score >= 60:
    ...
```

> [!tip] Как проверять развилку
> Проверь **три точки на каждой границе**: чуть меньше, ровно на границе, чуть больше
> (для `score >= 90` это 89, 90, 91). И добавь крайние случаи: 0 и максимум. Если хоть один
> случай не попадает ни в одну ветку или попадает в две — ошибка в условиях.

# Короткая запись и «пустые» значения

Если выбор нужно сделать внутри одной строки, есть тернарное выражение:

```python
status = "совершеннолетний" if age >= 18 else "несовершеннолетний"
```

Оно удобно для коротких случаев; для длинной логики его не используют — читается хуже,
чем обычная развилка.

> [!note] Правда и ложь в условии (продвинутое)
> В условие можно поставить не только сравнение. Пустая строка `""`, число `0`, пустая
> коллекция и `None` считаются ложными, всё остальное — истинным. Поэтому пишут
> `if name:` вместо `if name != ""`. Как это устроено, разбирается в инженерном модуле;
> пока пользуйся сравнениями — они понятнее для читателя.

# Как это делают в проекте

**Привычка 1. Проверять границы тремя значениями.** Перед сдачей задачи прогнать чуть меньше,
ровно на границе и чуть больше. Это ловит и «потерянный случай» (значение не попадает
ни в одну ветку), и «перетянутое» условие из лестницы.

**Привычка 2. Не углублять вложенность.** Два уровня вложенности читаются, четыре — уже нет.
Если развилка «уходит вправо», её разбивают на отдельные условия или объединяют в составные.

**Привычка 3. Называть условия по смыслу.** `if is_ready:` и `if has_discount:` читаются
как фразы. `if flag == 1:` заставляет лезть в код и вспоминать, что такое `flag`.

**Привычка 4. Строить лестницу от строгого к мягкому.** Самые узкие условия — первыми,
широкое `else` — последним: тогда каждый случай обрабатывается ровно один раз.

# Ключевые термины

| Термин | Определение |
|---|---|
| **Условие** | выражение с ответом «истина/ложь»; на схеме — ромб |
| **Неполная развилка** | действие только при истинном условии: один `if` |
| **Полная развилка** | обе ветки: `if` … `else` |
| **Многозначная развилка** | лестница: `if` … `elif` … `else` |
| **`elif`** | «иначе, если» — очередная проверка в лестнице |
| **Составное условие** | несколько простых условий, соединённых `and` / `or` / `not` |
| **Вложенная развилка** | развилка внутри другой развилки |
| **Отступ** | сдвиг строк вправо, определяющий, что входит в ветку; 4 пробела |
| **Граничное значение** | значение ровно на границе условия (90 для `>= 90`) |
| **Потерянный случай** | значение, которое не обрабатывает ни одна ветка |

# Типичные заблуждения

- ❌ **«Отступы нужны для красоты».** В Python отступ определяет структуру программы. Неверный
  отступ — либо `IndentationError`, либо код делает не то, что задумано.
- ❌ **«`elif` проверяет всё заново».** Лестница останавливается на первом истинном условии:
  остальные не проверяются вообще.
- ❌ **«Порядок условий не важен».** Важен: `>= 60` перед `>= 90` «украдёт» все отличные оценки.
- ❌ **«`and` и `or` взаимозаменяемы».** `условие1 and условие2` требует обоих, `or` — любого
  одного. Перепутав, получают пропуск «по любому из двух условий» вместо «по обоим».
- ❌ **«Если случаи не описаны, программа скажет».** Не скажет: она просто ничего не сделает
  или оставит старую переменную. Потерянный случай не виден без проверки границ.
- ❌ **«`if x = 5:` — нормально».** Один `=` — присваивание; для сравнения нужен `==`.
- ❌ **«Сравнивать дробные числа можно смело».** `0.1 + 0.2 == 0.3` — `False`. Для границ
  и сравнений такой проверки недостаточно: сравнивают с точностью.
- ❌ **«Вложенность — признак сложной задачи».** Чаще это признак запутанного решения:
  ту же логику почти всегда можно записать составным условием или двумя отдельными проверками.

# Проверь себя

1. Почему в Python нельзя «просто сдвинуть строку» — что изменится?
2. Сколько условий проверится в лестнице, если первое истинно?
3. Что произойдёт со студентом с 95 баллами, если лестницу начать с `score >= 60`?
4. Как проверить границу `score >= 90` и зачем именно три значения?
5. Когда составное условие с `or` истинно, а когда ложно?
6. Что такое потерянный случай и как он выглядит в коде?

> [!example]- Ответы
> 1. Изменится смысл: отступ определяет, какие строки входят в ветку. Строка с меньшим отступом
>    выполнится всегда, с большим — только внутри ветки. Неверный отступ даёт либо
>    `IndentationError`, либо тихо неверную логику.
> 2. **Одно** — первое истинное. До остальных очередь не дойдёт, потому что лестница
>    заканчивает работу на первой истине.
> 3. Он получит «хорошо»: условие `>= 60` истинно и для 95, а проверка `>= 90` стоит ниже
>    и не выполнится. Поэтому строгие условия ставят первыми.
> 4. Значениями 89, 90 и 91: чуть меньше границы, ровно на границе, чуть больше. Так видно,
>    что обе стороны и сама граница обрабатываются так, как задумано, и ни одно значение
>    не потерялось.
> 5. Истинно, когда истинно хотя бы одно из простых условий (или оба сразу). Ложно — только
>    если ложны все части.
> 6. Это значение, для которого не выполняется ни одно условие, а ветки `else` нет (или есть,
>    но подразумевалось другое). В коде: ветка ничего не делает, переменная остаётся без
>    значения — и дальше либо ошибка, либо неверный старый результат.
