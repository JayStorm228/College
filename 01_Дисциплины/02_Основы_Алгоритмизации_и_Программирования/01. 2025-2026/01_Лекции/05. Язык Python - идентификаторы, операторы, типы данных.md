# От схемы к языку

В блоке А решение задачи записывалось схемой и псевдокодом:

```text
ВВОД a, b
s := a + b
ВЫВОД s
```

Python — один из способов записать тот же алгоритм так, чтобы его выполнил компьютер:

```python
a = 5
b = 3
s = a + b
print(s)
```

Разница только в записи: `:=` превратилось в `=`, а `ВВОД` и `ВЫВОД` — в функции `input()`
и `print()`. Логика осталась той же, и это главное: **писать код — значит записывать знакомый
алгоритм на языке**.

Python — **интерпретируемый** язык: специальная программа-интерпретатор читает файл строка
за строкой сверху вниз и сразу выполняет то, что прочитала. Отсюда два следствия:

- порядок строк — часть программы (ровно как порядок блоков на схеме);
- ошибка обнаруживается при выполнении: до неё программа могла уже что-то посчитать.

# Алфавит и служебные слова

Программа на Python состоит из символов:

| Что | Что входит |
|---|---|
| латиница | `a`–`z`, `A`–`Z` — русские буквы в коде не используются |
| цифры | `0`–`9` |
| знаки | `+ - * / = ( ) [ ] { } : , . _ " ' #` и другие |
| служебные слова | `if`, `else`, `for`, `while`, `def`, `return`, `import`, `True`, `False`, `None` и т. п. |

**Служебные слова** (их ещё называют ключевыми) — зарезервированные слова языка. Их нельзя
использовать как имена. Заучивать список не нужно: редактор подсвечивает их другим цветом,
а интерпретатор сообщит об ошибке, если такое слово попало в имя.

> [!note] Комментарии
> Всё после знака `#` до конца строки Python игнорирует — это **комментарий**, пояснение
> для человека. Хороший комментарий объясняет «почему», а не «что»: что именно делает строка
> `s = a + b`, видно и без него.

# Имена: переменные, константы, функции

**Переменная** — имя, за которым закреплено значение. Значение можно менять, имя остаётся.
В Python у переменной три важные особенности:

1. **имя** — то, как ты обращаешься к значению в коде;
2. **значение** — то, что в переменной лежит;
3. **тип значения** — определяется автоматически, отдельно его указывать не надо.

Правила имён (**идентификаторов**):

- начинается с буквы (латиница) или `_`, не с цифры: `count`, `_tmp`, но не `2count`;
- состоит из букв, цифр и `_`, без пробелов: `total_sum`, но не `total sum`;
- не совпадает со служебным словом: `for = 5` — синтаксическая ошибка;
- регистр важен: `age` и `Age` — разные переменные.

По соглашению PEP 8 (стандарт оформления кода Python) имена пишут так:

| Что именуем | Стиль | Пример |
|---|---|---|
| переменная | `змеиный_регистр`, строчные | `total_price`, `average_score` |
| функция | тоже строчные, обычно глагол | `count_words()`, `find_max()` |
| класс | `CamelCase` с большой буквы | `Triangle`, `StudentCard` |
| константа | ЗАГЛАВНЫМИ | `MAX_SCORE = 100`, `PI = 3.14` |

> [!important] Имя — это документация
> `s = a + b` понятно только автору и только сейчас. `total = price + delivery` понятно через
> месяц и любому читателю. Привычка называть по смыслу — самая дешёвая из хороших привычек:
> она экономит часы отладки.

# Динамическая типизация

Python — язык с **динамической типизацией**: тип значения выясняется во время выполнения, а не
заранее. Одна и та же переменная в разное время может хранить значения разных типов:

```python
value = 42          # сейчас int
value = "сорок два" # теперь str — так можно
print(type(value))  # <class 'str'>
```

Функция `type()` показывает тип значения. Аннотации — подсказка читателю, что ты **ожидаешь**
увидеть в переменной; интерпретатор их не проверяет:

```python
count: int = 0
name: str = "Павел"
price: float = 199.90
```

> [!warning] «Переменная имеет тип» — неточность
> Тип есть у **значения**, а не у имени. Правильнее говорить «переменная `count` сейчас указывает
> на целое число». Понимание этой мелочи пригодится, когда появится список, в котором могут
> лежать значения разных типов.

# Основные типы данных

| Тип | Обозначение | Примеры | Для чего |
|---|---|---|---|
| целое число | `int` | `0`, `42`, `-7` | счётчики, количества, номера |
| число с плавающей точкой | `float` | `3.14`, `-0.5`, `1e3` | измерения, деньги, любые дроби |
| строка | `str` | `"привет"`, `'Python'` | текст, имена, сообщения |
| логический | `bool` | `True`, `False` | результат проверки условия |
| «ничего» | `NoneType` | `None` | отсутствие значения |

`1e3` — это экспоненциальная запись: `1 * 10³ = 1000.0`. Тип у такого значения — `float`.

# Числа и арифметика

Операции над числами:

| Операция | Знак | Пример | Результат |
|---|---|---|---|
| сложение | `+` | `5 + 3` | `8` |
| вычитание | `-` | `5 - 3` | `2` |
| умножение | `*` | `5 * 3` | `15` |
| деление | `/` | `7 / 2` | `3.5` — **всегда** `float` |
| целочисленное деление | `//` | `7 // 2` | `3` |
| остаток от деления | `%` | `7 % 2` | `1` |
| возведение в степень | `**` | `2 ** 10` | `1024` |

Порядок операций — как в математике: сначала `**`, потом `*`, `/`, `//`, `%`, затем `+` и `-`.
Скобки меняют порядок:

```python
average = (a + b) / 2   # сначала сложение, потом деление — верно
wrong = a + b / 2       # сначала делится b — почти всегда не то, что нужно
```

> [!warning] `//` не округляет, а отбрасывает
> Целочисленное деление отбрасывает дробную часть **вниз**, а не «округляет к ближайшему»:
> `7 // 2` даёт `3`, `-7 // 2` даёт `-4` (не `-3`!). Для округления есть `round()`.

Остаток `%` — самый полезный «неочевидный» оператор: он отвечает на вопросы «число чётное?»
(`n % 2 == 0`), «какой последний разряд?» (`n % 10`), «пора перейти на новую строку?».

> [!note] Почему 0.1 + 0.2 даёт 0.30000000000000004
> Дробные числа хранятся в двоичном виде, и `0.1` в нём точно не представимо — как `1/3`
> не записать точно в десятичной дроби. Это не ошибка Python, так устроены все языки.
> Для вывода результата используют округление: `round(x, 2)` или форматирование
> `f"{x:.2f}"`. Сравнивать дробные числа «через `==`» почти всегда плохая идея.

# Логические значения и сравнения

Сравнения возвращают `bool` — `True` или `False`:

| Знак | Значит |
|---|---|
| `==` | равно |
| `!=` | не равно |
| `<`, `>`, `<=`, `>=` | меньше, больше, не больше, не меньше |

> [!warning] `=` и `==` — разные вещи
> Один знак равенства **присваивает** значение: `a = 5`. Два знака **сравнивают**: `a == 5`.
> Перепутать их — классическая ошибка; в условии это ловится, но лучше не привыкать.

Логические операции: `and` (и), `or` (или), `not` (не).

```python
is_adult = age >= 18
can_ride = height >= 140 and age >= 12
has_discount = is_student or is_pensioner
```

В Python можно писать цепочки сравнений — они читаются как в математике:

```python
in_range = 0 <= score <= 100
```

# Приведение типов

Значение одного типа можно преобразовать в другой:

| Функция | Что делает | Пример | Результат |
|---|---|---|---|
| `int()` | в целое (дробную часть отбрасывает) | `int("42")`, `int(3.99)` | `42`, `3` |
| `float()` | в дробное | `float("3.14")` | `3.14` |
| `str()` | в строку | `str(42)` | `"42"` |
| `bool()` | в логическое | `bool(0)`, `bool(5)` | `False`, `True` |
| `round()` | округляет | `round(3.14159, 2)` | `3.14` |

Ловушки, на которые наступают все:

```python
int("3.14")   # ошибка ValueError: строка не похожа на целое число
int("три")    # ошибка ValueError
int(3.99)     # 3 — именно отбрасывание, а не округление
```

# Вывод и ввод

**Вывод.** Функция `print()` выводит значения в консоль:

```python
print("Цена:", 199.9)                 # Цена: 199.9  — значения через пробел
print("a", "b", sep=" | ")            # a | b         — свой разделитель
print("Строка без перевода", end=" ") # end заменяет перевод строки в конце
```

Первая строка обычная, а в двух других — две настройки `print()`, которые дописывают в скобках
в виде `имя=значение`:

- `sep` (separator) — чем разделять значения, по умолчанию пробелом;
- `end` — чем заканчивать вывод, по умолчанию переводом строки.

Нужны они редко — в таблицах и когда вывод идёт «в одну строку», — но знать о них стоит:
встречаются в чужом коде.

Для вставки значений внутрь текста используют **f-строки** — перед кавычками ставится буква `f`,
а в фигурных скобках пишут имена переменных и даже выражения:

```python
price = 199.9
count = 3
total = price * count
print(f"Товаров: {count}, сумма: {total:.2f} руб.")
```

`{total:.2f}` — формат: два знака после запятой. Так выводят деньги и измерения, чтобы
не показывать `599.6999999999999`.

**Ввод.** Функция `input()` читает строку, которую набрал пользователь:

```python
name = input("Как тебя зовут? ")
age = int(input("Сколько тебе лет? "))   # преобразуем строку в число
print(f"Привет, {name}! Через год тебе будет {age + 1}.")
```

> [!important] `input()` всегда возвращает строку
> Каким бы ни был ввод, `input()` отдаёт `str`. Чтобы считать число, нужен `int(input(...))`
> или `float(input(...))`. Если этого не сделать, `"5" + "3"` даст `"53"`, а не `8`.
> И помни: если пользователь введёт не число, `int()` выбросит `ValueError` — что с этим делать,
> разбирается в [[06. Среды разработки и виртуальное окружение]].

# Ошибки: читать и обрабатывать

Программа может остановиться на середине — например, если пользователь ввёл «двадцать» там,
где ожидалось число. Это не поломка компьютера: Python **сообщает**, что случилось и где,
а дальше выбор программиста — исправить код или обработать ошибку.

## Как читать сообщение об ошибке

Попробуем спросить возраст, а в ответ ввести слово:

```python
age = int(input("Сколько тебе лет? "))     # вводим: двадцать
```

Python остановится и напечатает примерно такое:

```text
Traceback (most recent call last):
  File "main.py", line 1, in <module>
    age = int(input("Сколько тебе лет? "))
          ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
ValueError: invalid literal for int() with base 10: 'двадцать'
```

Это **traceback** — «обратный след»: от места остановки назад к причинам. Читать его нужно
с **конца**, а не с начала:

1. последняя строка — **тип ошибки** и причина: `ValueError`, «не могу превратить строку
   `двадцать` в целое число»;
2. выше — **файл и номер строки**: `main.py`, строка 1;
3. под ними — сам код этой строки.

> [!important] Три шага вместо угадывания
> 1. Посмотреть **тип** ошибки — он называет причину. 2. Найти **строку** в своём коде.
> 3. Подумать, какие значения там оказались. Этих пяти минут хватает почти всегда — вместо
> «попробую поменять тут и там».

**Основные ошибки, которые встретятся в курсе:**

| Ошибка | Когда возникает | Что делать |
|---|---|---|
| `SyntaxError` | нарушен синтаксис: забыта скобка, кавычка, двоеточие | исправить написанное — программа даже не начала выполняться |
| `NameError` | имя не определено: опечатка или переменная ещё не создана | проверить имя и порядок строк |
| `TypeError` | операция не подходит типу: `"5" + 5` | привести типы: `int("5") + 5` |
| `ValueError` | тип подходит, значение — нет: `int("двадцать")` | проверить ввод: пользователь ввёл не число |
| `ZeroDivisionError` | деление на ноль | проверить знаменатель до деления |
| `IndexError` | выход за границы последовательности | проверить индексы |
| `FileNotFoundError` | файла по указанному пути нет | проверить путь и имя файла |

## Ожидаемую ошибку можно обработать: `try` / `except`

Иногда ошибку **ждут** и не хотят останавливать программу: просят число, а человек может ввести
слово. Такой участок оборачивают в `try`:

```python
try:
    age = int(input("Сколько тебе лет? "))
except ValueError:
    print("Нужно ввести целое число, например 15")
```

Читается так: **попробуй** выполнить код в `try`; если случится `ValueError`, не падай —
выполни то, что написано в `except`.

Как правильно выбирать, что перехватывать:

- указывать **конкретный** тип ошибки (`except ValueError`), а не всё подряд
  (`except Exception`) — иначе программа проглотит и настоящие ошибки, о которых надо знать;
- `except` без типа не пишут вовсе: он прячет причины;
- держать в `try` **только тот участок**, где ошибку ждут, а не весь код сразу.

> [!note] Что дальше с исключениями
> Полный набор возможностей — `else`, `finally`, `raise` и свои классы исключений — разбирается
> в **инженерном модуле** в конце курса. Там же видно, почему `except Exception: pass` — привычка,
> из-за которой потом сутками ищут ошибку. Пока достаточно базиса: `try`, конкретный `except`,
> понятное сообщение пользователю.

# Встроенные функции и модуль math

Часть математики уже есть в языке — это **встроенные функции**, их не надо импортировать:

| Функция | Что делает | Пример |
|---|---|---|
| `abs(x)` | модуль числа | `abs(-7)` → `7` |
| `round(x, n)` | округление до `n` знаков | `round(3.14159, 2)` → `3.14` |
| `pow(x, y)` | степень (то же, что `x ** y`) | `pow(2, 10)` → `1024` |
| `min(...)`, `max(...)` | минимум и максимум | `max(3, 9, 4)` → `9` |
| `sum(...)` | сумма последовательности | `sum([1, 2, 3])` → `6` |

В записи `sum([1, 2, 3])` используется **список** — набор значений в квадратных скобках.
Списки подробно разбираются в [[11. Кортежи, списки, словари]]; пока читай такую запись
как «несколько чисел подряд».

Всё остальное — в модуле `math`:

```python
import math

print(math.sqrt(16))      # 4.0 — квадратный корень
print(math.pi)            # 3.141592653589793
print(math.floor(3.9))    # 3 — вниз
print(math.ceil(3.1))     # 4 — вверх
print(math.sin(math.pi / 2))  # 1.0 — аргумент в радианах
```

> [!tip] Импорт с алиасом вместо «звёздочки»
> `import math as m` — понятная короткая запись: `m.sqrt(16)`. Запись `from math import *`
> тянет в программу сотни имён, о которых читатель не знает: непонятно, откуда взялась функция.
> Исключение — когда нужны одна-две функции: `from math import sqrt, pi`.

# Как это делают в проекте

**Привычка 1. Имя объясняет смысл.** `total_price`, `items_count`, `is_ready` вместо `a`, `b`, `c`;
однобуквенные имена допустимы только для счётчиков в коротких циклах.

**Привычка 2. Пробелы вокруг операторов.** `total = price * count` читается быстрее, чем
`total=price*count`. Это правило PEP 8, и ему следует весь Python-код в мире.

**Привычка 3. f-строки вместо склейки.** `f"Итого: {total:.2f}"` понятнее и короче, чем
`"Итого: " + str(total)`, а точность задаётся прямо в шаблоне.

**Привычка 4. Не бояться `type()`.** Когда программа ведёт себя странно, первым делом проверяют
тип: `print(type(value))`. Девять из десяти «непонятных» ошибок у начинающих — это строка там,
где ожидалось число.

> [!note] Про проверки ввода
> В учебных задачах данные обычно вводят «правильно», и это нормально. В настоящей работе
> ввод приходит от человека, и в нём бывает что угодно: буквы вместо числа, запятая вместо
> точки, пустая строка. Базис защиты разобран выше — `try` / `except` с конкретным типом
> ошибки; более строгие способы (проверка диапазона, ограничение попыток, свои исключения) —
> в инженерном модуле в конце курса.

# Ключевые термины

| Термин | Определение |
|---|---|
| **Идентификатор** | имя, данное переменной, функции или классу по правилам языка |
| **Переменная** | имя, за которым закреплено значение; значение можно менять |
| **Константа** | имя для значения, которое не должно меняться; по соглашению пишется заглавными |
| **Динамическая типизация** | тип определяется во время выполнения по значению, а не заранее |
| **Аннотация типа** | запись «какой тип ожидается», подсказка человеку, интерпретатор её не проверяет |
| **Служебное слово** | зарезервированное слово языка, его нельзя использовать как имя |
| **`int`, `float`, `str`, `bool`** | целое, дробное, строка, логическое значение |
| **Приведение типов** | преобразование значения одного типа в другой: `int("42")` |
| **f-строка** | строка с подстановкой значений: `f"Итого: {total:.2f}"` |
| **Модуль** | файл с готовыми функциями и константами, подключается через `import` |
| **Комментарий** | текст после `#`, который интерпретатор игнорирует |
| **PEP 8** | стандарт оформления кода Python: имена, пробелы, длина строк |
| **Исключение (ошибка)** | сигнал, что операция не может быть выполнена: `ValueError`, `TypeError`, `IndexError` и другие |
| **Traceback** | сообщение Python о том, где и почему программа остановилась |
| **`try` / `except`** | конструкция «попробуй выполнить, а при такой-то ошибке сделай вот это» |

# Типичные заблуждения

- ❌ **«`input()` возвращает число, если ввести число».** Возвращает всегда строку. Нужно число —
  преобразуй: `int(input(...))`.
- ❌ **«`"5" + "3"` — это 8».** Это `"53"`: строки складываются «встык». Числа складывает
  только числовой `+`.
- ❌ **«`//` округляет».** Оно отбрасывает дробную часть вниз: `-7 // 2` равно `-4`. Для
  округления — `round()`.
- ❌ **«Дробные числа можно сравнивать через `==`».** `0.1 + 0.2 == 0.3` даст `False`: числа
  хранятся приближённо. Сравнивай с точностью: `abs(a - b) < 1e-9`.
- ❌ **«`=` и `==` — одно и то же».** Первое присваивает, второе сравнивает. `a = 5` в условии —
  ошибка, `a == 5` — проверка.
- ❌ **«`abs`, `round`, `max` — это функции `math`».** Они встроенные и работают без `import`.
  В `math` лежат `sqrt`, `sin`, `floor`, `log` и другие.
- ❌ **«Аннотации типов проверяются».** Нет: `count: int = "текст"` сработает без ошибок.
  Аннотация — для читателя и для инструментов, а не для интерпретатора.
- ❌ **«Ошибка — значит, программа плохая».** Ошибка — это сообщение: тип, причина, строка.
  Читать его с конца быстрее, чем угадывать, что поменять.
- ❌ **«`except Exception` надёжнее, потому что ловит всё».** Он ловит и настоящие сбои, о которых
  нужно знать: программа «работает», а причина потеряна. Ловят конкретный тип.
- ❌ **«Русские буквы в именах — норм».** Технически Python их допускает, но такой код трудно
  набирать и невозможно передать другому: имена пишут латиницей.

# Проверь себя

1. Чем переменная отличается от значения и от константы?
2. Какой тип у значения `7 / 2` и какой — у `7 // 2`?
3. Что выведет `print(type(input("Число: ")))`, если ввести `42`?
4. Почему `a + b / 2` и `(a + b) / 2` дают разные результаты?
5. Какие из функций `abs`, `sqrt`, `min`, `round`, `sin` доступны без `import`?
6. Зачем нужна f-строка и как в ней задать два знака после запятой?
7. Что написано в последней строке traceback и почему читать его надо с конца?
8. Когда используют `try` / `except` и почему в `except` указывают конкретный тип ошибки?

> [!example]- Ответы
> 1. **Значение** — то, что хранится (например, `42`). **Переменная** — имя, через которое
>    к этому значению обращаются; значение по имени можно заменить. **Константа** — имя для
>    значения, менять которое не собираются: по соглашению его пишут заглавными (`MAX_SCORE`),
>    язык это никак не запрещает, это договорённость между программистами.
> 2. `7 / 2` → `3.5`, тип `float` (обычное деление всегда даёт дробное). `7 // 2` → `3`,
>    тип `int` (целочисленное деление отбрасывает дробную часть).
> 3. `<class 'str'>`. `input()` всегда возвращает строку, даже если набраны только цифры.
> 4. В `a + b / 2` сначала выполняется деление (у него выше приоритет), потом сложение.
>    В `(a + b) / 2` скобки заставляют сложить, а потом разделить. Это разные алгоритмы,
>    и первый почти всегда не тот, что нужен.
> 5. Без `import` работают `abs`, `min`, `round` — это встроенные функции. `sqrt` и `sin`
>    лежат в модуле `math`: нужен `import math` и вызов `math.sqrt(...)`, `math.sin(...)`.
> 6. Чтобы вставить значения внутрь текста и не склеивать куски оператором `+`.
>    Точность задаётся форматом: `f"{total:.2f}"` — два знака после запятой.
> 7. Последняя строка называет **тип** ошибки и её причину, например
>    `ValueError: invalid literal for int()...`. Выше — файл и номер строки, ещё выше — сам код.
>    Поэтому читают с конца: сначала «что случилось», потом «где».
> 8. Когда ошибку **ожидают** и не хотят останавливать программу — чаще всего при вводе данных
>    человеком. Конкретный тип (`except ValueError`) не даёт проглотить настоящие ошибки:
>    `except Exception` скрывает причину.
