# 06. Практика. Гибкие методологии

> [!abstract] О чём работа
> **Теория:** [[08. Гибкие методологии — Agile, Scrum, Kanban]].
> **Что закрепляется:** различия Agile, Scrum и Kanban, планирование первого спринта и оформление доски с ограничением WIP.
> **Состав работы:** тестовые вопросы, открытые вопросы и ситуационная задача.
> Ответы и их формулировки сохранены из выполненной работы.

# Ход работы

## Блок А. Тестовые вопросы

**1.** Что из перечисленного является ценностью манифеста Agile?

а) Документация важнее работающего продукта.  
б) Готовность к изменениям важнее следования первоначальному плану.  
в) Процессы и инструменты важнее людей и взаимодействия.

Ответ: Б

**2.** Какая роль в Scrum отвечает за приоритизацию задач?

а) Скрам-мастер.  
б) Команда разработки.  
в) Владелец продукта.

Ответ: В

**3.** Что является главным отличием Kanban от Scrum?

а) В Kanban нет ролей.  
б) В Kanban работа течёт непрерывно, без фиксированных спринтов.  
в) В Kanban не нужны задачи.

Ответ: Б

**4.** Что такое инкремент в Scrum?

а) Список задач на спринт.  
б) Работающий продукт, выдаваемый в конце спринта.  
в) Ежедневная встреча команды.

Ответ: б

**5.** В какой ситуации водопадная модель предпочтительнее гибких методологий?

а) Разработка мобильного приложения для стартапа.  
б) Создание критической системы безопасности для атомной станции.  
в) Разработка интернет-магазина с часто меняющимися требованиями.

Ответ: б

## Блок Б. Открытые вопросы

**Вопрос 1.** Объясните своими словами разницу между Agile и Scrum. Почему люди часто путают эти понятия?

Ответ: 
- Agile - набор ценностей при разработке
- Scrum - конкретный способ реализации этих ценностей

**Вопрос 2.** Представьте, что вы Скрам-мастер. На ретроспективе команда жалуется, что спринты постоянно срываются из-за того, что задачи «прилетают» в середине спринта от заказчика. Какие действия вы предпримете?

Ответ: Я бы предпочёл выделить прилетевшие требования заказчика в следующий спринт, чтобы не срывать текущий. Также стоит согласовать с заказчиком передачу требований на одной из ретроспектив.

**Вопрос 3.** Почему в гибких методологиях тестирование встроено в каждый спринт, а не откладывается на конец проекта? Что произойдёт, если отложить тестирование?

Ответ: В гибких методологиях важно, чтобы каждый спринт проходило тестирование. Потому что на выходе получается одна из версий продукта. В следующем спринте поверх предыдущей версии будет добавлено несколько фич. Это приводит к накоплению тех. долга и к потенциальным багам в продукте.

**Вопрос 4.** Сравните ограничения работы в процессе (WIP) в Kanban и объёма работ в спринте в Scrum. Какую проблему они решают?

Ответ: 
- Kanban - ограничение количества задач на человека. Задачи выполняются по мере разгрузки людей, следующая не начнётся, пока не освободится "место". Это позволяет ограничить поступление новых задач и ограничить зависания работы на отдельных этапах.
- Scrum - Количество задач на команду за спринт. Команда выбирает задачи, ориентируясь на свои возможности выполнения за спринт. Это позволяет бороться с завышенным планированием и попытками команды взять на себя больше, чем она может сделать.

## Блок В. Ситуационная задача

**Ситуация:** Ваша команда из 4 человек разрабатывает мобильное приложение «Трекер привычек». У вас есть 2 недели на первый спринт. Известны следующие задачи:

1. Дизайн экрана списка привычек
2. Создание таблицы «Привычки» в базе данных
3. Функция добавления новой привычки
4. Функция отметки привычки как выполненной
5. Дизайн экрана статистики
6. Функция удаления привычки
7. Иконка приложения
8. Функция установки напоминания

**Задание 1 (5 баллов).** Выберите 3-4 задачи, которые вы возьмёте в первый спринт. Обоснуйте свой выбор: почему именно эти задачи, а не другие? Какие задачи вы отложите на следующий спринт?

Ответ: 
1. Задачи: 2, 3, 4, 6.
2. Обоснование: Они связаны между собой и реализуют базовые операции над любой базой. В конце можно будет получить почти что полноценный CLI вариант проекта. Уже поверх этой реализации проще всего будет накатить визуальную составляющую и прочие фичи.

**Задание 2 (5 баллов).** Нарисуйте текстом структуру Kanban-доски для этого проекта: какие колонки будут, какие задачи в каких колонках находятся в начале спринта. Укажите ограничение WIP (количество задач «в работе» одновременно).

|    Функция добавления новой привычки    | Создание таблицы "привычки" в БД |             |           |
| Функция отметки привычки как выполненой |                                  |             |           |
|        Функция удаления привычки        |                                  |             |           |
